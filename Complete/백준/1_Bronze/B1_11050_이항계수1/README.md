## 🔗 문제 링크

[백준 11050번 - 이항 계수 1](https://www.acmicpc.net/problem/11050)

**난이도**: Bronze 1

---

## 🤔 접근법

자연수 N과 정수 K가 주어졌을 때 이항 계수 C(N, K)를 구하는 문제.

**이항 계수 정의**: C(n, k) = n! / (k! × (n-k)!)

여러 가지 방법으로 해결 가능하다: 재귀 팩토리얼, 최적화 for문, 동적 프로그래밍 등

이 문제는 **N ≤ 10**으로 매우 작지만, 효율성 측면에서 **최적화 for문**이 가장 우수하다.

---

## 💡 정답 풀이 방법

### 📌 3가지 구현 방법 비교

#### 1. **[Answer(재귀).cpp.txt](./Answer(재귀).cpp.txt)** - 재귀 팩토리얼 방식

   **알고리즘**: 팩토리얼 재귀 함수 구현

   ```cpp
   C(n, k) = n! / (k! × (n-k)!)
   ```

   **특징**:
   - ✅ 직관적, 이해하기 쉬움
   - ✅ 수학 공식과 1:1 대응
   - ❌ 중복 계산 (3번의 팩토리얼)
   - ❌ 재귀 스택 사용

   **시간 복잡도**: O(n) - 각 팩토리얼마다 n번 곱셈

   **공간 복잡도**: O(n) - 재귀 스택

<br>

#### 2. **[Answer(단순 for문).cpp.txt](./Answer(단순 for문).cpp.txt)** - 최적화 for문 ✅ 추천

   **알고리즘**: 약분 최적화

   ```cpp
   C(n, k) = [n × (n-1) × ... × (n-k+1)] / k!
   ```

   **핵심 아이디어**:
   ```
   n! / (n-k)! = n × (n-1) × ... × (n-k+1)

   ⚠️ (n-k)! 부분이 약분되므로 계산 불필요!
   ```

   **특징**:
   - ✅ **가장 효율적** - 최소한의 곱셈만 수행
   - ✅ 오버플로우 위험 감소
   - ✅ 재귀 없음
   - ✅ k가 작을수록 압도적으로 유리

   **시간 복잡도**: O(min(k, n-k))

   **공간 복잡도**: O(1)

<br>

#### 3. **[Answer(단순 for + 모듈러).cpp.txt](./Answer(단순 for + 모듈러).cpp.txt)** - N이 클 때

   **알고리즘**: 페르마의 소정리를 이용한 모듈러 연산

   ```cpp
   C(n, k) mod p = [분자 × 분모^(-1)] mod p
   ```

   **핵심 개념**:
   ```
   모듈러 연산에서는 나눗셈 직접 불가능!
   ❌ (a / b) % MOD
   ✅ (a × b^(-1)) % MOD  → 역원을 구해서 곱셈으로 변환

   페르마의 소정리:
   - p가 소수이고 gcd(a, p) = 1이면
   - a^(p-1) ≡ 1 (mod p)
   - 따라서: a^(-1) ≡ a^(p-2) (mod p)
   ```

   **특징**:
   - ✅ N이 매우 클 때 (N ≤ 100,000) 필수
   - ✅ 오버플로우 완전 방지
   - ✅ 거듭제곱 분할 정복: O(log MOD)
   - ❌ 구현 복잡도 높음

   **시간 복잡도**: O(k + log MOD)

   **공간 복잡도**: O(1)

## 📊 구체적 예시로 비교

### **예제: C(10, 2)**

| 방법 | 계산 과정 | 연산 횟수 |
|------|----------|----------|
| **재귀** | 10! = 3,628,800<br>2! = 2<br>8! = 40,320<br>→ 3,628,800 / (2 × 40,320) = 45 | 곱셈 19번<br>나눗셈 2번 |
| **최적화** | 10 × 9 = 90<br>2 × 1 = 2<br>→ 90 / 2 = 45 | 곱셈 3번<br>나눗셈 1번 |
| **차이** | - | **6.3배 빠름** |

### **예제: C(100, 2) - 차이가 극명해짐**

| 방법 | 계산 과정 | 연산 횟수 |
|------|----------|----------|
| **재귀** | 100! (약 10^157, 오버플로우 위험)<br>2! = 2<br>98! (엄청 큰 수) | 곱셈 199번<br>⚠️ 오버플로우 |
| **최적화** | 100 × 99 = 9,900<br>2 × 1 = 2<br>→ 9,900 / 2 = 4,950 | 곱셈 3번<br>✅ 안전 |
| **차이** | - | **66배 빠름** |

## ⏱️ 시간복잡도 상세 비교

| 방법 | 시간 복잡도 | C(10, 2) | C(100, 2) | C(100, 50) |
|------|------------|---------|----------|-----------|
| **재귀** | O(n) | 20번 | 200번 | 250번 |
| **최적화** | O(min(k, n-k)) | 2번 | 2번 | 50번 |
| **모듈러** | O(k + log MOD) | 2번 + log | 2번 + log | 50번 + log |

**⚠️ 핵심**: k가 작을수록 최적화 for문이 압도적으로 유리!

## 💡 왜 사람들은 재귀로 푸는가?

1. **직관적이고 이해하기 쉬움** - 수학 공식과 1:1 대응
2. **구현이 간단함** - 재귀 함수 3줄
3. **이 문제의 제약 조건** - N ≤ 10이라 성능 차이 미미 (1ms 미만)
4. **교육적 목적** - 재귀 연습, 팩토리얼 개념 학습
5. **코딩테스트 특성** - 정답만 맞으면 됨, 구현 속도 중요

## 📌 핵심 정리

✅ **최적화 for문이 실제로 가장 효율적** - O(min(k, n-k))

✅ **약분 최적화가 핵심** - (n-k)! 계산 불필요

✅ **재귀는 직관적** - 하지만 비효율적 (O(n))

✅ **N이 크면 모듈러 필수** - 페르마의 소정리 활용
