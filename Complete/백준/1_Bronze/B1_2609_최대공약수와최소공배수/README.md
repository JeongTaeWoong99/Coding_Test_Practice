## 📊 유클리드 호제법 작동 원리

### 🔍 핵심 원리

**유클리드 호제법 (Euclidean Algorithm)**:
```
GCD(a, b) = GCD(b, a % b)
base case: b == 0일 때, GCD(a, 0) = a
```

**왜 이게 성립하는가?**
- a를 b로 나눈 나머지를 r이라고 하면: `a = b × q + r` (q는 몫)
- a와 b의 공약수는 b와 r의 공약수와 같다
- 따라서 `GCD(a, b) = GCD(b, r)` = `GCD(b, a % b)`

## ❓ 큰 수가 앞에 와야 하는가?

### 🎯 결론: 필수 아님, 하지만 효율적!

**✅ 큰 수가 앞에 오는 경우 (권장)**:
```cpp
GCD(24, 18)  // 24 > 18
→ GCD(18, 24 % 18)
→ GCD(18, 6)
→ GCD(6, 0)
→ return 6

총 3번의 재귀 호출
```

**✅ 작은 수가 앞에 오는 경우 (자동 교환됨)**:
```cpp
GCD(18, 24)  // 18 < 24
→ GCD(24, 18 % 24)  ← 18 % 24 = 18 (나머지가 자기 자신!)
→ GCD(24, 18)       ← 첫 단계에서 자동으로 큰 수가 앞으로!
→ GCD(18, 6)
→ GCD(6, 0)
→ return 6

총 4번의 재귀 호출 (1번 추가!)
```

### 📊 왜 작은 수가 앞에 와도 작동하는가?

**핵심**: `a < b`일 때, `a % b = a` (나머지가 자기 자신)

```
예: 18 % 24 = 18  (18을 24로 나누면 몫 0, 나머지 18)

따라서:
GCD(18, 24)
→ GCD(24, 18 % 24)
→ GCD(24, 18)  ← 자동으로 큰 수가 x, 작은 수가 y로 교환됨!
```

**결과**: 첫 번째 재귀 호출이 **스왑 역할**을 하고, 이후 정상 진행

### 💡 권장사항

**코드 작성 시 권장**:
```cpp
// 입력받을 때 큰 수를 먼저 넣기 (선택사항)
if(a < b) swap(a, b);  // 큰 수를 a에 저장

cout << GCD(a, b) << "\n";
```

**하지만 필수는 아님**:
- 유클리드 호제법은 어느 순서로 호출해도 **정확한 결과**를 보장
- 다만 큰 수를 앞에 두면 **재귀 호출 1회 절약** (미세한 성능 향상)
- 입력이 작은 문제에서는 차이가 거의 없음

**✅ 이 문제의 경우**: 입력을 그대로 사용해도 무방 (자동 교환)

## 📌 테스트 케이스로 보는 실행 흐름

**입력: 24 18**

### Step 1: GCD(24, 18) 계산 과정

```
1단계: GCD(24, 18)
   → y(18) != 0 이므로 재귀 호출
   → GCD(18, 24 % 18)
   → GCD(18, 6)

2단계: GCD(18, 6)
   → y(6) != 0 이므로 재귀 호출
   → GCD(6, 18 % 6)
   → GCD(6, 0)

3단계: GCD(6, 0)
   → y(0) == 0 이므로 base case
   → return 6  ✅
```

**최대공약수 = 6**

<br>

### 📊 재귀 호출 스택 시각화
※ 최대 공약수를 찾으면, 단순 리턴을 통해, 값을 찾음(더해 지거나, 빼 지는게 아님!)

```
GCD(24, 18)
│
├─> GCD(18, 6)
│   │
│   ├─> GCD(6, 0)
│   │   │
│   │   └─> return 6  ⬆️
│   │
│   └─> return 6  ⬆️
│
└─> return 6  ⬆️

결과: 6
```

<br>

### 📐 나머지 연산 상세 분석

| 호출 | x | y | x % y | 다음 호출 |
|------|---|---|-------|-----------|
| 1단계 | 24 | 18 | 24 % 18 = **6** | GCD(18, 6) |
| 2단계 | 18 | 6 | 18 % 6 = **0** | GCD(6, 0) |
| 3단계 | 6 | 0 | - | **return 6** |

**✅ 핵심 포인트**:
- 매 단계마다 나머지가 점점 작아진다 (24 → 18 → 6 → 0)
- 나머지가 0이 되는 순간, 그때의 x값이 최대공약수!

<br>

### Step 2: LCM(24, 18) 계산 과정

```
LCM(24, 18) = (24 × 18) / GCD(24, 18)
            = 432 / 6
            = 72  ✅
```

**최소공배수 = 72**

## 💡 왜 유클리드 호제법이 효율적인가?

### 비교: 브루트 포스 vs 유클리드 호제법

**❌ 브루트 포스 방식** (비효율적):
```cpp
// 두 수 중 작은 값부터 1까지 감소시키며 공약수 찾기
// 24 > 18, 18부터 1까지 둘 다 나눴을 때, 나머지가 0이 나오는 6을 찾을 때 까지 반복!

int gcd = 1;
for(int i = min(a, b); i >= 1; i--)
{
    if(a % i == 0 && b % i == 0) 
    {
        gcd = i;
        break;
    }
}
```

시간 복잡도 : O(min(a, b)) → 최악의 경우 10,000번 반복!

**✅ 유클리드 호제법** (효율적):
```cpp
int GCD(int x, int y) 
{
    if(y == 0) 
        return x;
    
    return GCD(y, x % y);
}
```
시간 복잡도 : O(log(min(a, b))) → 24, 18의 경우 단 3번만 호출!

**성능 비교 (a=10000, b=9999)**:
- 브루트 포스: 최대 **9,999번** 반복
- 유클리드 호제법: 약 **20번** 재귀 호출

**속도 차이: 약 500배!** 🚀

## 🎯 최소공배수(LCM) 공식 증명

**왜 LCM(a, b) = (a × b) / GCD(a, b) 인가?**

```
a = GCD × m  (m은 a를 GCD로 나눈 몫)
b = GCD × n  (n은 b를 GCD로 나눈 몫)

LCM = GCD × m × n  (m과 n은 서로소)

따라서:
LCM = (GCD × m × n)
    = (GCD × m) × n
    = a × n
    = a × (b / GCD)
    = (a × b) / GCD  ✅
```

**예시: a=24, b=18, GCD=6**
```
24 = 6 × 4
18 = 6 × 3

LCM = 6 × 4 × 3 = 72
    = (24 × 18) / 6
    = 432 / 6
    = 72  ✅
```

## 🔧 구현 시 주의사항

### 2️⃣ 오버플로우 주의

```cpp
// ❌ 잘못된 코드 (오버플로우 가능)
int LCM(int x, int y) 
{
    return (x * y) / GCD(x, y);  // x * y가 int 범위 초과 가능!
}

// ✅ 올바른 코드 (오버플로우 방지)
int LCM(int x, int y) 
{
    return (x / GCD(x, y)) * y;  // 먼저 나누기
}
```

**단, 이 문제는 입력이 10,000 이하이므로 오버플로우 없음**

### 3️⃣ 재귀 vs 반복문

**재귀 방식** (가독성 좋음):
```cpp
int GCD(int x, int y) 
{
    if(y == 0) 
        return x;
    
    return GCD(y, x % y);
}
```

**반복문 방식** (스택 오버플로우 방지):
```cpp
int GCD(int x, int y) 
{
    while(y != 0) 
    {
        int temp = y;
        y        = x % y;
        x        = temp;
    }
    
    return x;
}
```

**두 방식 모두 시간 복잡도는 O(log(min(a, b)))로 동일**

## ✅ 핵심 정리

**🔸 최대공약수(GCD)**: 유클리드 호제법 - `GCD(a, b) = GCD(b, a % b)`

**🔸 최소공배수(LCM)**: `LCM(a, b) = (a × b) / GCD(a, b)`

**🔸 시간 복잡도**: O(log(min(a, b))) - 매우 효율적!
