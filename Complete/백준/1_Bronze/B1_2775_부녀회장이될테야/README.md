## 🔗 문제 링크

[백준 2775번 - 부녀회장이 될테야](https://www.acmicpc.net/problem/2775)

## 🤔 접근법

아파트의 각 층, 각 호에 사는 사람 수를 구하는 DP 문제.

조건:
- 0층의 i호에는 i명이 산다
- k층의 n호에 살려면 (k-1)층의 1호부터 n호까지 사람 수의 합만큼 데려와야 한다

이 문제는 **DP 바텀업 방식**으로 0층부터 14층까지 미리 모든 경우를 계산해두고, 테스트케이스마다 O(1)로 조회하는 방식이 가장 효율적이다.

---

## 💡 정답 풀이 방법

**알고리즘**: 다이나믹 프로그래밍 (DP - Bottom-up)

**핵심 아이디어**:
```
1. 2차원 DP 배열 선언: arr[층][호]
2. 기저 사례 초기화:
   - arr[i][0] = 1 (모든 층의 1호는 1명)
   - arr[0][i] = i+1 (0층의 i호는 i+1명, 인덱스 보정)
3. 점화식 적용:
   - arr[k][n] = arr[k][n-1] + arr[k-1][n]
   - (현재 위치) = (왼쪽) + (아래)
4. 모든 경우를 미리 계산 (0층~14층, 1호~14호)
5. 테스트케이스마다 arr[k][n-1] 조회 (1호 → 인덱스 0)
```

**시간 복잡도**: O(14×14) + O(T) ≈ O(1)
- 초기화 및 DP 테이블 구성: O(196)
- 테스트케이스 조회: O(T) × O(1)

**공간 복잡도**: O(14×14) = O(196)

## 📊 DP 테이블 예시

```
       1호  2호  3호  4호
2층 -  1    4    10   20
1층 -  1    3    6    10
0층 -  1    2    3    4
```

**계산 과정**:

※ 내 위치 값 = 내 아래 칸 + 내 왼쪽 칸

```
arr[1][2] = arr[1][1] + arr[0][2] = 3 + 2 = 3 (1층 3호)
          = (1층 2호) + (0층 3호)

arr[2][2] = arr[2][1] + arr[1][2] = 1 + 3 = 4 (2층 3호)
          = (2층 2호) + (1층 3호)
```

## 💡 다른 풀이 방법

이 문제는 여러 방법으로 풀 수 있다:

### 1. DP 탑다운 (재귀 + 메모이제이션)
- 필요한 값만 재귀로 계산
- 장점: 직관적, 필요한 부분만 계산
- 단점: 재귀 깊이 관리 필요

### 2. 조합론 (수학 공식)
- `k층 n호 = C(n+k-1, k)`
- 장점: 가장 빠름, 메모리 효율적
- 단점: 수학적 이해 필요

### 3. 1차원 DP (공간 최적화)
- 2차원 배열 → 1차원 배열
- 장점: 메모리 O(14)로 감소
- 단점: 테스트케이스마다 재계산

**결론**: 바텀업 방식이 구현 난이도와 성능 면에서 가장 균형잡힌 솔루션이다.
