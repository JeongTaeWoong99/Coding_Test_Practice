## 🔗 문제 링크

[백준 2869번 - 달팽이는 올라가고 싶다](https://www.acmicpc.net/problem/2869)

**난이도**: Silver 5

---

## 🤔 접근법

달팽이가 높이 V미터인 나무 막대를 올라가는 문제.

낮에는 A미터 올라가고, 밤에는 B미터 미끄러진다. 

☆ 단, **정상에 도달하면 미끄러지지 않는다**.

달팽이가 나무 막대를 모두 올라가는데 걸리는 **최소 날짜**를 구하는 문제.

**핵심**: 단순 시뮬레이션은 시간 초과 발생 (V 최대 10억) → **수학적 계산**으로 O(1)에 해결

---

## 💡 정답 풀이 방법

**알고리즘**: 수학(Mathematics)

**핵심 아이디어**:
```
1. 마지막 날에는 A만큼 올라가서 정상 도달
2. 마지막 업 전까지 도달해야 할 목표 = goal - up
3. 이 목표를 하루 순수익(up - down)으로 나눔
4. 나머지로 하루가 더 필요한지 판단
```

```cpp
   - V가 1,000,000,000 (10억)일 경우

```

**수학적 계산의 장점**:
```cpp
✅ O(1) 시간에 정답 계산
   - 반복문 없이 몇 번의 연산만으로 해결
   - 어떤 입력이 들어와도 즉시 계산 완료
```

### 2️⃣ 수학 공식 단계별 유도

#### 📐 Step 1: 패턴 파악

달팽이의 이동 패턴을 시각화하면:

```
패턴: 업 → 다운 → 업 → 다운 → ... → 업(도착)
      └─ 1사이클 ─┘ └─ 2사이클 ─┘     └ 마지막 업
```

**예제 1 시뮬레이션** (up=2, down=1, goal=5):

```
              위치 변화 그래프
높이 ↑
 5m  |                           ★(도착!)
 4m  |                     ╱──╲
 3m  |               ╱──╲  │
 2m  |         ╱──╲  │     │
 1m  |   ╱──╲  │     │
 0m  └────┴────┴────┴────┴────→ 시간
     0    1    2    3    4    (일)

1일차: 0 → (+2) → 2 → (-1) → 1
2일차: 1 → (+2) → 3 → (-1) → 2
3일차: 2 → (+2) → 4 → (-1) → 3
4일차: 3 → (+2) → 5 → 도착! (미끄러지지 않음)

답: 4일
```

**핵심 관찰**:
- 하루 순수익 = `up - down` = 2 - 1 = 1
- 마지막 날 전까지 3까지 올라가야 함
- 마지막 날에 +2해서 5에 도달!

---

#### 📐 Step 2: 마지막 업 분리

**왜 마지막 업을 분리하는가?**

```
일반 사이클: 업(+A) → 다운(-B) = 순수익 (A - B)
마지막 날:   업(+A) → 도착! (다운 없음)
             ↑
             이 부분이 특별함!
```

**목표 설정**:
- 전체 목표: `goal`
- 마지막 업 전 목표: `goal - up`
- 마지막 날에 `up`만큼 올라가서 `goal` 도달

**시각적 표현**:
```
goal (5m) ━━━━━━━━━━━━━ ← 최종 목표
          ↑
          | up (2m)
          |
goal-up(3m) ━━━━━━━━━━━ ← 마지막 업 전 목표
          ↑
          | (up - down) × day
          |
0m ━━━━━━━━━━━━━━━━━━ ← 시작점
```

---

#### 📐 Step 3: 필요한 날짜 계산 (몫)

**마지막 업 전까지 도달하는 날짜**:

```cpp
targetBeforeLastUp = goal - up
day = targetBeforeLastUp / diff  // 정수 나눗셈 (몫)
```

**예제로 이해하기**:

| 예제 | up | down | goal | diff | targetBeforeLastUp | day (몫) |
|------|-----|------|------|------|--------------------|----------|
| 1 | 2 | 1 | 5 | 1 | 3 | 3 |
| 2 | 5 | 1 | 6 | 4 | 1 | 0 |
| 3 | 100 | 99 | 1000000000 | 1 | 999999900 | 999999900 |

**⚠️ 주의**: 몫만으로는 정답이 아님! 나머지를 확인해야 함!

---

#### 📐 Step 4: 나머지로 하루 더 필요한지 판단

**나머지의 의미**:

```
나머지 = targetBeforeLastUp % diff

나머지 = 0: 딱 맞아떨어짐 → day일 동안 사이클로 목표 도달
나머지 > 0: 부족함 → 하루 더 필요
```

**예제 1 상세 계산** (up=2, down=1, goal=5):

```
targetBeforeLastUp = 5 - 2 = 3
diff = 2 - 1 = 1
day = 3 / 1 = 3

나머지 = 3 % 1 = 0 (딱 맞음!)

✅ 3일 동안 사이클로 3까지 도달 가능
   1일차: 0 → 1
   2일차: 1 → 2
   3일차: 2 → 3

   + 마지막 업 1일 → 총 4일
```

**예제 2 상세 계산** (up=5, down=1, goal=6):

```
targetBeforeLastUp = 6 - 5 = 1
diff = 5 - 1 = 4
day = 1 / 4 = 0

나머지 = 1 % 4 = 1 (부족!)

❌ 0일로는 1에 도달 불가 (0까지만 도달)
   → 하루 더 필요!

   1일차: 0 → 5 → 4 (목표 1 초과!)

   그런데 사실 1일차에 업(+5)으로 이미 6에 도달!

✅ 1일 동안 사이클로 4까지 도달
   + 마지막 업 1일 → 총 2일
```

---

### 3️⃣ 최종 코드 로직

```cpp
// 하루 올라가는 높이 차이
diff = up - down;

// 마지막 업을 제외한 목표 높이
int targetBeforeLastUp = goal - up;

// 이 높이까지 도달하는데 필요한 날짜 (몫)
day = targetBeforeLastUp / diff;

// 나머지 확인으로 하루 더 필요한지 판단
if (targetBeforeLastUp % diff == 0)
{
    // 딱 맞아떨어짐 = day일 동안 사이클 + 마지막 업 1일
    cout << day + 1 << "\n";
}
else
{
    // 나머지 있음 → 하루 더 필요 + 마지막 업 1일
    cout << day + 2 << "\n";
}
```

**경우별 정리**:

| 경우 | 나머지 | 출력 | 의미 |
|------|--------|------|------|
| 딱 맞음 | 0 | day + 1 | day일 사이클 + 마지막 업 1일 |
| 부족 | > 0 | day + 2 | day일 사이클 + 하루 더 + 마지막 업 1일 |

---

### 4️⃣ 다른 풀이 방법과 비교

**방법 1: 나머지로 판단 (현재 코드)**
```cpp
if (targetBeforeLastUp % diff == 0)
    cout << day + 1;
else
    cout << day + 2;
```
✅ 장점: 직관적, 이해하기 쉬움
❌ 단점: 조건문 필요

**방법 2: 수식으로 올림 처리 (정답 코드)**
```cpp
days = (goal - down - 1) / (up - down) + 1;
```
✅ 장점: 조건문 없이 한 줄로 해결
❌ 단점: 공식 유도 과정이 복잡함

**공식 유도 과정**:
```
목표: ceil((goal - up) / (up - down)) + 1

정수 나눗셈 올림 공식:
ceil(A / B) = (A + B - 1) / B

대입:
ceil((goal - up) / (up - down))
= (goal - up + up - down - 1) / (up - down)
= (goal - down - 1) / (up - down)

최종:
days = (goal - down - 1) / (up - down) + 1
```

**두 방법 모두 정답이지만**:
- 방법 1이 **이해하기 쉽고** 실수가 적음
- 방법 2가 **코드가 짧고** 간결함

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ long long 사용 - 언제 필요한가?

**문제 조건 확인**:
```
1 ≤ B < A ≤ V ≤ 1,000,000,000
```

**int 범위**: -2,147,483,648 ~ 2,147,483,647 (약 -21억 ~ 21억)

**long long 범위**: -9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807 (약 -920경 ~ 920경)

---

#### 🔍 변수별 범위 분석

**1) up, down, goal 변수**:
```cpp
int up, down, goal;  // 이건 괜찮을까?
```

**분석**:
- 최댓값: 1,000,000,000 (10억)
- int 최댓값: 2,147,483,647 (약 21억)
- 10억 < 21억 → ✅ **int 가능!**

---

**2) targetBeforeLastUp 변수**:
```cpp
int targetBeforeLastUp = goal - up;
```

**분석**:
- 최댓값: goal - 1 = 999,999,999 (약 10억)
- int 최댓값: 2,147,483,647 (약 21억)
- 10억 < 21억 → ✅ **int 가능!**

---

**3) diff 변수**:
```cpp
int diff = up - down;
```

**분석**:
- 최댓값: 1,000,000,000 - 1 = 999,999,999
- int 최댓값: 2,147,483,647 (약 21억)
- 10억 < 21억 → ✅ **int 가능!**

---

**4) day 변수**:
```cpp
int day = targetBeforeLastUp / diff;
```

**분석**:
- 최댓값 경우: goal=1,000,000,000, up=2, down=1
- targetBeforeLastUp = 999,999,998
- diff = 1
- day = 999,999,998 / 1 = 999,999,998
- int 최댓값: 2,147,483,647 (약 21억)
- 10억 < 21억 → ✅ **int 가능!**

---

#### 📊 변수 범위 요약표

| 변수 | 계산식 | 최댓값 | int 가능? | long long 필요? |
|------|--------|--------|-----------|-----------------|
| up | 입력 | 10억 | ✅ | ❌ |
| down | 입력 | 10억 | ✅ | ❌ |
| goal | 입력 | 10억 | ✅ | ❌ |
| diff | up - down | 10억 | ✅ | ❌ |
| targetBeforeLastUp | goal - up | 10억 | ✅ | ❌ |
| day | targetBeforeLastUp / diff | 10억 | ✅ | ❌ |

**결론**: 이 문제는 **모든 변수가 int 범위 내**에 있음!

---

#### ⚠️ 그런데 왜 long long을 쓰는 사람이 많을까?

**이유 1: 안전 마진**
```cpp
✅ long long 사용 → 오버플로우 걱정 없음
❌ int 사용 → 범위 계산 실수 시 위험
```

**이유 2: 유사 문제와의 혼동**
```cpp
// 비슷한 문제지만 long long 필요한 경우
백준 1072번 - 게임:
- X ≤ 1,000,000,000
- 승률 계산: (wins × 100) / games
- wins × 100 = 100,000,000,000 (1000억)
- int 범위 초과! → long long 필수
```

**이유 3: 습관**
```cpp
// 많은 사람들의 안전한 습관
typedef long long ll;
ll up, down, goal;  // "일단 long long 쓰고 보자"
```

---

#### 🎯 실전 팁: 언제 long long을 써야 하는가?

**✅ long long이 필요한 경우**:
```
1. 입력값이 10억 초과 (21억 이상)
2. 곱셈 결과가 int 범위 초과
   예: a × b (a, b가 각각 10억일 때)
3. 누적 합이 int 범위 초과
   예: sum += arr[i] (반복 10억 번)
```

**❌ long long이 불필요한 경우**:
```
1. 입력값이 10억 이하 (이 문제!)
2. 나눗셈만 하는 경우 (몫은 항상 작아짐)
3. 뺄셈만 하는 경우 (결과가 항상 작아짐)
```

**📝 안전한 선택**:
```cpp
// 확실하지 않으면 long long 사용 권장
typedef long long ll;
ll up, down, goal;

// 단, 메모리 제한이 빡빡하면 int 고려
// int: 4바이트, long long: 8바이트
```

### 2️⃣ 마지막 업 처리 실수

```cpp
❌ day = goal / diff;  // 마지막 업을 고려하지 않음!

✅ targetBeforeLastUp = goal - up;
   day = targetBeforeLastUp / diff;
```

**반례**:
```
입력: 2 1 5
❌ day = 5 / 1 = 5 → 틀림!
✅ day = (5-2) / 1 = 3 → 맞음! (나머지 체크 후 +1)
```

---

### 3️⃣ 나머지 처리 실수

```cpp
❌ if ((goal - up) / diff == 0)  // 몫을 체크하면 안 됨!

✅ if ((goal - up) % diff == 0)  // 나머지를 체크해야 함!
```

**이유**:
- 몫이 0: 1일도 안 걸린다는 뜻 (틀림!)
- 나머지가 0: 딱 맞아떨어진다는 뜻 (맞음!)

---

### 4️⃣ 출력 값 실수

```cpp
❌ if (나머지 == 0)
       cout << day;      // 마지막 업을 안 더함!

✅ if (나머지 == 0)
       cout << day + 1;  // 마지막 업 1일 추가
```

**이유**:
- `day`는 **마지막 업 전까지** 걸리는 날짜
- 마지막 업하는 날 **1일을 반드시 추가**해야 함!

## 📊 시간복잡도 분석

**전체 시간복잡도**: **O(1)**

**상세 분석**:
```
1. 입력 처리: O(1)
   - up, down, goal 입력

2. 계산: O(1)
   - diff 계산
   - targetBeforeLastUp 계산
   - day 계산 (나눗셈)
   - 나머지 계산 (나머지 연산)

3. 출력: O(1)

총합: O(1)
```

**시간 제한 체크**:
- 시간 제한: 0.25초 (매우 짧음!)
- O(1) 연산 → **즉시 완료** ✅

**비교**:
```
단순 시뮬레이션: O(V)
- V = 1,000,000,000일 때
- 약 10억 번 반복
- 시간 초과 발생!

수학적 계산: O(1)
- 어떤 입력이든 동일
- 4~5번의 연산만 수행
- 시간 내 여유롭게 통과 ✅
```
