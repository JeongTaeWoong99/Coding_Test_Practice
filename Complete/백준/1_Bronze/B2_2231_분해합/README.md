## 🤔 접근법

(브론즈 문제라고 해서, 무시하면 안된다. 무식하게 브루트포스로 풀긴 했는데, 먼가 아닌 것 같아서, 생각을 해봤다.)

(아이디어가 떠오르지 않아서, 다른 정답을 확인하니, 범위 축소를 통한, 엄청 효율적인 방법이 있었다.)

자연수 N의 생성자를 찾는 문제. 

생성자 M은 `M + (M의 각 자릿수 합) = N`을 만족한다.

브루트포스로 해결 가능하지만, **탐색 범위를 최적화**하면 성능을 크게 향상시킬 수 있다.

## 💡 정답 풀이 방법

### 1️⃣ 핵심 아이디어: 탐색 범위 최적화

**🔑 핵심 원리**:
```
M + (M의 각 자릿수 합) = N

여기서 (M의 각 자릿수 합)의 최댓값은?
→ 모든 자릿수가 9일 때 : 9 × 자릿수

예시:
  N = 216 (3자리수)
  → 자릿수 합 최댓값 = 9 × 3 = 27
  → M의 최솟값 = 216 - 27 = 189

★☆ 즉, 189부터 N까지 찾으면 됨!(1,000,000 범위까지 찾을 필요 없이, N 안에 값이 나옴!)
(=> 198 발견!)

  N = 500,000 (6자리수)
  → 자릿수 합 최댓값 = 9 × 6 = 54
  → M의 최솟값 = 500,000 - 54 = 499,946

마찬가지, 499,946 ~ N까지에서 찾으면 됨! 
(=> 499957 발견!)
```

**📊 탐색 범위 계산**:
```
시작점 : max(1, N - 9 × 자릿수)
끝점   : N - 1
```

이렇게 하면 **불필요한 탐색을 대폭 줄일 수 있다**!

---

### 2️⃣ 상세 풀이 단계

1. **자릿수 계산**: `to_string(n).length()`로 N의 자릿수를 구한다. => 스트링으로 바꾸고, 그 길이를 구한다. 길이가 3이면, 3자리 수!


2. **시작점 계산**: `start = max(1, n - 9 × digit)`
   - N에서 최대 자릿수 합을 뺀 값이 생성자의 최솟값

3.**탐색**: `start`부터 `n-1`까지 반복하며 검사
   - `i + GetDigitSum(i) == n`인 i를 찾는다

4. **자릿수 합 계산**: 문자열 변환 없이 수학적 방법 사용
   ```cpp
   while (num > 0) 
   {
       sum += num % 10;  // 마지막 자릿수
       num /= 10;        // 자릿수 제거
   }
   ```

5. **출력**: 생성자를 찾으면 출력, 없으면 0 출력

### 🔍 탐색 범위 최적화 상세 설명

#### 왜 `N - 9 × 자릿수`부터 시작하는가?

**수학적 증명**:
```
M + (M의 자릿수 합) = N

M의 자릿수 합은 최대 9 × digit (모든 자릿수가 9일 때)
따라서:
  M ≥ N - (9 × digit)

즉, M은 절대로 N - 9×digit 보다 작을 수 없다!
```

**구체적 예시**:

| N 값 | 자릿수 | 자릿수 합 최댓값 | 시작점 | 탐색 범위 |
|------|--------|----------------|--------|----------|
| 216 | 3 | 9×3 = 27 | 216-27 = 189 | 189~215 (27회) |
| 1,000 | 4 | 9×4 = 36 | 1000-36 = 964 | 964~999 (36회) |
| 1,000,000 | 7 | 9×7 = 63 | 999,937 | 999,937~999,999 (63회) |

**예시 1: N = 216**
```
가능한 생성자 범위: 189 ~ 215

✅ 198 + (1+9+8) = 198 + 18 = 216  ← 정답!

❌ 188 이하는 확인할 필요 없음:
   188 + (1+8+8) = 188 + 17 = 205 < 216
   187 + (1+8+7) = 187 + 16 = 203 < 216
   ...

→ 188 이하는 자릿수 합을 더해도 절대 216에 도달 불가!
```

**예시 2: N = 1,000,000**
```
만약 최적화 없이 1부터 탐색하면:
→ 1,000,000번 반복

최적화 후:
→ 999,937 ~ 999,999 (최대 63번만 반복)

성능 향상: 약 16,000배!
```

#### 시각화

```
N = 216일 때:

    1          189     198    216
    |-----------|-------|------|
      불필요     탐색 구간
     (제외)    (27개만 확인)

기존 방법: 1~216 (216회)
최적화:   189~215 (27회)  ← 8배 향상!
```

## 🎯 핵심 개념 정리

**1. 탐색 범위 최적화**
```cpp
int digit = to_string(n).length();  // 자릿수
int start = max(1, n - 9 * digit);  // 시작점
```
→ 불필요한 탐색을 대폭 줄임!

**2. 수학적 자릿수 합 계산**
```cpp
while (num > 0) {
    sum += num % 10;  // 마지막 자릿수 추가
    num /= 10;        // 자릿수 제거
}
```
→ 문자열 변환 불필요!

**3. 브루트포스의 최적화**
- 모든 경우를 다 확인하되
- **확인 범위를 수학적으로 줄이는 것**이 핵심!

---

**⏱️ 시간복잡도**: O(D²) - D는 N의 자릿수 (최대 7)
- 기존: O(N × log₁₀N)
- 최적화: O(D × D) ≈ O(49) (상수 시간)
