## 🤔 접근법

(공식이 너무 헷갈린다... 오히려 이런 문제가 더 어려운 것 같다. 추후 다시 풀어볼 예정.)

자연수 A를 B번 곱한 수를 C로 나눈 나머지를 구하는 문제이다. 즉, **A^B % C**를 계산해야 한다.

B가 최대 2,147,483,647(약 21억)으로 매우 크기 때문에, 단순 반복문으로는 시간 초과가 발생한다.

핵심은 **분할 정복**을 이용해서 거듭제곱을 빠르게 계산하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 분할 정복을 이용한 거듭제곱 (Exponentiation by Squaring)

**핵심 아이디어**:
```
1. A^B를 직접 계산하지 말고, 절반씩 나누어 계산
2. A^B = (A^(B/2))^2      => (B가 짝수)
3. A^B = (A^(B/2))^2 × A  => (B가 홀수)
4. 모듈러 연산 성질 활용: (a × b) % C = ((a % C) × (b % C)) % C
5. 재귀적으로 B를 절반씩 줄여가며 계산
```

**시간 복잡도**: O(log B) - ※ B는 제곱하는 수(A^B)
- B를 절반씩 줄여가므로 log₂(B) 번의 재귀 호출
- B가 21억이어도 약 31번의 재귀 호출로 해결

**공간 복잡도**: O(log B)
- 재귀 스택의 깊이

## 🔑 핵심 포인트

### 1️⃣ 왜 `typedef long long LL`을 사용하는가?

```cpp
typedef long long LL;
LL A, B, C;
```

**⚠️ 오버플로우 발생 지점**:
```cpp
ret = (ret * ret) % C;  // 17번 라인
ret = (ret * A) % C;    // 20번 라인
```

**문제 상황**:
- A, B, C는 최대 2,147,483,647 (int 최댓값)
- `ret`는 최대 C-1 = 2,147,483,646
- `ret * ret` 계산 시: **4,611,686,014,132,420,609** (int 범위 초과!)

**해결책**:
- `long long` 사용으로 중간 계산 오버플로우 방지
- `long long` 범위: -9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807

### 2️⃣ 분할 정복 공식

```cpp
// a : 밑, b : 지수, c : 나눌 수
// 반환값 : a^b % c
// ※ 전역 변수(A, B, C)를 매개변수로 받아서, 함수 내부에서 독립적으로 사용
// ※ 재귀 과정에서 b만 변화(분할)하고, a와 c는 고정값으로 전달됨
LL DICO(LL a, LL b, LL c)
{
    if (b == 1) return a % c;        // 기저 사례

    LL ret = DICO(a, b / 2, c);      // 절반으로 분할: a^b → a^(b/2) 계산

    ret = (ret * ret) % c;           // [짝수/홀수 공통] 제곱: (a^(b/2))^2
                                     // → 짝수든 홀수든 일단 제곱부터!

    if (b % 2) ret = (ret * a) % c;  // [홀수일 때만] a를 한 번 더 곱해줌
                                     // b/2로 나눌 때 나머지 1 버려짐 → 보정
    return ret;
}
```

**✅ 설계 포인트:**
- **모든 필요한 값(a, b, c)을 매개변수로 전달** - 함수 독립성 확보
- **전역 변수 의존 제거** - 순수 함수로 설계
- **소문자 변수명 통일 (a, b, c)** - 일관성 유지
- **재귀 시 a, c는 고정, b만 변화** - 분할 정복의 핵심

**동작 원리**:

**B가 짝수일 때 (예: B=8)**:
```
A^8 = (A^4)^2           ← ret = (ret * ret) % c 만 실행
A^4 = (A^2)^2           ← if (b % 2) 조건 false (추가 곱셈 없음)
A^2 = (A^1)^2
```

**B가 홀수일 때 (예: B=11)**:
```
A^11 = (A^5)^2 × A      ← ret = (ret * ret) % c 실행 후
A^5  = (A^2)^2 × A      ← if (b % 2) 조건 true (a 추가 곱셈!)
                           11/2 = 5 (나머지 1 버려짐 → 보정 필요)
```

### 3️⃣ 모듈러 연산 성질

```cpp
(a × b) % C = ((a % C) × (b % C)) % C
```

**적용**:
```cpp
A^B % C = ((A^(B/2) % C)^2) % C        // B가 짝수
A^B % C = ((A^(B/2) % C)^2 × A) % C    // B가 홀수
```

**왜 매번 % C를 해야 하는가?**
- 중간 계산 값이 너무 커지는 것을 방지
- 오버플로우 방지
- 결과에는 영향 없음 (모듈러 연산의 분배 법칙)

## 📊 예제 동작 과정 (10^11 % 12)

**입력**: `A=10, B=11, C=12`

☆☆ 호출 트리를 보면, ☆☆

B = 11는 5 * 5로 쪼개지고(홀수니까 마지막에 A를 한번 더 곱해줌),

B = 5는 2*2 로 쪼개지고(홀수니까 마지막에 A를 한번 더 곱해줌),

B = 2는 1*1 로 쪼개지고

B = 1는 B가 1이니까, 기저 사례에 걸려서 리턴한다.


### 🔍 재귀 호출 트리

```
DICO(10, 11, 12)  ← 목표: 10^11 % 12
│
├─ b=11 (홀수)
│  ├─ DICO(10, 5, 12) 호출  ← 10^5 % 12 계산
│  │  │
│  │  ├─ b=5 (홀수)
│  │  │  ├─ DICO(10, 2, 12) 호출  ← 10^2 % 12 계산
│  │  │  │  │
│  │  │  │  ├─ b=2 (짝수)
│  │  │  │  │  ├─ DICO(10, 1, 12) 호출  ← 10^1 % 12 계산
│  │  │  │  │  │  └─ return 10 % 12 = 10  ✅ 기저 사례
│  │  │  │  │  │
│  │  │  │  │  ├─ ret = 10
│  │  │  │  │  ├─ ret = (10 * 10) % 12 = 100 % 12 = 4
│  │  │  │  │  ├─ b=2는 짝수 → a 추가 곱셈 없음
│  │  │  │  │  └─ return 4  ← 10^2 % 12 = 4
│  │  │  │  │
│  │  │  ├─ ret = 4
│  │  │  ├─ ret = (4 * 4) % 12 = 16 % 12 = 4
│  │  │  ├─ b=5는 홀수 → ret = (4 * 10) % 12 = 40 % 12 = 4
│  │  │  └─ return 4  ← 10^5 % 12 = 4
│  │  │
│  ├─ ret = 4
│  ├─ ret = (4 * 4) % 12 = 16 % 12 = 4
│  ├─ b=11는 홀수 → ret = (4 * 10) % 12 = 40 % 12 = 4
│  └─ return 4  ← 10^11 % 12 = 4 ✅
```

## 🔑 핵심 이해 포인트

### ✅ 왜 시간복잡도가 O(log B)인가?

```
B = 21억 (2^31)
21억 → 10억 → 5억 → 2.5억 → ... → 1

매번 절반씩 줄어들므로:
log₂(21억) ≈ 31번의 재귀 호출

단순 반복: 21억 번 vs 분할 정복: 31번 → 엄청난 차이!
```

### ✅ 왜 매번 % C를 하는가?

```cpp
// ❌ 잘못된 방법 (오버플로우!)
ret = ret * ret;
ret = ret % C;

// ✅ 올바른 방법
ret = (ret * ret) % C;
```

**이유**:
- `ret * ret`가 `long long` 범위도 초과할 수 있음
- 매번 % C를 하면 ret는 항상 C보다 작게 유지됨
- 모듈러 연산의 분배 법칙으로 결과는 동일

### ✅ 홀수 처리

```cpp
if (b % 2) ret = (ret * a) % C;
```

**왜 필요한가?**
- `A^11 = A^10 × A = (A^5)^2 × A`
- B를 절반으로 나누면 나머지가 버려짐
- 홀수일 때는 A를 한 번 더 곱해줘야 함

**예시**:
```
11 / 2 = 5 (나머지 1 버려짐)
→ A^11 = (A^5)^2 × A^1
```

## ⏱️ 시간복잡도

**O(log B)** 
- ※ B는 제곱하는 수(A^B)

**분석**:
- B를 절반씩 줄여가며 재귀 호출
- 재귀 깊이: log₂(B)
- B = 2,147,483,647 → 약 31번의 재귀 호출
- 각 재귀에서 상수 시간 연산만 수행

**📌 시간복잡도 비교**:
```
단순 반복문: O(B) = O(21억) → 시간 초과 ❌
분할 정복: O(log B) = O(31) → 통과 ✅
```

## 💾 공간복잡도

**O(log B)**

**분석**:
- 재귀 스택의 깊이 = log₂(B)
- 각 스택 프레임당 O(1) 공간
- 총 공간: O(log B)

## 🎯 왜 이렇게 설계했는가? (함수 설계 철학)

### ❓ 질문: "A와 C도 고정인데, 왜 매개변수로 전달하나요?"

**정답: 일관성, 독립성, 재사용성 때문입니다!**

### 📊 설계 방식 비교

#### ❌ 방식 1: 전역 변수만 사용

```cpp
LL A, B, C;  // 전역 변수

LL DICO(LL currentB)
{
    if (currentB == 1) return A % C;
    LL ret = DICO(currentB / 2);
    ret = (ret * ret) % C;
    if (currentB % 2) ret = (ret * A) % C;
    return ret;
}

// main
cin >> A >> B >> C;
cout << DICO(B) << "\n";  // 어떤 A, C를 쓰는지 불명확
```

**문제점:**
- ❌ 함수가 전역 변수에 의존 (coupling)
- ❌ 다른 A, C 값으로 테스트 어려움
- ❌ 변수명 혼란 (대문자 A, C vs 소문자 currentB)

---

#### ⚠️ 방식 2: A, B만 매개변수 (기존 방식)

```cpp
LL A, B, C;  // 전역 변수

LL DICO(LL a, LL b)
{
    if (b == 1) return a % C;  // C는 전역!
    LL ret = DICO(a, b / 2);
    ret = (ret * ret) % C;     // 통일성 없음
    if (b % 2) ret = (ret * a) % C;
    return ret;
}
```

**문제점:**
- ❌ a, b는 소문자 (매개변수), C는 대문자 (전역) → 일관성 없음
- ❌ C를 변경하려면 전역 변수 수정 필요

---

#### ✅ 방식 3: 모든 값을 매개변수로 전달 (현재 방식)

```cpp
LL A, B, C;  // 전역 변수 (입력 저장용)

LL DICO(LL a, LL b, LL c)  // 모두 매개변수
{
    if (b == 1) return a % c;
    LL ret = DICO(a, b / 2, c);
    ret = (ret * ret) % c;     // 통일성 있음
    if (b % 2) ret = (ret * a) % c;
    return ret;
}

// main
cin >> A >> B >> C;
cout << DICO(A, B, C) << "\n";  // 명확한 전달
```

**장점:**
- ✅ 함수가 완전히 독립적 (순수 함수)
- ✅ 변수명 일관성 (a, b, c 모두 소문자)
- ✅ 다른 값으로 여러 번 호출 가능
- ✅ 테스트 및 디버깅 용이

---

### 🔑 핵심 원칙

#### 1️⃣ 일관성 (Consistency)

**❌ 나쁜 예:**
```cpp
LL DICO(LL a, LL b)  // a, b는 매개변수
{
    return (a * b) % C;  // C는 전역 변수 (혼란!)
}
```

**✅ 좋은 예:**
```cpp
LL DICO(LL a, LL b, LL c)  // 모두 매개변수
{
    return (a * b) % c;  // 일관성 있음
}
```

---

#### 2️⃣ 독립성 (Independence) - 순수 함수

**순수 함수란?**
- 같은 입력 → 항상 같은 출력
- 외부 상태에 의존하지 않음
- 부작용(side effect) 없음

**✅ 순수 함수:**
```cpp
LL result = DICO(10, 11, 12);  // 10^11 % 12
LL result2 = DICO(10, 11, 13); // 10^11 % 13 (다른 모듈러)
```

**❌ 비순수 함수:**
```cpp
C = 12;
LL result = DICO(10, 11);  // 전역 C=12 사용
C = 13;
LL result2 = DICO(10, 11); // 전역 C=13 사용 (헷갈림!)
```

---

#### 3️⃣ 재사용성 (Reusability)

**✅ 여러 테스트 케이스 처리:**
```cpp
int T;
cin >> T;
while(T--) {
    cin >> A >> B >> C;
    cout << DICO(A, B, C) << "\n";  // 명확하고 깔끔
}
```

**✅ 다양한 값으로 테스트:**
```cpp
assert(DICO(10, 11, 12) == 4);
assert(DICO(2, 10, 1000) == 24);
assert(DICO(5, 3, 7) == 6);
```

### 📌 "재귀에서 a, c는 고정인데 왜 매번 전달?"

**맞는 지적입니다! a와 c는 재귀 과정에서 변하지 않습니다.**

```cpp
DICO(10, 11, 12)
  ├─ DICO(10, 5, 12)   // a=10, c=12 고정
  │   ├─ DICO(10, 2, 12)
  │   │   └─ DICO(10, 1, 12)
```

**하지만 매개변수로 전달하는 이유:**

| 항목 | 설명 |
|-----|------|
| **함수 시그니처 명확성** | `DICO(a, b, c)` → "a의 b제곱을 c로 나눈 나머지" 즉시 이해 |
| **함수 독립성** | 전역 변수 없이 동작 가능 |
| **다른 문제 재사용** | 이 함수를 다른 코드에 복사해도 바로 작동 |
| **테스트 용이성** | 다양한 a, c 값으로 쉽게 테스트 |

### 💡 코딩테스트 팁

**전역 변수를 쓰는 경우:**
- ✅ 배열 크기 (N, M 등)
- ✅ 맵/그래프 (arr, visited 등)
- ✅ 방향 배열 (dy, dx 등)
- ✅ 큰 배열 (스택 오버플로우 방지)

**매개변수로 전달하는 경우:**
- ✅ 계산 함수의 입력값
- ✅ 재귀 함수의 변화하는 값
- ✅ 독립적으로 동작해야 하는 함수

**이 문제에서:**
- 전역: `A, B, C` (입력 저장용)
- 매개변수: `a, b, c` (함수 독립성 확보)

### ✅ 결론

**"a, c는 고정인데 매개변수로 전달하는 이유"**

1. **일관성**: a, b, c 모두 동일한 방식으로 처리
2. **독립성**: 함수가 전역 상태에 의존하지 않음
3. **명확성**: 함수 시그니처만 봐도 동작 이해 가능
4. **재사용성**: 다른 값으로도 쉽게 호출 가능

**코딩테스트에서는 둘 다 통과하지만, 좋은 코딩 습관은 매개변수 방식!** 🎯

## ⚡ 성능 비교: 매개변수 vs 전역변수

### ❓ 질문: "매개변수가 전역변수보다 빠른가요?"

**정답: 대부분의 경우 매개변수가 더 빠르거나 비슷합니다!**

### 🧠 메모리 구조 이해

#### C++의 메모리 영역

| 메모리 영역 | 용도 | 접근 속도 | 예시 |
|----------|------|---------|------|
| **스택 (Stack)** | 지역 변수, 매개변수 | ⚡ **매우 빠름** | `int x;`, `void f(int a)` |
| **데이터 (Data)** | 전역 변수, 정적 변수 | 🐢 스택보다 느림 | `int g_var;` (전역) |
| **힙 (Heap)** | 동적 할당 | 🐌 **가장 느림** | `new`, `malloc` |

**⚠️ 주의: 전역 변수는 힙이 아닌 데이터 영역에 저장됩니다!**
- C#의 참조 타입(힙)과는 다릅니다
- C++에서는 스택보다 느리지만, 힙보다는 빠릅니다

---

### 📊 성능 차이 요인

#### 1️⃣ 캐시 지역성 (Cache Locality)

**✅ 매개변수 (스택):**
```cpp
LL DICO(LL a, LL b, LL c)  // 스택에 연속 배치
{
    // a, b, c가 CPU 캐시에 함께 로드됨
    return (a * b) % c;
}
```

**특징:**
- 함수 호출 시 스택 프레임에 연속으로 배치
- CPU 캐시 히트율 높음 (L1 캐시 활용)
- 메모리 접근 예측 가능

**❌ 전역 변수 (데이터 영역):**
```cpp
LL A, B, C;  // 데이터 영역에 떨어져 있을 수 있음

LL DICO(LL b)
{
    // A, C를 데이터 영역에서 별도로 가져와야 함
    return (A * b) % C;
}
```

**특징:**
- 메모리 상 분산 배치 가능
- 캐시 미스 가능성 높음
- 추가 메모리 접근 필요

---

#### 2️⃣ 컴파일러 최적화

**✅ 매개변수:**
```cpp
LL DICO(LL a, LL b, LL c)
{
    // 컴파일러가 레지스터에 직접 할당 가능
    // a, b, c → rdi, rsi, rdx 레지스터
    return (a * b) % c;
}
```

**어셈블리 (최적화):**
```asm
mov rax, rdi    ; a를 레지스터로
imul rax, rsi   ; a * b
div rdx         ; % c
```

**❌ 전역 변수:**
```cpp
LL A, B, C;

LL DICO(LL b)
{
    // 전역 변수는 메모리에서 읽어와야 함
    return (A * b) % C;
}
```

**어셈블리 (최적화 어려움):**
```asm
mov rax, [A]    ; 메모리에서 A 로드
imul rax, rdi   ; A * b
mov rcx, [C]    ; 메모리에서 C 로드
div rcx         ; % C
```

---

#### 3️⃣ 멀티스레드 환경

**✅ 매개변수:**
- 각 스레드가 독립적인 스택 사용
- 동기화 필요 없음
- Thread-safe

**❌ 전역 변수:**
- 모든 스레드가 공유
- Race condition 위험
- 동기화 오버헤드

---

### 🔬 실제 성능 측정

#### 테스트 코드

```cpp
// 방법 1: 매개변수
LL DICO_param(LL a, LL b, LL c) {
    if (b == 1) return a % c;
    LL ret = DICO_param(a, b / 2, c);
    ret = (ret * ret) % c;
    if (b % 2) ret = (ret * a) % c;
    return ret;
}

// 방법 2: 전역 변수
LL A, B, C;
LL DICO_global(LL b) {
    if (b == 1) return A % C;
    LL ret = DICO_global(b / 2);
    ret = (ret * ret) % C;
    if (b % 2) ret = (ret * A) % C;
    return ret;
}

// 벤치마크
for (int i = 0; i < 100000; i++) {
    DICO_param(2, 1000000000, 1000000007);  // 매개변수
    DICO_global(1000000000);                // 전역 변수
}
```

#### 예상 결과 (GCC -O2 최적화)

| 방법 | 평균 시간 | 상대 속도 |
|-----|---------|---------|
| **매개변수** | 100ms | 1.0x (기준) |
| **전역 변수** | 105~110ms | 1.05~1.1x (약 5~10% 느림) |

**📌 차이가 작은 이유:**
- 재귀 깊이가 log(B) = 약 30으로 작음
- 전역 변수도 컴파일러가 어느 정도 최적화
- 실제 계산 시간이 메모리 접근보다 큼
