## 🤔 접근법

(응용이 들어간 문제... 나중에 한번 더 풀어보자.)

N명의 학생에게 M가지 색상의 보석을 나눠줄 때, **질투심(가장 많이 받은 학생의 보석 개수)을 최소화**하는 문제이다.

핵심은 **이분 탐색**을 사용하여 "최대 X개씩 나눠줄 수 있는가?"를 판단하면서 최솟값을 찾는 것!

**조건:**
- 한 학생은 같은 색상의 보석만 받을 수 있음
- 보석을 못 받는 학생이 있어도 됨
- 모든 보석을 나눠줘야 함 (남으면 안 됨)

---

## 💡 정답 풀이 방법

**알고리즘**: 이분 탐색 (Binary Search) + 매개 변수 탐색 (Parametric Search)

**핵심 아이디어**:
```
1. 이분 탐색 범위 설정:
   - left = 1 (최소 1개는 줄 수 있음)
   - right = max(보석 개수) (가장 많은 보석 색상)

2. 중간값 mid로 "최대 mid 개씩 나눠줄 수 있는가?" 확인:
   - 각 색상별로 필요한 학생 수 계산
   - 필요한 학생 수 = (보석 개수 / mid) + (나머지가 있으면 +1)
   - 전체 필요 학생 수가 N명 이하면 가능

3. 이분 탐색으로 최솟값 찾기:
   - 가능하면 더 작은 값 시도 (right = mid - 1)
   - 불가능하면 더 큰 값 시도 (left = mid + 1)

4. 최솟값 출력
```

**시간 복잡도**: O(M × log(max))
- M = 보석 색상 수 (최대 300,000)
- log(max) = 이분 탐색 깊이 (최대 log(10^9) ≈ 30)
- 전체: 약 9,000,000 (충분히 통과)

**공간 복잡도**: O(M)
- jewelNumArr 배열: O(M)
- 기타 변수들: O(1)

## 🔑 핵심 포인트

### 1️⃣ left = 1로 시작하는 이유

```cpp
ll _left = 1;   // ★ 최소 1개는 줄 수 있음
ll _right, mid; // _right는 입력받으면서 최댓값으로 갱신
```

**✅ 중요한 이유:**

1. **Division by Zero 방지**:
   - `left = 0`으로 시작하면 `mid = 0`이 될 수 있음
   - Check 함수에서 `jewelNumArr[i] / checkMid` 계산 시 **런타임 에러 발생**
   - `left = 1`로 시작하면 `mid >= 1` 보장

2. **논리적 의미**:
   - 한 학생에게 최소 1개는 줄 수 있음
   - 0개를 주는 것은 의미 없음 (아무것도 안 주는 것)

3. **이분 탐색 범위**:
   - 답의 범위: 1 ~ (가장 많은 보석 개수)
   - 0은 답이 될 수 없음

### 2️⃣ Check 함수 (매개 변수 탐색)

```cpp
bool Check(ll checkMid)
{
    ll needStuNum = 0;  // 필요한 학생 수

    for(int i = 0; i < colorNum; i++)
    {
        needStuNum += jewelNumArr[i] / checkMid;  // checkMid 개씩 나눠줄 수 있는 학생 수

        if(jewelNumArr[i] % checkMid)              // 나머지가 있으면 한 명 더 필요
            needStuNum++;
    }

    return stuNum >= needStuNum;  // 학생 수가 충분한지 확인
}
```

**✅ 핵심**:
- `checkMid` 개씩 나눠줄 때 필요한 학생 수 계산
- 나머지가 있으면 한 명 더 필요 (올림 계산)
- ★ 필요한 학생 수가 전체 학생 수 이하면 가능

**📊 예시:**
```
파란색 보석 7개를 최대 3개씩 나눠주면?
- 7 / 3 = 2명 (2명에게 3개씩)
- 7 % 3 = 1개 (나머지 1개)
- 총 3명 필요 (2 + 1)

빨간색 보석 4개를 최대 3개씩 나눠주면?
- 4 / 3 = 1명 (1명에게 3개)
- 4 % 3 = 1개 (나머지 1개)
- 총 2명 필요 (1 + 1)

전체: 5명 필요 → 학생 5명 → 가능! ✅
```

### 3️⃣ 이분 탐색 로직

```cpp
while(_left <= _right)
{
    mid = (_left + _right) / 2;

    if(Check(mid))  // mid 개씩 나눠줄 수 있음
    {
        minRet = min(minRet, mid);  // 최솟값 갱신
        _right = mid - 1;           // 더 작은 값 탐색 (질투심 줄이기)
    }
    else  // mid 개씩 나눠줄 수 없음 (학생이 부족함)
    {
        _left = mid + 1;  // 더 큰 값 탐색 (한 명당 더 많이 줘야 함)
    }
}
```

**✅ 핵심**:
- 가능하면: 더 작은 값으로 시도 (질투심 최소화)
- 불가능하면: 더 큰 값으로 시도 (한 명당 더 많이 줘야 함)
- 최솟값을 찾는 최적화 문제

### 4️⃣ 이분 탐색 vs 완전 탐색

**완전 탐색 (브루트포스):**
```cpp
for(int i = 1; i <= maxJewel; i++)
{
    if(Check(i))
        answer = i;
}
// 시간복잡도: O(M × max) = 300,000 × 10^9 = 초과
```

**이분 탐색:**
```cpp
while(left <= right)
{
    mid = (left + right) / 2;
    // ...
}
// 시간복잡도: O(M × log(max)) = 300,000 × 30 = 9,000,000 ✅
```

**✅ 핵심**: 이분 탐색으로 10^9 → log(10^9) ≈ 30으로 줄임

## 📊 예시 실행 흐름

**입력**:
```
5 2
7
4
```

**실행 과정**:
```
학생: 5명
색상: 2가지 (파란색 7개, 빨간색 4개)

이분 탐색 범위: [1, 7]

─────────────────────────────────────────
1회차: mid = 4
Check(4):
  - 파란색 7개: 7/4 = 1, 7%4 = 3 → 2명 필요
  - 빨간색 4개: 4/4 = 1, 4%4 = 0 → 1명 필요
  - 총 3명 필요, 학생 5명 → 가능 ✅

minRet = 4, _right = 3

─────────────────────────────────────────
2회차: mid = 2
Check(2):
  - 파란색 7개: 7/2 = 3, 7%2 = 1 → 4명 필요
  - 빨간색 4개: 4/2 = 2, 4%2 = 0 → 2명 필요
  - 총 6명 필요, 학생 5명 → 불가능 ❌

_left = 3

─────────────────────────────────────────
3회차: mid = 3
Check(3):
  - 파란색 7개: 7/3 = 2, 7%3 = 1 → 3명 필요
  - 빨간색 4개: 4/3 = 1, 4%3 = 1 → 2명 필요
  - 총 5명 필요, 학생 5명 → 가능 ✅

minRet = 3, _right = 2

─────────────────────────────────────────
4회차: _left > _right → 종료

최종 답: 3
```

**출력**: `3`

## ⏱️ 시간복잡도

**O(M × log(max))**
- M = 보석 색상 수 (최대 300,000)
- log(max) = 이분 탐색 깊이 (최대 log(10^9) ≈ 30)
- 전체: 약 9,000,000 (충분히 빠름)

**이분 탐색의 위력:**
- 완전 탐색: O(M × max) = 10^14 (시간 초과)
- 이분 탐색: O(M × log(max)) = 10^7 (통과) ✅

## 🚨 주의사항

1. **left = 1 필수**: 0으로 시작하면 Division by Zero 런타임 에러 발생
2. **올림 계산**: `jewelNumArr[i] / checkMid + (나머지가 있으면 +1)`
3. **이분 탐색 방향**: 가능하면 더 작은 값, 불가능하면 더 큰 값
4. **범위 설정**: left = 1, right = max(보석 개수)
5. **매개 변수 탐색**: "최대 X개씩 나눠줄 수 있는가?"를 판단하는 Check 함수 필수
