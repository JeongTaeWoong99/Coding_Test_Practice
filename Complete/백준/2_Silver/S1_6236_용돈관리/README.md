## 🤔 접근법

현우는 N일 동안 M번만 통장에서 돈을 빼서 쓰려고 한다.

매번 K원씩 인출하는데, **남은 돈으로 하루를 보낼 수 없으면 남은 돈을 다시 넣고 K원을 재인출**한다.

핵심은 **이분 탐색(매개 변수 탐색)**을 사용하여 **M번 이하로 인출 가능한 최소 금액 K를 찾는 것**!

**조건:**
- 정확히 M번만 인출 (M번 이하도 가능)
- 남은 돈이 충분해도 통장에 넣고 다시 인출할 수 있음 (M번 맞추기 위해)
- 최소 인출 금액 K를 구하기

---

## 💡 핵심 아이디어

### 🔑 이분 탐색 (Parametric Search)

**문제 조건:**
- N일 동안 사용할 금액이 주어짐
- M번만 통장에서 인출
- 남은 돈으로 하루를 보낼 수 없으면 재인출
- 인출 금액 K의 최솟값 구하기

**알고리즘 흐름:**
```
1. 이분 탐색 범위 설정:
   - left (최소값): 가장 큰 일일 사용액 (이보다 작으면 해당 날을 감당 불가)
   - right (최대값): 충분히 큰 값 (예: 10억)

2. 이분 탐색으로 인출 금액 탐색:
   - mid = (left + right) / 2
   - Check(mid): mid 원으로 M번 이하로 인출 가능한지 확인

3. Check 함수:
   - 남은 돈으로 오늘 사용할 금액을 감당할 수 없으면 재인출
   - 인출 횟수를 세서 M번 이하인지 확인

4. 이분 탐색 조건:
   - Check(mid)가 true → 더 작은 금액 시도 (right = mid - 1)
   - Check(mid)가 false → 금액 증가 (left = mid + 1)
```

**시간 복잡도**: O(N × log(max))
- N = 날짜 수 (최대 100,000)
- max = 최대 인출 금액 (10억)
- log(10억) ≈ 30
- 전체: O(100,000 × 30) = O(3,000,000) (충분히 통과)

**공간 복잡도**: O(N)
- arr 배열: O(N)

## 🔑 주요 구현 포인트

### 1️⃣ 이분 탐색 범위 설정

```cpp
ll lo = mx;              // 최소값 : 가장 큰 일일 사용액
ll hi = 1000000004;      // 최대값 : 충분히 큰 값

for(int i = 0; i < n; i++)
{
    cin >> arr[i];
    mx = max(arr[i], mx);  // 가장 큰 일일 사용액 찾기
}
```

**✅ 핵심**:
- **lo (최소값)**: 가장 큰 일일 사용액
  - 이유: 인출 금액이 가장 큰 일일 사용액보다 작으면 해당 날을 감당할 수 없음
- **hi (최대값)**: 충분히 큰 값 (10억 이상)
  - 이유: 모든 날을 하루에 한 번씩 인출해도 충분한 값

---

### 2️⃣ Check 함수로 가능 여부 판단

```cpp
bool Check(int mid)
{
    int cnt         = 1;        // 인출 횟수
    int setMoney    = mid;      // K원 인출 금액 저장
    int remainMoney = setMoney; // 세팅

    for(int i = 0; i < n; i++)
    {
        // 현재 남은 돈으로 오늘 사용할 금액을 감당할 수 없으면
        if(remainMoney - arr[i] < 0)
        {
            remainMoney = setMoney;  // 통장에서 다시 K원 인출
            cnt++;                   // 인출 횟수 증가
        }

        // 오늘 사용할 금액 차감
        remainMoney -= arr[i];
    }

    return cnt <= m;     // M번 이하로 인출 가능한지 확인
}
```

**✅ 핵심**:
- **cnt**: 인출 횟수 (1부터 시작)
- **setMoney**: K원 인출 금액 저장 (재인출 시 사용)
- **remainMoney**: 현재 남은 돈
- **조건**: `remainMoney - arr[i] < 0`
  - 현재 남은 돈에서 오늘 사용할 금액을 빼면 음수가 되는지 확인
  - 음수가 되면 오늘 사용할 금액을 감당할 수 없으므로 재인출
- **반환**: `cnt <= m`
  - M번 이하로 인출 가능하면 true

**📊 다른 표현 방식과의 비교:**
```cpp
// 방법 1: 음수 비교 (현재 코드)
if(remainMoney - arr[i] < 0)

// 방법 2: 양수 비교 (더 간결)
if(remainMoney < arr[i])

// 방법 3: 기타레슨 스타일
if(remainMoney + arr[i] > mid)  // X (로직이 다름)
```

**💡 참고**:
- 방법 1과 방법 2는 동일한 로직
- 현재 코드는 방법 1 사용 (음수 체크)
- 기타레슨은 "누적합 + 다음 값 > 용량" 패턴
- 용돈 관리는 "남은 돈 - 사용액 < 0" 패턴

---

### 3️⃣ 이분 탐색으로 최소 금액 찾기

```cpp
while(lo <= hi)
{
    int mid = (lo + hi) / 2;

    // mid 원으로 M번 이하 인출 가능
    if(Check(mid))
    {
        hi  = mid - 1;  // 더 작은 금액 탐색
        ret = mid;      // 현재 값 저장
    }
    // mid 원으로 M번 초과 인출 필요
    else
    {
        lo = mid + 1;   // 더 큰 금액 탐색
    }
}
```

**✅ 핵심**:
- **Check(mid) == true**: mid 원으로 M번 이하로 인출 가능
  - ret에 mid 저장 (더 작은 금액이 있을 수 있으므로)
  - hi = mid - 1 (더 작은 금액 시도)
- **Check(mid) == false**: mid 원으로 M번 초과 인출 필요
  - lo = mid + 1 (금액 증가 필요)

## 📊 예제 실행 흐름

**입력**:
```
7 5
100
400
300
100
500
101
400
```

**실행 과정**:
```
1. 범위 설정:
   - lo = 500 (가장 큰 일일 사용액)
   - hi = 1000000004

2. 이분 탐색:

   ① mid = 500000252
      Check(500000252) = true (cnt = 1 ≤ 5)
      → 모든 날을 하루에 인출 가능
      → ret = 500000252, hi = 500000251

   ② mid = 250000375
      Check(250000375) = true (cnt = 1 ≤ 5)
      → ret = 250000375, hi = 250000374

   ... (계속 탐색)

   최종적으로 mid = 500일 때:
      Check(500) = true (cnt = 5 ≤ 5)
      → 1일: 100 (남음: 400)
      → 2일: 400 사용 (남음: 0) → 재인출
      → 3일: 300 (남음: 200)
      → 4일: 100 (남음: 100) → 재인출 (M번 맞추기)
      → 5일: 500 사용 (남음: 0) → 재인출
      → 6일: 101 (남음: 399)
      → 7일: 400 사용 불가 → 재인출
      → cnt = 5 ≤ 5 (가능)
      → ret = 500

   mid = 499일 때:
      Check(499) = false (cnt > 5)
      → 5일째 500원을 감당할 수 없음
      → lo = 500

   종료: lo > hi
```

**출력**: `500`

## 🚨 주의사항

1. **lo (최소값) 설정**: 가장 큰 일일 사용액 (이보다 작으면 해당 날을 감당 불가)
2. **양수 비교 권장**: `remain < arr[i]` (음수 비교 `remain - arr[i] < 0` 보다 직관적)
3. **이분 탐색 방향**: 가능하면 더 작은 금액, 불가능하면 더 큰 금액
4. **매개 변수 탐색**: "K원으로 M번 이하 인출 가능한가?"를 판단하는 Check 함수 필수
5. **M번 정확히 vs M번 이하**: 문제에서는 M번 이하로 인출해도 됨 (M번 맞추기 위해 재인출 가능)
