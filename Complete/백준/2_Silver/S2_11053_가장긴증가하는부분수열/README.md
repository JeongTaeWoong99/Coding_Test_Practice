## 🔗 문제 링크

[백준 11053번 - 가장 긴 증가하는 부분 수열](https://www.acmicpc.net/problem/11053)

**난이도**: Silver 2

---

## 🤔 접근법

(앞서 풀었던 문제 쉬운 버전이라 쉽게 품.)

수열 A가 주어졌을 때, **가장 긴 증가하는 부분 수열(LIS, Longest Increasing Subsequence)의 길이**를 구하는 문제.

- 부분 수열: 원래 수열에서 일부 원소를 선택한 수열 (순서 유지)
- 증가하는 부분 수열: 선택된 원소들이 증가하는 순서를 이루는 수열
- 예: {10, 20, 10, 30, 20, 50} → LIS = {10, 20, 30, 50}, 길이 = 4

**핵심은 이분 탐색을 활용한 O(N log N) LIS 알고리즘**으로 효율적으로 해결!

---

## 💡 정답 풀이 방법

**알고리즘** : LIS (이분 탐색 활용) - Longest Increasing Subsequence

**핵심 아이디어**:
```
1. LIS 배열을 유지하며 입력을 순회
2. 각 숫자마다 lower_bound로 들어갈 위치 찾기
3. 해당 위치에 숫자를 배치하여 LIS 배열 갱신
4. 새로운 위치면 길이 증가, 기존 위치면 교체
5. 최종적으로 LIS의 길이 출력
```

---

## 🔑 핵심 포인트

### 1️⃣ LIS 배열 초기화

```cpp
const int INF = 2008;  // 문제 조건보다 큰 값
int lis[1004];         // LIS를 저장하는 배열
int len = 0;           // 현재 LIS의 길이

fill_n(lis, 1004, INF);  // 배열을 INF로 초기화
```

**✅ 핵심**: INF로 초기화하여 lower_bound가 올바르게 동작하도록 설정
- INF는 입력 범위(1~1000)보다 큰 값
- lower_bound는 "이상"인 첫 위치를 찾음
- INF로 초기화하면 빈 위치를 쉽게 구분 가능

### 2️⃣ 이분 탐색으로 위치 찾기

```cpp
for (int i = 0; i < n; i++)
{
    cin >> num;

    // lower_bound로 num이 들어갈 위치 찾기
    int pos = lower_bound(lis, lis + len, num) - lis;

    // 새로운 값이면 길이 증가
    if (lis[pos] == INF) len++;

    // LIS 배열 갱신
    lis[pos] = num;
}
```

**✅ 핵심**: lower_bound로 O(log N)에 위치 찾기
- `lower_bound(lis, lis + len, num)`: num 이상인 첫 위치 반환
- `- lis`: 포인터를 인덱스로 변환
- `lis[pos] == INF`: 새로운 위치 (LIS 길이 증가)
- `lis[pos] != INF`: 기존 위치 (값만 교체)

### 3️⃣ LIS 배열의 의미

```cpp
// LIS 배열은 "길이별 최소 끝 값"을 저장
// 예: 입력 {10, 20, 10, 30, 20, 50}

i=0: num=10 → lis = [10, INF, INF, ...] len=1
i=1: num=20 → lis = [10, 20, INF, ...]  len=2
i=2: num=10 → lis = [10, 20, INF, ...]  len=2 (교체 안 함, 이미 10)
i=3: num=30 → lis = [10, 20, 30, ...]   len=3
i=4: num=20 → lis = [10, 20, 30, ...]   len=3 (교체 안 함, 이미 20)
i=5: num=50 → lis = [10, 20, 30, 50]    len=4 ✅
```

**✅ 핵심**: LIS 배열은 실제 LIS가 아니라 "길이별 최소 끝 값"
- `lis[i]`: 길이 i+1인 증가 부분 수열의 최소 끝 값
- 이 방식으로 O(N log N)에 LIS 길이를 구할 수 있음

### 4️⃣ lower_bound의 동작

```cpp
// lower_bound(시작, 끝, 값)
// → "값 이상"인 첫 번째 원소의 위치 반환

예: lis = [10, 20, 30, INF, INF, ...]

num=25 → lower_bound 결과: lis[2] (30의 위치)
num=30 → lower_bound 결과: lis[2] (30의 위치)
num=40 → lower_bound 결과: lis[3] (INF의 위치, 새로운 값!)
```

**✅ 핵심**: lower_bound는 "이상" 조건
- num보다 크거나 같은 첫 위치 반환
- 해당 위치의 값을 num으로 교체하면 "더 작은 끝 값" 유지
- 더 작은 끝 값 → 나중에 더 많은 값 추가 가능 → 최적

## 🔍 왜 이 알고리즘이 작동하는가?

### 💡 핵심 아이디어: 그리디 + 이분 탐색

**그리디 전략**:
```
"같은 길이의 증가 부분 수열이라면, 끝 값이 작을수록 좋다"

예:
[10, 20] vs [15, 25] (둘 다 길이 2)

→ [10, 20]을 선택하는 것이 유리!
  왜? 다음에 21이 오면 [10, 20, 21]로 확장 가능
  하지만 [15, 25]는 불가능
```

**이분 탐색 최적화**:
```
각 숫자를 처리할 때, O(N)으로 순차 탐색하는 대신
lower_bound를 사용하여 O(log N)에 위치 찾기

→ 전체 시간복잡도: O(N log N)
```

### 🧠 동작 과정 상세 분석

```
입력: [10, 20, 10, 30, 20, 50]

i=0: num=10
  - lis = [INF, INF, ...]
  - pos = 0 (lower_bound 결과)
  - lis[0] == INF → len++
  - lis = [10, INF, ...]
  - len = 1

i=1: num=20
  - lis = [10, INF, ...]
  - pos = 1 (20 >= 10, 20 < INF)
  - lis[1] == INF → len++
  - lis = [10, 20, INF, ...]
  - len = 2

i=2: num=10
  - lis = [10, 20, INF, ...]
  - pos = 0 (10 >= 10)
  - lis[0] == 10 (이미 같은 값) → len 유지
  - lis = [10, 20, INF, ...] (변화 없음)
  - len = 2

i=3: num=30
  - lis = [10, 20, INF, ...]
  - pos = 2 (30 >= 20, 30 < INF)
  - lis[2] == INF → len++
  - lis = [10, 20, 30, INF, ...]
  - len = 3

i=4: num=20
  - lis = [10, 20, 30, INF, ...]
  - pos = 1 (20 >= 20)
  - lis[1] == 20 (이미 같은 값) → len 유지
  - lis = [10, 20, 30, INF, ...] (변화 없음)
  - len = 3

i=5: num=50
  - lis = [10, 20, 30, INF, ...]
  - pos = 3 (50 >= 30, 50 < INF)
  - lis[3] == INF → len++
  - lis = [10, 20, 30, 50, INF, ...]
  - len = 4 ✅

결과: 4
```

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ INF 값 설정 오류

```cpp
❌ const int INF = 1000;  // 입력 범위와 같음! 틀림!

✅ const int INF = 2008;  // 입력 범위(1~1000)보다 충분히 큼
```

**이유**:
- 입력 범위: 1 ≤ Ai ≤ 1,000
- INF를 1000으로 설정하면 입력값과 구분 안 됨
- lower_bound가 올바르게 동작하지 않음

### 2️⃣ len 증가 조건 오류

```cpp
❌ if (pos == len) len++;  // 인덱스 비교 (틀릴 수 있음)

✅ if (lis[pos] == INF) len++;  // 값 비교 (확실함)
```

**이유**:
- `pos == len`은 대부분 맞지만 엣지 케이스 존재
- `lis[pos] == INF`가 더 명확하고 안전함

### 3️⃣ 배열 크기 설정

```cpp
❌ int lis[1000];  // N과 같음 (경계 오류 가능)

✅ int lis[1004];  // 여유 있게 설정
```

**이유**:
- N ≤ 1,000이므로 최소 1001 필요
- 안전을 위해 1004로 설정

### 4️⃣ lower_bound 범위 설정

```cpp
❌ int pos = lower_bound(lis, lis + 1004, num) - lis;  // 전체 배열 탐색

✅ int pos = lower_bound(lis, lis + len, num) - lis;   // len까지만 탐색
```

**이유**:
- 전체 배열 탐색하면 INF 이전 위치를 찾지 못할 수 있음
- `lis + len`으로 실제 사용 중인 범위만 탐색

## 🔬 알고리즘 상세 분석

### 💡 DP vs 이분 탐색 LIS 비교

| 방법 | 시간복잡도 | 공간복잡도 | 특징 |
|-----|----------|----------|------|
| **DP** | O(N²) | O(N) | LIS 복원 가능, 구현 간단 |
| **이분 탐색** | O(N log N) | O(N) | 길이만 구할 때 최적, 이 문제 정답 |

**DP 방식 (참고)**:
```cpp
int dp[1004];  // dp[i] = i번째까지의 LIS 길이

for (int i = 0; i < n; i++)
{
    dp[i] = 1;  // 최소 길이 1
    for (int j = 0; j < i; j++)
    {
        if (arr[j] < arr[i])
            dp[i] = max(dp[i], dp[j] + 1);
    }
}

int answer = *max_element(dp, dp + n);
```

**이 문제에서 이분 탐색 선택 이유**:
- N ≤ 1,000 → DP도 가능 (O(1,000,000) = 충분)
- 하지만 이분 탐색이 더 효율적 (O(N log N))
- **상위 문제(백준 12015, 14003)는 N ≤ 1,000,000이므로 이분 탐색 필수**

---

## ⏱️ 시간복잡도

**O(N log N)**

**상세 분석**:
```
1. 배열 초기화: O(N)
   - fill_n(lis, 1004, INF)

2. LIS 구하기: O(N log N)
   - N개의 숫자 순회: O(N)
   - 각 숫자마다 lower_bound: O(log N)
   - 총합: N × log N

총합: O(N) + O(N log N) = O(N log N)
```

**시간 제한 체크**:
- N ≤ 1,000 (문제 조건)
- **1,000 × log(1,000) ≈ 10,000** << **100,000,000** (1초 기준)
- 여유롭게 통과 ✅

---

## 💾 공간복잡도

**O(N)** - 선형 공간

**분석**:
- `lis[1004]`: LIS 배열 → O(N)
- `n`, `num`, `len`: 변수 → O(1)
- 총 공간: O(N) ≈ **O(1,000)**

## 🎯 알고리즘 분류

- **다이나믹 프로그래밍(Dynamic Programming)**: DP로도 풀 수 있음
- **이분 탐색(Binary Search)**: lower_bound 활용
- **가장 긴 증가하는 부분 수열(LIS)**: 대표 문제
