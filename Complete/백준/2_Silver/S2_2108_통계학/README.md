## 🤔 접근법

(성공하긴 했지만, STL 의존으로 인해 메모리와 시간이 비효율적이긴 함.)

N개의 수가 주어졌을 때 네 가지 기본 통계값을 구하는 문제:

1. **산술평균**: N개의 수들의 합을 N으로 나눈 값 (소수점 첫째 자리에서 반올림)
2. **중앙값**: 정렬 후 중앙에 위치하는 값
3. **최빈값**: 가장 많이 나타나는 값 (여러 개면 두 번째로 작은 값)
4. **범위**: 최댓값과 최솟값의 차이

**핵심은 입력값의 범위가 -4000 ~ 4000으로 제한**되어 있어, **Counting 배열**을 활용하면 정렬 없이도 중앙값과 최빈값을 구할 수 있다!

---

## 🔑 핵심 포인트

### 1️⃣ 산술평균 - 반올림 주의! ⚠️

```cpp
// ❌ 잘못된 방법 - 정수 나눗셈은 버림
cout << sum / n << '\n';

// ✅ 올바른 방법 - round() 함수로 반올림
cout << (int)round((double)sum / n) << '\n';
```

**반례**:
- sum=8, n=3 → 2.666... → 반올림하면 **3** (정수 나눗셈은 2)
- sum=-8, n=3 → -2.666... → 반올림하면 **-3** (정수 나눗셈은 -2)

### 2️⃣ 음수 처리 - OFFSET 보정

```cpp
const int OFFSET = 4000;  // 음수를 양수 인덱스로 변환

// -4000 → 0, 0 → 4000, 4000 → 8000
freq[temp + OFFSET]++;
```

### 3️⃣ 최빈값 - 두 번째로 작은 값

```cpp
// freq 배열을 0부터 순회하면 자동으로 정렬된 순서!
// 첫 번째 최빈값만 저장하고, 두 번째가 나오면 갱신

if (freq[i] > maxFreq)       // 새로운 최대 빈도
{
    maxFreq = freq[i];
    mode    = i - OFFSET;       // 첫 번째 최빈값
    modeCnt = 1;
}
else if (freq[i] == maxFreq) // 같은 빈도
{
    if (modeCnt == 1)        // 두 번째 최빈값일 때만 갱신
        mode = i - OFFSET;
    modeCnt++;
}
```

### 성능 차이 원인 분석

#### 📦 메모리 차이 (3916 KB)

| 항목 | STL 정렬 | Counting |
|------|----------|----------|
| `vector<int> v` | O(N) = 500,000 × 4B = **~2MB** | ❌ 없음 |
| `vector<int> freqV` | O(최빈값 개수) | ❌ 없음 |
| `int freq[]` | 8001 × 4B = 32KB | 8001 × 4B = 32KB |
| `minVal, maxVal` | ❌ 없음 | 8B |

**결론**: `vector` 동적 할당이 메모리 차이의 주요 원인

#### ⏱️ 시간 차이 (32 ms)

| 항목 | STL 정렬 | Counting |
|------|----------|----------|
| 중앙값 | `sort()` → **O(N log N)** | 배열 순회 → **O(8001)** |
| 범위 | 정렬 후 접근 → O(1) | 입력 시 갱신 → O(N) |
| 최빈값 vector | `clear()` + `emplace_back()` | ❌ 없음 |

**결론**: `sort()`의 O(N log N)이 시간 차이의 주요 원인

## 🎯 어떤 방식을 선택할까?

| 상황 | 추천 방식 |
|------|----------|
| 값의 범위가 작을 때 (-4000 ~ 4000) | ✅ **Counting 방식** |
| 값의 범위가 클 때 (10^9 등) | ✅ **STL 정렬 방식** |
| 빠른 구현이 필요할 때 | ✅ STL 정렬 방식 (직관적) |
| 메모리/시간 최적화 필요할 때 | ✅ Counting 방식 |

★★★ **이 문제는 값의 범위가 -4000 ~ 4000으로 작아서 Counting 방식이 효율적!**

## ⏱️ 시간복잡도

**STL 정렬 방식**: O(N log N)

**Counting 방식**: O(N + K) (K = 값의 범위 = 8001)

**분석**:
- N = 500,000 (최대 입력 개수)
- STL: 500,000 × log(500,000) ≈ 500,000 × 19 ≈ 9,500,000
- Counting: 500,000 + 8,001 ≈ 508,001

**✅ 결론**: 두 방식 모두 시간 제한(2초) 내 해결 가능

## 💾 공간복잡도

**Counting 방식**: O(K)
- `int freq[]`: O(K) = O(8001)
