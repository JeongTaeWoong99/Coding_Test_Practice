## 🔗 문제 링크

[백준 1072번 - 게임](https://www.acmicpc.net/problem/1072)

**난이도**: Silver 3

---

## 🤔 접근법

현재 승률 Z(소수점 버림)가 변하려면 최소 몇 게임을 더 이겨야 하는지 구하는 문제.

**핵심**: **이분 탐색(Binary Search)** 으로 승률이 변하는 최소 게임 수 찾기.

---

## 💡 정답 풀이 방법

### 🎯 방법: 이분 탐색(Binary Search)

1. **초기 승률 계산**: `Z = (wins × 100) / games` (소수점 버림)

2. **이분 탐색 범위 설정**:
   - `lo = 1` (최소 1게임)
   - `hi = games` (최대 현재 게임 수만큼)

3. **승률 변화 체크**:
   - `(wins + mid) × 100 / (games + mid) > initPer` 이면
   - 승률이 변함 → `ret = mid`, `hi = mid - 1` (더 작은 값 탐색)
   - 승률이 안 변함 → `lo = mid + 1` (더 큰 값 필요)

4. **특수 케이스**:
   - 승률이 99% 이상이면 절대 변하지 않음 → `-1` 출력
   - Z = 100%는 이미 최댓값이라 변할 수 없음
   - Z = 99%는 100%로 가려면 무한대 게임 필요

**시간복잡도**: O(log N)

---

## 🔑 핵심 개념

### 🔍 이분 탐색 원리

```cpp
ll initPer = wins * 100 / games;  // 초기 승률

ll lo = 1;
ll hi = games;  // 최대 탐색 범위

while(lo <= hi)
{
    mid = (lo + hi) / 2;

    // 승률이 변하는지 체크
    if((wins + mid) * 100 / (games + mid) > initPer)
    {
        ret = mid;      // 가능한 답 저장
        hi = mid - 1;   // 더 작은 값 탐색
    }
    else
    {
        lo = mid + 1;   // 더 큰 값 필요
    }
}
```

**동작 과정 예시**:
```
입력: games = 10, wins = 8
초기 승률 Z = 8 × 100 / 10 = 80%

lo=1, hi=10, mid=5:
(8+5) × 100 / (10+5) = 13 × 100 / 15 = 86% > 80% ✅
→ ret = 5, hi = 4

lo=1, hi=4, mid=2:
(8+2) × 100 / (10+2) = 10 × 100 / 12 = 83% > 80% ✅
→ ret = 2, hi = 1

lo=1, hi=1, mid=1:
(8+1) × 100 / (10+1) = 9 × 100 / 11 = 81% > 80% ✅
→ ret = 1, hi = 0

lo > hi 종료

결과: 1게임
```

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ long long 타입 사용 필수!

```cpp
❌ int games, wins;  // 오버플로우 발생!
✅ typedef long long ll;
   ll games, wins;
```

**이유**:
- X ≤ 1,000,000,000 (10억)
- `wins × 100`이 `int` 범위 초과
- 반드시 `long long` 사용

### 2️⃣ 이분 탐색 범위 설정

```cpp
✅ ll hi = games;           // 최적 (문제 제약 범위)
✅ ll hi = 1e9;             // 가능 (충분한 범위) = 10억 = 1000000000
❌ ll hi = LLONG_MAX;       // 시간 초과 (불필요한 범위)
```

**이유**:
- 승률은 최대 99%까지만 변할 수 있음
- `LLONG_MAX`는 불필요하게 큰 범위 (63회 반복)
- `games` 또는 `1e9`면 충분 (30회 반복)

### 3️⃣ 승률 99% 이상 체크

```cpp
// 승률이 99% 이상이면 절대 변하지 않음
ll initPer = wins * 100 / games;
if(initPer >= 99)
{
    cout << -1 << "\n";
    return 0;
}
```

**이유**:
- Z = 100%: 이미 최댓값 (변할 수 없음)
- Z = 99%: 100%로 가려면 무한대 게임 필요
- 따라서 `-1` 출력

### 4️⃣ 초기값 설정

```cpp
✅ ll ret = -1;  // 승률이 변하지 않으면 -1
```

**이유**:
- 이분 탐색으로 답을 못 찾으면 `-1` 유지
- 승률이 변하지 않는 케이스 처리

## ⏱️ 시간복잡도 분석

**전체 시간복잡도**: **O(log N)**

**상세 분석**:
```
1. 입력 처리: O(1)
   - games, wins 입력

2. 이분 탐색: O(log N)
   - 범위: 1 ~ games (최대 10억)
   - 반복 횟수: log₂(10억) ≈ 30회

3. 출력: O(1)

총합: O(log N)
```

**시간 제한 체크**:
- N ≤ 1,000,000,000 (10억)
- log₂(10억) ≈ 30회
- **30회 연산** << **1억** → 시간 내 여유롭게 통과 ✅
