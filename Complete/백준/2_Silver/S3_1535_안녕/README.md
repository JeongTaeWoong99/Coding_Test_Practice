## 🤔 접근법

(1번만 사용할 수 있다는 것 에서 역방향 바텀업 메모이제이션 DP)

전형적인 **배낭 문제(Knapsack Problem)** 변형.

세준이는 체력 100을 가지고 있고, N명의 사람에게 인사를 할 수 있다.
- 각 사람에게 인사하면 체력 `L[i]`를 잃고, 기쁨 `J[i]`를 얻는다.
- 각 사람에게는 **최대 1번만** 인사 가능.
- **체력이 0이 되면 안 됨** (죽어서 기쁨을 못 느낌).

**핵심**: 체력 100 이내에서 최대 기쁨을 얻기.

---

## 💡 정답 풀이 방법

**알고리즘**: 0/1 배낭 문제 (0/1 Knapsack) - 바텀업 DP

### 🎯 DP 정의

```cpp
dp[j] = 체력 j를 사용했을 때 얻을 수 있는 최대 기쁨
```

### 🔄 점화식

```cpp
dp[j] = max(dp[j], dp[j - cost[i]] + happy[i])
```

**의미**:
- `dp[j]`: i번째 사람에게 인사 안 함
- `dp[j - cost[i]] + happy[i]`: i번째 사람에게 인사함

### 🚨 중요 포인트 1: 역순 순회 (j = 100 → cost[i])

```cpp
for (int i = 0; i < n; ++i)
{
    for (int j = 100; j > cost[i]; --j)  // ✅ 역순!
    {
        dp[j] = max(dp[j], dp[j - cost[i]] + happy[i]);
    }
}
```

**왜 역순인가?**

**✅ 역순 (j = 100 → 1)**:
- 각 사람을 **최대 1번만** 선택 가능
- `dp[j]`를 갱신할 때, `dp[j - cost[i]]`는 **이전 단계(i-1)의 값**을 사용
- 동일한 사람을 중복 선택하지 않음

**❌ 정순 (j = 1 → 100)**:
- `dp[j]`를 갱신한 후, 더 큰 `j'`에서 `dp[j]`를 다시 사용
- **같은 사람을 여러 번 선택**할 수 있게 됨 (무한 배낭)

**예시**:
```
사람 0: cost=1, happy=20

정순일 경우:
dp[1] = 20 (사람 0 선택)
dp[2] = max(0, dp[2-1] + 20) = max(0, 20 + 20) = 40  ❌ 사람 0을 2번 선택!
dp[3] = max(0, dp[3-1] + 20) = max(0, 40 + 20) = 60  ❌ 사람 0을 3번 선택!

역순일 경우:
dp[100] = max(0, dp[99] + 20) = 20 (사람 0 선택)
dp[99]  = max(0, dp[98] + 20) = 20 (사람 0 선택)
...
dp[1] = max(0, dp[0] + 20) = 20 (사람 0 선택)
→ 각 체력에서 최대 1번만 선택 가능 ✅
```

### 🚨 중요 포인트 2: j > cost[i] (>= 아님!)

```cpp
for (int j = 100; j > cost[i]; --j)  // ✅ j > cost[i]
```

**왜 `>=`가 아니라 `>`인가?**

**문제 조건**: "체력이 0이나 음수가 되면 죽어서 아무런 기쁨을 못 느낀 것이 된다."

```
j >= cost[i]로 하면:
j = cost[i]일 때도 인사 가능
→ 인사 후 체력 = j - cost[i] = 0 ❌ 죽음!

j > cost[i]로 하면:
j = cost[i] + 1부터 가능
→ 인사 후 체력 = j - cost[i] >= 1 ✅ 생존!
```

**예시**:
```
사람 1: cost=21, happy=30

❌ j >= cost[i]:
j=21일 때: dp[21] = max(0, dp[0] + 30) = 30
→ 인사 후 체력 = 21 - 21 = 0 (죽음!)

✅ j > cost[i]:
j=22부터 가능
→ 인사 후 체력 = 22 - 21 = 1 (생존!)
```

### 🎯 전체 알고리즘

1. **초기화**: `dp[0~100] = 0` (모든 체력에서 초기 기쁨은 0)

2. **각 사람마다 DP 갱신** (i = 0 → n-1):
   - 체력을 **역순으로 순회** (j = 100 → cost[i] + 1)
   - `dp[j] = max(dp[j], dp[j - cost[i]] + happy[i])`

3. **결과**: `dp[100]` (체력 100으로 얻을 수 있는 최대 기쁨)

## 📊 테스트케이스 1번 시뮬레이션

### 🎯 입력
```
3
1 21 79
20 30 25
```

**사람 정보**:
- 사람 0: cost=1, happy=20
- 사람 1: cost=21, happy=30
- 사람 2: cost=79, happy=25

**초기 상태**:
```
dp[0~100] = 0 (모든 값이 0)
```

---

### 🔄 사람 0 처리 (cost=1, happy=20)

**순회**: j = 100 → 2 (j > 1이므로)

**핵심 변화만 표시**:
```cpp
j=100: dp[100] = max(0, dp[99] + 20) = max(0, 0 + 20) = 20
j=99:  dp[99]  = max(0, dp[98] + 20) = max(0, 0 + 20) = 20
j=98:  dp[98]  = max(0, dp[97] + 20) = max(0, 0 + 20) = 20
...
j=2:   dp[2]   = max(0, dp[1] + 20)  = max(0, 0 + 20) = 20
```

**결과**:
```
dp[0] = 0
dp[1] = 0  (j > 1 조건 때문에 갱신 안 됨)
dp[2~100] = 20
```

**의미**: 체력 2 이상이면 사람 0에게 인사 가능 (체력 1 소모, 기쁨 20 획득)

---

### 🔄 사람 1 처리 (cost=21, happy=30)

**순회**: j = 100 → 22 (j > 21이므로)

**핵심 변화**:
```cpp
j=100: dp[100] = max(20, dp[79] + 30) = max(20, 20 + 30) = 50
       (사람 0 선택 OR 사람 0+1 선택)

j=99:  dp[99]  = max(20, dp[78] + 30) = max(20, 20 + 30) = 50

j=79:  dp[79]  = max(20, dp[58] + 30) = max(20, 20 + 30) = 50

...

j=22:  dp[22]  = max(20, dp[1] + 30)  = max(20, 0 + 30) = 30
       (사람 1만 선택)
```

**결과**:
```
dp[0] = 0
dp[1] = 0
dp[2~21] = 20    (사람 0만 선택)
dp[22~100] = 50  (사람 0 + 사람 1 선택)

※ dp[22]는 30이지만, dp[23]부터는 50
```

**정확한 값**:
```
dp[22] = 30  (사람 1만 선택: 체력 22 → 체력 1, 기쁨 30)
dp[23~100] = 50  (사람 0 + 1 선택: 체력 사용 22, 기쁨 50)
```

---

### 🔄 사람 2 처리 (cost=79, happy=25)

**순회**: j = 100 → 80 (j > 79이므로)

**핵심 변화**:
```cpp
j=100: dp[100] = max(50, dp[21] + 25) = max(50, 20 + 25) = max(50, 45) = 50
       (사람 0+1 선택 OR 사람 0+2 선택)
       → 50이 더 크므로 갱신 안 됨

j=99:  dp[99]  = max(50, dp[20] + 25) = max(50, 20 + 25) = max(50, 45) = 50

j=80:  dp[80]  = max(50, dp[1] + 25)  = max(50, 0 + 25) = max(50, 25) = 50
```

**결과**:
```
dp[0] = 0
dp[1] = 0
dp[2~21] = 20
dp[22] = 30
dp[23~79] = 50
dp[80~100] = 50  (변화 없음, 사람 2 선택이 더 불리함)
```

## 🔑 핵심 개념

### 1️⃣ 0/1 배낭 문제 (0/1 Knapsack)

**특징**:
- 각 물건을 **0개 또는 1개**만 선택 가능
- 무게 제한 내에서 가치 최대화

### 2️⃣ 역순 순회의 필요성

```cpp
// ✅ 0/1 배낭 (각 물건 최대 1번)
for (int i = 0; i < n; i++)
    for (int j = W; j >= w[i]; j--)  // 역순
        dp[j] = max(dp[j], dp[j-w[i]] + v[i]);

// ✅ 무한 배낭 (각 물건 무제한)
for (int i = 0; i < n; i++)
    for (int j = w[i]; j <= W; j++)  // 정순
        dp[j] = max(dp[j], dp[j-w[i]] + v[i]);
```

**차이점**:
- **역순**: 이전 단계의 값 보존 → 중복 선택 방지
- **정순**: 현재 단계의 값 재사용 → 중복 선택 허용

### 3️⃣ 조건 `j > cost[i]`의 의미

```cpp
for (int j = 100; j > cost[i]; --j)
```

**왜 `j > cost[i]`인가?**

```
인사 후 체력 = j - cost[i]

조건: 인사 후 체력 > 0
→ j - cost[i] > 0
→ j > cost[i] ✅
```

**경계 케이스**:
```
cost[i] = 100인 경우:
j > 100 조건을 만족하는 j가 없음
→ 해당 사람에게 인사 불가 (인사하면 체력 0)
```

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ 역순 순회 필수

```cpp
❌ for (int j = cost[i]; j <= 100; j++)  // 정순 → 중복 선택!

✅ for (int j = 100; j > cost[i]; --j)   // 역순 → 1번만 선택
```

### 2️⃣ 체력 0 방지

```cpp
❌ for (int j = 100; j >= cost[i]; --j)  // j=cost[i]일 때 체력 0!

✅ for (int j = 100; j > cost[i]; --j)   // 체력 항상 1 이상
```

### 3️⃣ 배열 크기

```cpp
❌ int dp[100];  // dp[100] 접근 → 범위 초과!

✅ int dp[104];  // 여유롭게 설정
```

### 4️⃣ 체력 초과 케이스

```
모든 cost[i]가 100 이상인 경우:
→ 아무에게도 인사 불가
→ dp[100] = 0 ✅
```

## 💡 다른 풀이 방법

### 🎯 방법 1: 2차원 DP (메모리 O(N × 100))

```cpp
// dp[i][j] = i번째 사람까지 고려, 체력 j 사용 시 최대 기쁨
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= 100; j++)
        if (j > cost[i-1])
            dp[i][j] = max(dp[i-1][j], dp[i-1][j-cost[i-1]] + happy[i-1]);
        else
            dp[i][j] = dp[i-1][j];
```

**장점**: 명확한 점화식
**단점**: 메모리 2배 사용

### 🎯 방법 2: 1차원 DP (메모리 O(100)) - 현재 코드

```cpp
// dp[j] = 체력 j 사용 시 최대 기쁨
for (int i = 0; i < n; i++)
    for (int j = 100; j > cost[i]; --j)
        dp[j] = max(dp[j], dp[j-cost[i]] + happy[i]);
```

**장점**: 메모리 효율적
**단점**: 역순 순회 이해 필요

## 🔍 시간복잡도 분석

### 📌 전체 시간복잡도: O(N × 100)

**변수 정의**:
- N: 사람 수 (최대 20)
- 체력 범위: 1 ~ 100

**단계별 분석**:
```cpp
for (int i = 0; i < n; ++i)           // N번 반복
{
    for (int j = 100; j > cost[i]; --j)  // 최대 100번 반복
    {
        dp[j] = max(dp[j], ...);         // O(1)
    }
}
```

**계산**:
- 외부 루프: O(N) = O(20)
- 내부 루프: O(100)
- 총 연산: 20 × 100 = **2,000회**

**✅ 결과**: 2,000 << 100,000,000 (1억) → **충분히 통과!**
