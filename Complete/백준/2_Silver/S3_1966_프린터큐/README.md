## 🔗 문제 링크

[백준 1966번 - 프린터 큐](https://www.acmicpc.net/problem/1966)

**난이도**: Silver 3

---

## 🤔 접근법

(문제를 이해하면, 쉽게 풀 수 있는데... 문제를 이해 못해서 얼타다가 결국 품!)

프린터 큐에서 특정 문서가 몇 번째로 인쇄되는지 구하는 문제.

**핵심**: 중요도가 높은 문서가 먼저 인쇄되고, 앞에 더 높은 중요도 문서가 있으면 현재 문서는 뒤로 재배치됨.

**두 가지 핵심 자료구조**:
- `queue<pair<int, int>>` : 원래 인덱스와 중요도 저장
- `priority_queue<int>` : 현재 최고 중요도를 O(1)에 확인

---

## 💡 정답 풀이 방법

**알고리즘**: 큐 시뮬레이션 + 우선순위 큐

**핵심 아이디어**:
```
1. 일반 큐(nQ)에 {원래 인덱스, 중요도} 저장

2. 우선순위 큐(pQ)에 모든 중요도 저장 (최대 힙)

3. 시뮬레이션 시작:
   - nQ 앞에서 문서 꺼냄
   - 중요도 == pQ.top() → 인쇄 (cnt++)
   - 중요도 < pQ.top() → 뒤로 재배치
   
4. 찾는 문서 인쇄 시 cnt 출력
```

---

## 🔑 핵심 개념

### 1️⃣ 두 가지 큐의 역할

```cpp
priority_queue<int>   pQ;  // 최대 힙: 현재 남은 문서 중 최고 중요도 추적
queue<pair<int, int>> nQ;  // {원래 인덱스, 중요도} 저장
```

**✅ 핵심**:
- `pQ.top()`: 현재 남은 문서들 중 **최고 중요도**를 O(1)에 확인
- `nQ`: 원래 순서(인덱스)를 유지하면서 중요도와 함께 저장

### 2️⃣ 인쇄 가능 여부 판단

```cpp
if (pri == pQ.top())  // 현재 문서가 최고 중요도인가?
{
    pQ.pop();  // 우선순위 큐에서도 제거
    cnt++;     // 인쇄 순서 증가

    if (idx == m)  // 찾던 문서인가?
    {
        cout << cnt << '\n';
        break;
    }
}
else  // 더 높은 중요도 문서가 있음
{
    nQ.emplace(idx, pri);  // 뒤로 재배치
}
```

**✅ 핵심**:
- `pri == pQ.top()`: 현재 문서가 남은 문서 중 가장 중요하면 인쇄
- 아니면 큐의 맨 뒤로 재배치

### 3️⃣ 왜 우선순위 큐를 사용하는가?

**❌ 우선순위 큐 없이**:
```cpp
// 매번 큐를 순회하며 최대값 찾기
bool hasHigher = false;
for (auto& doc : nQ)
    if (doc.second > currentPri) hasHigher = true;
```
→ 매번 O(N) 탐색 필요

**✅ 우선순위 큐 사용**:
```cpp
if (pri == pQ.top())  // O(1)에 최대값 확인
```
→ O(1)에 최대값 확인 가능!

## 📊 예제 분석

### 🎯 예제 입력 2: `4 2` / `1 2 3 4`

```
문서 4개, 2번째 문서(C)가 몇 번째로 인쇄되는지?
중요도: A=1, B=2, C=3, D=4
```

### 📌 단계별 실행 과정

| Step | 동작 | nQ 상태 | pQ.top() | cnt |
|------|------|---------|----------|-----|
| 초기 | - | [A(1), B(2), C(3), D(4)] | 4 | 0 |
| 1 | A(1) 꺼냄, 1≠4 → 뒤로 | [B(2), C(3), D(4), A(1)] | 4 | 0 |
| 2 | B(2) 꺼냄, 2≠4 → 뒤로 | [C(3), D(4), A(1), B(2)] | 4 | 0 |
| 3 | C(3) 꺼냄, 3≠4 → 뒤로 | [D(4), A(1), B(2), C(3)] | 4 | 0 |
| 4 | D(4) 꺼냄, 4==4 → 🖨️ | [A(1), B(2), C(3)] | 3 | 1 |
| 5 | A(1) 꺼냄, 1≠3 → 뒤로 | [B(2), C(3), A(1)] | 3 | 1 |
| 6 | B(2) 꺼냄, 2≠3 → 뒤로 | [C(3), A(1), B(2)] | 3 | 1 |
| 7 | C(3) 꺼냄, 3==3 → 🖨️ | idx==m → **출력: 2** | - | 2 |

**🎯 결과: 2**

### 🎯 예제 입력 3: `6 0` / `1 1 9 1 1 1`

```
문서 6개, 0번째 문서(A)가 몇 번째로 인쇄되는지?
중요도: A=1, B=1, C=9, D=1, E=1, F=1
```

| Step | 동작 | 핵심 |
|------|------|------|
| 1~2 | A, B 뒤로 재배치 | 1 ≠ 9 |
| 3 | C(9) 인쇄 | cnt=1 |
| 4~7 | D, E, F, A 순서대로 인쇄 | 모두 중요도 1 |

**🎯 결과: 5** (A는 5번째로 인쇄)

## 🚨 주의사항

### 1️⃣ 인덱스와 중요도 구분

```cpp
nQ.emplace(idx, priority);  // {원래 인덱스, 중요도}

int idx = nQ.front().first;   // 원래 인덱스
int pri = nQ.front().second;  // 중요도
```

**✅ 핵심**: `idx`는 찾는 문서 판별용, `pri`는 인쇄 가능 여부 판별용

---

## ⏱️ 시간복잡도

**O(N² × T)** (최악의 경우)

**분석**:
- T개의 테스트 케이스
- 각 테스트 케이스에서:
  - 입력: O(N)
  - 시뮬레이션: 최악의 경우 O(N²) (모든 문서가 여러 번 재배치)
  - 실제로는 각 문서가 최대 N번 재배치 가능

**시간 제한 체크**:
- N ≤ 100, T ≤ (여러 개)
- 실제로는 중요도가 다양하므로 평균적으로 훨씬 빠름
- 충분히 시간 내 통과 가능 ✅

---

## 💾 공간복잡도

**O(N)**

- `pQ`: 최대 N개의 중요도 저장
- `nQ`: 최대 N개의 {인덱스, 중요도} 쌍 저장
- 총합: O(N + N) = **O(N)**
