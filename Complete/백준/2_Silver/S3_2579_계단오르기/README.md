## 🔗 문제 링크

[백준 2579번 - 계단 오르기](https://www.acmicpc.net/problem/2579)

**난이도**: Silver 3

---

## 🤔 접근법

(base케이스와 조건을 어렵게 생각하지 않으면, 쉽게 풀 수 있었다. 너무 어렵게 생각함.)

계단을 올라가며 점수를 최대로 얻는 문제. 단, **연속 3개의 계단을 밟으면 안 됨**.

**규칙**:
1. 한 번에 1칸 또는 2칸 오를 수 있음
2. 연속된 세 개의 계단을 모두 밟으면 안 됨
3. 마지막 계단은 반드시 밟아야 함

**핵심 아이디어**:
- i번째 계단을 밟는 경우는 **2가지**뿐!
- 어느 경우든 **중간에 하나를 건너뛰므로** 3연속이 될 수 없음

```
경우 1: i-2에서 2칸 점프 → i (i-1 안 밟음)
        ○ ○ ●

경우 2: i-3에서 i-1로 2칸 점프 → i로 1칸 점프 (i-2 안 밟음)
        ○ ● ●
```

---

## 💡 정답 풀이 방법

**알고리즘**: Bottom-up DP (반복문)

**점화식**:
```cpp
dp[i] = max(
    dp[i-2] + a[i],           // 경우 1: 2칸 점프 (i-1 안 밟음)
    dp[i-3] + a[i-1] + a[i]   // 경우 2: 1칸+1칸 (i-2 안 밟음)
)
```

**초기값 (Base case)**:
```cpp
dp[1] = a[1]                          // 첫 번째 계단
dp[2] = a[1] + a[2]                   // 1-2 연속 (OK)
dp[3] = max(a[1] + a[3], a[2] + a[3]) // 1-3 or 2-3
```

## 🔑 핵심 포인트

### 1️⃣ 왜 3연속이 안 생기는가?

```
dp[i] = max(
    dp[i-2] + a[i],           ← i-1을 안 밟음 (○ ○ ●)
    dp[i-3] + a[i-1] + a[i]   ← i-2를 안 밟음 (○ ● ●)
)

두 경우 모두 중간에 하나를 건너뛰므로 3연속 불가능!
```

### 2️⃣ DP 배열 갱신 과정 (예제 입력)

```
입력: n=6, a[] = {10, 20, 15, 25, 10, 20}

dp[1] = 10
dp[2] = 10 + 20 = 30
dp[3] = max(10 + 15, 20 + 15) = max(25, 35) = 35

dp[4] = max(dp[2] + a[4], dp[1] + a[3] + a[4])
      = max(30 + 25, 10 + 15 + 25)
      = max(55, 50) = 55

dp[5] = max(dp[3] + a[5], dp[2] + a[4] + a[5])
      = max(35 + 10, 30 + 25 + 10)
      = max(45, 65) = 65

dp[6] = max(dp[4] + a[6], dp[3] + a[5] + a[6])
      = max(55 + 20, 35 + 10 + 20)
      = max(75, 65) = 75

출력: 75 ✅
```

### 3️⃣ 경로 추적 (최적 경로)

```
dp[6] = 75 ← dp[4] + a[6] = 55 + 20 (2칸 점프)
dp[4] = 55 ← dp[2] + a[4] = 30 + 25 (2칸 점프)
dp[2] = 30 ← a[1] + a[2] = 10 + 20

최적 경로: 1 → 2 → 4 → 6
점수: 10 + 20 + 25 + 20 = 75 ✅
```

## 🆚 바텀업 vs 탑다운 비교

### 코드 구조 차이

| 항목 | 바텀업 (반복문) | 탑다운 (재귀) |
|-----|---------------|--------------|
| **방향** | 1 → N 순방향 | N → 1 역방향 |
| **초기화** | dp[1], dp[2], dp[3] 직접 설정 | Base case로 반환 |
| **메모이제이션** | 자동 (순서대로 채움) | `dp[i] != -1` 체크 필요 |

### 성능 비교

| 항목 | 바텀업 | 탑다운 |
|-----|-------|-------|
| **시간복잡도** | O(N) | O(N) |
| **공간복잡도** | O(N) | O(N) + 재귀 스택 |
| **실제 속도** | **빠름 ⭐** | 느림 |
| **메모리** | **적음 ⭐** | 많음 |
| **함수 호출** | 없음 | N번 |
| **캐시 효율** | 높음 (순차 접근) | 낮음 (랜덤 접근) |

### 바텀업이 더 빠른 이유

```
1. 함수 호출 오버헤드 없음
   - 탑다운: solve() 함수를 N번 호출
   - 바텀업: 단순 반복문

2. CPU 캐시 효율
   - 탑다운: 랜덤한 순서로 메모리 접근
   - 바텀업: dp[1] → dp[2] → ... 순차 접근 (캐시 hit율 ↑)

3. 스택 메모리
   - 탑다운: 재귀 깊이만큼 스택 사용
   - 바텀업: 스택 사용 없음
```

### 언제 어떤 방식을 선택?

| 상황 | 추천 |
|-----|-----|
| 성능이 중요할 때 | **바텀업** ⭐ |
| 점화식을 직관적으로 표현하고 싶을 때 | 탑다운 |
| N이 매우 클 때 (스택 오버플로우 방지) | **바텀업** ⭐ |
| 모든 상태를 계산할 필요가 없을 때 | 탑다운 |

**✅ 이 문제 (N ≤ 300)**: 둘 다 OK, 바텀업이 약간 유리

## ⏱️ 시간복잡도

**O(N)**
- 반복문으로 4부터 N까지 순회
- 각 i마다 상수 시간 연산 O(1)

---

## 💾 공간복잡도

**O(N)**
- `a[304]`: 계단 점수 저장
- `dp[304]`: 최대 점수 저장
