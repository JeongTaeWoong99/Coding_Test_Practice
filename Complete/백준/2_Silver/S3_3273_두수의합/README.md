## 🔗 문제 링크

[백준 3273번 - 두 수의 합](https://www.acmicpc.net/problem/3273)

**난이도**: Silver 3

---

## 🤔 접근법

n개의 서로 다른 양의 정수로 이루어진 수열에서, 두 수의 합이 x가 되는 쌍의 개수를 구하는 문제.

**핵심**: 정렬 후 **투 포인터(Two Pointers)** 알고리즘을 활용한 효율적인 탐색.

---

## 💡 정답 풀이 방법

### 🎯 방법: 투 포인터(Two Pointers) - 내 코드

1. **정렬**: 수열을 오름차순으로 정렬

2. **양쪽 포인터 설정**: 왼쪽(LP)과 오른쪽(RP) 포인터 배치

3. **합 비교**:
   - `v[LP] + v[RP] == x` → 쌍 개수 증가, LP++, RP--
   - `v[LP] + v[RP] < x` → LP++ (합을 키워야 함)
   - `v[LP] + v[RP] > x` → RP-- (합을 줄여야 함)

**시간복잡도**: O(N log N) - 정렬 + O(N) 탐색

---

## 🔑 핵심 개념

### 🔍 투 포인터 원리

```cpp
sort(v.begin(), v.end());  // 정렬

int LP = 0;                // 왼쪽 포인터
int RP = v.size() - 1;     // 오른쪽 포인터

while (LP < RP)
{
    int sum = v[LP] + v[RP];

    if (sum == x)
    {
        ret++;
        LP++;
        RP--;
    }
    else if (sum < x)
        LP++;   // 합을 키워야 함
    else
        RP--;   // 합을 줄여야 함
}
```

**동작 과정 예시**:
```
입력:
n = 9
수열: [5, 12, 7, 10, 9, 1, 2, 3, 11]
x = 13

정렬 후: [1, 2, 3, 5, 7, 9, 10, 11, 12]

LP=0, RP=8: 1 + 12 = 13 ✅ → ret++, LP++, RP--
LP=1, RP=7: 2 + 11 = 13 ✅ → ret++, LP++, RP--
LP=2, RP=6: 3 + 10 = 13 ✅ → ret++, LP++, RP--
LP=3, RP=5: 5 + 9 = 14 > 13 → RP--
LP=3, RP=4: 5 + 7 = 12 < 13 → LP++
LP=4, RP=4: LP >= RP 종료

결과: 3개
```

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ 정렬 필수!

```cpp
❌ 정렬 없이 투 포인터 사용 → 틀림!
✅ sort(v.begin(), v.end()); → 먼저 정렬
```

**이유**:
- 투 포인터는 정렬된 배열에서만 올바르게 동작
- 정렬되지 않으면 합의 대소 비교가 의미 없음

### 2️⃣ 중복 카운팅 방지

```cpp
✅ LP < RP 조건으로 같은 쌍을 두 번 세지 않음
✅ 1 ≤ i < j ≤ n 조건이 자동으로 만족됨
```

**이유**:
- (ai, aj)와 (aj, ai)는 같은 쌍
- LP < RP로 중복 방지

### 3️⃣ 포인터 이동 순서

```cpp
if (sum == x)
{
    ret++;
    RP--;
    LP++;   // 두 포인터 모두 이동!
}
```

**이유**:
- 수열의 모든 수가 서로 다름 (문제 조건)
- 같은 합이 나오면 두 포인터를 모두 이동해야 함

## ⏱️ 시간복잡도 분석

**전체 시간복잡도**: **O(N log N)**

**상세 분석**:
```
1. 입력 처리: O(N)
   - N개의 수 입력

2. 정렬: O(N log N)
   - sort() 함수 (퀵소트/머지소트 기반)

3. 투 포인터 탐색: O(N)
   - LP는 0 → N으로 최대 N번 이동
   - RP는 N → 0으로 최대 N번 이동
   - 합계: 최대 N번

총합: O(N) + O(N log N) + O(N) = O(N log N)
```

**시간 제한 체크**:
- N ≤ 100,000 (문제 조건)
- N log N ≈ 100,000 × 17 ≈ 1,700,000 (170만)
- **170만 연산** << **1억** → 시간 내 여유롭게 통과 ✅

## 🔬 투 포인터 시간복잡도 상세 분석

### ⚠️ 중요: 투 포인터는 O(N)이다!

```
총 시간복잡도: O(N log N)
├── 정렬: O(N log N)  ← sort() 함수
└── 투 포인터 탐색: O(N)  ← ⭐ 이 부분이 핵심!
```

**✅ 결론**: 정렬 때문에 O(N log N)이지, **투 포인터 자체는 O(N)**!

### 🔑 투 포인터가 O(N)인 이유

**핵심 원리**: 각 포인터는 **한 방향으로만 이동**합니다!

```
✅ LP는 0부터 시작해서 N-1까지 최대 N번 이동
✅ RP는 N-1부터 시작해서 0까지 최대 N번 이동
✅ 둘 중 하나가 이동할 때마다 거리가 1씩 좁혀짐
✅ 처음 거리: N-1 (LP=0, RP=N-1)
✅ 최종 거리: 0 (LP == RP)
✅ 총 이동 횟수: 최대 N번

→ 시간복잡도: O(N) ⭐
```
