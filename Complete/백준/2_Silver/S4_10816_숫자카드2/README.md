## 🔗 문제 링크

[백준 10816번 - 숫자 카드 2](https://www.acmicpc.net/problem/10816)

**난이도**: Silver 4

---

## 🤔 접근법

(unordered_map으로 풀었지만, 더 최적화가 가능했음. 그리고, 이분 탐색이 더 효율적이다.)

N개의 숫자 카드 중 각 숫자가 몇 개 있는지 세는 문제.

M개의 질문에 대해 각 숫자가 몇 개인지 빠르게 답해야 함.

**핵심**: 각 숫자의 **개수를 저장**하고, **빠르게 조회**할 수 있는 자료구조 사용.

**3가지 해결 방법**:
1. **unordered_map** : 해시 테이블 (평균 O(1) 조회)
2. **배열** : 직접 인덱싱 (O(1) 조회, 고정 메모리)
3. **이분 탐색** : 정렬 후 equal_range (O(log N) 조회, 최소 메모리)

---

## 💡 정답 풀이 방법 (unordered_map 최적화)

### 🎯 방법 1: unordered_map (추천!)

**알고리즘**: 해시맵 활용

**핵심 아이디어**:
```
1. unordered_map으로 각 숫자의 개수를 저장
2. reserve()로 버킷 미리 할당 → 리해싱 방지
3. find()로 조회 → 없는 키 생성 방지
```

**⚡ 최적화 포인트**:
```cpp
// ❌ 최적화 전 (43828 KB / 488 ms)
unordered_map<int,int> unMap;
cin >> n;
for (int i = 0; i < n; ++i)
{
    cin >> temp;
    unMap[temp]++;
}
for (int i = 0; i < m; ++i)
{
    cin >> temp;
    cout << unMap[temp] << " ";  // ❌ 없는 키도 생성!
}
```

```cpp
// ✅ 최적화 후 (21804 KB / 376 ms)
unordered_map<int,int> unMap;
cin >> n;
unMap.reserve(n);  // ✅ 1. 버킷 미리 할당

for (int i = 0; i < n; ++i)
{
    cin >> temp;
    unMap[temp]++;
}

for (int i = 0; i < m; ++i)
{
    cin >> temp;

    auto it = unMap.find(temp);  // ✅ 2. find() 사용
    cout << (it != unMap.end() ? it->second : 0) << " ";
}
```

**📊 최적화 효과**:

| 항목       | 최적화 전  | 최적화 후  | 개선율        |
|-----------|-----------|-----------|--------------|
| **메모리** | 43828 KB  | 21804 KB  | **-50.2%** ⭐ |
| **시간**   | 488 ms    | 376 ms    | **-23.0%**    |

**✅ 최적화 분석**:

**1️⃣ `reserve(n)` 효과**:
- **리해싱 방지**: 해시 테이블이 커질 때마다 자동 확장(리해싱) 발생
- 리해싱 시 모든 원소를 새 버킷으로 재배치 → 시간/메모리 낭비
- `reserve(n)`으로 미리 충분한 버킷 할당 → 리해싱 0회
- **시간 개선**: 리해싱 오버헤드 제거
- **메모리 개선**: 불필요한 중간 버킷 배열 생성 방지

**2️⃣ `find()` vs `operator[]`**:
- `unMap[temp]`: 키가 없으면 **새로운 키-값 쌍 자동 생성** (값 0으로 초기화)
- `find()`: 키가 없으면 `end()` 반환, **생성하지 않음**
- **메모리 개선**: M개 질문 중 unMap에 없는 숫자들이 생성되지 않음
  - 예: N=10, M=500,000이고 질문 숫자가 모두 다르면
  - 최적화 전: 500,000개 키 생성 → 메모리 폭발 💥
  - 최적화 후: 10개 키만 유지 → 메모리 절약 ✅

**💡 핵심 정리**:
```
reserve(n) → 리해싱 방지 → 시간 -23%, 메모리 일부 감소
find() → 불필요한 키 생성 방지 → 메모리 -50% ⭐
```

### 🎯 방법 2: 배열 (시간 최고)

**핵심 아이디어**:
```
1. 범위: -10,000,000 ~ 10,000,000
2. 오프셋 10,000,000을 더해서 0 ~ 20,000,000으로 변환
3. 배열 cnt[20000001]에 직접 카운트
```

**코드**:
```cpp
const int OFFSET = 10000000;
int cnt[20000001];

cin >> n;
for (int i = 0; i < n; ++i)
{
    cin >> temp;
    cnt[temp + OFFSET]++;
}

for (int i = 0; i < m; ++i)
{
    cin >> temp;
    cout << cnt[temp + OFFSET] << " ";
}
```

**📊 성능**:

| 항목       | 성능                     |
|-----------|-------------------------|
| **메모리** | 80144 KB (고정)          |
| **시간**   | 248 ms ⭐ (가장 빠름)     |

**✅ 특징**:
- **장점**: O(1) 직접 접근, 가장 빠른 속도
- **단점**: 범위에 관계없이 고정 메모리 사용 (약 76MB)
- **적합**: 숫자 범위가 작고, 속도가 최우선일 때

### 🎯 방법 3: 이분 탐색 (메모리 최고)

**핵심 아이디어**:
```
1. 입력받은 카드를 정렬
2. equal_range()로 해당 값의 범위 찾기
3. upper_bound - lower_bound = 개수
```

**코드**:
```cpp
vector<int> cards;
cin >> n;
cards.reserve(n);

for (int i = 0; i < n; ++i)
{
    cin >> temp;
    cards.push_back(temp);
}

sort(cards.begin(), cards.end());

for (int i = 0; i < m; ++i)
{
    cin >> temp;
    auto range = equal_range(cards.begin(), cards.end(), temp);
    cout << range.second - range.first << " ";
}
```

**📊 성능**:

| 항목       | 성능                      |
|-----------|--------------------------|
| **메모리** | 3980 KB ⭐ (가장 적음)     |
| **시간**   | 268 ms                   |

**✅ 특징**:
- **장점**: 메모리 효율 최고, 실제 데이터 크기만 사용
- **단점**: 정렬 필요 (O(N log N))
- **적합**: 메모리 제한이 빡빡하거나, 데이터 범위가 매우 클 때

### 🔍 equal_range() 함수 상세 설명

※ equal_range 내부적으로 이분 탐색을 통해, 위치를 찾음. ※

**함수 원형**:
```cpp
pair<iterator, iterator> equal_range(begin, end, value);
```

**반환값**:
- `first`: `lower_bound(value)` - value 이상인 첫 위치
- `second`: `upper_bound(value)` - value 초과인 첫 위치
- `개수 = second - first`

**동작 예시**:
```
정렬된 cards: [1, 2, 3, 3, 3, 5, 7]
                      ↑     ↑
                      ↓     ↓
auto range = equal_range(cards.begin(), cards.end(), 3);

range.first  → 인덱스 2 (첫 번째 3)
range.second → 인덱스 5 (3보다 큰 첫 값 = 5)

개수 = range.second - range.first = 5 - 2 = 3 ✅
```

**✅ equal_range() vs lower_bound() + upper_bound()**:
```cpp
// ❌ 비효율적: 이분 탐색 2번
auto lower = lower_bound(cards.begin(), cards.end(), temp);
auto upper = upper_bound(cards.begin(), cards.end(), temp);
cout << upper - lower << " ";

// ✅ 효율적: 이분 탐색 1번 (내부 최적화)
auto range = equal_range(cards.begin(), cards.end(), temp);
cout << range.second - range.first << " ";
```

**시간복잡도**:
- `lower_bound()` : O(log N)
- `upper_bound()` : O(log N)
- `equal_range()` : O(log N) ⭐ (한 번의 탐색으로 양쪽 경계 찾음)

### 🔬 unordered_map 최적화 상세 분석

#### 1️⃣ reserve() 동작 원리

**해시 테이블의 리해싱**:
```
초기 버킷 수: 8 (예시)

삽입 1-8개: [버킷 8개] → OK
삽입 9개째: 부하율(load factor) 초과!
  → 리해싱 발생: 버킷 8개 → 16개로 확장
  → 모든 원소(8개)를 새 버킷으로 재배치

삽입 9-16개: [버킷 16개] → OK
삽입 17개째: 리해싱 발생: 16개 → 32개
  → 모든 원소(16개)를 새 버킷으로 재배치

...
```

**reserve(n) 사용 시**:
```
reserve(500000) 호출
  → 버킷 수를 미리 500000개 이상으로 설정
  → 리해싱 0회 발생!
  → 시간/메모리 절약 ✅
```

**효과**:
- **시간**: 리해싱 오버헤드 제거 (재배치 비용 0)
- **메모리**: 중간 크기 버킷 배열 생성 안 함

---

#### 2️⃣ find() vs operator[] 메모리 차이

**시나리오**: N=10, M=500,000 (질문 숫자가 모두 카드에 없음)

```cpp
// ❌ operator[] 사용 (최적화 전)
for (int i = 0; i < m; ++i)
{
    cin >> temp;
    cout << unMap[temp] << " ";  // 없으면 생성!
}

결과:
  - unMap 크기: 10 + 500,000 = 500,010개
  - 메모리: 약 40-50MB
```

```cpp
// ✅ find() 사용 (최적화 후)
for (int i = 0; i < m; ++i)
{
    cin >> temp;
    auto it = unMap.find(temp);
    cout << (it != unMap.end() ? it->second : 0) << " ";
}

결과:
  - unMap 크기: 10개 (그대로)
  - 메모리: 약 1KB
```

**차이**: **50MB vs 1KB** → 50,000배 차이!

## ⏱️ 시간복잡도 분석

### unordered_map (최적화)

**전체 시간복잡도**: **O(N + M)**

**상세 분석**:
```
1. 카드 입력 및 카운트 : O(N)
   - N번 반복, 각 삽입 O(1) (평균)

2. 질문 처리 : O(M)
   - M번 반복, 각 find() O(1) (평균)

총합 : O(N + M)
```

**N = M = 500,000일 때**:
- 100만 연산 → 0.01초 → **여유 있게 통과** ✅

---

### 배열

**전체 시간복잡도**: **O(N + M)**

**상세 분석**:
```
1. 카드 카운트 : O(N)
   - 배열 인덱스 접근 O(1)

2. 질문 처리 : O(M)
   - 배열 인덱스 접근 O(1)

총합 : O(N + M)
```

**특징**: 해시 충돌 없음, 가장 빠름!

---

### 이분 탐색

**전체 시간복잡도**: **O(N log N + M log N)**

**상세 분석**:
```
1. 정렬 : O(N log N)
   - sort() 함수 (병합 정렬 등)

2. 질문 처리 : O(M log N)
   - M번 반복, 각 equal_range() O(log N)

총합 : O(N log N + M log N)
```

**N = M = 500,000일 때**:
- 500,000 × 19 + 500,000 × 19 ≈ 19,000,000
- 1900만 연산 → 0.19초 → **통과** ✅
