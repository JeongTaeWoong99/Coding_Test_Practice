## 🔗 문제 링크

[백준 1940번 - 주몽](https://www.acmicpc.net/problem/1940)

**난이도**: Silver 4

---

## 🤔 접근법

두 재료의 고유번호 합이 M이 되면 갑옷을 만들 수 있는 문제.

N개의 재료 중 2개를 선택하여 합이 M인 경우를 찾는 **조합(Combination)** 문제.

**핵심**: 모든 재료 쌍을 확인하되, 중복을 피하기 위해 이전 재료들과만 비교.

---

## 💡 정답 풀이 방법

### 🎯 방법 1: 브루트 포스(Brute Force) - 내 코드

1. **이중 반복문**: 모든 재료 쌍을 확인

2. **중복 방지**: `j`와 `k < j`로 이미 확인한 쌍은 제외

3. **합 비교**: `arr[j] + arr[k] == M`이면 카운트 증가

**시간복잡도**: O(N²) - N ≤ 15,000이므로 충분히 통과 가능

### 🎯 방법 2: 투 포인터(Two Pointers) - 최적화

1. **정렬**: 재료 배열을 오름차순 정렬

2. **양쪽 포인터**: 왼쪽(left)과 오른쪽(right) 포인터 설정

3. **합 비교**:
   - `arr[left] + arr[right] == M` → 갑옷 개수 증가, left++, right--
   - `arr[left] + arr[right] < M` → left++ (합을 키워야 함)
   - `arr[left] + arr[right] > M` → right-- (합을 줄여야 함)

**시간복잡도**: O(N log N) - 정렬 + O(N) 탐색

---

## 🔑 핵심 개념

### 📐 브루트 포스 원리

```cpp
for (int j = 0; j < N; j++)
{
    for (int k = 0; k < j; k++)  // k < j로 중복 방지!
    {
        if (arr[j] + arr[k] == M)
            ret++;
    }
}
```

**✅ 핵심**: `k < j` 조건으로 (0,1)과 (1,0)의 중복을 방지

**예시**:
```
재료: [2, 7, 4, 1, 5, 3], M = 9

j=1, k=0: 7 + 2 = 9 ✅
j=2, k=0: 4 + 2 = 6 ❌
j=2, k=1: 4 + 7 = 11 ❌
j=3, k=0: 1 + 2 = 3 ❌
...
j=5, k=4: 3 + 5 = 8 ❌
j=5, k=1: 3 + 7 = 10 ❌
j=4, k=3: 5 + 1 = 6 ❌
j=4, k=2: 5 + 4 = 9 ✅

결과: 2개
```

### 🔍 투 포인터 원리

```cpp
sort(arr, arr + N);  // 정렬: [1, 2, 3, 4, 5, 7]

int left = 0, right = N - 1;

while (left < right)
{
    int sum = arr[left] + arr[right];

    if (sum == M)
    {
        ret++;
        left++;
        right--;
    }
    else if (sum < M)
        left++;   // 합을 키워야 함
    else
        right--;  // 합을 줄여야 함
}
```

**동작 과정**:
```
정렬된 배열: [1, 2, 3, 4, 5, 7], M = 9

left=0, right=5: 1 + 7 = 8 < 9 → left++
left=1, right=5: 2 + 7 = 9 ✅ → ret++, left++, right--
left=2, right=4: 3 + 5 = 8 < 9 → left++
left=3, right=4: 4 + 5 = 9 ✅ → ret++, left++, right--
left=4, right=3: left >= right 종료

결과: 2개
```

## 🔍 두 방법 비교

| 항목 | 브루트 포스 | 투 포인터 |
|-----|-----------|---------|
| **시간복잡도** | O(N²) | O(N log N) |
| **공간복잡도** | O(1) | O(1) |
| **구현 난이도** | ★★☆☆☆ | ★★★☆☆ |
| **코드 간결성** | ★★★★★ | ★★★★☆ |
| **N=15,000** | 2.25억 연산 (경계선) | 15,000 log 15,000 ≈ 6만 연산 ✅ |

### 내 코드의 선택
✅ **브루트 포스 사용 이유**:
- N ≤ 15,000으로 O(N²) = 2.25억 연산은 C++에서 통과 가능
- 코드가 간결하고 직관적
- 정렬이 필요 없어 추가 작업 불필요

💡 **개선 여지**:
- N이 더 크다면(N > 50,000) 투 포인터가 필수
- 투 포인터는 정렬 후 O(N) 탐색으로 더 효율적

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ 중복 카운팅 방지

```cpp
❌ for (int j = 0; j < N; j++)
      for (int k = 0; k < N; k++)  // (0,1)과 (1,0)을 각각 카운트!

✅ for (int j = 0; j < N; j++)
      for (int k = 0; k < j; k++)  // k < j로 중복 방지
```

**이유**:
- 같은 쌍을 두 번 세면 결과가 2배로 나옴
- (재료1, 재료2)와 (재료2, 재료1)은 같은 조합!

### 2️⃣ 같은 재료 두 번 사용 방지

```cpp
❌ for (int j = 0; j < N; j++)
      for (int k = 0; k <= j; k++)  // j == k 허용 → 같은 재료 2번 사용!

✅ for (int j = 0; j < N; j++)
      for (int k = 0; k < j; k++)   // k < j로 자기 자신 제외
```

**이유**:
- 갑옷은 **두 개의 다른 재료**로 만듦
- 같은 재료 한 개만으로는 불가능

### 3️⃣ 배열 크기 설정

```cpp
❌ int arr[15000];  // N=15000일 때 arr[15000] 접근 → 범위 초과!

✅ int arr[15004];  // 여유 있게 설정
```

## ⏱️ 시간복잡도 분석

### 브루트 포스

**시간복잡도**: O(N²)

**분석**:
- N = 15,000일 때
- 15,000 × 15,000 = 225,000,000 (2.25억) 연산
- **C++ 기준 1초에 약 1~3억 연산 가능** → 통과 가능 ✅

### 투 포인터

**시간복잡도**: O(N log N)

**분석**:
- 정렬: O(N log N) ≈ 15,000 × 14 ≈ 210,000
- 투 포인터 탐색: O(N) = 15,000
- 총합: 약 225,000 연산 → **매우 여유 있게 통과** ✅

---

## 🔬 투 포인터 시간복잡도 상세 분석

### ⚠️ 중요: 투 포인터는 O(N)이다!

많은 사람들이 **"while 반복문이니까 O(N log N)?"** 라고 오해하지만, 실제로는:

```
총 시간복잡도: O(N log N)
├── 정렬: O(N log N)  ← sort() 함수
└── 투 포인터 탐색: O(N)  ← ⭐ 이 부분이 핵심!
```

**✅ 결론**: 정렬 때문에 O(N log N)이지, **투 포인터 자체는 O(N)**!

---

### 🔑 투 포인터가 O(N)인 이유

**핵심 원리**: 각 포인터는 **한 방향으로만 이동**합니다!

```cpp
int left = 0, right = N - 1;

while (left < right)  // ⭐ 이게 O(N)인 이유!
{
    int sum = arr[left] + arr[right];

    if (sum == M)
    {
        ret++;
        left++;   // ← left는 오른쪽으로만 이동 (역행 없음!)
        right--;  // ← right는 왼쪽으로만 이동 (역행 없음!)
    }
    else if (sum < M)
        left++;   // ← left는 오른쪽으로만 이동
    else
        right--;  // ← right는 왼쪽으로만 이동
}
```

---

### 📊 포인터 이동 횟수 상세 분석

```
배열: [1, 2, 3, 4, 5, 7]  (N=6), M=9
      ↑              ↑
    left=0        right=5

┌──────┬──────┬───────┬──────────┬──────────────────────┬────────────┐
│ 단계 │ left │ right │   sum    │        동작          │ 누적 이동  │
├──────┼──────┼───────┼──────────┼──────────────────────┼────────────┤
│  1   │  0   │   5   │ 1+7 = 8  │ left++  (sum < 9)    │ left: 1회  │
│  2   │  1   │   5   │ 2+7 = 9  │ ret++, left++, right--│ left: 2회  │
│      │      │       │          │                      │ right: 1회 │
│  3   │  2   │   4   │ 3+5 = 8  │ left++  (sum < 9)    │ left: 3회  │
│  4   │  3   │   4   │ 4+5 = 9  │ ret++, left++, right--│ left: 4회  │
│      │      │       │          │                      │ right: 2회 │
│  5   │  4   │   3   │ 종료     │ left >= right        │ 총: 6회    │
└──────┴──────┴───────┴──────────┴──────────────────────┴────────────┘

총 이동 횟수:
  left 이동: 0 → 1 → 2 → 3 → 4  (4번)
  right 이동: 5 → 4 → 3         (2번)
  합계: 6번 = N번!
```

---

### ⭐ 왜 O(N)인가? - 핵심 증명

```
✅ left는 0부터 시작해서 N-1까지 최대 N번 이동
✅ right는 N-1부터 시작해서 0까지 최대 N번 이동
✅ 둘 중 하나가 이동할 때마다 거리가 1씩 좁혀짐
✅ 처음 거리: N-1 (left=0, right=N-1)
✅ 최종 거리: 0 (left == right)
✅ 총 이동 횟수: 최대 N번

→ 시간복잡도: O(N) ⭐
```

**중요**: while 반복문이라고 무조건 O(N log N)이 아닙니다!
- **이진 탐색**: O(log N) - 범위가 절반씩 줄어듦
- **투 포인터**: O(N) - 포인터가 단방향으로만 이동

---

### 🆚 O(N²) vs O(N) 비교

**브루트 포스 (이중 반복문)**:
```cpp
for (int j = 0; j < N; j++)          // N번 외부 반복
{
    for (int k = 0; k < j; k++)      // 평균 N/2번 내부 반복
    {
        if (arr[j] + arr[k] == M)    // 총 N × N/2 = N²/2 ≈ O(N²)
            ret++;
    }
}
```

**투 포인터 (단일 반복문)**:
```cpp
while (left < right)  // 최대 N번 반복
{
    // left++: 최대 N번
    // right--: 최대 N번
    // 합쳐서 최대 N번!
}
```

---

### 📈 N에 따른 성능 차이

| N | 브루트 포스 (O(N²)) | 투 포인터 (O(N log N)) | 차이 배율 |
|---|-------------------|---------------------|---------|
| 100 | 10,000 | 664 (100 + 100log100) | **15배** |
| 1,000 | 1,000,000 | 9,966 | **100배** |
| 10,000 | 100,000,000 | 132,877 | **752배** |
| 100,000 | 10,000,000,000 | 1,660,964 | **6,020배** |
| 1,000,000 | 1,000,000,000,000 | 19,931,569 | **50,171배** |

**분석**:
```
N=100,000일 때:
  브루트 포스: 100억 연산 → 시간 초과! ❌ (약 100초 소요)
  투 포인터: 166만 연산 → 통과! ✅ (약 0.01초 소요)

차이: 약 6,000배!
```

### 💡 시간복잡도 오해 바로잡기

**❌ 잘못된 생각**:
```
"while 반복문이니까 O(N)이고,
그 안에서 비교 연산이 일어나니까 O(N log N)?"
```

**✅ 올바른 이해**:
```
투 포인터의 while은 단순히 "left와 right가 만날 때까지"를 의미!
- left는 0 → N으로 최대 N번 이동
- right는 N → 0으로 최대 N번 이동
- 둘이 동시에 이동해도 합쳐서 N번!

→ O(N) 확정! ⭐

총 시간복잡도 O(N log N)은 sort() 때문!
```

---

### 🎓 정리

**투 포인터 알고리즘의 시간복잡도**:

1️⃣ **정렬 단계**: O(N log N)
   - `sort(arr, arr + N)` 함수 호출
   - 병합 정렬, 퀵 정렬 등 사용

2️⃣ **투 포인터 탐색**: O(N)
   - left 이동: 최대 N번
   - right 이동: 최대 N번
   - 합계: 최대 N번 (둘이 만나면 종료)

3️⃣ **총 시간복잡도**: O(N log N) + O(N) = **O(N log N)**
   - 정렬이 지배적(dominant term)
   - O(N)은 상대적으로 무시 가능

**✅ 핵심 기억할 것**:
- 투 포인터 자체는 **O(N)**
- 정렬 때문에 전체는 **O(N log N)**
- N이 커질수록 브루트 포스보다 수천 배 빠름!
