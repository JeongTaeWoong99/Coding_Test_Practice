## 🔗 문제 링크

[백준 2164번 - 카드2](https://www.acmicpc.net/problem/2164)

**난이도**: Silver 4

---

## 🤔 접근법

큐를 사용해 쉽게 풀었다.

N장의 카드에서 반복적으로 **맨 위 카드를 버리고, 그 다음 카드를 맨 아래로 이동**하는 문제.

마지막에 남는 카드의 번호를 구해야 함.

**핵심**: 큐(Queue)의 FIFO 특성을 그대로 시뮬레이션!

---

## 💡 정답 풀이 방법

**알고리즘**: 큐(Queue) 시뮬레이션

**핵심 아이디어**:
```
1. 큐에 1부터 N까지 순서대로 삽입

2. 카드가 2개 이상 남아있는 동안:
   - 맨 앞 카드를 버림 (pop)
   - 그 다음 맨 앞 카드를 맨 뒤로 이동 (push(front) → pop)
   
3. 큐에 남은 1개의 카드 출력
```

---

## 🔑 핵심 포인트

### 1️⃣ 큐 초기화

```cpp
queue<int> qu;

// 큐에 1 ~ n 넣기
for (int i = 1; i <= n; ++i)
    qu.emplace(i);
```

**✅ 핵심**:
- 카드가 1번부터 N번까지 순서대로 쌓여있음
- 1번이 맨 위 (큐의 front)

### 2️⃣ 카드 버리기 + 맨 뒤로 이동

```cpp
while (qu.size() > 1)
{
    qu.pop();             // 앞 버리기
    qu.push(qu.front());  // 앞을 뒤로
    qu.pop();             // 앞 제거
}
```

**✅ 핵심**:
- `qu.pop()` : 맨 위 카드 버림
- `qu.push(qu.front())` : 현재 맨 앞 카드를 맨 뒤에 추가
- `qu.pop()` : 맨 앞 카드 제거 (이미 뒤에 추가했으므로 삭제)

**동작 예시 (N=6)**:
```
초기: [1, 2, 3, 4, 5, 6]

1 버림    → [2, 3, 4, 5, 6]
2를 뒤로  → [3, 4, 5, 6, 2]
3 버림    → [4, 5, 6, 2]
4를 뒤로  → [5, 6, 2, 4]
5 버림    → [6, 2, 4]
6을 뒤로  → [2, 4, 6]
2 버림    → [4, 6]
4를 뒤로  → [6, 4]
6 버림    → [4]

결과: 4
```

### 3️⃣ 마지막 카드 출력

```cpp
cout << qu.front();
```

**✅ 핵심**: 큐에 1개만 남아있으므로 `front()` 출력

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ 큐가 2개 이상일 때만 반복

```cpp
❌ while (qu.size() > 0)  // 1개 남았는데도 계속 반복 → 무한 루프!

✅ while (qu.size() > 1)  // 2개 이상일 때만 반복
```

**이유:**
- 1개 남으면 더 이상 작업할 필요 없음
- `qu.size() > 0`이면 1개 남았을 때도 계속 실행 → 오류

### 2️⃣ pop() 순서 주의

```cpp
❌ qu.push(qu.front());  // 뒤로 추가
   qu.pop();             // 버리기
   qu.pop();             // 또 버리기 → 2개를 버림!

✅ qu.pop();             // 버리기
   qu.push(qu.front());  // 뒤로 추가
   qu.pop();             // 추가한 원본 제거
```

**이유:**
- 위 코드는 맨 앞 카드를 버리고, 다음 카드를 뒤로 보내는 순서
- `push` 전에 `pop`을 먼저 해야 올바른 카드를 뒤로 보냄

### 3️⃣ 입출력 최적화

```cpp
✅ ios_base::sync_with_stdio(0);cin.tie(0);cout.tie(0);
```

**이유:**
- N ≤ 500,000
- 큐 연산이 최대 N번 발생
- 입출력 최적화로 시간 단축

## ⏱️ 시간복잡도

**전체 시간복잡도**: **O(N)**

**상세 분석**:
```
1. 큐 초기화 : O(N)
   - 1부터 N까지 삽입

2. 카드 처리 : O(N)
   - 각 카드마다 pop() 또는 push() 수행
   - 각 연산은 O(1)
   - 총 N개의 카드 처리

총합 : O(N) + O(N) = O(N)
```

**시간 제한 체크**:
- N ≤ 500,000
- 50만 연산 < 1억 → 시간 내 통과 가능 ✅
