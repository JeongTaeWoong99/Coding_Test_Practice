## 🔗 문제 링크

[백준 2670번 - 연속부분최대곱](https://www.acmicpc.net/problem/2670)

**난이도**: Silver 4

---

## 🤔 접근법

N개의 실수가 있을 때, 한 개 이상의 연속된 수들의 곱이 최대가 되는 부분을 찾는 문제.

**핵심**: 모든 연속 구간을 확인하거나, DP로 최적화하여 해결

---

## 💡 정답 풀이 방법

### 🎯 방법 1: 브루트 포스(Brute Force)

1. **이중 반복문**: 모든 시작점에서 모든 끝점까지 확인

2. **구간 곱 계산**: 각 구간의 곱을 누적하며 계산

3. **최댓값 갱신**: 매번 계산한 곱과 최댓값 비교

**시간복잡도**: O(N²) - N ≤ 10,000이므로 충분히 통과 가능

### 🎯 방법 2: 다이나믹 프로그래밍(DP) - 최적화

1. **DP 정의**: `dp[i]` = i번째 원소를 포함하여 끝나는 연속 부분의 최대 곱

2. **점화식**:
   ```
   dp[i] = max(arr[i], dp[i-1] × arr[i])
   ```
   - 새로 시작 vs 이전 곱에 이어서

3. **공간 최적화**: 배열 대신 변수 하나로 O(1) 공간

**시간복잡도**: O(N) - 한 번의 순회로 해결

## 🔑 핵심 개념

### 📐 브루트 포스 원리

```cpp
for (int start = 0; start < range; ++start)
{
    double curr = 1.0;  // 현재 구간의 곱 (1로 초기화)

    // 시작점부터 끝까지 연속된 구간 계산
    for (int end = start; end < range; ++end)
    {
        curr *= nums[end];    // 현재 숫자를 곱에 포함
        mx = max(mx, curr);   // 최댓값 갱신
    }
}
```

**✅ 핵심**: 모든 (start, end) 쌍에 대해 곱을 계산

**예시**:
```
배열: [1.1, 0.7, 1.3, 0.9, 1.4], N = 5

start=0:
  [0,0]: 1.1
  [0,1]: 1.1 × 0.7 = 0.77
  [0,2]: 0.77 × 1.3 = 1.001
  ...

start=1:
  [1,1]: 0.7
  [1,2]: 0.7 × 1.3 = 0.91
  [1,3]: 0.91 × 0.9 = 0.819
  ...

start=2:
  [2,2]: 1.3
  [2,3]: 1.3 × 0.9 = 1.17
  [2,4]: 1.17 × 1.4 = 1.638 ✅ 최댓값!
  ...
```

### 🔍 DP 원리

```cpp
// DP 초기화 (첫 번째 원소)
dp  = arr[0];
ret = dp;

// DP 로직 : i번째에서 끝나는 최대 곱 계산
for (int i = 1; i < n; i++)
{
    // 새로 시작 vs 이어서 곱하기 중 최댓값 선택
    if   (arr[i] > dp * arr[i]) dp  = arr[i];   // 새로 시작이 유리
    else                        dp *= arr[i];   // 이어서 곱하기가 유리

    ret = max(dp, ret);  // 전체 최댓값 갱신
}
```

**✅ 핵심**:
- `dp` 변수가 "현재까지의 최대 곱"을 저장
- 각 위치에서 "새로 시작" vs "이어서 곱하기" 선택

**동작 과정**:
```
배열: [1.1, 0.7, 1.3, 0.9, 1.4]

i=0: dp = 1.1, ret = 1.1
i=1: 0.7 vs 1.1×0.7(0.77) → 0.77 > 0.7 → dp = 0.77, ret = 1.1
i=2: 1.3 vs 0.77×1.3(1.001) → 1.3 > 1.001 → dp = 1.3, ret = 1.3
i=3: 0.9 vs 1.3×0.9(1.17) → 1.17 > 0.9 → dp = 1.17, ret = 1.3
i=4: 1.4 vs 1.17×1.4(1.638) → 1.638 > 1.4 → dp = 1.638, ret = 1.638 ✅
```

**왜 이 방법이 작동하는가?**

`arr[i] > dp × arr[i]`가 의미하는 것:
- **좌변** `arr[i]`: i번째부터 새로 시작
- **우변** `dp × arr[i]`: 이전 곱에 i번째를 이어붙이기

`arr[i] > dp × arr[i]`를 정리하면:
```
arr[i] > dp × arr[i]
arr[i] / arr[i] > dp
1 > dp
```

즉, **이전 누적곱 `dp`가 1보다 작으면** 새로 시작하는 것이 유리!

**예시**:
```
arr[i] = 2.0, dp = 0.3일 때:
- 새로 시작: 2.0
- 이어서 곱: 0.3 × 2.0 = 0.6
→ 2.0 > 0.6이므로 새로 시작! (dp < 1이므로)

arr[i] = 2.0, dp = 1.5일 때:
- 새로 시작: 2.0
- 이어서 곱: 1.5 × 2.0 = 3.0
→ 3.0 > 2.0이므로 이어서 곱하기! (dp > 1이므로)
```

## 🔍 두 방법 비교

| 항목 | 브루트 포스 | DP (최적화) |
|-----|-----------|---------|
| **시간복잡도** | O(N²) | O(N) |
| **공간복잡도** | O(N) | O(1) |
| **구현 난이도** | ★★☆☆☆ | ★★★☆☆ |
| **코드 간결성** | ★★★★☆ | ★★★★★ |
| **N=10,000** | 1억 연산 (경계선) | 1만 연산 ✅ |

### 코드 길이 비교

**브루트 포스**: 약 50줄
```cpp
double Go(const vector<double>& nums)
{
    range = nums.size();
    mx = -1;

    for (int start = 0; start < range; ++start)
    {
        double curr = 1.0;
        for (int end = start; end < range; ++end)
        {
            curr *= nums[end];
            mx = max(mx, curr);
        }
    }

    return mx;
}
```

**DP**: 약 30줄
```cpp
int main()
{
    cin >> n;
    for (int i = 0; i < n; i++) cin >> arr[i];

    dp  = arr[0];
    ret = dp;

    for (int i = 1; i < n; i++)
    {
        if   (arr[i] > dp * arr[i]) dp  = arr[i];
        else                        dp *= arr[i];
        ret = max(dp, ret);
    }

    cout << fixed << setprecision(3) << ret << '\n';
    return 0;
}
```

### 내 코드의 선택

✅ **DP 사용 이유**:
- N ≤ 10,000에서 O(N²) = 1억 연산은 경계선 (통과는 가능하지만 불안정)
- DP는 O(N) = 1만 연산으로 훨씬 안정적
- 코드가 더 간결하고 효율적
- 공간복잡도도 O(1)로 최적화 가능

💡 **브루트 포스가 유용한 경우**:
- N이 매우 작을 때 (N ≤ 100)
- 직관적 이해가 필요할 때
- DP 점화식을 찾기 어려운 복잡한 조건이 있을 때

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ double 출력 형식

```cpp
❌ cout << ret << "\n";  // 소수점 자릿수 조절 없음

✅ cout << fixed << setprecision(3) << ret << '\n';
```

**이유**:
- 문제에서 "소수점 이하 셋째 자리까지 출력" 명시
- `fixed`: 고정 소수점 형식
- `setprecision(3)`: 소수점 이하 3자리까지

### 2️⃣ 초기값 설정 (브루트 포스)

```cpp
❌ double mx = 0;  // 모든 값이 음수면 틀림!

✅ double mx = -1;  // 또는 nums[0]으로 초기화
```

**이유**:
- 문제에서 "0.0보다 크거나 같고" → 0도 가능
- 초기값을 0으로 하면 모든 값이 0일 때 문제
- 음수로 초기화하거나 첫 번째 값으로 초기화

### 3️⃣ DP 초기화

```cpp
❌ dp = 0, ret = 0;  // 첫 번째 원소를 놓침!

✅ dp = arr[0], ret = arr[0];  // 첫 번째 원소로 초기화
```

**이유**:
- 배열이 [5.0]처럼 원소가 1개일 때 답은 5.0
- 초기화를 0으로 하면 첫 번째 원소를 고려하지 못함

### 4️⃣ DP 비교 조건

```cpp
❌ if (dp < 1) dp = arr[i];  // dp가 정확히 1일 때는?

✅ if (arr[i] > dp * arr[i]) dp = arr[i];
```

**이유**:
- `dp < 1`로 판단하면 dp=1일 때 동작이 애매함
- 직접 비교가 더 정확하고 명확함

### 5️⃣ 배열 크기

```cpp
❌ double arr[10000];  // N=10000일 때 arr[10000] 접근 → 범위 초과!

✅ double arr[10001];  // 여유 있게 설정
```

## ⏱️ 시간복잡도 분석

### 브루트 포스

**시간복잡도**: O(N²)

**분석**:
- 외부 반복문: N번 (start)
- 내부 반복문: 평균 N/2번 (end)
- N = 10,000일 때
- 10,000 × 10,000 = 100,000,000 (1억) 연산
- **C++ 기준 1초에 약 1~3억 연산 가능** → 통과 가능하지만 경계선 ⚠️

### DP

**시간복잡도**: O(N)

**분석**:
- 입력: O(N)
- DP 순회: O(N)
- 출력: O(1)
- N = 10,000일 때
- 10,000 연산 → **매우 여유 있게 통과** ✅

## 💾 공간복잡도

### 브루트 포스
**O(N)**
- `vector<double> nums(n)`: 실수 저장 배열
- 추가 공간 거의 사용 안 함

### DP
**O(N)** 또는 **O(1)**
- 배열 사용: `arr[10001]` → O(N)
- 변수만 사용: `dp`, `ret` → O(1)

**최적화 버전**: 배열 없이 변수만 사용 시 O(1) 달성 가능

---

## 🎓 DP 최적화 심화

### 💡 공간복잡도 O(1) 최적화

현재 코드는 이미 O(1) 공간:
```cpp
double ret, dp;  // 변수 2개만 사용!
```

만약 DP 배열을 사용했다면:
```cpp
❌ double dp[10001];  // O(N) 공간
   dp[0] = arr[0];
   for (int i = 1; i < n; i++)
       dp[i] = max(arr[i], dp[i-1] * arr[i]);

✅ double dp = arr[0];  // O(1) 공간
   for (int i = 1; i < n; i++)
   {
       dp = max(arr[i], dp * arr[i]);
       ret = max(ret, dp);
   }
```

**핵심**: `dp[i]`는 `dp[i-1]`만 필요하므로 배열 불필요!

**공통 패턴**:
```
dp[i] = i번째를 포함하는 최적해

선택지:
1. i번째부터 새로 시작
2. 이전 결과에 이어붙이기

dp[i] = max(arr[i], dp[i-1] + arr[i])  // 합
dp[i] = max(arr[i], dp[i-1] × arr[i])  // 곱
```
