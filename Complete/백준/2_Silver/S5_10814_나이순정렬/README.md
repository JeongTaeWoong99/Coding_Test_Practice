## 🤔 접근법

(STL stable_sort를 알면 풀 수 있으나, 계수 정렬을 응용하면, 더 빠르게 풀 수 있다.)

온라인 저지에 가입한 사람들을 나이 순으로 정렬하되, **나이가 같으면 가입 순서**를 유지해야 하는 문제.

정렬 조건은 다음과 같다:
1. **나이가 증가하는 순**으로 정렬
2. **나이가 같으면 먼저 가입한 사람이 앞**에 오도록 정렬 (안정 정렬 필요!)

**핵심**: 두 가지 방법으로 해결 가능
1. **stable_sort (병합 정렬)**: 안정 정렬 보장 (O(N log N))
2. **계수 정렬 (Counting Sort)**: 나이 범위가 좁아서 최적 (O(N))

## 🔑 핵심 포인트

### 1️⃣ sort vs stable_sort 비교

**🚨 중요: 일반 `sort()`는 이 문제에 사용 불가!**

| 항목           | sort()  | stable_sort()      |
|--------------|---------|--------------------|
| **알고리즘**     | 인트로 솔트 (퀵+힙+삽입) | 병합 정렬 (Merge Sort) |
| **시간복잡도**    | O(N log N) | O(N log N)         |
| **추가 공간복잡도** | O(log N) - 재귀 스택만 | O(N) - 임시 배열 필요   |
| **안정성**      | ❌ 불안정 (순서 보장 안됨) | ✅ 안정 (순서 보장)       |
| **속도**       | 빠름 (in-place + swap) | 느림 (복사 2N번)   |
| **사용 시기**    | 순서 유지 불필요 | **순서 유지 필수**       |

**🔍 추가 공간복잡도가 다른 이유**:

```cpp
sort() - O(log N):
  ✅ in-place 정렬 (퀵소트 기반)
  ✅ 추가 배열 없음, 재귀 스택만 사용
  ✅ 재귀 깊이 = O(log N)

stable_sort() - O(N):
  ❌ 병합 시 임시 배열 필요
  ❌ N개 요소를 담을 공간 + 재귀 스택
  ❌ 총 O(N) 메모리
```

**⚡ 속도 차이가 나는 이유**:

```cpp
sort()가 빠른 이유:
  1. in-place 정렬: 같은 메모리 영역에서 작업
  2. swap 연산: 포인터/참조만 교환 (temp = a; a = b; b = temp;)
  3. 캐시 효율: 같은 메모리 블록 반복 접근 → CPU 캐시 히트율 높음
  4. 메모리 할당/해제 없음

stable_sort()가 느린 이유:
  1. 메모리 할당: O(N) 크기 임시 배열 new/malloc (오버헤드 발생)
  2. 복사 연산 2배: 원본 → 임시 (N번) + 임시 → 원본 (N번) = 2N번
  3. 캐시 미스: 원본 + 임시 두 곳 접근 → 캐시 효율 낮음
  4. 메모리 해제: delete/free 오버헤드

실제 차이:
  sort():        swap만 (빠름!)
  stable_sort(): 메모리 할당 + 복사 2N번 + 해제 (느림)
```

**❌ sort() 사용 시 문제점**:
```cpp
입력:
21 Junkyu
21 Dohyun

sort() 사용:
21 Dohyun  ❌ 순서가 바뀜!
21 Junkyu

stable_sort() 사용:
21 Junkyu  ✅ 가입 순서 유지!
21 Dohyun
```

**🔍 왜 sort()는 불안정할까?**

- ★ **퀵 정렬 기반**: pivot을 기준으로 swap하면서 정렬
- **swap 과정에서 순서가 뒤바뀔 수 있음**
- **성능을 위해 순서 보장을 포기**

**🔍 stable_sort()는 어떻게 순서를 보장할까?**

- **병합 정렬 기반**: 분할 후 병합하면서 정렬
- **병합 시 같은 값이면 원래 순서(앞 배열 우선) 유지**
- **추가 메모리(O(N)) 사용으로 순서 보장**

**병합 정렬 예시**:
```
입력: [21,Junkyu] [21,Dohyun] [20,Sunyoung]

분할:
[21,Junkyu] [21,Dohyun] [20,Sunyoung]
    ↓           ↓           ↓
[21,Junkyu] | [21,Dohyun] [20,Sunyoung]

병합 (왼쪽 우선 → 순서 유지):
[21,Junkyu] [21,Dohyun] | [20,Sunyoung]
         ↓
[20,Sunyoung] [21,Junkyu] [21,Dohyun]  ✅ 순서 유지!
```

### 2️⃣ 방법 1 : 계수 정렬 (Answer(정답_계수정렬).cpp.txt)

**핵심 아이디어**:
```
나이별로 버킷(vector<string>)을 만들고,
입력받는 순서대로 해당 나이의 버킷에 이름을 추가한다.
그 후 나이 순서(1~200)대로 버킷을 순회하며 출력하면,
자동으로 나이 순 + 가입 순으로 정렬된다!
```

**핵심 코드**:
```cpp
int    n, age;
string name;
vector<string> bucket[201];  // 나이별 버킷 (1~200)

int main()
{
    ios_base::sync_with_stdio(false);cin.tie(0);cout.tie(0);

    cin >> n;

    // 입력받으면서 나이별 버킷에 저장 (가입 순서 자동 유지)
    for(int i = 0; i < n; i++)
    {
        cin >> age >> name;
        bucket[age].emplace_back(name);  // 해당 나이 버킷에 추가
    }

    // 나이 순서대로 출력 (1~200)
    for(int i = 1; i <= 200; i++)
    {
        for(const auto& s : bucket[i])
            cout << i << ' ' << s << '\n';
    }

    return 0;
}
```

**✅ 장점**:
- 시간복잡도 O(N + K) where K=200 → **실질적으로 O(N)**
- **가장 빠름**: 24ms (stable_sort의 37%)
- **메모리 효율적**: 6904KB (stable_sort의 70%)
- **자동 안정 정렬**: 입력 순서대로 버킷에 추가되므로 순서 보장

**🔍 알고리즘 상세 분석**:

**예시 입력**:
```
3
21 Junkyu
21 Dohyun
20 Sunyoung
```

**처리 과정**:
```
입력 처리:
  cin >> 21 >> "Junkyu"
  → bucket[21] = ["Junkyu"]

  cin >> 21 >> "Dohyun"
  → bucket[21] = ["Junkyu", "Dohyun"]  ✅ 순서 유지!

  cin >> 20 >> "Sunyoung"
  → bucket[20] = ["Sunyoung"]

출력 순회 (i = 1 ~ 200):
  i=1~19: 비어있음 (출력 안됨)
  i=20: bucket[20] = ["Sunyoung"]
    → 20 Sunyoung
  i=21: bucket[21] = ["Junkyu", "Dohyun"]
    → 21 Junkyu
    → 21 Dohyun
  i=22~200: 비어있음 (출력 안됨)

최종 출력:
20 Sunyoung
21 Junkyu
21 Dohyun
```

**🎯 왜 이 방법이 가장 빠른가?**

1. **정렬 불필요**: 버킷에 넣는 순간 이미 정렬됨
2. **비교 연산 없음**: 나이를 인덱스로 바로 접근 (O(1))
3. **캐시 효율**: 순차 접근으로 캐시 히트율 높음
4. **오버헤드 없음**: 추가 정렬 함수 호출 없음

### 3️⃣ 방법 2 : stable_sort (Answer(성공_stable_sort).cpp.txt)

**핵심 코드**:
```cpp
int    n, age;
string name;
vector<pair<int, string>> v;

bool CMP(pair<int, string> a, pair<int, string> b)
{
    return a.first < b.first;  // 나이만 비교
}

int main()
{
    ios_base::sync_with_stdio(false);cin.tie(0);cout.tie(0);

    cin >> n;

    // 나이-이름 입력
    for(int i = 0; i < n; i++)
    {
        cin >> age >> name;
        v.emplace_back(age, name);
    }

    // stable_sort(병합 정렬 기반, 순서 보장)
    stable_sort(v.begin(), v.end(), CMP);

    // 출력
    for(const auto& cur : v)
        cout << cur.first << ' ' << cur.second << '\n';

    return 0;
}
```

**✅ 장점**:
- 코드가 간결하고 직관적
- 나이 범위에 제한 없음 (1~200 외 값도 처리 가능)
- STL 활용으로 안전하고 신뢰성 높음
- 병합 정렬로 안정 정렬 자동 보장

**❌ 단점**:
- 시간: 64ms (계수 정렬의 2.67배)
- 메모리: 9848KB (계수 정렬의 1.43배)
- 추가 메모리 O(N) 필요 (병합 정렬 특성)

**🔍 알고리즘 상세 분석**:

**예시 입력**:
```
3
21 Junkyu
21 Dohyun
20 Sunyoung
```

**처리 과정**:
```
입력 처리:
  v = [(21, "Junkyu"), (21, "Dohyun"), (20, "Sunyoung")]

stable_sort 호출:
  1. 분할:
     [(21, "Junkyu")] | [(21, "Dohyun")] [(20, "Sunyoung")]

  2. 병합 (나이 비교, 같으면 원래 순서 유지):
     [(21, "Junkyu")] [(21, "Dohyun")] | [(20, "Sunyoung")]
                      ↓
     [(20, "Sunyoung"), (21, "Junkyu"), (21, "Dohyun")]

출력:
  20 Sunyoung
  21 Junkyu
  21 Dohyun
```

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ sort() 사용 금지!

```cpp
❌ sort(v.begin(), v.end(), CMP);  // 순서 보장 안됨!

✅ stable_sort(v.begin(), v.end(), CMP);  // 순서 보장!
```

**이유**:
- `sort()`는 불안정 정렬 → 나이가 같을 때 순서가 뒤바뀔 수 있음
- 이 문제는 **가입 순서 유지가 필수** → `stable_sort()` 필수!

### 2️⃣ 비교 함수는 나이만 비교

```cpp
✅ bool CMP(pair<int, string> a, pair<int, string> b)
{
    return a.first < b.first;  // 나이만 비교 (이름은 비교 안함!)
}

❌ bool CMP(pair<int, string> a, pair<int, string> b)
{
    if(a.first != b.first)
        return a.first < b.first;
    return a.second < b.second;  // 이름까지 비교하면 안됨!
}
```

**이유**:
- 나이가 같을 때는 **가입 순서**로 정렬해야 함
- 이름을 비교하면 사전 순으로 정렬되어 버림 (오답!)
- `stable_sort()`가 알아서 순서를 유지하므로 나이만 비교하면 됨

**반례**:
```
입력:
21 Junkyu
21 Dohyun

❌ 이름까지 비교:
21 Dohyun  (사전 순으로 정렬됨)
21 Junkyu

✅ 나이만 비교 (stable_sort):
21 Junkyu  (가입 순서 유지)
21 Dohyun
```

### 3️⃣ 계수 정렬 시 범위 확인

```cpp
vector<string> bucket[201];  // 1~200 범위

// 나이가 0이거나 200 초과일 수 있으므로 주의!
// 문제에서는 1~200 보장
```

## 📊 시간복잡도 분석

### 방법 1 (계수 정렬)

**시간복잡도**: **O(N + K)** where K=200

```
1. 입력 처리: O(N)
   - N명의 나이-이름을 버킷에 추가

2. 출력 처리: O(N + K)
   - 나이 범위 K(1~200) 순회: O(K)
   - 각 버킷의 이름들 출력: O(N)

총합: O(N) + O(N + K) = O(N + K)
     = O(N + 200) ≈ O(N)
```

**실제 연산 횟수** (N=100,000):
```
입력: 100,000번 버킷 추가
출력: 200번 범위 순회 + 100,000번 이름 출력
총합: 약 200,200 연산
```

---

### 방법 2 (stable_sort)

**시간복잡도**: **O(N log N)**

```
1. 입력 처리: O(N)
   - N개의 pair를 vector에 저장

2. 정렬: O(N log N)
   - stable_sort() 함수 (병합 정렬)

3. 출력 처리: O(N)
   - N개의 pair를 출력

총합: O(N) + O(N log N) + O(N) = O(N log N)
```

**실제 연산 횟수** (N=100,000):
```
입력: 100,000 연산
정렬: 100,000 × log(100,000) ≈ 100,000 × 17 = 1,700,000 연산
출력: 100,000 연산
총합: 약 1,900,000 연산
```

---

### 성능 비교

| 방법 | 시간복잡도 | 실제 연산 (N=100,000) | 실제 시간 | 메모리 |
|------|-----------|---------------------|----------|--------|
| **계수 정렬** | O(N + K) | 200,200 | **24ms** | **6904KB** |
| **stable_sort** | O(N log N) | 1,900,000 | 64ms | 9848KB |
| **비율** | - | **9.5배 차이** | **2.67배 차이** | **1.43배 차이** |

**🔍 왜 이론보다 실제 차이가 작을까?**

- **이론**: 계수 정렬이 9.5배 연산량 적음
- **실제**: 2.67배 빠름

**이유**:
1. **캐시 효율**: stable_sort는 메모리 접근 패턴 최적화
2. **컴파일러 최적화**: STL은 고도로 최적화됨
3. **상수 시간**: 계수 정렬도 vector 관리 오버헤드 존재
4. **입출력 시간**: 실제로는 cin/cout 시간이 큼

**시간 제한 체크**:
- 문제 시간 제한: 3초
- 두 방법 모두 시간 제한 내 여유롭게 통과 ✅

## 💾 추가 공간복잡도

### 방법 1 (계수 정렬)

**O(N + K)** = **O(N + 200)** ≈ **O(N)**

- `vector<string> bucket[201]`: 최대 N개의 이름 저장
- 실제 메모리: 6904KB

---

### 방법 2 (stable_sort)

**O(N) + 병합 정렬 추가 메모리 O(N)** = **O(N)**

- `vector<pair<int, string>> v`: N개의 pair 저장 (약 4~5KB)
- `stable_sort` 추가 메모리: O(N) (병합 정렬 특성)
- 실제 메모리: 9848KB

---

### 메모리 비교

| 방법 | 추가 공간복잡도 | 실제 메모리 | 메모리 차이 |
|------|-----------|------------|-----------|
| **계수 정렬** | O(N + K) | 6904KB | 기준 |
| **stable_sort** | O(N) × 2 | 9848KB | **+43% 더 사용** |

**🔍 왜 계수 정렬이 메모리를 덜 쓸까?**

1. **구조 차이**:
   - 계수 정렬: `vector<string>` 배열 → 이름만 저장
   - stable_sort: `vector<pair<int, string>>` → 나이+이름 모두 저장

2. **추가 메모리**:
   - 계수 정렬: 추가 메모리 불필요
   - stable_sort: 병합 정렬 시 임시 배열 O(N) 필요

3. **오버헤드**:
   - 계수 정렬: 빈 버킷도 존재하지만 크기 작음 (200개)
   - stable_sort: pair 구조체 오버헤드, vector 동적 할당 오버헤드

**메모리 제한 체크**:
- 문제 메모리 제한: 256MB
- 두 방법 모두 메모리 제한 내 여유롭게 통과 ✅
