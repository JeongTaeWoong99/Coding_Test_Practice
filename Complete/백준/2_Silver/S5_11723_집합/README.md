## 🔗 문제 링크

[백준 11723번 - 집합](https://www.acmicpc.net/problem/11723)

**난이도**: Silver 5

---

## 🤔 접근법

(bool 배열로 성공. 비트마스킹으로도 풀 수 있음.)

비어있는 공집합 S에 대해 6가지 연산(add, remove, check, toggle, all, empty)을 수행하는 문제.

x의 범위가 1~20으로 매우 작고, 메모리 제한이 4MB로 작아서 **비트마스킹**이 권장되지만, **bool 배열**로도 충분히 해결 가능.

**핵심**: 집합의 원소 존재 여부만 관리하면 되므로 비트(0/1) 또는 bool(true/false)로 표현

---

## 💡 두 가지 풀이 방법

### 1️⃣ 비트마스킹 방식 (정답)

**핵심 아이디어**:
```
- 집합 S를 int 변수 하나로 표현 (4바이트 = 32비트)
- x번째 원소의 존재 여부 = x번째 비트의 값 (0 또는 1)
- 비트 연산으로 O(1)에 모든 연산 처리
```

**연산별 비트 연산**:

| 연산 | 비트 연산 | 설명 |
|------|----------|------|
| `add x` | `S \|= (1 << x)` | x번 비트를 1로 설정 (OR) |
| `remove x` | `S &= ~(1 << x)` | x번 비트를 0으로 설정 (AND NOT) |
| `check x` | `(S >> x) & 1` | x번 비트 값 확인 |
| `toggle x` | `S ^= (1 << x)` | x번 비트 반전 (XOR) |
| `all` | `S = (1 << 21) - 1` | 모든 비트를 1로 |
| `empty` | `S = 0` | 모든 비트를 0으로 |

### 2️⃣ bool 배열 방식 (성공)

**핵심 아이디어**:
```
- bool b[21] 배열로 집합 표현
- b[x] = true면 x가 집합에 존재, false면 미존재
- 직관적이고 이해하기 쉬움
```

**연산별 처리**:

| 연산 | 배열 연산 | 설명 |
|------|----------|------|
| `add x` | `b[x] = true` | x번 인덱스를 true로 |
| `remove x` | `b[x] = false` | x번 인덱스를 false로 |
| `check x` | `b[x]` | x번 인덱스 값 확인 |
| `toggle x` | `b[x] = !b[x]` | x번 인덱스 값 반전 |
| `all` | 반복문으로 전체 true | O(20) |
| `empty` | 반복문으로 전체 false | O(20) |

## 📊 두 방법 비교

### 실행 결과

| 방법 | 메모리 | 시간 |
|------|--------|------|
| 비트마스킹 | **2024 KB** | **572 ms** |
| bool 배열 | **2024 KB** | **572 ms** |

**✅ 결과: 동일!**

### 왜 차이가 없는가?

**1️⃣ 메모리가 동일한 이유:**
- 비트마스킹: int 4바이트
- bool 배열: 21바이트
- **둘 다 너무 작아서** 전체 프로그램 메모리(입출력 버퍼, bits/stdc++.h 등 ~2000KB)에 비하면 무의미한 차이

**2️⃣ 시간이 동일한 이유:**
- 비트마스킹: 모든 연산 O(1)
- bool 배열: add/remove/check/toggle O(1), all/empty O(20)
- O(20)은 상수이므로 실질적으로 O(1)
- **진짜 병목은 300만 번의 입출력!**

### 시간복잡도 비교

| 연산 | 비트마스킹 | bool 배열 |
|------|-----------|-----------|
| add/remove/check/toggle | O(1) | O(1) |
| all/empty | **O(1)** | O(20) ≈ O(1) |

## ⚡ 미미하게 시간을 줄이는 방법

### 문자열 첫 글자로 비교하기

기존 코드에서 `cmd == "remove"`처럼 **문자열 전체를 비교**하면 최대 6글자를 비교해야 합니다.

하지만 명령어들의 첫 글자가 대부분 다르므로 **첫 글자만 비교**하면 비교 횟수를 줄일 수 있습니다:

```
명령어: add, remove, check, toggle, all, empty
첫글자:  a    r       c      t       a    e

→ 'a'만 겹침 → 두 번째 글자로 구분 ('d' vs 'l')
```

**최적화 코드 예시**:
```cpp
if(cmd[0] == 'a')
{
    if(cmd[1] == 'd') { /* add */ }
    else              { /* all */ }
}
else if(cmd[0] == 'r') { /* remove */ }
else if(cmd[0] == 'c') { /* check */ }
else if(cmd[0] == 't') { /* toggle */ }
else                   { /* empty */ }
```

**결과**: 2024KB / 520ms (약 50ms 개선)

### 1️⃣ 입출력 최적화 필수!

```cpp
❌ cin/cout만 사용 → 시간 초과

```

**이유**: M이 최대 3,000,000으로 매우 많은 입출력 발생

### 2️⃣ set 자료구조 사용 주의

```cpp
❌ set<int> S; → 시간 초과!
✅ 비트마스킹 또는 bool 배열
```

**이유**: set의 insert/erase/count가 O(log n)이라 300만 번 연산 시 느림

### 3️⃣ all 연산에서 비트 범위 주의

```cpp
❌ S = (1 << 20) - 1;  // 0~19번 비트만 1
✅ S = (1 << 21) - 1;  // 0~20번 비트 1 (1~20 포함)
```

**이유**: x의 범위가 1~20이므로 20번 비트까지 필요

## 📊 시간복잡도 분석

**전체 시간복잡도**: **O(M)**

**상세 분석**:
```
1. M개의 연산 입력 및 처리
2. 각 연산은 O(1) (bool 배열의 all/empty도 O(20) = O(1))
3. 총합: O(M)
```

**시간 제한 체크**:
- M ≤ 3,000,000
- **300만 연산** < **1억** → 시간 내 통과 ✅
