## 🤔 접근법

N개의 수를 오름차순으로 정렬하는 문제.

N의 범위가 최대 1,000,000이고, 수의 범위는 **-1,000,000 ~ 1,000,000**(★ 절대값)이다.

중복되지 않는 정수를 빠르게 정렬해야 하는 문제.

**핵심**: 두 가지 방법으로 해결 가능
1. **계수 정렬 (Counting Sort)**: bool 배열로 존재 여부만 표시 (O(N + 범위))
2. **vector + sort()**: STL sort() 함수 활용 (O(N log N))

---

## 💡 풀이 방법 비교

### 📊 두 가지 풀이 방법

※ 두 방법으로 모두 풀었지만, vector + sort가 간단하고 쉬워서 먼저 생각남.

※ 하지만, 정답의 메모리와 시간이 느린 것 같아서, 다른 방법을 고민해보니, 계수 정렬로도 풀 수 있을 것 같음.


| 방법 | 알고리즘 | 시간복잡도 | 메모리 | 장점 | 단점 |
|------|---------|-----------|--------|------|------|
| **계수 정렬** | bool 배열 + 범위 순회 | O(N + 범위) | 2MB | 매우 빠름 | 음수 처리 복잡, 범위 제한 |
| **vector + sort** | 퀵소트/머지소트 | O(N log N) | 8MB | 간결, 안전, 범위 무관 | 상대적으로 느림 |

## 🔑 핵심 포인트

### 1️⃣ 방법 1 : 계수 정렬 (Answer(정답_계수정렬).cpp.txt)

**핵심 코드**:
```cpp
const int OFFSET  = 1000000;  // 음수 → 양수 변환 보정값
const int MAX_VAL = 2000004;  // 배열 크기 (-1000000 ~ 1000000)

int  n, temp;
bool arr[MAX_VAL];

// 입력 받으면서 해당 인덱스를 true로 설정
for (int i = 1; i <= n; ++i)
{
    cin >> temp;
    arr[temp + OFFSET] = true;  // 음수 보정 (예: -5 → arr[999995])
}

// 전체 범위를 순회하며 true인 값만 출력
for (int i = 0; i < MAX_VAL; ++i)
{
    if (arr[i])
        cout << (i - OFFSET) << '\n';  // 원래 값으로 복원
}
```

**✅ 장점**:
- 시간복잡도 O(N + 범위) - 매우 빠름
- 메모리 효율적 (bool 배열 2MB)
- 대량 데이터 처리에 최적

**❌ 단점**:

※한번 더 생각을 해야됨.

- 음수 처리를 위한 OFFSET 필요
- 값의 범위가 크면 메모리 낭비 (범위가 10억이면 불가능)
- 코드 복잡도 증가

**🔍 알고리즘 상세 분석**:

**인덱스 매핑 구조**:
```
실제 값 범위: -1,000,000 ~ 1,000,000

배열 인덱스 매핑:
┌─────────────────┬──────────────┬─────────────────┐
│  배열 인덱스    │  실제 값     │     설명        │
├─────────────────┼──────────────┼─────────────────┤
│  0              │ -1,000,000   │ 가장 작은 음수  │
│  999,999        │ -1           │ -1              │
│  1,000,000      │  0           │ 0 (중간점)      │
│  1,000,001      │  1           │ 1               │
│  2,000,000      │  1,000,000   │ 가장 큰 양수    │
└─────────────────┴──────────────┴─────────────────┘

공식:
  arr[temp + OFFSET] = true;      // 저장: 실제값 → 인덱스
  원래값 = i - OFFSET;             // 복원: 인덱스 → 실제값
```

**예시 1: 양수 5 처리**
```
입력: 5
arr[5 + 1000000] = true  →  arr[1000005] = true  ✅

출력 시:
i = 1000005
출력값 = 1000005 - 1000000 = 5  ✅
```

**예시 2: 음수 -5 처리**
```
입력: -5
arr[-5 + 1000000] = true  →  arr[999995] = true  ✅

출력 시:
i = 999995
출력값 = 999995 - 1000000 = -5  ✅
```

**예시 3: 0 처리**
```
입력: 0
arr[0 + 1000000] = true  →  arr[1000000] = true  ✅

출력 시:
i = 1000000
출력값 = 1000000 - 1000000 = 0  ✅
```

### 2️⃣ 방법 2 : vector + sort() (Answer(정답_벡터정렬).cpp.txt)

**핵심 코드**:
```cpp
int         n, temp;
vector<int> v;

ios_base::sync_with_stdio(false);cin.tie(0);cout.tie(0);  // 입출력 최적화

// 입력 받으면서 vector에 저장
for (int i = 0; i < n; ++i)
{
    cin >> temp;
    v.emplace_back(temp);
}

// STL sort() 함수로 정렬
sort(v.begin(), v.end());

// 정렬된 결과 출력
for (auto val : v)
    cout << val << '\n';
```

**✅ 장점**:

※ 간단하고 쉬움.

- 코드가 간결하고 직관적
- 음수/양수 구분 없이 자동 처리
- 값의 범위에 제한 없음
- `ios_base` 최적화로 충분히 빠름

**❌ 단점**:
- 시간복잡도 O(N log N) - 계수 정렬보다 느림
- 메모리 사용량 8MB (계수 정렬의 4배)

**🔧 입출력 최적화의 중요성**:

```cpp
❌ 최적화 없이:
   - 실행 시간: 약 600ms

✅ ios_base::sync_with_stdio(false);cin.tie(0);cout.tie(0);
   - 실행 시간: 약 300ms (2배 빠름!)
```

**이유**:
- `sync_with_stdio(false)`: C 스타일 입출력과의 동기화 해제
- `cin.tie(0)`: cin과 cout의 묶음 해제
- `cout.tie(0)`: cout 버퍼 플러시 최적화
- N이 100만일 때 입출력만 수십만 번 → 최적화 필수!

## 📊 시간복잡도 분석

### 방법 1 (계수 정렬)

**시간복잡도**: **O(N + 범위)**

```
1. 입력 처리: O(N)
   - N개의 수를 입력받아 배열에 표시

2. 출력 처리: O(범위)
   - 범위(2,000,001)만큼 순회하며 출력

총합: O(N + 2,000,001) ≈ O(N + 범위)
```

**실제 연산 횟수**:
```
N = 1,000,000일 때:
  입력: 1,000,000 연산
  출력: 2,000,001 연산
  총합: 3,000,001 연산 (약 0.03초)
```

---

### 방법 2 (vector + sort)

**시간복잡도**: **O(N log N)**

```
1. 입력 처리: O(N)
   - N개의 수를 vector에 저장

2. 정렬: O(N log N)
   - STL sort() 함수 (퀵소트/머지소트 기반)

3. 출력 처리: O(N)
   - N개의 수를 출력

총합: O(N) + O(N log N) + O(N) = O(N log N)
```

**실제 연산 횟수**:
```
N = 1,000,000일 때:
  입력: 1,000,000 연산
  정렬: 1,000,000 × log(1,000,000) ≈ 1,000,000 × 20 = 20,000,000 연산
  출력: 1,000,000 연산
  총합: 약 22,000,000 연산 (약 0.22초)

ios_base 최적화 적용 시: 약 0.11초 (2배 빠름)
```

| 방법 | 시간복잡도 | 실제 연산 | 실제 시간 (추정) | 메모리 |
|------|-----------|----------|----------------|--------|
| **계수 정렬** | O(N + 범위) | 300만 | 30ms | 2MB |
| **vector + sort** | O(N log N) | 2200만 | 110ms | 8MB |

**시간 제한 체크**:

- 두 방법 모두 시간 제한 내 통과 가능 ✅
- 하지만 계수 정렬이 약 3~4배 빠름

## 🎓 학습 포인트

### 1️⃣ 계수 정렬 vs 비교 정렬 트레이드오프

| 기준 | 계수 정렬             | vector + sort |
|------|-------------------|--------------|
| **시간복잡도** | O(N + 범위)         | O(N log N) |
| **추가 공간복잡도** | O(범위)             | O(N) |
| **속도** | 매우 빠름 (30ms)      | 빠름 (110ms) |
| **메모리** | 2MB               | 8MB |
| **코드 복잡도** | 중간 (OFFSET 처리)    | 낮음 (간결) |
| **범위 제한** | 있음 (≤ 10,000,000) | 없음 |
| **음수 처리** | 복잡 (OFFSET 필요)    | 간단 (자동) |
| **추천 상황** | N(= 입력) 크고 범위 작음  | 범위 크거나 음수 |

※ 입력이 많고 AND 체크 범위가 적음 => 계수

※ 입력이 적거나 OR 체크 범위가 큼(OR 음수) => vector + sort
