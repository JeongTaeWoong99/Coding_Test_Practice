## 🔗 문제 링크

[백준 2828번 - 사과 담기 게임](https://www.acmicpc.net/problem/2828)

**난이도**: Silver 5

---

## 🤔 접근법

스크린 위에서 떨어지는 사과를 바구니로 받는 게임 문제.

N칸으로 나뉜 스크린에서 M칸을 차지하는 바구니가 좌우로 이동하며 사과를 받아야 한다.

각 사과가 순서대로 떨어질 때, 모든 사과를 받기 위한 **바구니의 최소 이동 거리**를 구하는 문제.

**핵심**: 바구니의 현재 위치와 사과 위치를 비교하여 필요한 만큼만 이동하는 **그리디 알고리즘** 문제

---

## 💡 정답 풀이 방법

**알고리즘**: 그리디(Greedy) + 시뮬레이션(Simulation)

**핵심 아이디어**:
```
1. 바구니 초기 위치는 [1, M] (왼쪽 M칸)
2. 각 사과마다:
   - 사과가 바구니 범위 안 → 이동 불필요
   - 사과가 왼쪽 → 바구니 왼쪽 끝을 사과 위치로 이동
   - 사과가 오른쪽 → 바구니 오른쪽 끝을 사과 위치로 이동
3. 이동 거리를 누적하여 출력
```

---

## 🔑 핵심 포인트

### 2️⃣ 바구니 범위 관리

```cpp
int lPos = 1;           // 바구니 왼쪽 끝 (초기값: 1)
int rPos = lPos + M - 1; // 바구니 오른쪽 위치 계산(lPos + 범위 - 보정)
```

**✅ 핵심**:
- 바구니는 M칸을 차지하므로 왼쪽 끝이 `lPos`이면 오른쪽 끝은 `lPos + M - 1`
- 예: M=2, lPos=1 → rPos=2 (1번, 2번 칸 차지)
- 예: M=3, lPos=2 → rPos=4 (2번, 3번, 4번 칸 차지)
- `-1` 보정: 바구니가 연속된 칸을 차지하므로 시작점 포함해서 M칸

### 3️⃣ 사과 위치 판단 및 이동 로직

```cpp
// 사과가 바구니 범위 안
if(fallPos >= lPos && fallPos <= rPos)
    continue;  // 이동 불필요

// 사과가 왼쪽에 있으면
if(fallPos < lPos)
{
    ret  += (lPos - fallPos); // 이동 거리 추가(거리 차이 만큼 더해주기)
    lPos  = fallPos;          // ★ 바구니 왼쪽 끝 이동(M 범위에 영향 X이기 때문에, =로 변경.)
}

// 사과가 오른쪽에 있으면
else
{
    ret  += (fallPos - rPos);   // 이동 거리 추가(거리 차이 만큼 더해주기)
    lPos += (fallPos - rPos);   // ★ 바구니 왼쪽 끝 이동(M 범위에 영향을 받기 때문에, fallPos - rPos로 lPos 변경)
}
```

**✅ 핵심**: 세 가지 경우를 고려
1. **범위 안**: `lPos ≤ fallPos ≤ rPos` → 이동 안 함
2. **왼쪽**: `fallPos < lPos` → 왼쪽으로 `(lPos - fallPos)` 만큼 이동
   - `lPos = fallPos` : 왼쪽 끝을 사과 위치로 직접 이동 (M 범위에 영향 없음)
3. **오른쪽**: `fallPos > rPos` → 오른쪽으로 `(fallPos - rPos)` 만큼 이동
   - `lPos += (fallPos - rPos)` : 이동 거리만큼 왼쪽 끝도 함께 이동 (M 범위 유지)

### 4️⃣ 왼쪽/오른쪽 이동의 차이점 이해

**왼쪽 이동 (fallPos < lPos)**:
```
현재 바구니: [4, 5, 6] (M=3, lPos=4)
사과 위치: 2

목표: 왼쪽 끝을 2로 이동
lPos = fallPos = 2
결과: [2, 3, 4]

✅ 왜 `=`를 사용하는가?
   왼쪽으로 이동할 때는 왼쪽 끝이 사과 위치가 되어야 하므로
   직접 대입하면 됨 (M 범위는 자동으로 오른쪽으로 유지)
```

**오른쪽 이동 (fallPos > rPos)**:
```
현재 바구니: [1, 2, 3] (M=3, lPos=1, rPos=3)
사과 위치: 5

목표: 오른쪽 끝을 5로 이동
이동 거리 = fallPos - rPos = 5 - 3 = 2
lPos += 2 → lPos = 1 + 2 = 3
결과: [3, 4, 5]

✅ 왜 `+=`를 사용하는가?
   오른쪽으로 이동할 때는 오른쪽 끝(rPos)을 사과 위치로 만들어야 함
   rPos = lPos + M - 1 이므로, lPos를 (fallPos - rPos)만큼 증가시켜야
   rPos가 fallPos가 됨
``` 

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ 바구니 범위 계산 - `-1` 보정 필수!

```cpp
❌ rPos = lPos + M;        // 잘못된 계산 (범위가 M+1칸이 됨)
✅ rPos = lPos + M - 1;    // 올바른 계산 (범위가 M칸)
```

**이유**:
- M=2, lPos=1일 때:
  - `rPos = lPos + M` → rPos=3 → [1, 2, 3] (3칸, 잘못됨!)
  - `rPos = lPos + M - 1` → rPos=2 → [1, 2] (2칸, 올바름!)

**반례**:
```
5 2
1
3

❌ rPos = lPos + M → [1, 3] → fallPos 3이 범위 안 → 0
✅ rPos = lPos + M - 1 → [1, 2] → fallPos 3이 범위 밖 → 1
```

### 2️⃣ 왼쪽/오른쪽 이동 로직의 차이 이해

**왼쪽 이동 - 직접 대입 (`=`)**:
```cpp
✅ if(fallPos < lPos)
   {
       ret  += (lPos - fallPos);
       lPos  = fallPos;          // = 사용 (직접 대입)
   }
```

**이유**:
- 왼쪽 끝을 사과 위치로 직접 이동하면 됨
- M 범위는 자동으로 오른쪽으로 유지됨

**오른쪽 이동 - 누적 증가 (`+=`)**:
```cpp
✅ else
   {
       ret  += (fallPos - rPos);
       lPos += (fallPos - rPos);   // += 사용 (누적 증가)
   }

❌ lPos = fallPos;  // 잘못! (왼쪽 끝을 사과 위치로 설정하면 안 됨)
```

**이유**:
- 오른쪽으로 이동할 때는 **오른쪽 끝(rPos)**이 사과 위치가 되어야 함
- `rPos = lPos + M - 1`이므로, lPos를 `(fallPos - rPos)`만큼 증가시켜야 rPos가 fallPos가 됨

**예시**:
```
현재 바구니: [1, 2] (M=2, lPos=1, rPos=2)
fallPos: 5

목표: rPos를 5로 이동

❌ lPos = fallPos = 5
   → rPos = 5 + 2 - 1 = 6
   → [5, 6] (잘못! 오른쪽 끝이 6이 됨)

✅ lPos += (fallPos - rPos) = 1 + (5 - 2) = 4
   → rPos = 4 + 2 - 1 = 5
   → [4, 5] (올바름! 오른쪽 끝이 5)
```

### 3️⃣ 초기 위치 설정

```cpp
❌ int lPos = 0;        // 잘못! (문제에서 1번부터 시작)
✅ int lPos = 1;        // 올바름! (왼쪽 M칸 = 1번부터)
```

**이유**:
- 문제에서 "가장 처음에 바구니는 왼쪽 M칸을 차지"
- 스크린은 1번부터 N번까지 (0번 없음)

### 4️⃣ 변수명 일관성 유지

```cpp
✅ 명확한 변수명 사용:
   - lPos, rPos : 왼쪽/오른쪽 위치
   - fallPos : 사과가 떨어지는 위치
   - ret : 누적 이동 거리

❌ 애매한 변수명:
   - l, r : 너무 짧음
   - temp : 의미 불명확
   - result : 길고 불필요
```

**이유**:
- 코드 가독성 향상
- 디버깅 시 변수 역할 파악 용이
- 인라인 주석과 함께 사용하면 더욱 명확

## 📊 시간복잡도 분석

**전체 시간복잡도**: **O(J)**

**상세 분석**:
```
1. 입력 처리 : O(1)
   - N, M, J 입력

2. 사과 처리 : O(J)
   - J개의 사과를 순회하며 각각 O(1) 연산

총합 : O(J)
```

**시간 제한 체크**:
- J ≤ 20 (문제 조건)
- **20 연산** << **1억** → 매우 여유롭게 통과 ✅

---

## 💾 공간복잡도

**O(1)**
- 상수 개의 변수만 사용 (n, m, j, l, r, apple, ret)
- 추가 배열이나 자료구조 불필요

## 🎯 알고리즘 분류

- **그리디(Greedy)**: 각 사과마다 최소 이동 거리로 이동하는 것이 최적
- **시뮬레이션(Simulation)**: 바구니의 이동을 직접 시뮬레이션
