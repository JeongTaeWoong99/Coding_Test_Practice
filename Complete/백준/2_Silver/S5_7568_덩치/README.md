## 🔗 문제 링크

[백준 7568번 - 덩치](https://www.acmicpc.net/problem/7568)

**난이도**: Silver 5

---

## 🤔 접근법

문제의 범위가 작아서, 브루트포스로 가능함.

그리고, 문제 조건과 테스트 케이스를 보니,

각각 모두와 비교해서, 2개 다 크면 패스하고, 2개 다 작으면 등수를 올리면 됨.

하나라도 큰게 있으면, 동일하다고 보기 때문!

---

N명의 사람 중 각 사람의 덩치 등수를 구하는 문제.

덩치는 (몸무게, 키)로 표현되며, A가 B보다 덩치가 크려면 **무게와 키가 모두 커야** 한다.

각 사람의 등수는 **자신보다 덩치가 큰 사람의 수 + 1**로 결정된다.

**핵심** : 모든 사람을 서로 비교하는 **브루트포스** 알고리즘 문제. N ≤ 50이므로 O(N²) 가능.

---

## 💡 정답 풀이 방법

**알고리즘**: 브루트포스(Brute Force), 구현

**핵심 아이디어**:
```
1. 각 사람마다 등수를 1로 시작
2. 모든 사람과 비교하여 나보다 덩치가 큰 사람이 있으면 등수 증가
3. 덩치가 크다 = 무게도 크고 키도 큼
4. 비교 불가능한 경우(한쪽만 큰 경우)는 등수에 영향 없음
```

## 🔑 핵심 포인트

### 1️⃣ 자료구조 선택: vector<pair<int,int>>

```cpp
vector<pair<int,int>> v;  // (몸무게, 키) 저장
```

**✅ 핵심**: 두 개의 값을 하나의 단위로 저장
- `pair<int,int>`는 **하나의 완성된 타입**
- `v[i].first` = 몸무게, `v[i].second` = 키
- `vector<int,int>`는 **문법 오류**! (vector는 하나의 타입만 받음)

**❌ 흔한 실수**:
```cpp
vector<int,int> v;  // ❌ 컴파일 에러!
```

**이유**:
- `vector<T, Allocator>` 형태에서 두 번째는 메모리 할당자 (기본값 있음)
- `int, int`는 두 개의 타입이므로 불가능

### 2️⃣ 메모리 최적화: reserve vs resize

```cpp
v.reserve(n);  // ✅ 용량만 확보, 크기는 0

// 입력 받기
for (int i = 0; i < n; ++i)
{
    cin >> tempW >> tempH;
    v.emplace_back(tempW, tempH);  // 재할당 없이 추가
}
```

**✅ 핵심**: `reserve`와 `resize`의 차이 이해

| 구분 | reserve(n) | resize(n) |
|------|-----------|-----------|
| **size()** | 0 | n |
| **capacity()** | n | n |
| **실제 메모리** | n개 공간만 확보 | n개 할당 + (0,0) 초기화 |
| **v[0] 접근** | ❌ 런타임 에러 | ✅ 가능 (0,0) |
| **emplace_back** | 1번째에 추가 | n+1번째에 추가 ⚠️ |

**❌ resize를 사용하면 생기는 문제**:
```cpp
v.resize(3);              // size=3, [(0,0), (0,0), (0,0)]
v.emplace_back(55, 185);  // size=4, [(0,0), (0,0), (0,0), (55,185)] ⚠️
v.emplace_back(58, 183);  // size=5, [(0,0), (0,0), (0,0), (55,185), (58,183)]
// 결과: 2n개가 되어 버림!
```

**✅ 올바른 사용법**:
```
reserve(n)  : "n개 들어갈 공간만 미리 만들어줘!" (재할당 방지)
resize(n)   : "n개의 (0,0)을 만들어줘!" (v[i] = 값으로 사용 시)
```

**사용 예시**:
```cpp
// 방법 1: reserve + emplace_back (권장!)
v.reserve(n);
for (int i = 0; i < n; ++i)
    v.emplace_back(w, h);

// 방법 2: resize + 인덱스 접근
v.resize(n);
for (int i = 0; i < n; ++i)
    v[i] = {w, h};

// ❌ resize + emplace_back (2n개 생성!)
v.resize(n);
for (int i = 0; i < n; ++i)
    v.emplace_back(w, h);  // 잘못됨!
```

### 3️⃣ 성능 최적화: const auto& 사용

```cpp
// 비교할 인원 1명 선택(참조 사용으로 복사 비용 제거)
for (const auto& selectP : v)
{
    // 모든 인원과 비교
    for (const auto& currentP : v)
    {
        if (selectP.first < currentP.first && selectP.second < currentP.second)
            cnt++;
    }
}
```

**✅ 핵심**: `const auto&`의 의미와 효과

| 방법 | 복사 발생 | 수정 가능 | 성능 | 안전성 |
|------|----------|----------|------|--------|
| `auto` | ✅ (매번 복사) | ✅ (복사본 수정) | ⚠️ 느림 | ⚠️ 실수 가능 |
| `auto&` | ❌ (참조) | ✅ (원본 수정) | ✅ 빠름 | ⚠️ 실수로 수정 |
| `const auto&` | ❌ (참조) | ❌ (읽기 전용) | ✅ 빠름 | ✅ 컴파일러 보호 |

**성능 차이** (n=50일 때):
```
auto          : 50 × 50 = 2,500번 복사 발생
const auto&   : 0번 복사 (참조만 사용)
```

**왜 const를 붙이는가?**

1. **의도 명확화**: "읽기만 할 거야" 명시
2. **실수 방지**: 컴파일 타임에 수정 시도를 차단
3. **컴파일러 최적화**: 값이 안 바뀐다고 확신하므로 공격적 최적화 가능

**예시**:
```cpp
// ❌ 실수로 수정 가능
for (auto& p : v)
{
    p.first = 0;  // 원본이 바뀜! 버그 발생
}

// ✅ 컴파일 에러로 방지
for (const auto& p : v)
{
    p.first = 0;  // ❌ 컴파일 에러!
}
```

**선택 가이드**:
```
- 읽기만 할 때   → const auto& (기본 추천!)
- 수정 필요할 때 → auto&
- 복사 필요할 때 → auto
```

## 🚨 "맞왜틀" 방지 포인트

### 1️⃣ vector<pair<int,int>> vs vector<int,int>

```cpp
❌ vector<int,int> v;      // 컴파일 에러!
✅ vector<pair<int,int>> v;  // 올바름
```

**이유**:
- vector는 **하나의 타입**만 템플릿 인자로 받음
- `pair<int,int>`를 하나의 타입으로 사용해야 함

### 2️⃣ resize + emplace_back 조합 금지!

```cpp
❌ v.resize(n);
   for (int i = 0; i < n; ++i)
       v.emplace_back(w, h);  // 2n개 생성!

✅ v.reserve(n);
   for (int i = 0; i < n; ++i)
       v.emplace_back(w, h);  // n개 생성
```

**반례**:
```
3
55 185
58 183
88 186

❌ resize 사용: [(0,0), (0,0), (0,0), (55,185), (58,183), (88,186)]
   → 6개 생성, 등수 계산 오류

✅ reserve 사용: [(55,185), (58,183), (88,186)]
   → 3개 생성, 정상
```

### 4️⃣ 범위 기반 for문에서 복사 주의

```cpp
❌ for (auto selectP : v)  // 매번 복사 발생

✅ for (const auto& selectP : v)  // 참조 사용, 복사 없음
```

**이유**:
- N=50일 때 50×50=2,500번 복사
- `pair<int,int>`는 8바이트로 작지만, 복사 비용 누적
- `const auto&`로 복사 비용 제거 + 실수 방지

## 📊 시간복잡도 분석

**전체 시간복잡도**: **O(N²)**

**상세 분석**:
```
1. 입력 처리 : O(N)
   - N명의 정보 입력

2. 등수 계산 : O(N²)
   - N명을 각각 N명과 비교

총합 : O(N) + O(N²) = O(N²)
```

**시간 제한 체크**:
- N ≤ 50 (문제 조건)
- N² = 50 × 50 = 2,500
- **2,500 연산** << **1억** → 시간 내 여유롭게 통과 ✅

## 🎯 알고리즘 분류

- **브루트포스(Brute Force)**: 모든 경우를 직접 비교
- **구현(Implementation)**: 문제 조건을 그대로 구현
