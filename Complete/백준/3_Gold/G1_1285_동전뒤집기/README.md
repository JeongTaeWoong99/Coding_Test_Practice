## 🤔 접근법

(비트 마스킹 어렵다... 추후 다시 풀어보자)

N×N 크기의 동전판에서 한 행 또는 한 열을 뒤집어서 뒷면(T)이 위를 향하는 동전의 개수를 최소화하는 문제이다.

범위가 작아서 (N ≤ 20) 브루트포스로 해결 가능하지만, **행과 열을 모두 브루트포스하면 2^40으로 시간 초과**가 발생한다.

핵심 통찰: **행과 열의 뒤집기 순서는 상관없다!**
- 행을 뒤집든 열을 뒤집든 최종 결과는 동일
- 따라서 **행은 모두 시도**하고, **열은 그리디하게 결정**할 수 있다

### 🔍 왜 순서가 상관없을까?

**핵심 원리**: 각 칸의 최종 상태는 **"뒤집은 총 횟수"**로만 결정됨!

```
짝수 번 뒤집기 = 원래 상태
홀수 번 뒤집기 = 반대 상태

→ 순서는 중요하지 않고, "몇 번 뒤집었는가"만 중요!
```

**구체적 예시** (2×2 동전판):
```
초기 상태:
     1열  2열
    ┌────────┐
1행 │  H    T  │
2행 │  T    H  │
    └────────┘

경우 1: 1행 뒤집기 → 2열 뒤집기
  Step 1 (1행):  [T,H] / [T,H]
  Step 2 (2열):  [T,T] / [T,T]

경우 2: 2열 뒤집기 → 1행 뒤집기
  Step 1 (2열):  [H,H] / [T,T]
  Step 2 (1행):  [T,T] / [T,T]

✅ 결과가 동일! 순서와 무관하게 "1행 1번 + 2열 1번" = 같은 결과
```

**수학적 설명**:
```
(i, j) 칸의 최종 상태 = 초기 상태 XOR (i행 뒤집기) XOR (j열 뒤집기)

XOR 연산은 교환법칙 성립:
  A XOR B = B XOR A

→ 순서와 무관!
```

**왜 이게 중요한가?**
```
이 통찰 덕분에:
  ✅ 행: 모든 경우 시도 (2^N)
  ✅ 열: 각 경우마다 그리디 선택 (O(N))

만약 순서를 고려했다면:
  ❌ 행+열 순서 조합: 무수히 많음
  ❌ 시간복잡도: 계산 불가능
```

이 문제는 **비트마스킹을 활용한 효율적인 구현**이 핵심이다!

## 💡 정답 풀이 방법

**알고리즘**: 브루트포스 + 그리디 + 비트마스킹

**핵심 아이디어**:
```
1. 비트마스킹으로 각 행을 정수 하나로 표현 (H=0, T=1)
2. 재귀로 각 행을 뒤집을지 말지 모든 경우 시도 (2^N)
3. 모든 행 결정 후, 각 열마다 T 개수 확인
4. 열은 그리디하게 결정: min(T개수, H개수)
5. 모든 경우 중 최소값 선택
```

**시간 복잡도**: O(2^N × N^2)
- 행 경우의 수: 2^N (최대 2^20 = 1,048,576)
- 각 경우마다 열 확인: O(N^2) (N개 열 × N개 행)
- 비트 연산으로 매우 빠름 (약 4억 연산, 6초 내 통과)

**공간 복잡도**: O(N)
- arr 배열: O(N)
- 재귀 깊이: O(N)

## 🔑 핵심 포인트

### 1️⃣ 비트마스킹으로 행 표현

```cpp
int arr[44];  // 각 행을 정수 하나로 표현

// "HHT" 문자열을 정수로 변환
int value = 1;  // 2^0, 2^1, 2^2, ...
for (char j : S)
{
    if(j == 'T')
        arr[i] |= value;  // OR 연산으로 해당 비트를 1로 설정
    value *= 2;           // 다음 비트 위치로 이동
}
```

**✅ 핵심**:
- 각 문자를 하나의 비트로 표현 (H=0, T=1)
- "HHT" → 이진수 100 → 십진수 4
- 한 행을 int 하나로 표현 가능!

**🔍 왜 비트마스킹을 사용하는가?**
```
장점 1: 메모리 효율
  - 2D 배열: char[20][20] = 400바이트
  - 비트마스킹: int[20] = 80바이트

장점 2: 연산 속도
  - 행 뒤집기: ~arr[i] (O(1))
  - 2D 배열: for문 O(N)

장점 3: 코드 간결성
  - 비트 연산 한 줄로 처리
```

### 2️⃣ 행을 한 번에 뒤집기 (NOT 연산)

```cpp
arr[here] = ~arr[here];  // 모든 비트 반전
```

**✅ 핵심**:
- ~ 연산자는 모든 비트를 반전 (0→1, 1→0)
- 한 행의 모든 동전을 O(1)에 뒤집기 가능!

**예시**:
```
원본: "HHT" → arr = 100(2) = 4
반전: ~arr  → 011(하위 3비트) = "TTH"

비트 확인:
  i=1과 AND: ...011 & 001 = 001 (T)
  i=2와 AND: ...011 & 010 = 010 (T)
  i=4와 AND: ...011 & 100 = 000 (H)

✅ 정확히 "TTH"로 변환됨!
```

### 3️⃣ 특정 열의 비트 확인 (AND 연산)

```cpp
for(int i = 1; i <= (1 << (N - 1)); i *= 2)  // i = 1, 2, 4, 8, ...
{
    for(int j = 1; j <= N; j++)
    {
        if(arr[j] & i)  // j번째 행의 i번째 비트가 1(T)인지 확인
            cnt++;
    }
}
```

**✅ 핵심**:
- `arr[j] & i` : AND 연산으로 특정 비트만 확인
- 결과가 0이 아니면 해당 비트가 1(T)

**예시**: arr[1] = 4 (0100), 3번째 열(i=4) 확인
```
arr[1] : 0100  (4)
i      : 0100  (4)
─────────────
AND    : 0100  (4) → True (T)
```

### 4️⃣ 열은 그리디하게 결정

```cpp
sum += min(cnt, N - cnt);
```

**✅ 핵심**:
- `cnt` : 현재 T의 개수 (열을 뒤집지 않음)
- `N - cnt` : 열을 뒤집었을 때 T의 개수
- 항상 더 적은 쪽을 선택!

**예시** (N=3):
```
[T, T, H] → cnt=2
  뒤집지 않음: T 2개
  뒤집음: [H, H, T] → T 1개
  → min(2, 1) = 1 선택 ✅

[H, T, H] → cnt=1
  뒤집지 않음: T 1개
  뒤집음: [T, H, T] → T 2개
  → min(1, 2) = 1 선택 ✅
```

### 5️⃣ 재귀로 모든 행 경우의 수 탐색

```cpp
void GO(int here)
{
    if(here == N + 1)  // 모든 행 결정 완료
    {
        // 각 열의 T 개수 확인 및 최소값 계산
    }

    GO(here + 1);              // here번째 행을 뒤집지 않음
    arr[here] = ~arr[here];    // here번째 행을 뒤집음
    GO(here + 1);
}
```

**✅ 핵심**:
- 각 행마다 뒤집을지/안 뒤집을지 2가지 선택
- N개 행 → 2^N 가지 경우의 수
- 재귀로 모든 경우 탐색

## 📊 예제 실행 흐름 (상세 분석)

**입력**:
```
3
HHT
THH
THT
```

### 📌 Step 1: 비트마스킹 변환

```
문자열 → 정수 변환 과정:

1번 행 "HHT":
  H(0번) → 비트 2^0 = 1 → 0
  H(1번) → 비트 2^1 = 2 → 0
  T(2번) → 비트 2^2 = 4 → 1
  ─────────────────────────
  이진수: 100 → arr[1] = 4

2번 행 "THH":
  T(0번) → 비트 2^0 = 1 → 1
  H(1번) → 비트 2^1 = 2 → 0
  H(2번) → 비트 2^2 = 4 → 0
  ─────────────────────────
  이진수: 001 → arr[2] = 1

3번 행 "THT":
  T(0번) → 비트 2^0 = 1 → 1
  H(1번) → 비트 2^1 = 2 → 0
  T(2번) → 비트 2^2 = 4 → 1
  ─────────────────────────
  이진수: 101 → arr[3] = 5
```

**초기 상태**:
```
arr[1] = 4  (100 → HHT)
arr[2] = 1  (001 → THH)
arr[3] = 5  (101 → THT)
```

### 📌 Step 2: 재귀 탐색 (일부 경우만 보기)

#### 🔸 Case 1: 아무 행도 뒤집지 않음

```
현재 상태:
arr[1] = 4  (100 → HHT)
arr[2] = 1  (001 → THH)
arr[3] = 5  (101 → THT)

행렬로 표현:
      열1  열2  열3
    ┌────────────┐
행1 │  H    H    T  │ arr[1] = 100
행2 │  T    H    H  │ arr[2] = 001
행3 │  T    H    T  │ arr[3] = 101
    └────────────┘
```

**열별 T 개수 확인**:
```
📍 1번째 열 (i=1, 이진수 001):

arr[1] & 1 : 100 & 001 = 000 (0) → H
arr[2] & 1 : 001 & 001 = 001 (1) → T ✅
arr[3] & 1 : 101 & 001 = 001 (1) → T ✅

cnt = 2 (T가 2개)
min(2, 3-2) = min(2, 1) = 1

📍 2번째 열 (i=2, 이진수 010):

arr[1] & 2 : 100 & 010 = 000 (0) → H
arr[2] & 2 : 001 & 010 = 000 (0) → H
arr[3] & 2 : 101 & 010 = 000 (0) → H

cnt = 0 (T가 0개)
min(0, 3-0) = min(0, 3) = 0

📍 3번째 열 (i=4, 이진수 100):

arr[1] & 4 : 100 & 100 = 100 (4) → T ✅
arr[2] & 4 : 001 & 100 = 000 (0) → H
arr[3] & 4 : 101 & 100 = 100 (4) → T ✅

cnt = 2 (T가 2개)
min(2, 3-2) = min(2, 1) = 1
```

**총합**: 1 + 0 + 1 = **2개**

#### 🔸 Case 2: 1번 행만 뒤집기

```
arr[1] = ~4 → ...011 (하위 3비트만 보면 011 → TTH)
arr[2] = 1  (001 → THH)
arr[3] = 5  (101 → THT)

행렬로 표현:
      열1  열2  열3
    ┌────────────┐
행1 │  T    T    H  │ arr[1] = 011
행2 │  T    H    H  │ arr[2] = 001
행3 │  T    H    T  │ arr[3] = 101
    └────────────┘
```

**열별 T 개수 확인**:
```
📍 1번째 열: [T, T, T] → cnt=3 → min(3, 0) = 0
📍 2번째 열: [T, H, H] → cnt=1 → min(1, 2) = 1
📍 3번째 열: [H, H, T] → cnt=1 → min(1, 2) = 1
```

**총합**: 0 + 1 + 1 = **2개**

#### 🔸 Case 3: 2번, 3번 행 뒤집기

```
arr[1] = 4    (100 → HHT)
arr[2] = ~1 → ...110 (하위 3비트: 110 → HTT)
arr[3] = ~5 → ...010 (하위 3비트: 010 → HTH)

행렬로 표현:
      열1  열2  열3
    ┌────────────┐
행1 │  H    H    T  │ arr[1] = 100
행2 │  H    T    T  │ arr[2] = 110
행3 │  H    T    H  │ arr[3] = 010
    └────────────┘
```

**열별 T 개수 확인**:
```
📍 1번째 열 (i=1):

arr[1] & 1 : 100 & 001 = 000 (0) → H
arr[2] & 1 : 110 & 001 = 000 (0) → H
arr[3] & 1 : 010 & 001 = 000 (0) → H

cnt = 0 → min(0, 3) = 0

📍 2번째 열 (i=2):

arr[1] & 2 : 100 & 010 = 000 (0) → H
arr[2] & 2 : 110 & 010 = 010 (2) → T ✅
arr[3] & 2 : 010 & 010 = 010 (2) → T ✅

cnt = 2 → min(2, 1) = 1

📍 3번째 열 (i=4):

arr[1] & 4 : 100 & 100 = 100 (4) → T ✅
arr[2] & 4 : 110 & 100 = 100 (4) → T ✅
arr[3] & 4 : 010 & 100 = 000 (0) → H

cnt = 2 → min(2, 1) = 1
```

**총합**: 0 + 1 + 1 = **2개**

## 🔍 비트마스킹 상세 분석

### 📌 비트 연산자 정리

| 연산자 | 기능 | 예시 |
|--------|------|------|
| `\|` (OR) | 특정 비트를 1로 설정 | `4 \| 2 = 6` (100 \| 010 = 110) |
| `&` (AND) | 특정 비트 확인 | `5 & 1 = 1` (101 & 001 = 001) |
| `~` (NOT) | 모든 비트 반전 | `~4 = ...1011` (100 → 011) |
| `<<` (Left Shift) | 왼쪽으로 이동 (×2) | `1 << 3 = 8` (1 → 1000) |

### 📌 문자열 → 비트마스킹 변환 과정

```cpp
// "HHT" → 4 변환 과정

arr[i] = 0     // 초기값: 00000000
value = 1      // 비트 위치: 2^0

// 1번째 문자 'H'
if('H' == 'T') → False
arr[i] = 0     // 변화 없음
value = 2      // 다음 비트로 이동

// 2번째 문자 'H'
if('H' == 'T') → False
arr[i] = 0     // 변화 없음
value = 4      // 다음 비트로 이동

// 3번째 문자 'T'
if('T' == 'T') → True
arr[i] |= 4    // OR 연산: 0 | 4 = 4
arr[i] = 4     // 이진수: 00000100
value = 8      // 다음 비트로 이동 (사용 안 함)

// 최종: arr[i] = 4 (이진수: 100 → HHT)
```

### 📌 특정 열의 비트 확인 과정

```cpp
// 3번째 열(i=4) 확인 과정

i = 4  (이진수: 0100)

// 1번 행 확인
arr[1] & i : 0100 & 0100 = 0100 (True → T)

// 2번 행 확인
arr[2] & i : 0001 & 0100 = 0000 (False → H)

// 3번 행 확인
arr[3] & i : 0101 & 0100 = 0100 (True → T)

cnt = 2 (T가 2개)
```

### 📌 행 뒤집기 (NOT 연산) 과정

```cpp
// arr[1] = 4 (100 → HHT) 뒤집기

원본:      00000100 (4)
~연산:     11111011 (하위 비트만 보면 011)

// 각 비트 확인
arr[1] & 1 : ...1011 & 0001 = 0001 (T)
arr[1] & 2 : ...1011 & 0010 = 0010 (T)
arr[1] & 4 : ...1011 & 0100 = 0000 (H)

결과: TTH ✅
```

**⚠️ 주의**: 상위 비트도 반전되지만, AND 연산 시 N비트까지만 사용하므로 문제없음!

## ⏱️ 시간복잡도

**O(2^N × N^2)**

### 상세 분석

```
1️⃣ 재귀 호출 횟수: 2^N
   - 각 행마다 뒤집을지 말지 2가지 선택
   - N개 행 → 2^N 가지 경우

2️⃣ 각 경우마다 계산: O(N^2)
   - 외부 루프: N개 열 순회 → O(N)
   - 내부 루프: N개 행 순회 → O(N)
   - 총: O(N × N) = O(N^2)

3️⃣ 전체 시간복잡도
   - 2^N × N^2
   - N=20일 때: 2^20 × 400 = 419,430,400 (약 4억)
```

**왜 통과하는가?**
- 비트 연산은 매우 빠름 (CPU 1 사이클)
- 시간 제한 6초 (넉넉함)
- 실제 실행 시간: 약 1~2초

---

## 💾 공간복잡도

**O(N)**

- `arr[44]` : O(N)
- 재귀 스택 깊이: O(N)

---

## 🚨 주의사항

1. **비트마스킹 필수**: 2D 배열로 하면 행 뒤집기가 O(N)이 되어 느림
2. **NOT 연산 주의**: 상위 비트도 반전되지만 AND 연산 시 문제없음
3. **행만 브루트포스**: 열까지 브루트포스하면 2^40으로 시간 초과
4. **그리디 증명**: 열은 독립적이므로 각 열마다 최적 선택 가능
5. **N ≤ 20**: 2^20 = 1,048,576으로 충분히 가능

## 💡 핵심 정리

### 🎯 알고리즘 핵심

```
✅ 행 : 브루트포스 (모든 경우 시도) → 2^N
✅ 열 : 그리디 (각 경우마다 최적 선택) → O(N)
✅ 비트마스킹 : 효율적인 구현 → O(1) 연산
```

### 🔑 왜 이 방법이 통하는가?

```
1️⃣ 순서 무관성
   - 행을 먼저 뒤집든 열을 먼저 뒤집든 결과는 동일
   - 따라서 행/열을 분리하여 생각 가능

2️⃣ 열의 독립성
   - 각 열의 결정은 다른 열에 영향을 주지 않음
   - 따라서 각 열마다 독립적으로 최적 선택 가능

3️⃣ 그리디 최적성
   - 열은 뒤집을지 말지 2가지만 선택 가능
   - min(T개수, H개수)가 항상 최적
```

### 📊 시간복잡도 비교

| 방법 | 시간복잡도 | N=20일 때 |
|------|----------|----------|
| Naive (행+열 모두 브루트포스) | O(2^(2N)) | 2^40 ≈ 1조 ❌ |
| **이 코드 (행 브루트포스 + 열 그리디)** | **O(2^N × N^2)** | **4억** ✅ |
| 이상적 (DP 등) | O(2^N × N) | 2천만 (하지만 구현 복잡) |

### 🔧 비트마스킹 장점

```
✅ 메모리 효율: int 하나로 한 행 표현
✅ 연산 속도: ~arr[i]로 O(1)에 행 뒤집기
✅ 코드 간결: 비트 연산으로 간단하게 구현
✅ 캐시 효율: 연속된 메모리 사용
```

## 🎓 배운 점

1. **비트마스킹의 실전 활용**: 문자열을 정수로 표현하여 효율적인 연산
2. **그리디 + 브루트포스 결합**: 전체를 브루트포스하지 않고 일부만 시도
3. **시간복잡도 최적화**: 2^40 → 2^20 × N^2로 감소
4. **비트 연산의 위력**: O(N) 연산을 O(1)로 단축
5. **순서 무관성 활용**: 행/열 뒤집기 순서가 상관없음을 이용
