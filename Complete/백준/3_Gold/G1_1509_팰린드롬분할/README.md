## 🔗 문제 링크

[백준 1509번 - 팰린드롬 분할](https://www.acmicpc.net/problem/1509)

**난이도**: Gold 1

---

## 🤔 접근법

(복습 1회)

문자열을 팰린드롬 조각들로 나눌 때 최소 분할 개수를 구하는 문제.

처음에는 모든 경우를 나열하려 했지만, 길이 n=2500에서 **경우의 수가 2^(n-1)** 이므로 완전 탐색은 불가능.

→ **DP 두 단계**로 해결 :
1. `isPalin[i][len]` : s[i..i+len-1]이 팰린드롬인지 전처리 (O(n²))
2. `dp[i]` : s[i..n-1]을 팰린드롬으로 분할하는 최솟값 (메모이제이션)

---

## ❌ 브루트포스 — 왜 안 되는가?

### 경우의 수 폭발

각 문자 사이마다 "자르기 / 안 자르기" 선택이 존재 :

```
A A A A
 ^ ^ ^
 각 위치마다 2가지 선택 → 2^(n-1) 가지
```

| n    | 경우의 수      | 실현 가능? |
|------|---------------|----------|
| 10   | 512           | ✅        |
| 30   | 약 5억         | ❌ 위험   |
| 2500 | 2^2499 (무한) | ❌ 불가능 |

---

## ✅ DP 방식 — 정답

### 1단계 : isPalin 전처리

`isPalin[i][len]` = s[i..i+len-1]이 팰린드롬이면 `true`

```
기저 사례 :
  isPalin[i][1] = true          (원소 1개, 항상 팰린드롬)
  isPalin[i][2] = (s[i]==s[i+1]) (원소 2개)

점화식 (길이 3 이상) :
  isPalin[i][len] = (s[i] == s[i+len-1]) && isPalin[i+1][len-2]
                     ↑ 양 끝이 같은가?      ↑ 안쪽 구간이 팰린드롬인가?
```

짧은 길이부터 채우기 때문에 `isPalin[i+1][len-2]`는 항상 계산된 상태.

### 2단계 : dp 메모이제이션

`dp[i]` = s[i..n-1]을 팰린드롬으로 분할하는 최솟값

```
dp[n]   = 0  (기저 사례 : 문자열 끝)
dp[i]   = min(dp[i + len] + 1)
          isPalin[i][len] == true 인 len에 대해서만
```

같은 `i`에서 출발하는 계산은 **한 번만** 수행 (메모이제이션).

## 🔍 DP 배열 채워지는 과정 (예제 1) : "AAAA"

```
입력 : AAAA (인덱스 0~3, n=4)

isPalin 요약 (T인 것만) :
  길이1 : [0][1] [1][1] [2][1] [3][1]  (모든 단일 문자)
  길이2 : [0][2]="AA"  [1][2]="AA"  [2][2]="AA"
  길이3 : [0][3]="AAA" [1][3]="AAA"
  길이4 : [0][4]="AAAA"
```

### 📊 dp 초기화 → 재귀 호출

```
fill → dp = [ INF, INF, INF, INF, INF ]
              0     1     2     3     4

DP(0) 시작
│
├─ len=1, isPalin[0][1]=T → DP(1) 호출
│    │
│    ├─ len=1, isPalin[1][1]=T → DP(2) 호출
│    │    │
│    │    ├─ len=1, isPalin[2][1]=T → DP(3) 호출
│    │    │    │
│    │    │    ├─ len=1, isPalin[3][1]=T → DP(4): here==n → return 0 ★
│    │    │    └─ dp[3]=1, return 1
│    │    │
│    │    ├─ len=2, isPalin[2][2]=T → DP(4): 0 ★ (재사용)
│    │    │         ret = min(1, 0+1) = 1  (변화 없음)
│    │    │
│    │    └─ dp[2]=1, return 1
│    │
│    ├─ len=2, isPalin[1][2]=T → DP(3): dp[3]=1 ★ (재사용)
│    │         ret = min(INF, 1+1) = 2
│    │
│    ├─ len=3, isPalin[1][3]=T → DP(4): 0 ★ (재사용)
│    │         ret = min(2, 0+1) = 1  ← 최솟값!
│    │
│    └─ dp[1]=1, return 1
│
├─ ret = min(INF, 1+1) = 2
│
├─ len=2, isPalin[0][2]=T → DP(2): dp[2]=1 ★ (재사용)
│         ret = min(2, 1+1) = 2  (변화 없음)
│
├─ len=3, isPalin[0][3]=T → DP(3): dp[3]=1 ★ (재사용)
│         ret = min(2, 1+1) = 2  (변화 없음)
│
├─ len=4, isPalin[0][4]=T → DP(4): 0 ★ (재사용)
│         ret = min(2, 0+1) = 1  ← 최솟값!
│
└─ dp[0]=1, return 1
```

### 📊 최종 dp 테이블

```
  i  │  dp[i]  │  의미
 ────┼─────────┼──────────────────────────
  4  │    0    │  끝 (기저)
  3  │    1    │  "A" 한 조각
  2  │    1    │  "AA" 한 조각
  1  │    1    │  "AAA" 한 조각
  0  │    1    │  "AAAA" 한 조각  ← 정답!
```

**출력** : `1`

## 🔑 핵심 포인트

### 1️⃣ 전처리 순서가 핵심

```
isPalin[i][len]을 계산하려면 isPalin[i+1][len-2]가 필요
→ 작은 len부터 순서대로 채워야 참조할 값이 항상 준비됨
```

### 2️⃣ dp는 재귀 + 메모이제이션

```cpp
int &ret = dp[here];
if(dp[here] != INF) return dp[here];  // 이미 계산 → 재사용

for(int len = 1; here + len <= n; len++)
{
    if(isPalin[here][len])
        ret = min(ret, DP(here + len) + 1);
}
```

### 3️⃣ bool vs int

```cpp
bool isPalin[2504][2504];  // bool : 메모리 1byte, 의미 명확
                           // 2504 × 2504 × 1byte ≈ 6.25MB ✅
```

## ⚠️ 흔한 오해 : isPalin T 개수 ≠ 정답

isPalin 테이블의 T 개수와 정답(최소 분할 수)은 **무관**하다.

isPalin은 단지 "어떤 구간이 팰린드롬인가?" 를 기록할 뿐이고,
정답은 항상 **dp[0]** 에서 나온다.

```
"ABA" isPalin에서 len=3 열의 T 개수 = 1  →  정답도 1  (우연의 일치!)

"AB"  isPalin에서 len=1 열의 T 개수 = 2  →  정답은 2  (우연히 같음)
      len=2 열의 T 개수 = 0            →  정답은 2  (다름)

"ABBA" isPalin에서 len=4 열의 T 개수 = 1  →  정답도 1  (우연의 일치!)
```

**정답이 결정되는 실제 경로** (ABA 예시) :

```
isPalin[0][3] = T
    ↓  "ABA 전체가 팰린드롬" 이라는 정보를 dp에 전달
DP(0) 에서 len=3 선택  →  DP(3) + 1 = 0 + 1 = 1
    ↓
dp[0] = 1  →  출력 1
```

→ isPalin은 **재료**, dp는 **요리**. 정답은 요리(dp)가 결정한다.

## 💾 공간복잡도

**O(n²)**

- `isPalin[2504][2504]` (bool) : 2504 × 2504 × 1byte ≈ 6.25MB
- `dp[2504]` (int) : 약 10KB
- 총 약 6.3MB (메모리 제한 128MB 내 ✅)
