## 🤔 접근법

(함참 고민한 끝에 이분 탐색과 기저 사례까지는 생각을 했는데)

(ansRet - 1으로 마지막에 탐승하는 기구를 고르는 방법은 생각하지 못함...)

N명의 아이들이 줄을 서서 놀이공원의 M개 1인승 놀이기구를 기다리고 있다.

각 놀이기구는 운행 시간이 정해져 있고, 운행이 끝나면 탑승자가 내린다.

놀이기구가 비면 줄의 가장 앞 아이가 탑승하며, **여러 개가 동시에 비면 작은 번호 놀이기구에 먼저 탑승**한다.

**마지막 아이(N번째 아이)가 타게 되는 놀이기구 번호**를 구하는 문제이다.

핵심은 **이분 탐색**으로 N번째 아이가 탑승하는 시간을 찾고, 그 시간에 어느 놀이기구에 타는지 결정하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 이분 탐색 (Binary Search) + 시뮬레이션

**핵심 아이디어**:
```
1. 이분 탐색으로 "N번째 아이가 탑승하는 시간(ansRet)" 찾기
   - Check(mid) : mid 시간까지 n명 이상 탑승 가능한지 확인
   - 최소 시간을 찾는 Lower Bound 방식

2. ansRet - 1 시간까지 탑승한 아이 수 계산

3. ansRet 시간에 비어있는 놀이기구들을 순서대로 확인
   - 작은 번호부터 순서대로 (0번부터)
   - 비어있으면 childCnt++ (한 명씩 탑승)
   - childCnt == n이 되는 순간 그 놀이기구가 정답!
```

**시간 복잡도**: O(log(MAX_TIME) × M + M)
- 이분 탐색: O(log(600억)) ≈ O(36)
  - 각 Check 호출마다: O(M) (최대 10,000)
  - 총: O(36 × 10,000) = O(360,000)
- 최종 탐색: O(M) (최대 10,000)
- **총 시간복잡도**: O(400,000) → 충분히 통과

**공간 복잡도**: O(M)
- arr 배열: O(10,004)

## 🔑 핵심 포인트

### 1️⃣ 왜 이분 탐색을 사용하는가?

**문제점**:
```
N이 최대 20억이므로, 시뮬레이션으로 1분씩 진행하면 시간 초과!(무식하게 풀기 불가능)
```

**해결책**:
```
시간을 이분 탐색하여 "N번째 아이가 탑승하는 시간"을 빠르게 찾기!

시간 범위: 0분 ~ 600억 분
→ log₂(600억) ≈ 36번의 탐색으로 정답 시간 찾기 가능
```

### 2️⃣ MAX_TIME이 600억인 이유

**최악의 경우**:
```
N = 2,000,000,000 (20억 명)
M = 1 (놀이기구 1개)
운행 시간 = 30분 (최대값)

계산:
- 0분: 1명 탑승
- 30분: 1명 탑승
- 60분: 1명 탑승
- ...
- t분까지 탑승 = 1 + (t / 30)

20억 번째 아이 탑승 시간:
t = (2,000,000,000 - 1) × 30 = 59,999,999,970분 ≈ 600억 분
```

### 3️⃣ Check 함수의 역할

```cpp
bool Check(ll mid)
{
    childCnt = m;  // 0분에 m명 탑승

    for(ll i = 0; i < m; i++)
    {
        childCnt += mid / arr[i];  // i번 놀이기구에서 탑승한 아이 수
    }

    return childCnt >= n;  // mid 시간까지 n명 이상 탑승 가능한지
}
```

**핵심**:
- mid 시간까지 총 몇 명이 탑승했는지 계산
- `mid / arr[i]` : i번 놀이기구가 mid 시간까지 몇 번 비었는지
  - 예: mid=10, arr[i]=3 → 10/3 = 3번 (3분, 6분, 9분)
- `childCnt >= n` : n명 이상 탑승 가능하면 true

**이분 탐색 방향**:
- true (n명 이상 탑승 가능) → ansRet 갱신, hi = mid - 1 (더 작은 시간 탐색)
- false (n명 미만) → lo = mid + 1 (더 큰 시간 탐색)

### 4️⃣ 왜 ansRet - 1까지 먼저 계산하는가?

**이유**:
```
ansRet 시간에 여러 놀이기구가 동시에 비는 경우,
작은 번호부터 순서대로 태워야 함!

따라서 ansRet-1까지의 누적 인원을 먼저 구하고,
ansRet 시간에 0번부터 순서대로 확인하면서 n번째를 찾음
```

**예시**:
```
ansRet = 12분, n = 10명, m = 3, arr = [3, 4, 6]

[Step 1] ansRet-1 = 11분까지 탑승 인원:
- 0분: 3명 (초기)
- 0번 놀이기구(3분): 11/3 = 3회 → 3명
- 1번 놀이기구(4분): 11/4 = 2회 → 2명
- 2번 놀이기구(6분): 11/6 = 1회 → 1명
- childCnt = 3 + 3 + 2 + 1 = 9명

[Step 2] ansRet = 12분에 확인:
- i=0: 12 % 3 == 0 ✅ → childCnt=10 → childCnt==n ✅
  → 0번 놀이기구 (1-indexed로 1번) 출력!
```

### 5️⃣ if + if 구조의 중요성

```cpp
if(ansRet % arr[i] == 0)
{
    childCnt++;  // 탑승
}

// 독립적으로 체크!
if(childCnt == n)
{
    cout << i + 1 << "\n";
    return 0;
}
```

**⚠️ 주의**:
- `if + else if`를 사용하면 안 됨!
- 두 조건을 **독립적으로** 체크해야 함
- 탑승하자마자 n번째가 되는 경우를 놓치지 않기 위함

```
n = 3 (3명의 아이)
m = 5 (5개의 놀이기구)
arr = [7, 8, 9, 7, 8]
```

### 📌 Step 1: 기저 케이스 확인
```
n <= m ?

→ 출력: 3
```

**🎯 정답**: `3`

**💬 설명**:
```
0분: [1번, 2번, 3번, 4번, 5번] 놀이기구에 각각 1명씩 탑승
→ 1번 아이 → 1번 놀이기구 (0번 인덱스)
→ 2번 아이 → 2번 놀이기구 (1번 인덱스)
→ 3번 아이 → 3번 놀이기구 (2번 인덱스) ✅

아이가 놀이기구 개수 이하이므로,
처음에 모두 각자 놀이기구에 탑승 가능!
```

## 📊 예제 2 상세 실행 흐름

**입력**:
```
7 2
3 2
```

### 📌 초기 상태
```
n = 7 (7명의 아이)
m = 2 (2개의 놀이기구)
arr = [3, 2]
lo = 0, hi = 60000000004
```

### 📌 Step 1: 기저 케이스 확인
```
n <= m ?
7 <= 2 ❌

→ 이분 탐색 진행
```

### 📌 Step 2: 이분 탐색으로 ansRet 찾기

#### 🔸 Round 1
```
lo = 0, hi = 60000000004
mid = 30000000002

Check(30000000002):
  childCnt = 2
  childCnt += 30000000002 / 3 = 10000000000
  childCnt += 30000000002 / 2 = 15000000001
  childCnt = 2 + 10000000000 + 15000000001 = 25000000003

  25000000003 >= 7 ? ✅ true

→ ansRet = 30000000002
→ hi = 30000000001
```

#### 🔸 Round 2 ~ 최종
```
이분 탐색 계속 진행...

최종적으로 ansRet = 6분을 찾음
```

### 📌 Step 3: ansRet = 6분 확인

**Check(6) 검증**:
```
childCnt = 2 (0분에 2명)
childCnt += 6 / 3 = 2 (0번 놀이기구: 3분, 6분에 2명 탑승)
childCnt += 6 / 2 = 3 (1번 놀이기구: 2분, 4분, 6분에 3명 탑승)
childCnt = 2 + 2 + 3 = 7 ✅

7 >= 7 ✅ → ansRet = 6
```

**Check(5) 검증**:
```
childCnt = 2 (0분에 2명)
childCnt += 5 / 3 = 1 (0번 놀이기구: 3분에 1명)
childCnt += 5 / 2 = 2 (1번 놀이기구: 2분, 4분에 2명)
childCnt = 2 + 1 + 2 = 5

5 >= 7 ❌ → 5분으로는 부족!
```

**→ ansRet = 6분이 정답 시간!**

### 📌 Step 4: ansRet - 1 = 5분까지 탑승 인원 계산

```
childCnt = 2  // 0분에 2명 탑승

i=0: childCnt += (6 - 1) / 3 = 5 / 3 = 1
     childCnt = 2 + 1 = 3

i=1: childCnt += (6 - 1) / 2 = 5 / 2 = 2
     childCnt = 3 + 2 = 5

→ 5분까지 5명 탑승
```

### 📌 Step 5: ansRet = 6분에 탑승하는 아이들 확인

```
6분에 비어있는 놀이기구:
- 0번: 6 % 3 == 0 ✅
- 1번: 6 % 2 == 0 ✅

작은 번호부터 순서대로 확인:

▶ i=0 (0번 놀이기구):
  if(6 % 3 == 0) → true ✅
    childCnt++ → childCnt = 6

  if(childCnt == 7) → false ❌
    계속 진행

▶ i=1 (1번 놀이기구):
  if(6 % 2 == 0) → true ✅
    childCnt++ → childCnt = 7

  if(childCnt == 7) → true ✅
    cout << 1 + 1 << "\n"
    출력: 2
    return 0
```

**🎯 정답**: `2`

**💬 시뮬레이션 전체 흐름**:
```
시간 | 0번(3분) | 1번(2분) | 탑승 순서
-----|----------|----------|----------
0분  | 1번 아이 | 2번 아이 | 1번, 2번
2분  |    -     | 3번 아이 | 3번
3분  | 4번 아이 |    -     | 4번
4분  |    -     | 5번 아이 | 5번
6분  | 6번 아이 | 7번 아이 | 6번, 7번 ✅
     | (먼저)   | (나중)   |

→ 6분에 두 놀이기구가 동시에 비지만,
  작은 번호인 0번이 먼저 탑승 (6번 아이)
  그 다음 1번 놀이기구에 7번 아이 탑승! ✅
```

## ⏱️ 시간복잡도

**O(log(MAX_TIME) × M + M)**

**분석**:
1. **이분 탐색**: O(log(600억)) ≈ O(36)
   - Check 함수: O(M) (최대 10,000)
   - 총: O(36 × 10,000) = O(360,000)

2. **최종 탐색**: O(M) (최대 10,000)
   - ansRet - 1까지 계산: O(M)
   - ansRet 시간 확인: O(M)
   - 총: O(M + M) = O(2M) = O(M)

3. **전체**: O(360,000 + 10,000) = **O(370,000)** → 충분히 통과

**O(M)**

- `arr[10004]`: O(10,004) ≈ O(M)
- 나머지 변수들: O(1)

## 🚨 주의사항

1. **long long 사용 필수**: N이 최대 20억이므로 int 범위 초과
2. **MAX_TIME 계산**: N × 운행시간(30) ≈ 600억
3. **if + if 구조**: `else if`를 사용하면 탑승 직후 n번째가 되는 경우 놓침
4. **0-indexed → 1-indexed**: 답 출력 시 `i + 1`
5. **기저 케이스**: n <= m이면 바로 n 출력
6. **동시 탑승**: ansRet 시간에 여러 놀이기구가 비면 작은 번호부터 탑승

## 💡 핵심 정리

```
이 문제의 핵심 아이디어:

1️⃣ 이분 탐색 활용
   - 시간을 직접 시뮬레이션하면 시간 초과
   - 이분 탐색으로 O(log N)에 정답 시간 찾기

2️⃣ 특정 시간까지 탑승 인원 계산
   - mid / arr[i] : i번 놀이기구가 mid 시간까지 몇 번 비었는지
   - 모든 놀이기구의 합으로 총 탑승 인원 계산

3️⃣ 정확한 놀이기구 찾기
```
