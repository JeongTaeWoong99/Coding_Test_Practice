## 🔗 문제 링크

[백준 1700번 - 멀티탭 스케줄링](https://www.acmicpc.net/problem/1700)

**난이도**: Gold 1

---

## 🤔 접근법

기숙사에서 한 개의 멀티탭을 이용하는 준규는 전기용품의 사용 순서를 알고 있다.

이 정보를 바탕으로 **플러그를 뺀 횟수를 최소화**하는 것이 목표이다.

핵심은 **멀티탭이 가득 찼을 때, 앞으로 가장 나중에 사용될 전기용품(또는 사용되지 않을 전기용품)을 제거**하는 것!

이는 **그리디 알고리즘**의 고전적인 문제로, **최적 오프라인 캐싱(Optimal Offline Caching)** 알고리즘이라고도 불린다.

---

## 💡 정답 풀이 방법

**알고리즘**: 그리디 알고리즘 (Greedy Algorithm)

**핵심 아이디어**:
```
1. 전기용품을 사용 순서대로 처리
2. 이미 멀티탭에 꽂혀있으면 패스
3. 멀티탭이 가득 찼을 때:
   - 현재 꽂혀있는 각 전기용품이 앞으로 언제 다시 사용되는지 확인
   - 가장 나중에 사용될 것(또는 사용 안 될 것) 제거
4. 새 전기용품 꽂기
```

**왜 이 방법이 최적인가?**
- 가장 나중에 사용될 전기용품을 제거하면, 다음에 다시 뽑을 필요가 없거나 최대한 늦춰진다
- 이른 시점에 사용될 전기용품을 제거하면, 곧바로 다시 꽂아야 하므로 비효율적
- 따라서 **"미래를 알고 있을 때"의 최적 전략**

**시간 복잡도**: O(K × N²)
- K: 전기용품 사용 횟수 (최대 100)
- 각 전기용품마다:
  - 멀티탭 확인: O(N) (최대 100개)
  - 미래 사용 확인: O(K) (최대 100회)
- 총: O(K × N²) = 100 × 100² = 1,000,000 (충분히 통과)

**공간 복잡도**: O(N + K)
- arr 배열: O(K)
- visited 배열: O(104) = O(1)
- currentTap 벡터: O(N)

## 🔑 핵심 포인트

### 1️⃣ 그리디 선택 기준

```cpp
// 현재 꽂혀있는 각 전기용품에 대해
for(int tap : currentTap)
{
    int here_pick = INF;  // 이 전기용품이 다시 사용되는 인덱스 (없으면 INF)

    // 앞으로 이 전기용품이 언제 다시 사용되는지 찾기
    for(int j = i + 1; j < n; j++)
    {
        if(tap == arr[j])
        {
            here_pick = j;  // 다시 사용되는 인덱스 저장
            break;
        }
    }

    // 가장 나중에 사용되는 전기용품을 찾음
    if(last_idx < here_pick)
    {
        last_idx = here_pick;
        pos      = tap;
    }
}
```

**핵심**:
- `here_pick = INF`: 앞으로 사용 안 되면 INF로 설정
- `last_idx < here_pick`: 더 나중에 사용되는 것 찾기
- 사용 안 되는 전기용품(INF)이 있으면 그것을 우선 제거
- 모두 사용될 예정이면 가장 나중에 사용될 것 제거

### 2️⃣ visited 배열 역할

```cpp
int visited[104];  // 현재 멀티탭에 꽂혀있는지 여부 (1: 꽂힌 상태)

// 이미 멀티탭에 꽂혀있으면 패스
if(!visited[arr[i]])
{
    // 전기용품 처리 로직
}
```

**핵심**:
- 같은 전기용품을 중복해서 꽂는 것을 방지
- O(1)에 빠르게 확인 가능
- 전기용품 번호가 최대 104 이하이므로 배열 크기 104로 충분

### 3️⃣ vector::erase 사용

```cpp
currentTap.erase(find(currentTap.begin(), currentTap.end(), pos));
```

**핵심**:
- `find`: currentTap에서 pos 값을 가진 요소 찾기 → O(N)
- `erase`: 해당 요소 제거 → O(N)
- 총 O(N)이지만 N이 최대 100이므로 충분히 빠름

**대안 (최적화)**:
```cpp
// iterator를 직접 저장하면 O(1)에 제거 가능
// 하지만 N이 작아서 불필요
```

### 4️⃣ 왜 INF를 사용하는가?

```cpp
const int INF = 987654321;
int here_pick = INF;  // 앞으로 사용 안 되면 INF
```

**이유**:
- 앞으로 사용되지 않는 전기용품을 표현하기 위함
- `last_idx < here_pick` 비교에서 INF가 가장 큰 값이므로 우선 선택됨
- 실제 인덱스는 최대 K(100)이므로 INF(987654321)와 구분 가능

**예시**:
```
현재 멀티탭: [1, 2, 3]
앞으로 사용 인덱스:
  - 1번: 10 (10번째에 다시 사용)
  - 2번: 5  (5번째에 다시 사용)
  - 3번: INF (앞으로 사용 안 됨)

→ last_idx = max(10, 5, INF) = INF
→ 3번 제거 (가장 나중 = 사용 안 됨)
```


### 📍 i=4, arr[4]=1 처리 ⭐ (멀티탭 가득 참)

```
visited[1] = 0 (안 꽂혀있음)
currentTap.size() = 2 == k (가득 참!)

→ 제거할 전기용품 찾기:

현재 꽂혀있는 전기용품: [2, 3]

▶ tap=2 확인:
  - i+1=5부터 n=7까지 확인
  - arr[5]=2 발견!
  - here_pick = 5
  - last_idx = max(0, 5) = 5
  - pos = 2

▶ tap=3 확인:
  - i+1=5부터 n=7까지 확인
  - 3이 없음!
  - here_pick = INF
  - last_idx = max(5, INF) = INF

visited[3] = 0
cnt = 1
currentTap = [2]

→ 1번 전기용품 꽂기
currentTap = [2, 1]
visited[1] = 1
```

**💬 설명**:
- 2번은 5번째에 다시 사용됨
- 3번은 앞으로 사용 안 됨 (INF)
- **앞으로 사용되지 않는 3번을 제거!**

<br>

### 📍 i=5, arr[5]=2 처리

```
visited[2] = 1 (이미 꽂혀있음)

→ 패스

cnt = 1
```

<br>

### 📍 i=6, arr[6]=7 처리 ⭐ (멀티탭 가득 참)

```
visited[7] = 0 (안 꽂혀있음)
currentTap.size() = 2 == k (가득 참!)

→ 제거할 전기용품 찾기:

현재 꽂혀있는 전기용품: [2, 1]

▶ tap=2 확인:
  - i+1=7부터 n=7까지 확인
  - 2가 없음! (범위 종료)
  - here_pick = INF

→ 1번 제거
```

**💬 설명**:
- 2번과 1번 모두 앞으로 사용 안 됨 (INF)
- 둘 다 INF이면 마지막으로 확인한 1번 제거

## ⏱️ 시간복잡도

**O(K × N²)**

**분석**:
1. **외부 루프**: 전기용품 사용 순서 순회 → O(K)
2. **멀티탭 가득 찼을 때**:
   - currentTap 순회: O(N) (최대 N개)
   - 각 전기용품마다 미래 사용 확인: O(K)
   - 총: O(N × K)
3. **전체**: O(K × N × K) = O(K² × N)

**하지만 실제로는 더 빠름**:
- N ≤ 100, K ≤ 100
- 멀티탭이 가득 찼을 때만 탐색 발생
- 최악의 경우: 100 × 100 × 100 = 1,000,000 (충분히 통과)

---

## 💾 공간복잡도

**O(N + K)**

**분석**:
- `arr[104]`: O(K) ≈ O(100)
- `visited[104]`: O(1)
- `currentTap`: O(N) (최대 N개)
- **총합**: O(N + K)

---

## 🚨 주의사항

1. **INF 값**: 앞으로 사용되지 않는 전기용품을 표현하기 위해 충분히 큰 값 사용
2. **visited 배열 관리**: 전기용품을 빼거나 꽂을 때 visited 상태 업데이트 필수
3. **vector::erase**: find()와 erase() 조합으로 특정 값 제거
4. **그리디 정당성**: 미래를 알고 있을 때 가장 나중에 사용될 것을 제거하는 것이 최적
5. **중복 사용**: 같은 전기용품을 여러 번 사용할 수 있으므로 visited로 체크

```
   - 캐시(멀티탭)가 가득 찼을 때 교체 전략
   - LRU(Least Recently Used)가 아닌 "가장 나중에 사용될 것" 제거

→ 그리디 알고리즘의 고전적인 문제! 🎯
```
