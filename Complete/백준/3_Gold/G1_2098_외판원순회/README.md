[백준 2098번 - 외판원 순회](https://www.acmicpc.net/problem/2098)

**난이도**: Gold 1

## 🤔 접근법

(너무 어렵다... 이해하기도 힘들군...)

외판원 순회 문제(Traveling Salesman Problem, TSP)는 컴퓨터 과학에서 가장 유명한 NP-hard 문제입니다.

**문제 요약**:
- N개의 도시가 있고, 각 도시 간 이동 비용이 주어짐
- 한 도시에서 출발하여 모든 도시를 정확히 한 번씩 방문하고 출발 도시로 돌아오는 최소 비용 구하기
- 갈 수 없는 경로도 존재 (비용 = 0)

**핵심**:
- DP로 중복 계산 방지 (메모이제이션)
- N ≤ 16으로 범위가 작음 → **비트마스킹 DP** 사용 가능
- 방문 상태를 비트로 표현 → 2^16 = 65,536가지 상태

---

## 💡 정답 풀이 방법

**알고리즘**: 비트마스킹 DP (Bitmask Dynamic Programming)

**핵심 아이디어**:
```
1. 방문 상태를 비트마스크로 표현
   - 예: 0b1011 → 0, 1, 3번 도시 방문

2. DP 정의
   - dp[here][visited] = 현재 here번 도시에 있고,
                         visited 상태로 방문했을 때
                         나머지 도시를 모두 방문하고 돌아오는 최소 비용

3. 재귀로 모든 경우 탐색
   - 아직 방문하지 않은 도시들을 하나씩 방문
   - 메모이제이션으로 이미 계산한 상태는 재계산 안 함

4. 모든 도시 방문 완료 시
   - 시작 도시(0번)로 돌아가는 비용 반환
```

**시간 복잡도**: O(n² × 2^n)
- 상태의 개수 : n × 2^n (현재 도시 × 방문 상태)
- 각 상태마다 n개 도시 확인
- n=16일 때 : 16 × 2^16 × 16 = 16,777,216 (약 1,600만)

**공간 복잡도**: O(n × 2^n)
- dp 배열 : n × 2^n
- n=16일 때: 16 × 65,536 = 1,048,576 (약 100만)

## 🔑 핵심 포인트

### 1️⃣ 비트마스킹으로 방문 상태 표현

```cpp
int dp[MAX_N][1 << MAX_N];  // dp[도시][방문상태]
```

**비트마스킹이란?**
- 각 비트가 해당 도시의 방문 여부를 나타냄
- 0: 방문 안 함, 1: 방문함

**예시** (n=4일 때):
```
0b0001 (1)  → 0번 도시만 방문
0b0011 (3)  → 0, 1번 도시 방문
0b1111 (15) → 0, 1, 2, 3번 모든 도시 방문
```

**왜 비트마스킹을 사용하는가?**
```
✅ 메모리 효율적 : int 하나로 최대 32개 상태 표현
✅ 연산 속도 빠름 : 비트 연산은 O(1)
✅ 상태 표현 간결 : 2D 배열 대신 비트 사용
```

---

### 2️⃣ 비트마스킹 핵심 코드 설명

#### 📌 (1) 모든 도시를 방문했는지 확인

```cpp
if(visited == (1 << n) - 1)
```

**동작 원리**:
```
n = 4일 때:

(1 << n) 계산:
  1 << 4 = 1을 왼쪽으로 4칸 이동

  0b00001 (1)
  ← ← ← ←  (4칸 이동)
  0b10000 (16)

(1 << n) - 1 = 16 - 1 = 15:
  0b10000 - 1 = 0b01111

  결과: 0b1111 (모든 비트가 1)
  의미: 0, 1, 2, 3번 도시 모두 방문!
```

**시각화**:
```
비트 위치:  3  2  1  0
           ─  ─  ─  ─
0b1111 =  [1][1][1][1]  → 4개 도시 모두 방문
           │  │  │  └─ 도시 0
           │  │  └──── 도시 1
           │  └─────── 도시 2
           └────────── 도시 3

visited == (1 << 4) - 1
visited == 15
→ 모든 도시 방문 완료!
```

---

#### 📌 (2) 특정 도시를 이미 방문했는지 확인

```cpp
if(visited & (1 << i)) continue;  // i번 도시 방문 여부
```

**동작 원리 (AND 연산)**:
```
예: visited = 0b1011, i = 1 확인

(1 << 1) = 0b0010  (1을 1칸 이동)

visited & (1 << i):
  0b1011  (visited)
& 0b0010  (1 << 1)
─────────
  0b0010  (결과: 0이 아님 → True)

→ 1번 도시 방문함!
```

**다양한 예시**:
```
visited = 0b1011 (0, 1, 3번 방문)

i=0: 0b1011 & 0b0001 = 0b0001 (True)  ✅ 방문함
i=1: 0b1011 & 0b0010 = 0b0010 (True)  ✅ 방문함
i=2: 0b1011 & 0b0100 = 0b0000 (False) ❌ 방문 안 함
i=3: 0b1011 & 0b1000 = 0b1000 (True)  ✅ 방문함
```

---

#### 📌 (3) 특정 도시를 방문 상태로 추가

```cpp
TSP(i, visited | (1 << i))  // i번 도시 방문 추가
```

**동작 원리 (OR 연산)**:
```
예: visited = 0b1011, i = 2 추가

(1 << 2) = 0b0100  (1을 2칸 이동)

visited | (1 << i):
  0b1011  (visited)
| 0b0100  (1 << 2)
─────────
  0b1111  (결과: 2번 비트가 1로 변경)

→ 2번 도시 추가! (0, 1, 2, 3번 모두 방문)
```

**순차적 방문 예시**:
```
초기: 0b0001 (0번만)
  ↓
0번에서 1번 방문:
  0b0001 | 0b0010 = 0b0011 (0, 1번)
  ↓
1번에서 2번 방문:
  0b0011 | 0b0100 = 0b0111 (0, 1, 2번)
  ↓
2번에서 3번 방문:
  0b0111 | 0b1000 = 0b1111 (0, 1, 2, 3번 모두!)
```

---

### 3️⃣ return dist[here][0] ? dist[here][0] : INF 설명

```cpp
// 모든 도시를 방문한 후
return dist[here][0] ? dist[here][0] : INF;
```

**이 코드의 의미**:
```
dist[here][0] ? dist[here][0] : INF

삼항 연산자:
  조건 ? 참일_때_값 : 거짓일_때_값

의미:
  dist[here][0]이 0이 아니면 → dist[here][0] 반환
  dist[here][0]이 0이면     → INF 반환
```

**왜 이렇게 하는가?**

문제 조건에서 `dist[here][0] == 0`은 **갈 수 없는 경로**를 의미합니다!

**예시**:
```
현재 위치: 3번 도시
모든 도시 방문 완료: [0, 1, 2, 3]

Case 1: dist[3][0] = 10
  → 3번에서 0번으로 갈 수 있음 (비용 10)
  → return 10

Case 2: dist[3][0] = 0
  → 3번에서 0번으로 갈 수 없음!
  → return INF (불가능한 경로)
```

**INF로 제외시키는 원리**:
```cpp
ret = min(ret, TSP(i, visited | (1 << i)) + dist[here][i]);

// 만약 TSP()가 INF를 반환하면?
ret = min(ret, INF + dist[here][i]);
ret = min(ret, INF + 10);
ret = min(ret, 매우 큰 값);

// 다른 경로가 있다면 그 경로가 선택됨
ret = min(100, INF) = 100 ✅

// 모든 경로가 INF라면?
ret = min(INF, INF, INF) = INF
→ 결국 불가능한 경로로 판정!
```

**강사님 설명: "INF로 못가면 제외시켜버린다"**

맞습니다! ✅
- `dist[here][0] == 0` → 못 가는 경로 → `INF` 반환
- `min()` 연산에서 INF는 자동으로 제외됨
- 다른 가능한 경로 중 최소값이 선택됨

**구체적 예시**:
```
3가지 경로:
1. 0→1→2→3→0 : 비용 35
2. 0→2→1→3→X : INF (3→0 불가능)
3. 0→3→1→2→0 : 비용 40

min(35, INF, 40) = 35 ✅
→ INF인 경로 2는 자동 제외!
```

### 4️⃣ 메모이제이션 (DP)

```cpp
int &ret = dp[here][visited];
if(ret != -1) return ret;  // 이미 계산했으면 재사용
```

**참조(&)를 사용하는 이유**:
```cpp
int &ret = dp[here][visited];  // 참조로 가져오기

ret = INF;  // dp[here][visited]를 직접 수정
ret = min(...);  // dp[here][visited] 업데이트

return ret;  // dp[here][visited] 반환
```

**장점**:
- `dp[here][visited]`를 직접 수정 가능
- 코드가 간결해짐
- 복사 오버헤드 없음

**메모이제이션 효과**:
```
Without DP (중복 계산):
  TSP(1, 0b0011) 계산
  TSP(1, 0b0011) 또 계산
  TSP(1, 0b0011) 또 또 계산
  → 시간 초과!

With DP (메모이제이션):
  TSP(1, 0b0011) 첫 계산 → 결과 저장
  TSP(1, 0b0011) 재사용 → O(1)
  TSP(1, 0b0011) 재사용 → O(1)
  → 빠름!
```

#### 📍 Level 1: TSP(0, 0b0001)

```
visited = 0b0001 (1) ≠ 0b1111 (15)
→ 아직 모든 도시 방문 안 함

ret = dp[0][1] = -1 (아직 계산 안 함)

다음 방문 가능한 도시:
  i=0: 0b0001 & 0b0001 = 1 (이미 방문) → skip
  i=1: 0b0001 & 0b0010 = 0 (방문 안 함) ✅
  i=2: 0b0001 & 0b0100 = 0 (방문 안 함) ✅
  i=3: 0b0001 & 0b1000 = 0 (방문 안 함) ✅

→ 1, 2, 3번 중 선택
```

**분기 1: 1번 도시로 이동**
```
dist[0][1] = 10 ✅ (갈 수 있음)

TSP(1, 0b0001 | 0b0010) 호출
  = TSP(1, 0b0011)
  = TSP(1, 3)
```

**분기 2: 2번 도시로 이동**
```
dist[0][2] = 15 ✅ (갈 수 있음)

TSP(2, 0b0001 | 0b0100) 호출
  = TSP(2, 0b0101)
  = TSP(2, 5)
```

**분기 3: 3번 도시로 이동**
```
dist[0][3] = 20 ✅ (갈 수 있음)

TSP(3, 0b0001 | 0b1000) 호출
  = TSP(3, 0b1001)
  = TSP(3, 9)
```

현재 위치: 1번 도시

남은 도시: 2, 3번

visited = 0b0011 (3) ≠ 0b1111 (15)

현재 위치: 2번 도시
방문 상태: 0b0111 (0, 1, 2번 방문)

visited = 0b0111 (7) ≠ 0b1111 (15)

다음 방문 가능한 도시:

#### 🔙 거슬러 올라가기 (Backtracking)

**Level 3로 복귀: TSP(2, 0b0111)**
```
ret = min(ret, TSP(3, 0b1111) + dist[2][3])
ret = min(INF, 8 + 12)
ret = min(INF, 20)
ret = 20

dp[2][7] = 20 저장
return 20
```

**Level 2로 복귀: TSP(1, 0b0011) - 분기 1-1**
```
ret = min(ret, TSP(2, 0b0111) + dist[1][2])
ret = min(INF, 20 + 9)
ret = min(INF, 29)
ret = 29
```

**TSP(1, 0b0011) - 분기 1-2 계산**
```
TSP(3, 0b1011) 계산...
→ TSP(2, 0b1111) → dist[2][0] = 6
→ 6 + 12 = 18 (3→2→0)
→ 18 + 10 = 28 (1→3→2→0)

ret = min(29, 28)
ret = 28

dp[1][3] = 28 저장
return 28
```

**Level 1로 복귀: TSP(0, 0b0001) - 분기 1**
```
ret = min(ret, TSP(1, 0b0011) + dist[0][1])
ret = min(INF, 28 + 10)
ret = min(INF, 38)
ret = 38
```

## 🆚 다른 방법으로 시도했을 때 실패 이유

### 비교표: 비트마스킹 DP vs 다른 방법

| 방법 | 시간복잡도 | 공간복잡도 | 결과 | 실패 이유 |
|------|-----------|----------|------|----------|
| **비트마스킹 DP** | **O(n² × 2^n)** | **O(n × 2^n)** | **✅ 통과** | - |
| DFS 백트래킹 | O(n!) | O(n) | ❌ 시간 초과 | n=16일 때 16! ≈ 200억 |
| set + map DP | O(n² × 2^n) | O(n × 2^n) | ❌ 시간 초과 | set/map이 느림 (log) |
| BFS | O(n! × n) | O(n!) | ❌ 메모리 초과 | 큐에 모든 경로 저장 |

---

### 1️⃣ DFS 백트래킹 (메모이제이션 없음)

**코드**:
```cpp
void TSP(int here, int depth, int cost, bool visited[])
{
    if(depth == n)
    {
        ans = min(ans, cost + dist[here][0]);
        return;
    }

    for(int i = 0; i < n; i++)
    {
        if(visited[i]) continue;
        visited[i] = true;
        TSP(i, depth + 1, cost + dist[here][i], visited);
        visited[i] = false;  // 백트래킹
    }
}
```

**왜 실패하는가?**

```
시간복잡도: O(n!)

n=16일 때:
  16! = 20,922,789,888,000 (약 20조!)

예상 시간:
  20조 연산 ÷ 1억 연산/초 = 209,227초
  = 약 58시간! ❌
```

**문제점**:
- 같은 상태를 수백만 번 재계산
- 메모이제이션이 없어서 중복 계산 폭발

**예시**:
```
경로 1: 0 → 1 → 2 → 3 (현재 3번, {0,1,2,3} 방문)
경로 2: 0 → 2 → 1 → 3 (현재 3번, {0,1,2,3} 방문)

→ 두 경로 모두 동일한 상태!
→ 하지만 백트래킹은 각각 계산!
→ 엄청난 중복!
```

---

### 2️⃣ set + map DP

**코드**:
```cpp
map<pair<int, set<int>>, int> dp;

int TSP(int here, set<int> visited)
{
    if(visited.size() == n)
        return dist[here][0] ? dist[here][0] : INF;

    pair<int, set<int>> state = {here, visited};
    if(dp.find(state) != dp.end())
        return dp[state];

    int ret = INF;
    for(int i = 0; i < n; i++)
    {
        if(visited.count(i)) continue;

        set<int> next = visited;
        next.insert(i);

        ret = min(ret, TSP(i, next) + dist[here][i]);
    }

    return dp[state] = ret;
}
```

**왜 실패하는가?**

```
이론적 시간복잡도: O(n² × 2^n) (비트마스킹과 동일)

하지만 실제 시간:
  1. set 복사: O(n) 매번!
  2. map 탐색: O(log(n × 2^n))
  3. set 비교: O(n)

실제 시간복잡도: O(n³ × 2^n × log(n × 2^n))

n=16일 때:
  16³ × 2^16 × log(16 × 65536)
  = 4096 × 65536 × 20
  = 약 53억 연산 → 시간 초과!
```

**비트마스킹과 비교**:
```
비트마스킹 DP:
  - 배열 접근: O(1)
  - 상태 복사: 없음 (int 하나)
  - 비트 연산: O(1)

set + map DP:
  - map 탐색: O(log n)
  - set 복사: O(n)
  - set 비교: O(n)

→ 비트마스킹이 수백 배 빠름!
```

### 3️⃣ BFS

**코드**:
```cpp
struct State {
    int here;
    set<int> visited;
    int cost;
};

queue<State> q;
q.push({0, {0}, 0});

while(!q.empty())
{
    State cur = q.front();
    q.pop();

    if(cur.visited.size() == n)
    {
        ans = min(ans, cur.cost + dist[cur.here][0]);
        continue;
    }

    for(int i = 0; i < n; i++)
    {
        if(cur.visited.count(i)) continue;

        set<int> next = cur.visited;
        next.insert(i);

        q.push({i, next, cur.cost + dist[cur.here][i]});
    }
}
```

**왜 실패하는가?**

```
메모리 복잡도: O(n! × n)

큐에 저장되는 상태 개수:
  - 경로 길이 1: n개
  - 경로 길이 2: n × (n-1)개
  - 경로 길이 3: n × (n-1) × (n-2)개
  - ...
  - 경로 길이 n: n!개

n=16일 때:
  16! = 20조 개 상태
  각 상태마다 set<int> 저장 (최소 64바이트)

  20조 × 64바이트 = 1,280조 바이트
  = 1.28 페타바이트! ❌
```

**문제점**:
- 모든 경로를 큐에 저장
- 메모이제이션 없음
- 같은 상태를 중복 저장

---

### ✅ 왜 비트마스킹 DP만 통과하는가?

**핵심 이유**:

1. **메모이제이션 필수**
   - 같은 상태를 재계산하지 않음
   - n! → n² × 2^n으로 감소

2. **비트마스킹의 효율성**
   - 배열 접근: O(1)
   - 비트 연산: O(1)
   - 메모리: int 하나 (4바이트)

3. **n ≤ 16의 범위**
   - 2^16 = 65,536 (적당)
   - 16! = 20조 (불가능)

**시간 비교 (n=16)**:
```
비트마스킹 DP: 16² × 2^16 = 16,777,216 (약 0.16초) ✅
DFS 백트래킹: 16! ≈ 20조 (약 58시간) ❌
set + map DP:  16³ × 2^16 × 20 ≈ 53억 (약 53초) ❌
BFS:           16! × 메모리 초과 ❌
```

## ⏱️ 시간복잡도 상세 분석

**O(n² × 2^n)**

### 📌 계산 과정

```
1️⃣ 상태의 개수: n × 2^n
   - 현재 도시: n가지 (0 ~ n-1)
   - 방문 상태: 2^n가지 (각 도시 방문/미방문)

2️⃣ 각 상태마다 계산: O(n)
   - 다음 방문할 도시 선택: n번 반복
   - 비트 연산: O(1)

3️⃣ 전체 시간복잡도
   - (n × 2^n) × n = n² × 2^n
```

### 📌 n=16일 때 실제 계산

```
16² × 2^16
= 256 × 65,536
= 16,777,216
≈ 1,600만 연산

CPU 성능 (약 1억 연산/초):
  16,777,216 ÷ 100,000,000 ≈ 0.16초 ✅
```

### 📌 왜 빠른가?

```
✅ 비트 연산 속도
   - CPU 레벨 연산 (1 사이클)
   - 배열 접근 O(1)

✅ 메모이제이션
   - 각 상태를 딱 1번만 계산
   - dp 배열로 O(1) 접근

✅ 캐시 효율
   - 배열은 메모리 연속 배치
   - CPU 캐시 히트율 높음
```

## 💾 공간복잡도

**O(n × 2^n)**

```
dp[MAX_N][1 << MAX_N]
= dp[16][65536]
= 1,048,576개 int
= 1,048,576 × 4바이트
= 4,194,304바이트
≈ 4MB ✅
```

**추가 메모리**:
```
dist[16][16] = 256 int = 1KB
재귀 스택: 최대 n = 16 depth = 매우 적음

총합: 약 4MB (충분히 작음)
```

## 🚨 주의사항

1. **DP 초기화 필수**
   ```cpp
   memset(dp, -1, sizeof(dp));
   ```
   - -1: 아직 계산 안 함
   - 0으로 초기화하면 0과 미계산 구분 불가

2. **비트마스킹 범위**
   ```cpp
   1 << n  // n이 너무 크면 오버플로우!
   ```
   - n ≤ 30 정도까지만 안전
   - int는 32비트

3. **INF 값 설정**
   ```cpp
   const int INF = 987654321;
   ```
   - 충분히 큰 값 (10억 정도)
   - INT_MAX 사용 시 덧셈 오버플로우 주의

4. **dist[i][j] == 0의 의미**
   - 갈 수 없는 경로
   - 비용 0이 아님!

5. **시작 도시**
   ```cpp
   TSP(0, 1)  // 0번 도시, 0b0001 상태
   ```
   - 0번 도시에서 시작
   - 어느 도시에서 시작해도 결과는 동일 (순환)

## 💡 핵심 정리

### 🎯 알고리즘 핵심

```
1️⃣ 비트마스킹으로 상태 표현
   - int 하나로 모든 방문 상태 표현
   - 빠르고 메모리 효율적

2️⃣ DP로 중복 계산 제거
   - 같은 상태는 한 번만 계산
   - O(n!) → O(n² × 2^n) 감소

3️⃣ 재귀로 완전 탐색
   - 모든 가능한 경로 탐색
   - 메모이제이션으로 최적화
```

### 🔑 비트마스킹 3대 연산

```cpp
// 1. 모든 방문 확인
if(visited == (1 << n) - 1)

// 2. i번 방문 확인
if(visited & (1 << i))

// 3. i번 방문 추가
visited | (1 << i)
```

### ⚠️ 핵심 실수 방지

```
✅ dp 초기화: memset(dp, -1, sizeof(dp))
✅ INF 처리: dist == 0이면 INF 반환
✅ 참조 사용: int &ret = dp[here][visited]
✅ 비트 연산: << (shift), & (and), | (or)
```

## 🎓 배운 점

1. **비트마스킹의 강력함**
   - 상태를 정수 하나로 압축
   - O(1) 연산으로 모든 처리
   - 배열 인덱스로 직접 사용 가능

2. **DP의 필수성**
   - 메모이제이션 없이는 불가능
   - O(n!) → O(n² × 2^n) 변환

3. **비트 연산 마스터**
   - Shift (<<): 비트 위치 지정
   - AND (&): 특정 비트 확인
   - OR (|): 특정 비트 설정

4. **TSP 문제의 본질**
   - NP-hard 문제
   - 작은 n에서만 정확한 해 구할 수 있음
   - 비트마스킹 DP가 사실상 최선
