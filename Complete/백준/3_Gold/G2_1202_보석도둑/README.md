## 🔗 문제 링크

[백준 1202번 - 보석 도둑](https://www.acmicpc.net/problem/1202)

**난이도**: Gold 2

---

## 🤔 접근법

N개의 보석과 K개의 가방이 주어진다.

각 보석은 무게와 가격을 가지고 있고, 각 가방은 최대 무게 제한이 있다.

가방 하나에는 보석을 최대 1개만 담을 수 있다.

**핵심은 작은 가방부터 처리하면서, 담을 수 있는 보석 중 가장 비싼 것을 선택**하는 것!

이 문제는 **그리디 알고리즘 + 우선순위 큐**로 해결해야 한다.

---

## 💡 정답 풀이 방법

**알고리즘**: 그리디 알고리즘 + 우선순위 큐 (최대 힙)

**핵심 아이디어**:
```
1. 보석을 무게 기준 오름차순 정렬
2. 가방을 용량 기준 오름차순 정렬
3. 작은 가방부터 처리:
   - 현재 가방에 담을 수 있는 모든 보석을 우선순위 큐(최대힙)에 추가
   - 큐에서 가장 비싼 보석 선택
4. 모든 가방 처리 후 누적 가격 합 출력
```

**왜 이 알고리즘이 최적해를 보장하는가?**
- 작은 가방은 선택지가 적다 → 먼저 처리해서 최선의 선택
- 큰 가방은 선택지가 많다 → 나중에 처리해도 좋은 보석 선택 가능
- 우선순위 큐로 항상 가장 비싼 보석을 O(log N)에 선택

**시간 복잡도**: O(N log N + K log N)
- 보석 정렬: O(N log N)
- 가방 정렬: O(K log K)
- 우선순위 큐 연산: O(N log N)
- **총 O(N log N)** → 300,000 기준 충분히 통과

**공간 복잡도**: O(N + K)
- jewels 벡터: O(N)
- bags 벡터: O(K)
- priority_queue pq: O(N) (최악의 경우)

## 🔑 핵심 포인트

### 1️⃣ 왜 보석과 가방을 오름차순 정렬하는가?

```cpp
sort(jewels.begin(), jewels.end());  // 보석 무게 오름차순
sort(bags.begin(), bags.end());      // 가방 용량 오름차순
```

**이유**:
- 작은 가방부터 처리하면 **점진적으로 선택지가 늘어남**
- 무게가 가벼운 보석부터 확인하면 **중복 확인 방지**
- 큰 가방에서는 이전에 확인한 보석들도 모두 담을 수 있으므로 효율적

### 2️⃣ jewelIdx가 증가만 하는 이유

```cpp
int jewelIdx = 0;  // 전역적으로 선언

for (int i = 0; i < K; i++)
{
    while (jewelIdx < N && jewels[jewelIdx].first <= bags[i])
    {
        pq.push(jewels[jewelIdx].second);
        jewelIdx++;  // 계속 증가만 함
    }
}
```

**핵심 원리**:
- 보석과 가방 모두 **오름차순 정렬**되어 있음
- 이전 가방(작은 용량)에 담을 수 있던 보석은 다음 가방(큰 용량)에도 담을 수 있음
- **한 번 확인한 보석은 다시 확인할 필요 없음!**

**시간복잡도 개선**:
- while문이 이중 루프처럼 보이지만, jewelIdx는 **전체 N번만 증가**
- 총 while문 실행 횟수: O(N) (N번의 push 연산)
- 각 가방마다 새로운 보석들만 추가 → 효율적!

### 3️⃣ 우선순위 큐를 비우지 않는 이유

```cpp
priority_queue<ll> pq;  // 최대힙

// 가방 순회
for (int i = 0; i < K; i++)
{
    while (...)
    {
        pq.push(...);  // 계속 누적
    }

    if (!pq.empty())
    {
        pq.pop();      // 1개만 꺼냄 (비우지 않음!)
    }
}
```

**이유**:
- 작은 가방에서 선택 못한 보석들이 큐에 남아있음
- 큰 가방에서 그 보석들을 선택할 수 있음!
- **예**: 무게1인 보석(가격65)는 가방2(용량2)에서 못 담았지만, 가방10(용량10)에서 담을 수 있음

### 4️⃣ 최대 힙 사용

```cpp
priority_queue<ll> pq;  // 기본 = 최대힙 (큰 값이 top)
```

**핵심**:
- C++의 `priority_queue`는 기본적으로 **최대 힙**
- `pq.top()`으로 항상 **가장 비싼 보석**을 O(1)에 접근
- `pq.pop()`으로 제거 후 자동으로 다음 최댓값이 top이 됨

**cf. 최소 힙 만들기**:
```cpp
priority_queue<int, vector<int>, greater<int>> minPQ;  // 최소힙
```

### 5️⃣ long long 사용 필수

```cpp
typedef long long ll;
ll N, K;
ll ret = 0;  // 최대 가격 합 (오버플로우 방지)
```

**이유**:
- N, K 최대 300,000
- 가격 최대 1,000,000
- 최악의 경우: 300,000 × 1,000,000 = 3 × 10¹¹
- int 범위(~2 × 10⁹) 초과 → **오버플로우**

## 📊 예제 2 상세 시뮬레이션

**입력**:
```
3 2          # 보석 3개, 가방 2개
1 65         # 무게 1, 가격 65
5 23         # 무게 5, 가격 23
2 99         # 무게 2, 가격 99
10           # 가방1 용량 10
2            # 가방2 용량 2
```

### 🎯 Step 1: 정렬 후 상태

```cpp
jewels = [(1,65), (2,99), (5,23)]  // 무게 오름차순
bags   = [2, 10]                    // 용량 오름차순
```

<br>

### 🔄 Step 2: 알고리즘 실행 과정

#### 초기 상태
```
jewelIdx = 0     // 현재 확인할 보석 인덱스
ret = 0          // 누적 가격
pq = []          // 우선순위 큐 (비어있음)
```

<br>

#### 🎒 [1단계] i=0, bags[0] = 2 처리

```cpp
for (int i = 0; i < K; i++)  // i=0
{
    // 현재 가방에 담을 수 있는 모든 보석을 pq에 추가
    while (jewelIdx < N && jewels[jewelIdx].first <= bags[i])
    {
        pq.push(jewels[jewelIdx].second);
        jewelIdx++;
    }
```

**while 루프 실행**:

| 반복 | 조건 확인 | jewels[jewelIdx] | 동작 | pq 상태 | jewelIdx |
|-----|----------|------------------|------|---------|----------|
| 1 | jewelIdx(0) < 3 ✅<br>jewels[0].first(1) <= bags[0](2) ✅ | (1, 65) | pq.push(65) | [65] | 1 |
| 2 | jewelIdx(1) < 3 ✅<br>jewels[1].first(2) <= bags[0](2) ✅ | (2, 99) | pq.push(99) | [99, 65] | 2 |
| 3 | jewelIdx(2) < 3 ✅<br>jewels[2].first(5) <= bags[0](2) ❌ | - | 탈출 | [99, 65] | 2 |

**while 종료 후 상태**:
```
pq = [99, 65]    // 최대힙 (99가 top)
jewelIdx = 2     // 다음 확인할 보석 인덱스
```

**가장 비싼 보석 선택**:
```cpp
    if (!pq.empty())
    {
        ret += pq.top();  // ret += 99
        pq.pop();         // 99 제거
    }
}
```

**1단계 종료**:
```
ret = 99
pq = [65]        // 65만 남음 (다음 가방에서 사용 가능!)
jewelIdx = 2
```

**💬 설명**:
- 가방 용량 2에는 무게 1, 2인 보석만 담을 수 있음
- 둘 중 더 비싼 99를 선택
- **65는 큐에 남아서 다음 가방에서 선택 가능!** ← 핵심!

<br>

#### 🎒 [2단계] i=1, bags[1] = 10 처리

```cpp
for (int i = 0; i < K; i++)  // i=1
{
    // 현재 가방에 담을 수 있는 모든 보석을 pq에 추가
    while (jewelIdx < N && jewels[jewelIdx].first <= bags[i])
    {
        pq.push(jewels[jewelIdx].second);
        jewelIdx++;
    }
```

**while 루프 실행**:

| 반복 | 조건 확인 | jewels[jewelIdx] | 동작 | pq 상태 | jewelIdx |
|-----|----------|------------------|------|---------|----------|
| 1 | jewelIdx(2) < 3 ✅<br>jewels[2].first(5) <= bags[1](10) ✅ | (5, 23) | pq.push(23) | [65, 23] | 3 |
| 2 | jewelIdx(3) < 3 ❌ | - | 탈출 | [65, 23] | 3 |

**while 종료 후 상태**:
```
pq = [65, 23]    // 최대힙 (65가 top)
jewelIdx = 3     // 모든 보석 확인 완료
```

**가장 비싼 보석 선택**:
```cpp
    if (!pq.empty())
    {
        ret += pq.top();  // ret += 65
        pq.pop();         // 65 제거
    }
}
```

**2단계 종료**:
```
ret = 99 + 65 = 164
pq = [23]        // 23은 사용 안 됨 (가방 부족)
jewelIdx = 3
```

**💬 설명**:
- 가방 용량 10에는 무게 5인 보석도 담을 수 있음
- 하지만 **이전 가방에서 못 담았던 65**가 큐에 남아있음!
- **65 vs 23** → 더 비싼 65 선택
- 이것이 바로 우선순위 큐를 비우지 않는 이유!

<br>

### ✅ Step 3: 최종 결과

```
출력: 164
```

**최적 배치**:
- 가방1(용량2): 무게2인 보석(가격99) 담기
- 가방2(용량10): 무게1인 보석(가격65) 담기
- 무게5인 보석(가격23)은 못 담음 (가방 부족)

<br>

### 🎯 핵심 정리

```
작은 가방부터 처리하면서:

가방1(용량2): 담을 수 있는 보석 [(1,65), (2,99)] → pq에 모두 추가
            → 가장 비싼 99 선택
            → 65는 큐에 남김 ← 핵심!

가방2(용량10): 담을 수 있는 새 보석 [(5,23)] → pq에 추가
             → pq = [65, 23] (65는 이전에 남긴 것!)
             → 가장 비싼 65 선택

총합: 99 + 65 = 164 ✅

💡 작은 가방에서 못 담은 보석도 큰 가방에서 선택 가능!
💡 우선순위 큐로 항상 가장 비싼 것을 선택!
```

## 🔍 변수명 개선 포인트

### ❌ 기존 코드 (이해하기 어려운 변수명)
```cpp
vector<pair<ll,ll>> v(N);   // v가 뭐지?
vector<ll> vv(K);           // vv가 뭐지?
int j = 0;                  // j는 무슨 의미?

for(int i = 0; i < K; i++)
{
    while(j < N && v[j].first <= vv[i])
        pq.push(v[j++].second);
}
```

### ✅ 개선된 코드 (명확한 변수명)
```cpp
vector<pair<ll,ll>> jewels;  // 보석들
vector<ll> bags;             // 가방들
int jewelIdx = 0;            // 보석 인덱스

for(int i = 0; i < K; i++)
{
    while(jewelIdx < N && jewels[jewelIdx].first <= bags[i])
        pq.push(jewels[jewelIdx++].second);
}
```

**개선 사항**:
- `v` → `jewels` (보석들)
- `vv` → `bags` (가방들)
- `j` → `jewelIdx` (현재 확인 중인 보석의 인덱스)
- `i` → 가방 인덱스 (의미가 명확하므로 그대로 유지)

## ⏱️ 시간복잡도

**O(N log N + K log N) = O(N log N)**

**분석**:
1. **보석 정렬**: O(N log N)
2. **가방 정렬**: O(K log K)
3. **우선순위 큐 연산**: O(N log N)
   - while문 총 실행 횟수: N번 (jewelIdx가 0→N까지 증가)
   - 각 push: O(log N)
   - 총 push: O(N log N)
   - 각 pop: O(log N)
   - 총 pop: O(K log K)
4. **전체**: O(N log N + K log K + N log N) ≈ **O(N log N)**

**제한 조건**:
- N, K ≤ 300,000
- 300,000 × log(300,000) ≈ 5,500,000 (충분히 빠름) ✅

---

## 💾 공간복잡도

**O(N + K)**

**분석**:
- `jewels` 벡터: O(N)
- `bags` 벡터: O(K)
- `pq` 우선순위 큐: O(N) (최악의 경우 모든 보석 저장)
- **총합**: O(N + K)

---

## 🚨 주의사항

1. **long long 필수**: 오버플로우 방지 (`ret`는 최대 3×10¹¹)
2. **정렬 순서**: 보석과 가방 모두 오름차순 정렬
3. **jewelIdx 증가**: while문에서 jewelIdx가 계속 증가만 함 (재방문 없음)
4. **큐 유지**: 우선순위 큐를 비우지 않고 누적 (작은 가방에서 못 담은 보석도 큰 가방에서 선택 가능)
5. **입출력 최적화**: `ios_base::sync_with_stdio(false)` 필수
6. **최대 힙**: C++ `priority_queue`는 기본적으로 최대 힙 (큰 값이 top)
