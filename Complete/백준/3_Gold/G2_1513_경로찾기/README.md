## 🔗 문제 링크

[백준 1513번 - 경로 찾기](https://www.acmicpc.net/problem/1513)

**난이도**: Gold 2

---

## 🤔 접근법

N×M 크기의 격자에서 (1, 1)에서 시작하여 (N, M)에 도착하는 경로를 구하는 문제입니다.

오락실 C개가 있고, **오락실은 증가하는 순서**로만 방문할 수 있습니다.

**핵심은 4차원 DP를 활용하여 "현재 위치, 남은 방문 횟수, 이전 방문 오락실 번호"를 상태로 관리**하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 다이나믹 프로그래밍 (4차원 DP)

**핵심 아이디어**:
```
1. DP 상태 정의:
   dp[y][x][remainVit][prev] = 경로의 수
   - (y, x): 현재 위치
   - remainVit: 앞으로 방문해야 할 오락실 수
   - prev: 이전에 방문한 오락실 번호

2. 재귀 탐색:
   - 현재 위치가 빈칸(0):
     → 그냥 지나가면서 아래/오른쪽으로 이동
   - 현재 위치가 오락실 (ar[y][x] > prev):
     → 방문하면서 remainVit - 1, prev를 현재 오락실 번호로 갱신

3. 종료 조건:
   - (n, m) 도착 시:
     → remainVit = 0이고 빈칸이면 성공
     → remainVit = 1이고 오락실(번호 > prev)이면 성공
```

**시간 복잡도**: O(N × M × C²)
- 상태 공간: O(N × M × C × C)
- 각 상태는 메모이제이션으로 1번만 계산
- 50 × 50 × 50 × 50 = 6,250,000번 연산

**공간 복잡도**: O(N × M × C²)
- dp 배열: O(N × M × C × C)
- 재귀 스택: O(N + M) (최대 깊이)

## 🔑 핵심 포인트

### 1️⃣ 4차원 DP 상태 설계

```cpp
int dp[54][54][54][54]; // dp[y][x][남은방문수][이전오락실번호]
```

**상태 정의**:
- `dp[y][x][remainVit][prev]`: (y, x) 위치에서 앞으로 `remainVit`개의 오락실을 방문하고,
  이전에 방문한 오락실이 `prev`번일 때 가능한 경로의 수

**왜 4차원인가?**
- Y, X: 현재 위치 (2차원)
- remainVit: 앞으로 몇 개를 더 방문해야 하는지
- prev: 이전 오락실 번호 (증가 순서 체크용)

---

### 2️⃣ 재귀 함수의 핵심 로직

```cpp
int Go(int curY, int curX, int remainVit, int prev)
{
    // 범위 벗어남
    if (curY > n || curX > m) return 0;

    // 목적지 도착
    if (curY == n && curX == m)
    {
        // 더 이상 방문할 오락실이 없고, 목적지가 빈칸
        if (remainVit == 0 && ar[curY][curX] == 0) return 1;

        // 방문할 오락실이 1개 남았고, 목적지가 오락실 (prev보다 큰 번호)
        if (remainVit == 1 && ar[curY][curX] > prev) return 1;

        return 0;
    }

    // 메모이제이션
    int &ret = dp[curY][curX][remainVit][prev];
    if (ret != -1) return ret;
    ret = 0;

    // 현재 위치가 빈칸
    if (ar[curY][curX] == 0)
        ret = (Go(curY + 1, curX, remainVit, prev) +
               Go(curY, curX + 1, remainVit, prev)) % mod;

    // 현재 위치가 오락실이고, prev보다 큰 번호
    else if (ar[curY][curX] > prev)
        ret = (Go(curY + 1, curX, remainVit - 1, ar[curY][curX]) +
               Go(curY, curX + 1, remainVit - 1, ar[curY][curX])) % mod;

    return ret;
}
```

**핵심 포인트**:

**1. 빈칸 처리**:
- 현재 위치가 빈칸이면 그냥 지나감
- `remainVit`와 `prev`는 그대로 유지

**2. 오락실 처리**:
- `ar[curY][curX] > prev` 체크 (증가하는 순서만 방문 가능)
- 방문 시: `remainVit - 1`, `prev`를 현재 오락실 번호로 갱신
- 조건을 만족하지 않으면 해당 경로는 탐색하지 않음 (자동으로 ret = 0 유지)

**3. 목적지 도착 조건**:
- `remainVit = 0`이고 목적지가 빈칸 → 성공
- `remainVit = 1`이고 목적지가 오락실 (번호 > prev) → 마지막 오락실 방문 후 성공

---

### 3️⃣ 오락실 번호 증가 순서 체크

```cpp
// 오락실 방문 가능 조건
if (ar[curY][curX] > prev)
```

**왜 이것만으로 충분한가?**
- `prev`: 이전에 방문한 오락실의 번호
- `ar[curY][curX]`: 현재 오락실의 번호
- `ar[curY][curX] > prev`이면 증가하는 순서가 보장됨

**예시**:
```
prev = 0 (시작) → 1번 오락실 방문 가능 (1 > 0)
prev = 1        → 2번 오락실 방문 가능 (2 > 1)
prev = 2        → 1번 오락실 방문 불가 (1 < 2) ❌
```

---

### 4️⃣ 메모이제이션 최적화

```cpp
int &ret = dp[curY][curX][remainVit][prev];
if (ret != -1) return ret;
```

**최적화 효과**:
- 같은 상태를 다시 방문하면 즉시 반환
- 중복 계산 제거 → 시간 복잡도 대폭 감소

**초기화**:
```cpp
memset(dp, -1, sizeof(dp));  // -1: 아직 계산 안 됨
```

## 📊 예제 1 상세 시뮬레이션

**입력**:
```
3 3 2
2 2
3 2
```

**배열 초기화**:
```
     X축 →
   1    2    3
Y  ┌────┬────┬────┐
│  │    │    │    │
1  │ 0  │ 0  │ 0  │  ← 시작 (1,1)
   │    │    │    │
   ├────┼────┼────┤
│  │    │ 🎮 │    │
2  │ 0  │ 1  │ 0  │  ← 오락실 1번 (2,2)
   │    │    │    │
   ├────┼────┼────┤
│  │    │ 🎮 │    │
3  │ 0  │ 2  │ 0  │  ← 오락실 2번 (3,2), 목적지 (3,3)
   │    │    │    │
   └────┴────┴────┘

ar[2][2] = 1 (오락실 1번)
ar[3][2] = 2 (오락실 2번)
```

---

### 🔹 0개 방문: Go(1, 1, 0, 0)

**조건**: 오락실을 하나도 방문하지 않고 (3, 3)에 도착

**경로 탐색**:
```
Go(1, 1, 0, 0)
│
├─ ar[1][1] = 0 (빈칸) → 지나감
│  remainVit = 0 (더 이상 방문 안 함)
│
├─ Go(2, 1, 0, 0) → 아래
│  └─ ar[2][1] = 0 → 지나감
│     └─ Go(2, 2, 0, 0) → 오른쪽
│        └─ ar[2][2] = 1 (오락실!)
│           BUT remainVit = 0 (방문 불가)
│           → else 조건 실행 안 됨 → ret = 0 ❌
│
└─ Go(1, 2, 0, 0) → 오른쪽
   └─ ar[1][2] = 0 → 지나감
      └─ Go(1, 3, 0, 0) → 오른쪽
         └─ ar[1][3] = 0 → 지나감
            └─ Go(2, 3, 0, 0) → 아래
               └─ ar[2][3] = 0 → 지나감
                  └─ Go(3, 3, 0, 0) → 아래 ✅ 목적지!
                     └─ remainVit = 0 && ar[3][3] = 0
                        → return 1 ✅
```

**성공 경로**:
```
경로: (1,1) → (1,2) → (1,3) → (2,3) → (3,3)
```

**결과**: `1개 경로`

---

### 🔹 1개 방문: Go(1, 1, 1, 0)

**조건**: 오락실을 정확히 1개 방문하고 (3, 3)에 도착

**주요 경로**:

**경로 1**: 오락실 1번 방문
```
Go(1, 1, 1, 0)
│
└─ Go(2, 1, 1, 0) → 아래
   └─ ar[2][1] = 0 → 지나감
      └─ Go(2, 2, 1, 0) → 오른쪽
         └─ ar[2][2] = 1 (오락실 1번!)
            └─ 1 > 0 (prev) → 방문 가능!
               └─ Go(2, 3, 0, 1) → 오른쪽
                  └─ ar[2][3] = 0 → 지나감
                     └─ Go(3, 3, 0, 1) → 아래
                        └─ remainVit = 0 && ar[3][3] = 0
                           → return 1 ✅
```

**경로 2**: 오락실 1번 방문 (다른 경로)
```
Go(1, 1, 1, 0)
│
└─ Go(1, 2, 1, 0) → 오른쪽
   └─ ar[1][2] = 0 → 지나감
      └─ Go(2, 2, 1, 0) → 아래
         └─ ar[2][2] = 1 (오락실 1번!)
            └─ 1 > 0 → 방문!
               └─ Go(2, 3, 0, 1) → 오른쪽
                  └─ Go(3, 3, 0, 1) → 아래
                     → return 1 ✅
```

**경로 3**: 오락실 2번 방문
```
Go(1, 1, 1, 0)
│
└─ Go(2, 1, 1, 0) → 아래
   └─ Go(3, 1, 1, 0) → 아래
      └─ ar[3][1] = 0 → 지나감
         └─ Go(3, 2, 1, 0) → 오른쪽
            └─ ar[3][2] = 2 (오락실 2번!)
               └─ 2 > 0 → 방문!
                  └─ Go(3, 3, 0, 2) → 오른쪽
                     └─ remainVit = 0 && ar[3][3] = 0
                        → return 1 ✅
```

**성공 경로**:
```
경로 1: (1,1) → (2,1) → (2,2)[오락실1] → (2,3) → (3,3)
경로 2: (1,1) → (1,2) → (2,2)[오락실1] → (2,3) → (3,3)
경로 3: (1,1) → (2,1) → (3,1) → (3,2)[오락실2] → (3,3)
```

**결과**: `3개 경로`

### 🔹 2개 방문: Go(1, 1, 2, 0)

**조건**: 오락실을 정확히 2개 방문 (1번 → 2번 순서대로)

**주요 경로**:

**경로 1**:
```
Go(1, 1, 2, 0)
│
└─ Go(2, 1, 2, 0) → 아래
   └─ Go(2, 2, 2, 0) → 오른쪽
      └─ ar[2][2] = 1 (오락실 1번!)
         └─ 1 > 0 → 방문!
            └─ Go(3, 2, 1, 1) → 아래
               └─ ar[3][2] = 2 (오락실 2번!)
                  └─ 2 > 1 → 방문!
                     └─ Go(3, 3, 0, 2) → 오른쪽
                        → return 1 ✅
```

**경로 2**:
```
Go(1, 1, 2, 0)
│
└─ Go(1, 2, 2, 0) → 오른쪽
   └─ Go(2, 2, 2, 0) → 아래
      └─ ar[2][2] = 1 → 방문!
         └─ Go(3, 2, 1, 1) → 아래
            └─ ar[3][2] = 2 → 방문!
               → return 1 ✅
```

**성공 경로**:
```
경로 1: (1,1) → (2,1) → (2,2)[오락실1] → (3,2)[오락실2] → (3,3)
경로 2: (1,1) → (1,2) → (2,2)[오락실1] → (3,2)[오락실2] → (3,3)
```

**결과**: `2개 경로`

## 📊 예제 4 분석 (엣지 케이스)

**입력**:
```
50 50 2
50 50
1 1
```

**배치**:
- 시작 위치 (1, 1): 오락실 2번
- 목적지 (50, 50): 오락실 1번

**분석**:
- 시작부터 오락실 2번을 밟게 됨
- 목적지가 오락실 1번인데, 이미 2번을 방문했으므로 방문 불가 (2 > 1)
- **모든 경로가 불가능**

**출력**:
```
0 0 0
```

🔸 0개 방문: 불가능 (시작 위치가 오락실이므로 무조건 방문)

🔸 1개 방문: 불가능 (목적지 오락실 번호가 더 작음)

🔸 2개 방문: 불가능 (증가 순서 위반)

---

## 🚨 주의사항

1. **4차원 DP**: N, M, C가 모두 50 이하이므로 메모리 충분
2. **오락실 번호 체크**: `ar[curY][curX] > prev` 조건으로 증가 순서 보장
3. **목적지 조건**: `remainVit = 0 (빈칸)` 또는 `remainVit = 1 (오락실)` 두 경우 모두 처리
4. **모듈러 연산**: 매 재귀 호출마다 `% mod` 적용 (오버플로우 방지)
5. **메모이제이션**: `-1` 초기화 필수

---

## ⏱️ 시간복잡도

**O(N × M × C²)**

**분석**:
1. **상태 공간**: N × M × C × C
2. **각 상태 계산**: O(1) (2개 재귀 호출, 메모이제이션으로 1번만)
3. **전체**: 50 × 50 × 50 × 50 = 6,250,000번 연산

**제한 조건**:
- N, M ≤ 50
- C ≤ 50
- 6,250,000번 연산 (충분히 빠름) ✅

---

## 💾 공간복잡도

**O(N × M × C²)**

**분석**:
- `ar[54][54]`: O(N × M)
- `dp[54][54][54][54]`: O(N × M × C²) = 약 81MB
- 재귀 스택: O(N + M) = 최대 100 깊이
- **총합**: O(N × M × C²)
