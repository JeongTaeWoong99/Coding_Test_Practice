## 🔗 문제 링크

[백준 1781번 - 컵라면](https://www.acmicpc.net/problem/1781)

**난이도**: Gold 2

---

## 🤔 접근법

각 문제마다 데드라인과 보상(컵라면 수)이 주어진다.

문제를 풀 때마다 단위 시간 1이 걸리며, 데드라인 내에 풀어야 보상을 받을 수 있다.

**핵심은 데드라인이 빠른 순서대로 정렬한 후, 우선순위 큐로 최적의 선택을 유지**하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 그리디 알고리즘 + 우선순위 큐 (최소 힙)

**핵심 아이디어**:
```
1. 문제들을 데드라인 기준 오름차순으로 정렬
2. 데드라인이 빠른 문제부터 순서대로 처리:
   - 우선순위 큐에 보상(컵라면 수)을 추가
   - 큐의 크기가 현재 데드라인을 초과하면:
     → 가장 적은 보상을 제거 (최소 힙의 top)
3. 큐에 남은 보상들을 모두 합산하여 출력
```

**시간 복잡도**: O(N log N)
- 정렬: O(N log N)
- 우선순위 큐 연산: O(N log N)
- 최종 합산: O(N)

**공간 복잡도**: O(N)
- vector v: O(N)
- priority_queue pq: O(N)

## 🔑 핵심 포인트

### 1️⃣ 왜 데드라인 기준으로 정렬하는가?

```cpp
sort(v.begin(), v.end());  // {데드라인, 컵라면 수} pair 정렬
```

**이유**:
- 데드라인이 빠른 문제부터 처리해야 선택의 여지가 많음
- 데드라인 d인 문제는 최대 d개의 문제를 선택할 수 있음
- 예: 데드라인 1인 문제는 무조건 1개만 선택 가능
- 예: 데드라인 3인 문제는 최대 3개까지 선택 가능

### 2️⃣ 우선순위 큐로 최적의 선택 유지

```cpp
priority_queue<int, vector<int>, greater<int>> pq;  // 최소 힙

pq.push(v[i].second);  // 보상 추가

if (pq.size() > v[i].first)  // 데드라인 초과 시
{
    pq.pop();  // 가장 적은 보상 제거
}
```

**핵심**:
- 최소 힙을 사용하여 **가장 적은 보상을 빠르게 찾음**
- 데드라인을 초과하면 가장 적은 보상을 제거
- 이를 통해 항상 **최적의 조합**을 유지

**예시**:
```
데드라인 3인 문제 처리 중, 큐에 [2, 5, 7, 9]가 있다면:
→ 크기 4 > 데드라인 3
→ 최소값 2를 제거
→ 큐: [5, 7, 9] (최적의 3개만 유지)
```

### 3️⃣ 왜 이 알고리즘이 항상 최적해를 보장하는가?

**그리디 선택 속성**:
1. 데드라인이 빠른 순서대로 처리
2. 각 단계에서 최선의 선택 (큰 보상 유지)
3. 이전 선택을 번복하지 않음

**최적 부분 구조**:
- 데드라인 d까지의 최적해 = 데드라인 d-1까지의 최적해 + 현재 문제의 최선 선택
- 우선순위 큐로 항상 상위 k개의 보상만 유지

### 4️⃣ pair 정렬의 기본 동작

```cpp
vector<pair<int, int>> v;  // {데드라인, 컵라면 수}
sort(v.begin(), v.end());
```

**정렬 기준**:
- 기본적으로 **first 기준 오름차순**
- first가 같으면 **second 기준 오름차순**
- 이 문제에서는 데드라인(first)만 중요하므로 완벽

## 📊 예시 실행 흐름

**입력**:
```
7
1 6
1 7
3 2
3 1
2 4
2 5
6 1
```

**정렬 후**: `{1,6}, {1,7}, {2,4}, {2,5}, {3,2}, {3,1}, {6,1}`

**처리 과정**:

| 단계 | 문제 | pq 상태 | pq.size() | 데드라인 | 동작 |
|-----|-----|---------|-----------|---------|------|
| 1 | {1,6} | [6] | 1 | 1 | 추가만 |
| 2 | {1,7} | [6,7] | 2 | 1 | 2 > 1 → 6 제거 → [7] |
| 3 | {2,4} | [4,7] | 2 | 2 | 추가만 |
| 4 | {2,5} | [4,5,7] | 3 | 2 | 3 > 2 → 4 제거 → [5,7] |
| 5 | {3,2} | [2,5,7] | 3 | 3 | 추가만 |
| 6 | {3,1} | [1,2,5,7] | 4 | 3 | 4 > 3 → 1 제거 → [2,5,7] |
| 7 | {6,1} | [1,2,5,7] | 4 | 6 | 추가만 |

**최종 큐**: [1, 2, 5, 7]

**합산**: 1 + 2 + 5 + 7 = **15** ✅

## 🚨 주의사항

1. **최소 힙 사용**: `greater<int>`로 선언하여 가장 적은 값이 top에 오도록 설정
2. **크기 비교**: `pq.size() > v[i].first`로 데드라인 초과 여부 확인
3. **정렬 필수**: 데드라인 기준 정렬하지 않으면 최적해 보장 불가
4. **입출력 최적화**: N ≤ 200,000이므로 `ios_base::sync_with_stdio(false)` 필수

## ⏱️ 시간복잡도

**O(N log N)**

**분석**:
- 입력: O(N)
- 정렬: O(N log N)
- 우선순위 큐 연산: O(N log N)
  - 각 문제마다 push/pop: O(log N)
  - N번 반복: O(N log N)
- 최종 합산: O(N)
- **총합**: O(N log N)

**제한 조건**:
- N ≤ 200,000
- 200,000 × log(200,000) ≈ 3,600,000 (충분히 빠름)
