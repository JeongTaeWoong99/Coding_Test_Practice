## 🔗 문제 링크

[백준 2109번 - 순회강연](https://www.acmicpc.net/problem/2109)

**난이도**: Gold 3

## 🤔 접근법

처음에는 각 날짜에 최대 강연료만 저장하는 단순한 배열 방식으로 접근했다.

```cpp
// 잘못된 접근
arr[tempD] = max(arr[tempD], tempP);  // d일차에만 배정
```

**❌ 문제점**:
- "d일 **안에**"라는 것은 1일 ~ d일 중 아무 날이나 가능하다는 의미
- 여러 강연이 같은 날짜를 원할 때, 하나만 선택하고 나머지는 버림
- 예: (p=100, d=2), (p=80, d=2) → 80을 1일차에 배정할 수 있는데 무시함

이 문제는 **그리디 알고리즘 + 우선순위 큐**로 해결해야 한다!

핵심은 **마감일 안에서 최대한 많은 강연을 고르되, 강연료가 높은 것을 우선**하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 그리디 알고리즘 + 우선순위 큐 (최소 힙)

**핵심 아이디어**:
```
1. 모든 강연을 {마감일, 강연료} 형태로 저장
2. 마감일 기준 오름차순 정렬
3. 마감일이 빠른 것부터 처리:
   - 현재 강연을 우선순위 큐에 추가
   - 선택한 강연 수가 마감일을 초과하면 가장 적은 강연료 제거
4. 최종적으로 남은 강연료들의 합이 정답
```

**왜 이 알고리즘이 작동하는가?**
- 마감일 d까지는 최대 d개의 강연만 가능
- 마감일이 빠른 것부터 처리하면서, 현재 시점에서 가능한 강연 중 **강연료가 높은 것**만 선택
- 최소 힙을 사용하여 가장 적은 강연료를 빠르게 제거 → 최대 수익 보장

## 🔑 핵심 포인트

### 1️⃣ 마감일 기준 정렬

```cpp
sort(v.begin(), v.end());  // {마감일, 강연료} 형태이므로 마감일 기준 정렬
```

**✅ 핵심**: 마감일이 빠른 것부터 처리해야 각 시점에서 최적의 선택 가능

### 2️⃣ 최소 힙 사용

```cpp
priority_queue<int, vector<int>, greater<int>> minPQ;  // 최소 힙
```

**✅ 핵심**:
- `greater<int>` → 최소 힙 (작은 값이 top)
- 강연료가 적은 것을 빠르게 찾아 제거하기 위함
- 최소 힙을 사용하면 O(log n) 시간에 최솟값 제거 가능

#### 🤔 왜 greater = 최소 힙인가?

**직관과 반대로 느껴지는 이유**:
- `greater` = "더 큰" 이라는 의미 → 최대 힙일 것 같지만?
- **실제로는 최소 힙**이 됩니다!

**핵심 원리**:

```cpp
비교자의 역할: "a가 b보다 우선순위가 낮은가?" 판단

less<int>(a, b):
  → a < b이면 true (a가 b보다 작으면 우선순위 낮음)
  → 큰 값이 우선순위 높음 → 큰 값이 top
  → 최대 힙 ✅

greater<int>(a, b):
  → a > b이면 true (a가 b보다 크면 우선순위 낮음)
  → 작은 값이 우선순위 높음 → 작은 값이 top
  → 최소 힙 ✅
```

**비교표**:

```
┌─────────────────────────┬─────────────────┬──────────────────┐
│ 선언 방식               │ 타입            │ top()의 값       │
├─────────────────────────┼─────────────────┼──────────────────┤
│ priority_queue<int>     │ 최대 힙         │ 가장 큰 값       │
│ less<int> (기본값)      │                 │                  │
├─────────────────────────┼─────────────────┼──────────────────┤
│ greater<int>            │ 최소 힙         │ 가장 작은 값     │
└─────────────────────────┴─────────────────┴──────────────────┘
```

**💡 암기 팁**:
- `greater<int>` → greater(더 큰 값)가 "낮은 우선순위" → 작은 값이 top → **최소 힙**
- `less<int>` → less(더 작은 값)가 "낮은 우선순위" → 큰 값이 top → **최대 힙**

### 3️⃣ 그리디 선택 로직

```cpp
minPQ.push(v[i].second);           // 현재 강연료 추가

if(minPQ.size() > v[i].first)      // 선택한 강연 수가 마감일 초과
{
    minPQ.pop();                   // 가장 적은 강연료 제거
}
```

**✅ 핵심**:
- 마감일 d까지는 최대 d개의 강연만 가능
- `minPQ.size() > d`이면 가장 적은 강연료를 제거
- 더 좋은 강연(높은 강연료)으로 대체하는 효과

### 4️⃣ {마감일, 강연료} 순서

```cpp
v.emplace_back(b, a);  // {마감일, 강연료} 순서로 저장
```

**✅ 핵심**:
- pair는 first 기준으로 정렬되므로 마감일을 first에 배치
- `v[i].first`: 마감일, `v[i].second`: 강연료

## ❓ 핵심 의문점 해결 (FAQ)

### 🤔 Q: i=3에서 p=8 대신 p=40이 들어오면 어떻게 되나요?

```
상황: i=2까지 진행하여 minPQ = [20, 100]인 상태
     (d=1, p=20)과 (d=2, p=100)이 선택됨

i=3에서 (d=2, p=40)이 들어온다면?
```

**✅ 정답: 1일차의 p=20이 제거되고, 2일차까지의 합이 140이 됩니다!**

#### 📊 상세 과정

```
┌─────────────────────────────────────────────────────────────┐
│ Step 3: (d=2, p=40) 처리                                    │
├─────────────────────────────────────────────────────────────┤
│ 1. push(40) → minPQ = [20, 40, 100]                           │
│    (최소 힙: 작은 값이 top)                                 │
│                                                             │
│ 2. size=3 > d=2 ❌                                          │
│    2일까지는 2개만 가능!                                    │
│                                                             │
│ 3. pop() → 최소값 20 제거                                   │
│    minPQ = [40, 100]                                           │
│                                                             │
│ 4. 최종 2일차까지 선택: 40 + 100 = 140 ✅                  │
└─────────────────────────────────────────────────────────────┘
```

#### 💡 왜 이렇게 동작하는가?

**핵심 원리**: 마감일이 늦은 강연일수록 배치 가능한 날짜가 많다!

```
(d=1, p=20):  1일차에만 배치 가능
(d=2, p=40):  1일차 또는 2일차에 배치 가능
(d=2, p=100): 1일차 또는 2일차에 배치 가능

최적 배치:
  1일차: p=40 배치  (d=2이므로 1일차에도 가능)
  2일차: p=100 배치
  총합: 140
```

**✨ 이것이 바로 그리디 알고리즘의 핵심!**

- p=20은 **d=1이므로 1일차에만** 배치 가능
- p=40과 p=100은 **d=2이므로 1~2일 중 어디든** 배치 가능
- 따라서 p=20을 버리고 p=40, p=100을 선택하는 것이 최적!

#### 🔑 알고리즘이 보장하는 것

```
마감일 d인 강연은 1 ~ d일 중 아무 날이나 배치 가능
→ 마감일이 늦을수록 유연성이 높음
→ 더 좋은 강연(높은 p)이 나중에 오면 이전의 낮은 p를 밀어낼 수 있음
→ 마감일 기준으로 정렬하여 처리하면 최적해 보장!
```

#### 📝 다른 예시

```
예: (d=1, p=50), (d=2, p=40), (d=2, p=30) 순서로 입력

i=0: (d=1, p=50) → minPQ = [50]
i=1: (d=2, p=40) → minPQ = [40, 50]          (2일까지 2개 가능)
i=2: (d=2, p=30) → minPQ = [30, 40, 50]
                 → size=3 > d=2
                 → pop() → 30 제거
                 → minPQ = [40, 50]

최종: 1일차=50, 2일차=40 → 총합 90 ✅

💡 p=30은 제거되지만, p=50과 p=40이 최적의 조합!
```

## ⏱️ 시간복잡도

**O(n log n)**

**분석**:
1. **정렬: O(n log n)**
   - C++의 `sort()` 함수는 **IntroSort (Introspective Sort)** 사용
   - QuickSort + HeapSort + InsertionSort의 하이브리드 알고리즘
   - **평균**: O(n log n) (QuickSort 기반)
   - **최악**: O(n log n) (HeapSort로 전환하여 보장)

2. **우선순위 큐 연산: O(n log n)**
   - 우선순위 큐는 **힙(Heap)** 자료구조 사용
   - n번의 push: O(n log n)
     - 각 push: O(log n) (힙 재정렬)
   - 최대 n번의 pop: O(n log n)
     - 각 pop: O(log n) (힙 재정렬)

3. **최종 합 계산: O(n)**

**전체**: O(n log n + n log n + n) = **O(n log n)**

## 🔍 정렬 알고리즘 상세 설명

### 📚 C++ `sort()` 함수의 내부 동작

C++ STL의 `sort()`는 **IntroSort (Introspective Sort)**를 사용합니다.

#### 🎯 IntroSort의 전략

```
1. 기본적으로 QuickSort 사용
   → 평균 O(n log n), 빠른 실행 속도

2. 재귀 깊이가 2*log(n)을 초과하면
   → HeapSort로 전환
   → 최악의 경우 O(n log n) 보장

3. 작은 부분 배열(크기 < 16)에서는
   → InsertionSort 사용
   → 작은 데이터에서는 InsertionSort가 더 빠름
```

#### 📊 각 정렬 알고리즘 비교

```
┌─────────────────┬──────────────┬──────────────┬──────────────┬──────────┐
│ 알고리즘        │ 평균         │ 최악         │ 공간복잡도   │ 안정성   │
├─────────────────┼──────────────┼──────────────┼──────────────┼──────────┤
│ QuickSort       │ O(n log n)   │ O(n²)        │ O(log n)     │ 불안정   │
│ HeapSort        │ O(n log n)   │ O(n log n)   │ O(1)         │ 불안정   │
│ InsertionSort   │ O(n²)        │ O(n²)        │ O(1)         │ 안정     │
│ IntroSort       │ O(n log n)   │ O(n log n)   │ O(log n)     │ 불안정   │
│ (C++ sort)      │              │              │              │          │
└─────────────────┴──────────────┴──────────────┴──────────────┴──────────┘
```

**💡 IntroSort = QuickSort의 속도 + HeapSort의 안정성**

#### 🔧 왜 O(n log n)인가?

**QuickSort 기반 분할 정복 (Divide and Conquer)**:

```
정렬할 배열 크기: n

1단계: 배열을 2개로 분할 → n/2, n/2
2단계: 각각을 2개로 분할 → n/4, n/4, n/4, n/4
3단계: 각각을 2개로 분할 → n/8 × 8개
...
log(n)단계: 크기 1인 배열 n개

각 단계에서 처리하는 총 원소 수: n
단계 수: log(n)

∴ 시간복잡도 = n × log(n) = O(n log n)
```

**시각화**:

```
                    [8개 원소]               ← 1단계: n개 비교
                   /          \
            [4개]                [4개]        ← 2단계: n개 비교
           /    \              /    \
        [2]    [2]          [2]    [2]       ← 3단계: n개 비교
       / \    / \          / \    / \
      [1][1][1][1]       [1][1][1][1]       ← 4단계: log(n)단계 완료

총 단계: log₂(8) = 3단계
각 단계 비교 횟수: 8개
총 비교 횟수: 8 × 3 = O(n log n)
```

#### 🎯 우선순위 큐(힙)도 O(log n)인 이유

**힙(Heap)은 완전 이진 트리**:

```
힙의 높이: log(n)

push 연산:
  1. 맨 끝에 삽입: O(1)
  2. 위로 올리며 재정렬: O(log n)  ← 트리 높이만큼

pop 연산:
  1. 루트 제거: O(1)
  2. 맨 끝 원소를 루트로: O(1)
  3. 아래로 내리며 재정렬: O(log n)  ← 트리 높이만큼

∴ push/pop 모두 O(log n)
```

**예시 (힙 크기 = 7)**:

```
       100              ← 높이 0 (루트)
      /   \
    50     40           ← 높이 1
   /  \   /  \
  20  10 30  8          ← 높이 2 (리프)

높이 = log₂(7) ≈ 3
재정렬 최대 이동: 3단계 = O(log n)
```

## 🚨 주의사항

1. **마감일 순서**: {마감일, 강연료} 순서로 저장하여 자동으로 마감일 기준 정렬
2. **최소 힙**: `greater<int>`를 사용하여 작은 값을 빠르게 제거
3. **크기 체크**: `minPQ.size() > v[i].first` 조건으로 마감일 내 강연 수 제한
4. **입출력 최적화**: `ios_base::sync_with_stdio(false)` 필수 (n ≤ 10,000)
