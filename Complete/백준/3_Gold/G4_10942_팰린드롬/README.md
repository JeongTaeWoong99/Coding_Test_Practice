## 🔗 문제 링크

[백준 10942번 - 팰린드롬?](https://www.acmicpc.net/problem/10942)

**난이도**: Gold 4

---

## 🤔 접근법

수열에서 구간 [S, E]가 팰린드롬인지를 M번 질문에 답하는 문제.

M = 최대 1,000,000, N = 최대 2,000이므로 매 쿼리마다 직접 확인하면 **최악 10억 연산 → TLE**.

→ **O(N²) 전처리**로 모든 구간의 팰린드롬 여부를 미리 계산한 뒤, **O(1) 쿼리 응답**이 필요.

---

## ❌ 내 방식 (투포인터) — 실패

### 아이디어

양 끝에서 포인터를 안쪽으로 이동하며 비교.

```cpp
// 매 쿼리마다 수행
int moveNum = 0;
while (true)
{
    if (arr[leftN + moveNum] != arr[rightN - moveNum]) { 출력 0; break; }
    if (leftN + moveNum >= rightN - moveNum)           { 출력 1; break; }
    moveNum++;
}
```

### 왜 실패하는가?

| 항목 | 투포인터 | DP |
|------|---------|-----|
| 쿼리 1회 비용 | O(N/2) = 최대 1,000 | O(1) |
| M번 쿼리 총합 | **O(M × N) = 10억** ❌ | O(M) ✅ |
| 시간 제한 0.5초 | **TLE** | **통과** |

> 투포인터 로직 자체는 올바르지만, **M이 100만이라 매 쿼리마다 O(N)은 감당 불가**.

---

## ✅ DP 방식 — 정답

### 핵심 아이디어

`dp[i][j]` = arr[i..j]가 팰린드롬이면 `true`, 아니면 `false`

```
기저 사례:
  dp[i][i]     = true                   (원소 1개, 항상 팰린드롬)
  dp[i][i+1]   = (arr[i] == arr[i+1])   (원소 2개)

점화식 (길이 3 이상):
  dp[i][j] = (arr[i] == arr[j]) && dp[i+1][j-1]
              ↑ 양 끝이 같은가?   ↑ 안쪽 구간이 팰린드롬인가?
```

**핵심** : 안쪽 → 바깥쪽 순서로 채워야 `dp[i+1][j-1]`이 이미 계산된 상태가 보장됨.

### gap 변수 의미

```
gap = j - i  (i와 j 사이의 거리)

gap = 0 : 길이 1  (dp[i][i])
gap = 1 : 길이 2  (dp[i][i+1])
gap = 2 : 길이 3  (dp[i][i+2])
...
gap = n-1 : 길이 n (전체 수열)
```

작은 gap부터 순서대로 채우면, 더 큰 gap 계산 시 안쪽 구간 dp 값이 항상 준비되어 있음.

## 🔑 주요 구현 포인트

### 1️⃣ 전처리 순서가 핵심

```
dp[1][7]을 계산하려면 dp[2][6]이 필요
dp[2][6]을 계산하려면 dp[3][5]가 필요
dp[3][5]를 계산하려면 dp[4][4]가 필요 (이미 계산됨!)

→ 작은 gap부터 순서대로 채워야 참조할 dp 값이 항상 준비되어 있음
```

### 2️⃣ 단일 if문으로 양 조건 동시 확인

```cpp
// 양 끝이 다르면 false (단락 평가로 dp 참조 안 함)
// 양 끝이 같고 안쪽도 팰린드롬이면 true
if (arr[i] == arr[i + gap] && dp[i + 1][i + gap - 1])
    dp[i][i + gap] = true;
```

> **단락 평가 (Short-circuit)** : `arr[i] != arr[i+gap]`이면 `dp[i+1][i+gap-1]`을 아예 확인 안 함 → 효율적

### 3️⃣ bool vs int

```cpp
bool dp[2004][2004];  // bool : 메모리 1byte, 의미 명확
int  dp[2004][2004];  // int  : 메모리 4byte
```

`bool`이 메모리 효율적이며 의미도 명확함.
2004×2004×1byte = 약 4MB (메모리 제한 256MB 내)

## ⏱️ 시간복잡도

**O(N² + M)**

| 단계 | 복잡도 | 계산 |
|------|--------|------|
| DP 전처리 | O(N²) | 2,000² = 4,000,000 |
| M번 쿼리 | O(M) | 1,000,000 |
| **합계** | **O(N² + M)** | **약 5,000,000** ✅ |

---

## 💾 공간복잡도

**O(N²)**

- `dp[2004][2004]` (bool) : 2004 × 2004 × 1byte ≈ 4MB
- `arr[2004]` : 약 8KB
- 총 약 4MB (메모리 제한 256MB 내 ✅)
