## 🔗 문제 링크

[백준 12869번 - 뮤탈리스크](https://www.acmicpc.net/problem/12869)

**난이도**: Gold 4

## 🤔 접근법

스타크래프트의 뮤탈리스크가 SCV를 공격하는 문제이다.

뮤탈리스크는 한 번에 최대 3개의 SCV를 공격할 수 있으며, 데미지는 9, 3, 1이다.

공격 순서를 바꿀 수 있기 때문에 6가지 공격 패턴이 존재한다(= 순열) : (9,3,1), (9,1,3), (3,9,1), (3,1,9), (1,9,3), (1,3,9).

모든 SCV를 파괴하기 위한 최소 공격 횟수를 구해야 한다.

BFS로 모든 상태를 탐색하면서 최단 경로를 찾는 방식으로 해결할 수 있다.

핵심은 **3차원 DP 테이블(visited 배열)을** 사용하여 각 상태(세 SCV의 체력)까지 도달하는 최소 공격 횟수를 **메모이제이션**하는 것!

이 문제는 **BFS + DP(메모이제이션)이** 결합된 전형적인 상태 공간 탐색 문제이다.

---

## 💡 정답 풀이 방법

**알고리즘**: BFS (너비 우선 탐색) + DP (동적 계획법 / 메모이제이션)

**핵심 아이디어**:
```
1. 3차원 DP 테이블 사용: dp[a][b][c] = 체력 (a,b,c) 상태를 만드는 최소 공격 횟수
   → visited 배열이 곧 DP 테이블!
2. 메모이제이션: 이미 계산된 상태(visited[a][b][c] != 0)는 다시 계산하지 않음
3. 6가지 공격 패턴을 모두 시도하여 다음 상태 생성
4. BFS로 모든 상태를 탐색하면서 visited[0][0][0]에 도달하면 종료
5. visited는 1-based로 관리 (0 = 미방문, 1 이상 = 공격 횟수 + 1)
```

**DP의 정의**:
```
dp[a][b][c] = 체력이 (a, b, c)인 상태로 만드는 최소 공격 횟수
             (0 = 아직 도달 불가능, 1 이상 = 최소 공격 횟수 + 1)
```

**시간 복잡도**: O(N³ × 6)
- N = 최대 체력 (60)
- 상태 공간: 61 × 61 × 61 = 226,981
- 각 상태에서 6가지 공격 패턴 시도
- 실제로는 대부분의 상태가 탐색되지 않아 훨씬 빠름

**공간 복잡도**: O(N³)
- visited 배열: 61 × 61 × 61 = 약 226KB
- BFS 큐: O(상태 개수)

## 🔑 핵심 포인트

### 1️⃣ 6가지 공격 패턴 정의

```cpp
int damage[6][3] = {
    {9, 3, 1}, {9, 1, 3}, {3, 1, 9},
    {3, 9, 1}, {1, 3, 9}, {1, 9, 3}
};
```

**✅ 핵심**:
- 뮤탈리스크는 최대 3개의 SCV를 공격 (9, 3, 1 데미지)
- 공격 순서를 바꿀 수 있으므로 3! = 6가지 패턴
- 2차원 배열로 미리 정의하여 간편하게 사용

### 2️⃣ DP 테이블 = 3차원 visited 배열 (메모이제이션의 핵심!)

```cpp
int visited[64][64][64]; // ⭐ 이것이 바로 DP 테이블!
```

**✅ 핵심**:
- `visited[a][b][c]` = 체력이 (a, b, c)인 상태를 만드는 **최소 공격 횟수**
- 0 = 아직 계산 안 됨 (미방문), 1 이상 = 이미 계산됨 (방문 완료)
- **메모이제이션**: `if(visited[na][nb][nc]) continue;` → 이미 계산된 상태는 스킵!
- 최대 체력이 60이므로 64 크기로 안전하게 선언

**🔍 DP vs BFS의 관계**:
```
일반 BFS: 단순히 최단 경로 탐색
BFS + DP: visited 배열에 "부분 문제의 최적해"를 저장 (메모이제이션)
         → 같은 상태를 여러 번 계산하지 않음
         → 이것이 바로 동적 계획법!
```

### 3️⃣ BFS 탐색 구조

```cpp
struct State
{
    int a, b, c; // 각 SCV의 체력
};
queue<State> q;
```

**✅ 핵심**:
- 구조체를 사용하여 3개의 SCV 체력을 하나의 상태로 관리
- BFS는 최단 경로를 보장하므로 처음 visited[0][0][0]에 도달한 값이 답

### 4️⃣ 데미지 적용 시 음수 방지

```cpp
int na = max(0, cur_a - damage[i][0]);
int nb = max(0, cur_b - damage[i][1]);
int nc = max(0, cur_c - damage[i][2]);
```

**✅ 핵심**:
- 체력이 0 이하가 되면 SCV는 파괴됨
- `max(0, ...)` 처리로 음수 방지
- 배열 인덱스로 사용되므로 음수 값이 들어가면 안 됨

### 5️⃣ visited는 1-based로 관리

```cpp
visited[a][b][c] = 1;  // 시작점은 1로 설정

// BFS 중...
visited[na][nb][nc] = visited[cur_a][cur_b][cur_c] + 1;

// 최종 답
return visited[0][0][0] - 1;  // 1을 빼서 실제 공격 횟수 반환
```

**✅ 핵심**:
- 0을 미방문 표시로 사용하기 위해 1-based로 관리
- 시작점을 1로 설정하고, 마지막에 -1로 보정

### 6️⃣ 메모이제이션 적용 코드 (DP의 핵심!)

```cpp
// 이미 방문한 상태면 건너뛰기 ⭐ 메모이제이션!
if(visited[na][nb][nc]) continue;  // 중복 계산 방지!

// 새로운 상태 방문 처리 및 큐에 추가
visited[na][nb][nc] = visited[cur_a][cur_b][cur_c] + 1; // ⭐ DP 값 갱신!
q.push({na, nb, nc});
```

**✅ 핵심**:
- `if(visited[na][nb][nc]) continue;` → 이미 계산된 상태는 재계산하지 않음!
- 이것이 바로 **메모이제이션 (Memoization)**의 원리!
- DP 테이블에 저장된 값을 재사용하여 중복 계산 방지
- 시간복잡도를 지수 시간에서 다항 시간으로 대폭 감소!

**🔍 메모이제이션이 없다면?**
```
메모이제이션 없이: 같은 상태를 여러 번 방문 → 지수 시간 O(6^depth)
메모이제이션 있음: 각 상태를 최대 1번만 방문 → 다항 시간 O(N³)
```

### 7️⃣ SCV 개수에 따른 초기화

```cpp
int scvHP[3];  // 최대 3개
memset(scvHP, 0, sizeof(scvHP));

// SCV 개수만큼 입력받기
for(int i = 0; i < N; i++)
    cin >> scvHP[i];

// 나머지는 0으로 유지 (이미 파괴된 상태)
BFS(scvHP[0], scvHP[1], scvHP[2]);
```

**✅ 핵심**:
- SCV가 1개 또는 2개인 경우도 있음
- 나머지는 0으로 초기화하여 이미 파괴된 것으로 처리
- 3개 미만이어도 동일한 BFS 로직 적용 가능

## ⏱️ 시간복잡도 (상세 분석)

### 📐 이론적 시간복잡도

**O(N³ × 6) = O(N³)**

여기서 N = 60 (최대 SCV 체력)

### 🔍 단계별 분석

#### 1️⃣ 상태 공간 크기
```
전체 가능한 상태 수 = 61 × 61 × 61 = 226,981개
```
- 각 SCV의 체력은 0~60 사이 (총 61가지)
- 3개의 SCV가 있으므로 3차원 상태 공간
- 이론적으로 최대 226,981개의 상태 존재

#### 2️⃣ 각 상태당 연산
```
각 상태에서 시도하는 작업:
  - 6가지 공격 패턴 순회: O(6)
  - 각 패턴당 연산:
    • 새로운 체력 계산 (max 연산 3번): O(3)
    • visited 확인: O(1)
    • 큐에 삽입: O(1)
  - 총 각 상태당: O(6) = O(1) (상수이므로)
```

#### 3️⃣ BFS + DP(메모이제이션) 탐색 특성
```
BFS + DP의 핵심 속성:
  ✅ 각 상태를 최대 1번만 방문 (visited 배열로 중복 방지) ← DP 메모이제이션!
  ✅ 큐에서 pop 연산: O(1)
  ✅ 큐에 push 연산: O(1)
  ✅ if(visited[na][nb][nc]) continue; ← 이미 계산된 부분 문제는 스킵!
```

**🔍 메모이제이션이 없다면?**

```
┌─────────────────────────────────────────────────────────────┐
│ 메모이제이션 **없이** (단순 완전 탐색)                        │
├─────────────────────────────────────────────────────────────┤
│ 깊이 1:        6개 상태                                      │
│ 깊이 2:       36개 상태  (6²)                                │

│ 깊이 4:    1,296개 상태  (6⁴)                                │

│ ...                                                          │
│ 깊이 15: 470,134,986개! (6^15) ← 시간 초과! ❌               │
├─────────────────────────────────────────────────────────────┤
│ 시간복잡도: O(6^depth) = 지수 시간                            │
│ 실제 실행: 4억 7천만 번의 연산 → 불가능!                      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 메모이제이션 **있음** (DP 적용)                               │

│ 깊이 2:      ~25개 상태 (누적:      31)                      │

├─────────────────────────────────────────────────────────────┤
│ 시간복잡도: O(N³) = 다항 시간 (최대 226,981)                  │
│ 실제 실행: 약 2만 번의 연산 → 0~4ms로 통과!                  │
└─────────────────────────────────────────────────────────────┘

📊 비교:
  - 메모이제이션 없이: 470,134,986 연산 (약 4.7억)
  - 메모이제이션 있음:      20,000 연산 (약 2만)
  - 차이: 약 23,500배! 🚀
```

**💡 왜 이렇게 차이가 날까?**
```
예: (3, 7, 3) 상태에 도달하는 경로가 여러 개 있다고 가정

메모이제이션 없이:
  (12,10,4) → (3,7,3)  ← 1번 계산
  (15,10,3) → (3,7,3)  ← 또 계산
  (12,13,4) → (3,7,3)  ← 또 계산
  → 같은 상태를 여러 번 계산! (지수적으로 증가)

메모이제이션 있음:
  (12,10,4) → (3,7,3)  ✅ visited[3][7][3] = 2 저장
  (15,10,3) → (3,7,3)  ❌ 이미 방문! continue
  (12,13,4) → (3,7,3)  ❌ 이미 방문! continue
  → 같은 상태는 1번만 계산!
```

```
총 시간복잡도 = (상태 수) × (각 상태당 연산)
             = O(61³) × O(6)
             = O(226,981) × O(6)
             = O(1,361,886)
             ≈ O(N³)
```

### 📊 실제 실행 시간 분석

**이론값 vs 실제값 차이가 큰 이유:**

```
이론적 최대: 226,981개 상태
실제 탐색: 약 5,000 ~ 20,000개 상태 (케이스에 따라 다름)
```

**실제로 훨씬 적은 이유:**

1. **도달 불가능한 상태가 많음**
   ```
   예: (60, 60, 60)에서 시작하는 경우
   → (51, 57, 59), (51, 59, 57), ... 등만 도달 가능
   → 대부분의 상태는 시작점에서 절대 도달 불가능
   ```

2. **BFS의 최단 경로 특성**
   ```
   visited[0][0][0]에 도달하는 순간 탐색 종료
   → 전체 상태 공간을 다 탐색하지 않음
   → 평균적으로 10~15회 공격이면 종료
   ```

3. **조기 종료 (Early Termination)**
   ```cpp
   if(visited[0][0][0]) break;  // 목표 도달 시 즉시 종료
   ```
   - 모든 SCV가 파괴되면 즉시 BFS 종료
   - 최악의 경우에도 깊이(공격 횟수)가 제한적

### 🎯 실제 실행 시간 예측

**입력 범위별 예상 탐색 상태 수:**

| SCV 체력 합계 | 예상 공격 횟수 | 탐색 상태 수 (추정) |
|--------------|---------------|-------------------|
| 3 이하       | 1회           | ~6개              |
| 10 이하      | 2~3회         | ~50개             |
| 30 이하      | 4~6회         | ~500개            |
| 60 이하      | 7~10회        | ~5,000개          |
| 180 (최대)   | 10~15회       | ~20,000개         |

**결론:**
- 이론적: O(226,981) ≈ 0.23M 연산
- 실제: O(5,000 ~ 20,000) ≈ 0.005M ~ 0.02M 연산
- **실제 실행 시간은 이론값의 1~10% 수준** 🚀

### ⚡ 성능 최적화 포인트

```cpp
// ✅ 최적화 1: visited 체크로 중복 방지

// ✅ 최적화 2: 목표 도달 시 즉시 종료

// ✅ 최적화 3: BFS는 자동으로 최단 경로 보장
```

## 🔄 DP: 탑다운 vs 바텀업 (이 문제는 어떤 방식?)

### 📌 DP의 두 가지 구현 방식

```
┌─────────────────────────────────────────────────────────────┐
│ 탑다운 (Top-Down) - 재귀 + 메모이제이션                       │
├─────────────────────────────────────────────────────────────┤
│ • 재귀 함수로 구현                                            │
│ • 큰 문제에서 시작하여 작은 문제로 분할                        │
│ • 필요한 부분만 계산 (Lazy Evaluation)                        │
│ • 예: DFS + 메모이제이션                                      │
│                                                              │
│ int solve(int a, int b, int c) {                            │
│     if (a == 0 && b == 0 && c == 0) return 0;              │
│     if (visited[a][b][c] != -1) return visited[a][b][c];   │
│     // ... 재귀 호출 ...                                     │
│     return visited[a][b][c] = min_value;                    │
│ }                                                            │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 바텀업 (Bottom-Up) - 반복문 + 테이블 채우기                   │
├─────────────────────────────────────────────────────────────┤
│ • 반복문으로 구현                                             │
│ • 작은 문제부터 시작하여 큰 문제로 확장                        │
│ • 모든 상태를 순서대로 계산                                   │
│ • 예: BFS + DP 테이블                                        │
│                                                              │
│ BFS() {                                                      │
│     visited[start] = 1;                                     │
│     while (!q.empty()) {                                    │
│         // 작은 상태 → 큰 상태로 확장                         │
│         visited[next] = visited[cur] + 1;                   │
│     }                                                        │
│ }                                                            │
└─────────────────────────────────────────────────────────────┘
```

### 🎯 이 문제는? **바텀업 방식!**

```
이 문제의 특징:
  - BFS로 구현 (큐 사용, 반복문)
  - 시작 상태 (12, 10, 4)에서 목표 상태 (0, 0, 0)으로 이동
  - 작은 체력 값으로 점진적으로 감소 (바텀업 방향)
  - visited 배열을 반복문으로 채워나감
```

**🔍 왜 바텀업인가?**

```
시작: (12, 10, 4) ← 큰 문제
  ↓ BFS로 상태 전이
(3, 7, 3), (9, 1, 3), ...  ← 중간 문제
  ↓ 계속 BFS
(0, 4, 2), (0, 1, 1), ...  ← 작은 문제
  ↓ 최종
(0, 0, 0) ← 가장 작은 문제 (목표)

→ 시작 상태부터 반복적으로 다음 상태를 계산해나감 (바텀업!)
→ BFS 특성상 레벨별로 순차적으로 탐색 (바텀업!)
```

### 💡 탑다운 vs 바텀업 비교표

| 구분 | 탑다운 (Top-Down) | 바텀업 (Bottom-Up) | 이 문제 |
|------|-------------------|-------------------|---------|
| **구현 방식** | 재귀 함수 | 반복문 (BFS) | ✅ 바텀업 |
| **방향** | 큰 문제 → 작은 문제 | 작은 문제 → 큰 문제 | ✅ 바텀업 |
| **계산 순서** | 필요할 때 계산 | 순서대로 모두 계산 | ✅ 바텀업 |
| **메모리** | 재귀 스택 + DP 테이블 | DP 테이블만 | ✅ 효율적 |
| **가독성** | 직관적 (문제 구조와 유사) | 약간 복잡 | - |

### 🔑 핵심 정리

```
이 문제는 BFS + DP (바텀업 방식)

✅ BFS의 레벨별 탐색 = 바텀업 DP의 순차적 계산
✅ visited 배열 = DP 테이블
✅ if(visited[na][nb][nc]) continue; = 메모이제이션

→ BFS와 DP가 완벽하게 결합된 문제!
```

## 🚨 주의사항

### 1️⃣ 이 문제의 핵심 개념

```
⚠️ 이 문제는 단순 BFS가 아닙니다!
→ BFS + DP (메모이제이션)이 결합된 문제입니다!

❌ 흔한 오해: "그냥 BFS 최단 경로 문제"
✅ 정확한 이해: "BFS + DP 최적화를 통한 상태 공간 탐색 문제"
```

### 2️⃣ visited 배열의 이중 역할

```cpp
visited[a][b][c]의 두 가지 역할:

1️⃣ BFS 관점: 방문 체크 배열
   - 이미 방문한 상태인지 확인
   - if(visited[na][nb][nc]) continue;

2️⃣ DP 관점: 메모이제이션 테이블
   - 해당 상태까지의 최소 공격 횟수 저장
   - 중복 계산 방지

→ 두 역할을 동시에 수행하는 것이 핵심!
```

### 3️⃣ 메모이제이션 필수!

```cpp
// ⭐ 이 한 줄이 시간복잡도를 결정합니다!
if(visited[na][nb][nc]) continue;  // 메모이제이션

이 줄이 없다면:
  - 시간복잡도: O(6^15) ≈ 4억 7천만 (시간 초과!)
  - 실제 실행: 불가능

이 줄이 있다면:
  - 시간복잡도: O(61³) ≈ 22만 (통과!)
  - 실제 실행: 0~4ms
```

### 4️⃣ 기타 주의사항

1. **visited는 1-based**: 0은 미방문 표시, 시작점은 1로 설정
2. **출력 시 -1 보정**: `visited[0][0][0] - 1`로 실제 공격 횟수 계산
3. **max(0, ...) 처리**: 체력이 음수가 되지 않도록 방지
4. **SCV 개수 처리**: N이 1 또는 2인 경우도 고려 (나머지는 0으로 초기화)
5. **바텀업 DP**: BFS의 레벨별 탐색 = 바텀업 DP의 순차적 계산
