## 🤔 접근법

(문제 지문이 길어서, 어떻게 풀어야 할지 헷갈렸다.)

(하지만, 쉽게 생각하면, 클리어 가능한 체력을 최대에서 부터 이분 탐색으로 구하면 되는 문제였다.)

용사가 N개의 방을 순서대로 지나며 공주를 구하러 가는 문제다.

각 방에는 **몬스터**가 있거나 **포션**이 있고, 몬스터와 싸우면 체력이 감소한다.

용사는 던전에 들어가기 전 **최대 체력(HMaxHP)을 수련으로 늘릴 수 있다**.

**핵심은 이분 탐색(매개 변수 탐색)을 사용하여 N번째 방까지 살아남을 수 있는 최소 체력을 찾는 것!**

---

## 💡 핵심 아이디어

### 🔑 이분 탐색 (Parametric Search)

**문제 조건:**
- N개의 방을 순서대로 통과해야 함
- 각 방에는 몬스터 또는 포션이 있음
- 몬스터 방: 전투 발생 (체력 감소)
- 포션 방: 공격력 증가 + 체력 회복
- 용사가 살아남으려면 최소 얼마의 체력이 필요한가?

**알고리즘 흐름:**
```
1. 이분 탐색 범위 설정:
   - left (최소값): 1 (체력은 최소 1 이상)
   - right (최대값): 1e18 + 4 (충분히 큰 값)

2. 이분 탐색으로 최대 체력 탐색:
   - mid = (left + right) / 2
   - Check(mid): mid 체력으로 N번째 방까지 살아남을 수 있는지 확인

3. Check 함수:
   - 각 방을 순서대로 시뮬레이션
   - 몬스터 방: 전투 후 체력 감소
   - 포션 방: 공격력 증가 + 체력 회복
   - 중간에 체력이 0 이하가 되면 false 반환
   - 모든 방 통과 시 true 반환

4. 이분 탐색 조건:
   - Check(mid)가 true → 더 작은 체력 시도 (right = mid - 1)
   - Check(mid)가 false → 체력 증가 필요 (left = mid + 1)
```

**시간 복잡도**: O(N × log(최댓값))
- 이분 탐색: O(log(1e18)) ≈ O(60)
- Check 함수: O(N) (최대 123,456)
- 전체: O(N × log(1e18)) = 123,456 × 60 ≈ 7,400,000 (충분히 통과)

**공간 복잡도**: O(N)
- t, a, h 배열: O(N)

## 🔑 주요 구현 포인트

### 1️⃣ 전투 시스템 계산

```cpp
// 몬스터 처치에 필요한 공격 횟수
ll loopCount = h[i] / currentAtk;
if (h[i] % currentAtk != 0)
    loopCount++;

// 내가 먼저 공격하므로, (공격 횟수 - 1)만큼 적의 공격을 받음
currentHP -= (loopCount - 1) * a[i];
```

**✅ 핵심**:
- **loopCount**: 몬스터를 죽이는 데 필요한 공격 횟수
  - `h[i] / currentAtk`: 나눗셈
  - 나머지가 있으면 +1 (올림 처리)
- **데미지 계산**: `(loopCount - 1) × a[i]`
  - 내가 먼저 공격하므로 마지막 공격 전에는 적도 공격함
  - 예: 3번 공격하면 → 내가 공격 → 적이 공격 → 내가 공격 → 적이 공격 → 내가 공격 (적 사망)
  - 적의 공격 횟수 = 내 공격 횟수 - 1

**📌 삼항 연산자 버전 (더 간결):**
```cpp
ll cnt = h[i] / init_attack + (h[i] % init_attack ? 1 : 0);
```

---

### 2️⃣ 포션 방 처리

```cpp
// 공격력 증가
currentAtk += a[i];

// 체력 회복 (최대 체력 초과 불가)
currentHP += h[i];
if (currentHP > mid)
    currentHP = mid;
```

**✅ 핵심**:
- 공격력 증가: `currentAtk += a[i]`
- 체력 회복: `currentHP += h[i]`
- **최대 체력 제한**: 회복 후 체력이 최대 체력(mid)을 초과할 수 없음

**📌 min 함수 버전 (더 간결):**
```cpp
currentHP = min(mid, currentHP + h[i]);
```

---

### 3️⃣ 중간 체크로 조기 종료

```cpp
// 각 방을 지날 때마다 체력 체크 (죽으면 즉시 false)
if (currentHP <= 0)
    return false;
```

**✅ 핵심**:
- 모든 방을 돈 후가 아니라 **각 방마다** 체력 체크
- 체력이 0 이하가 되면 **즉시 false 반환**
- **중요한 이유**:
  - 몬스터에게 죽은 후 포션을 먹는 불가능한 시나리오 방지
  - 예: 몬스터 방에서 체력 -100 → 포션 방에서 +50 → -50 (잘못된 계산)
  - 실제로는 몬스터 방에서 이미 죽었으므로 포션을 먹을 수 없음!

---

### 4️⃣ 이분 탐색 범위 설정

```cpp
lo = 1;          // 체력은 최소 1 이상
hi = LLONG_MAX;  // long long 최댓값 (또는 1e18 + 4)
```

**✅ 핵심**:
- **lo = 1**: 체력은 최소 1 이상이어야 함
- **hi = LLONG_MAX**: 충분히 큰 값
  - `LLONG_MAX`: 9,223,372,036,854,775,807 (약 9×10^18)
  - `1e18 + 4`: 1,000,000,000,000,000,004 (약 10^18)
  - 문제 조건상 체력이 이보다 클 일은 없음

**⚠️ 주의**:
- `LONG_MAX` 사용 금지!
  - Windows에서 `LONG_MAX` = `INT_MAX` = 약 21억
  - 필요한 체력이 1조를 넘을 수 있음 (예제 2번)
- 반드시 `LLONG_MAX` 또는 `1e18` 사용!

---

### 5️⃣ long long 타입 필수

```cpp
typedef long long ll;

ll n, atk;
ll t[130005], a[130005], h[130005];
ll lo, hi, ret;
```

**✅ 핵심**:
- 모든 변수를 `long long` 타입으로 선언
- **이유**:
  - N 최대 123,456
  - 공격력, 체력 최대 1,000,000
  - 최악의 경우 필요한 체력: 999,999,000,001 (약 1조)
  - `int` 범위(약 21억) 초과 → **오버플로우**

## 📊 예제 1 상세 시뮬레이션

**입력**:
```
3 3
1 1 20
2 3 10
1 3 100
```

### 🎯 Step 1: 초기 설정

```
n = 3, atk = 3
방 정보:
  방 1: t=1 (몬스터), a=1 (공격력), h=20 (체력)
  방 2: t=2 (포션), a=3 (공격력 증가), h=10 (체력 회복)
  방 3: t=1 (몬스터), a=3 (공격력), h=100 (체력)

이분 탐색 범위:
  lo = 1
  hi = 1e18 + 4
```

<br>

### 🔄 Step 2: 이분 탐색 과정

#### [1단계] mid = 49 확인

**Check(49) 실행:**

| 방 | 타입 | 동작 | currentHP | currentAtk |
|---|------|------|-----------|------------|
| 초기 | - | - | 49 | 3 |
| 1 | 몬스터 | loopCount = 20/3 = 7<br>데미지 = (7-1)×1 = 6<br>HP -= 6 | 43 | 3 |
| 2 | 포션 | 공격력 +3<br>체력 +10 (→ 49로 제한) | 49 | 6 |
| 3 | 몬스터 | loopCount = 100/6 = 17<br>데미지 = (17-1)×3 = 48<br>HP -= 48 | 1 | 6 |

**결과**: currentHP = 1 > 0 → **true**

**이분 탐색 갱신:**
- ret = 49 (현재 최소 체력)
- hi = 48 (더 작은 체력 시도)

<br>

#### [2단계] mid = 24 확인

**Check(24) 실행:**

| 방 | 타입 | 동작 | currentHP | currentAtk |
|---|------|------|-----------|------------|
| 초기 | - | - | 24 | 3 |
| 1 | 몬스터 | loopCount = 7<br>데미지 = 6 | 18 | 3 |
| 2 | 포션 | 공격력 +3<br>체력 +10 (→ 24로 제한) | 24 | 6 |
| 3 | 몬스터 | loopCount = 17<br>데미지 = 48 | -24 ❌ | 6 |

**결과**: currentHP = -24 ≤ 0 → **false**

**이분 탐색 갱신:**
- lo = 25 (체력 증가 필요)

<br>

#### [계속 탐색...]

최종적으로 `lo = 49`, `hi = 48`에서 종료

<br>

### ✅ Step 3: 최종 결과

```
출력: 49
```

**최적 시나리오 (체력 49로 시작):**
1. 방 1 (몬스터): 49 - 6 = 43
2. 방 2 (포션): 43 + 10 = 53 → 49로 제한
3. 방 3 (몬스터): 49 - 48 = 1 (생존!) ✅

## 📊 예제 2 상세 시뮬레이션

**입력**:
```
1 1
1 1000000 1000000
```

### 분석

```
방 1: 몬스터 (공격력 1,000,000, 체력 1,000,000)
용사 공격력: 1

몬스터 처치 공격 횟수: 1,000,000 / 1 = 1,000,000회
용사가 받는 데미지: (1,000,000 - 1) × 1,000,000 = 999,999,000,000

필요한 최소 체력: 999,999,000,000 + 1 = 999,999,000,001
```

**출력**: `999999000001`

**⚠️ 이 값은 약 1조 (10^12)로, int 범위(21억)를 훨씬 초과!**

## ⏱️ 시간복잡도

**O(N × log(최댓값))**

**분석**:
- N = 방의 수 (최대 123,456)
- 최댓값 = 1e18 (10^18)
- 이분 탐색: O(log(1e18)) ≈ O(60)
- Check 함수: O(N)
- 전체: O(123,456 × 60) ≈ O(7,400,000) (충분히 통과)
