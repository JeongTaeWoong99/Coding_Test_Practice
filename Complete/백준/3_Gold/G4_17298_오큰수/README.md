## 🔗 문제 링크

[백준 17298번 - 오큰수](https://www.acmicpc.net/problem/17298)

**난이도**: Gold 4

---

## 🤔 접근법

수열의 각 원소에 대해 **오른쪽에 있으면서** 그 원소보다 **큰 수 중 가장 왼쪽에 있는 수**(오큰수)를 찾는 문제.

처음에는 이중 반복문으로 접근했지만, N=1,000,000일 때 O(N²) 시간복잡도로는 시간 초과 발생!

핵심은 **스택 자료구조**를 사용하여 O(N)으로 해결하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 스택 (Stack)

**핵심 아이디어**:

```
1. 스택에는 "아직 오큰수를 찾지 못한 원소들의 인덱스"를 저장
2. 새로운 수가 들어올 때마다:
   - 스택의 top 인덱스가 가리키는 값보다 크면 → 오큰수 발견!
   - 오큰수를 찾은 원소는 스택에서 제거
   - 현재 인덱스를 스택에 추가
3. 모든 입력을 처리한 후에도 스택에 남은 원소들은 오큰수가 없음 (-1)
```

**시간복잡도**: O(N)
- 각 원소는 스택에 최대 1번 push, 1번 pop
- 총 연산 횟수: 2N = O(N)

**공간복잡도**: O(N)
- 스택의 최대 크기: N

## 🔍 스택 풀이 상세 동작 과정

### 📌 예제 1: [3, 5, 2, 7]

#### 초기 상태
```
arr = [3, 5, 2, 7]
ret = [-1, -1, -1, -1]  ← memset으로 -1 초기화
stk = []                ← 빈 스택
```

---

#### ➡️ i=0, arr[0]=3

**동작**:
1. `while` 조건: `stk.empty()` → true (스택이 비어있음)
2. `while` 문 실행 안 함
3. `stk.push(0)` → 인덱스 0을 스택에 추가

**상태**:
```
arr = [3, 5, 2, 7]
      ↑
      i=0

ret = [-1, -1, -1, -1]
stk = [0]  ← 인덱스 0 추가
       (3) ← arr[0] = 3
```

---

#### ➡️ i=1, arr[1]=5

**동작**:
1. `while` 조건: `!stk.empty() && arr[stk.top()] < arr[1]`
   - `!stk.empty()` → true (스택에 [0]이 있음)
   - `arr[stk.top()]` = `arr[0]` = 3
   - `arr[1]` = 5
   - **3 < 5** → true ✅
2. `while` 문 실행:
   - `ret[stk.top()]` = `ret[0]` = `arr[1]` = **5** ← **오큰수 발견!**
   - `stk.pop()` → 인덱스 0 제거
3. `while` 조건 재확인: `stk.empty()` → true (스택이 비었음)
4. `while` 문 종료
5. `stk.push(1)` → 인덱스 1을 스택에 추가

**상태**:
```
arr = [3, 5, 2, 7]
          ↑
          i=1

ret = [5, -1, -1, -1]  ← ret[0] = 5로 업데이트!
       ✅
stk = [1]  ← 인덱스 0 제거, 인덱스 1 추가
       (5) ← arr[1] = 5
```

**📊 의미**: arr[0]=3의 오큰수는 arr[1]=5

---

#### ➡️ i=2, arr[2]=2

**동작**:
1. `while` 조건: `!stk.empty() && arr[stk.top()] < arr[2]`
   - `!stk.empty()` → true (스택에 [1]이 있음)
   - `arr[stk.top()]` = `arr[1]` = 5
   - `arr[2]` = 2
   - **5 < 2** → false ❌
2. `while` 문 실행 안 함 (5가 2보다 크므로 오큰수 아님)
3. `stk.push(2)` → 인덱스 2를 스택에 추가

**상태**:
```
arr = [3, 5, 2, 7]
             ↑
             i=2

ret = [5, -1, -1, -1]  ← 변화 없음
       ✅
stk = [1, 2]  ← 인덱스 2 추가
       (5)(2) ← arr[1]=5, arr[2]=2
```

**📊 의미**: arr[1]=5보다 arr[2]=2가 작으므로, 2는 5의 오큰수가 될 수 없음

---

#### ➡️ i=3, arr[3]=7

**동작**:
1. **첫 번째 while 반복**:
   - `while` 조건: `!stk.empty() && arr[stk.top()] < arr[3]`
   - `arr[stk.top()]` = `arr[2]` = 2
   - `arr[3]` = 7
   - **2 < 7** → true ✅
   - `ret[2]` = `arr[3]` = **7** ← **오큰수 발견!**
   - `stk.pop()` → 인덱스 2 제거
   - 스택: [1]

2. **두 번째 while 반복**:
   - `while` 조건 재확인: `!stk.empty() && arr[stk.top()] < arr[3]`
   - `arr[stk.top()]` = `arr[1]` = 5
   - `arr[3]` = 7
   - **5 < 7** → true ✅
   - `ret[1]` = `arr[3]` = **7** ← **오큰수 발견!**
   - `stk.pop()` → 인덱스 1 제거
   - 스택: []

3. **세 번째 while 반복**:
   - `while` 조건 재확인: `stk.empty()` → true
   - `while` 문 종료

4. `stk.push(3)` → 인덱스 3을 스택에 추가

**상태**:
```
arr = [3, 5, 2, 7]
                ↑
                i=3

ret = [5, 7, 7, -1]  ← ret[1]=7, ret[2]=7로 업데이트!
       ✅ ✅ ✅
stk = [3]  ← 인덱스 1, 2 제거, 인덱스 3 추가
       (7) ← arr[3] = 7
```

**📊 의미**:
- arr[2]=2의 오큰수는 arr[3]=7
- arr[1]=5의 오큰수도 arr[3]=7

---

#### 🎯 최종 결과

**반복문 종료 후**:
```
ret = [5, 7, 7, -1]
       ✅ ✅ ✅ ✅

stk = [3]  ← 인덱스 3은 오큰수를 찾지 못함 (ret[3] = -1 유지)
```

**출력**: `5 7 7 -1` ✅

### 📌 예제 2: [9, 5, 4, 8]

#### 전체 동작 흐름

| i | arr[i] | while 동작 | ret 상태 | stk 상태 |
|---|--------|-----------|---------|---------|
| **0** | 9 | 스택 비어있음 → while 실행 안 함 | [-1, -1, -1, -1] | [0] (9) |
| **1** | 5 | arr[0]=9 > 5 → while 실행 안 함 | [-1, -1, -1, -1] | [0, 1] (9, 5) |
| **2** | 4 | arr[1]=5 > 4 → while 실행 안 함 | [-1, -1, -1, -1] | [0, 1, 2] (9, 5, 4) |
| **3** | 8 | **arr[2]=4 < 8** → ret[2]=8, pop<br>**arr[1]=5 < 8** → ret[1]=8, pop<br>arr[0]=9 > 8 → while 종료 | [-1, 8, 8, -1] | [0, 3] (9, 8) |

**최종 상태**:
```
ret = [-1, 8, 8, -1]
       ✅  ✅ ✅  ✅

stk = [0, 3]  ← 인덱스 0, 3은 오큰수를 찾지 못함
```

**출력**: `-1 8 8 -1` ✅

## 🔑 핵심 포인트

### 1️⃣ 왜 스택에 인덱스를 저장하는가?

```cpp
stack<int> stk;  // 값이 아닌 인덱스를 저장!
```

**이유**:
- ret 배열의 인덱스를 알아야 해당 위치에 오큰수를 저장할 수 있음
- `ret[stk.top()] = arr[i]` ← 스택의 top 인덱스 위치에 현재 값을 저장

**만약 값을 저장하면?**
```cpp
// ❌ 잘못된 방법
stack<int> stk;  // 값을 저장
stk.push(arr[i]);

// 문제: ret의 어느 인덱스에 저장해야 할지 알 수 없음!
ret[?] = arr[i];  // ? 를 알 수 없음
```

---

### 2️⃣ 왜 while 문을 사용하는가?

```cpp
while (!stk.empty() && arr[stk.top()] < arr[i])
{
    ret[stk.top()] = arr[i];
    stk.pop();
}
```

**※ arr[stk.top()] < arr[i]를 만족하면, top이 계속 pop 되면서, 모두 체크가 가능한 것 이다!**

**이유**:
- 현재 값(arr[i])보다 작은 값들을 **모두** 처리해야 하기 때문
- **예**: [5, 4, 7]에서 7이 들어오면:
  - 4의 오큰수 = 7
  - 5의 오큰수 = 7
  - **두 개 모두** 처리해야 함!

**만약 if 문을 사용하면?**
```cpp
// ❌ 잘못된 방법
if (!stk.empty() && arr[stk.top()] < arr[i])
{
    ret[stk.top()] = arr[i];
    stk.pop();
}

// 문제: 스택의 top 하나만 처리하고 끝남
// [5, 4, 7] 예시에서 4만 처리되고 5는 처리 안 됨!
```

---

### 3️⃣ 왜 O(N) 시간복잡도인가?

**분석**:
```
각 원소는 스택에:
  - 최대 1번 push
  - 최대 1번 pop

총 연산 횟수:
  - N번 push + N번 pop = 2N = O(N)
```

**예시**: [3, 5, 2, 7]
- 인덱스 0: push(0) → pop(0) = 2번
- 인덱스 1: push(1) → pop(1) = 2번
- 인덱스 2: push(2) → pop(2) = 2번
- 인덱스 3: push(3) = 1번 (pop 안 함)
- **총 7번 연산** = O(4) = O(N)

---

### 4️⃣ 스택에 남은 원소들은?

```cpp
// 반복문 종료 후 스택에 남은 원소들은 오큰수가 없음
stk = [3]  ← arr[3]은 오른쪽에 더 큰 수가 없음
```

**이유**:
- `memset(ret, -1, sizeof(ret))`로 초기화했기 때문에
- 오큰수를 찾지 못한 원소들은 자동으로 -1 유지

## 📊 시간복잡도 비교

### ❌ 이중 반복문 방식 (처음 시도)

```cpp
for (int i = 0; i < N; i++)
{
    for (int j = i - 1; j >= 0; j--)
    {
        if (ret[j] == -1 && arr[j] < arr[i])
        {
            ret[j] = arr[i];
        }
    }
}
```

**시간복잡도**: O(N²)

| N | 연산 횟수 | 시간 제한 (1초) |
|---|----------|--------------|
| 1,000 | 약 500,000번 | ✅ 통과 |
| 10,000 | 약 50,000,000번 | ⚠️ 아슬아슬 |
| **1,000,000** | 약 500,000,000,000번 | ❌ **시간 초과!** |

---

### ✅ 스택 방식

```cpp
for (int i = 0; i < N; i++)
{
    cin >> arr[i];

    while (!stk.empty() && arr[stk.top()] < arr[i])
    {
        ret[stk.top()] = arr[i];
        stk.pop();
    }

    stk.push(i);
}
```

**시간복잡도**: O(N)

| N | 연산 횟수 | 시간 제한 (1초) |
|---|----------|--------------|
| 1,000 | 약 2,000번 | ✅ 통과 |
| 10,000 | 약 20,000번 | ✅ 통과 |
| **1,000,000** | 약 2,000,000번 | ✅ **통과!** |

---

## ⏱️ 시간복잡도

**O(N)** - N은 수열의 크기

**분석**:
- 입력 처리: O(N)
- 각 원소의 스택 연산: push 1번 + pop 최대 1번 = O(2N) = O(N)
- 출력: O(N)
- **총합**: O(N) + O(N) + O(N) = O(N)

---

## 💾 공간복잡도

**O(N)**

**분석**:
- `arr` 배열: O(N)
- `ret` 배열: O(N)
- `stk` 스택: 최대 O(N) (모든 원소가 내림차순일 때)
- **총합**: O(N)
