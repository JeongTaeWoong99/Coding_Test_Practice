## 🔗 문제 링크

[백준 2240번 - 자두나무](https://www.acmicpc.net/problem/2240)

**난이도**: Gold 4

---

## 🤔 접근법

![img.png](img.png)

(DP는 어렵다)

자두가 T초 동안 1번 또는 2번 나무에서 떨어질 때, 최대 W번 이동하여 최대한 많은 자두를 받는 문제이다.

자두는 처음에 1번 나무 아래에 위치해 있으며, 나무 사이를 빠르게 이동할 수 있다.

매 초마다 어느 나무에서 자두가 떨어질지가 주어지므로, **각 시점에서 어느 나무에 있을지 선택**하는 문제이다.

이 문제는 **동적 계획법 (DP)** 으로 해결할 수 있으며, 특히 **탑다운 (재귀 + 메모이제이션)** 방식이 적합하다.

**핵심은 3차원 DP 테이블**을 사용하여 `[현재 시간][현재 위치][남은 이동 횟수]` 상태를 관리하는 것!

---

## 💡 핵심 아이디어

### 🔑 DP 정의

**DP 테이블**:
```cpp
dp[curTime][curTree][remainMove] =
    현재 시간이 curTime이고,
    현재 나무가 curTree(0 or 1)이며,
    남은 이동 횟수가 remainMove일 때
    앞으로 받을 수 있는 최대 자두 개수
```

**점화식**:
```cpp
dp[curTime][curTree][remainMove] =
    max(
        // 안 움직이기
        Go(curTime + 1, curTree, remainMove),
        // 다른 나무로 이동하기
        Go(curTime + 1, curTree^1, remainMove - 1)
    ) + (curTree == drop[curTime] - 1 ? 1 : 0)
```

**시간 복잡도**: O(T × 2 × W)
- T = 시간 (최대 1,000)
- 2 = 나무 개수
- W = 최대 이동 횟수 (최대 30)
- 총: 1,000 × 2 × 30 = 60,000번 연산

**공간 복잡도**: O(T × 2 × W)
- dp 배열: 1,004 × 2 × 34 = 약 68KB

## 🔑 주요 구현 포인트

### 1️⃣ ☆ 왜 탑다운 DP인가?

```
┌─────────────────────────────────────────────────────────────┐
│ 탑다운 (Top-Down) - 재귀 + 메모이제이션                       │
├─────────────────────────────────────────────────────────────┤
│ • 큰 문제에서 시작하여 작은 문제로 분할                        │
│ • 필요한 부분만 계산 (Lazy Evaluation)                        │
│ • 재귀적 구조가 문제와 직관적으로 일치                         │
│                                                              │
│ Go(0, 0, m) → Go(1, 0, m) → Go(2, 1, m-1) → ...            │
│   "시작"       "1초 후"      "2초 후 이동"                    │
│                                                              │
│ → 시간 순서대로 선택을 하는 문제 구조와 완벽히 일치!           │
└─────────────────────────────────────────────────────────────┘
※ (0 0)에서 시작한다는게 중요한게 아니라, 재귀 + 메모이제이션 '가지치기'로 제외하면서, 문제 해결!
※ 큰 문제였지만, 작은 문제로 만듬.

┌─────────────────────────────────────────────────────────────┐
│ 바텀업 (Bottom-Up) - 반복문                                   │
├─────────────────────────────────────────────────────────────┤
│ • 작은 문제부터 시작하여 큰 문제로 확장                        │
│ • 모든 상태를 순서대로 계산                                   │
│ • 반복문 3중 for문 필요 (시간, 위치, 이동 횟수)               │
│                                                              │
│ for(int t = n-1; t >= 0; t--)                               │
│   for(int tree = 0; tree < 2; tree++)                       │
│     for(int move = 0; move <= m; move++)                    │
│       dp[t][tree][move] = ...                               │
│                                                              │
│ → 구현이 복잡하고 직관성이 떨어짐                             │
└─────────────────────────────────────────────────────────────┘
※ (0 0)에서 시작해서, 전체 다(큰 부분) 계산함.
※ 작은 문제였지만, 전체 다 즉, 큰 문제로 해결.

```

**🎯 이 문제에서 탑다운을 선택한 이유**:

1. **문제 구조와 일치** : "0초부터 시작해서 매 초마다 선택" → 재귀 구조와 완벽히 일치
2. **구현 간결성** : 재귀 함수 하나로 모든 상태 전이 표현 가능
3. **필요한 상태만 계산** : 실제로 도달 가능한 상태만 계산 (최적화)
4. **직관적 이해** : 코드 흐름이 문제 설명과 동일하게 진행

### 2️⃣ 테스트 케이스 재귀 흐름 분석

**입력 예시**:
```
7 2
2
1
1
2
2
1
1
```

**재귀 호출 트리 (일부)**:
```
Go(0, 0, 2)  ← 시작: 0초, 1번 나무(0), 이동 가능 2번
│
├─ Go(1, 0, 2)  ← 0초: 안 움직임 (drop[0]=2이므로 자두 못 받음, +0)
│  │
│  ├─ Go(2, 0, 2)  ← 1초: 안 움직임 (drop[1]=1이므로 자두 받음, +1)
│  │  │
│  │  ├─ Go(3, 0, 2)  ← 2초: 안 움직임 (drop[2]=1이므로 자두 받음, +1)
│  │  │  └─ ... (계속 진행)
│  │  │
│  │  └─ Go(3, 1, 1)  ← 2초: 2번 나무로 이동 (drop[2]=1이므로 자두 못 받음, +0)
│  │     └─ ... (계속 진행)
│  │
│  └─ Go(2, 1, 1)  ← 1초: 2번 나무로 이동 (drop[1]=1이므로 자두 못 받음, +0)
│     └─ ... (계속 진행)
│
└─ Go(1, 1, 1)  ← 0초: 2번 나무로 이동 (drop[0]=2이므로 자두 받음, +1) ⭐
   │
   ├─ Go(2, 1, 1)  ← 1초: 안 움직임 (drop[1]=1이므로 자두 못 받음, +0)
   │  │
   │  ├─ Go(3, 1, 1)  ← 2초: 안 움직임 (drop[2]=1이므로 자두 못 받음, +0)
   │  │  └─ ...
   │  │
   │  └─ Go(3, 0, 0)  ← 2초: 1번 나무로 이동 (drop[2]=1이므로 자두 받음, +1) ⭐
   │     │
   │     ├─ Go(4, 0, 0)  ← 3초: 안 움직임 (drop[3]=2이므로 자두 못 받음, +0)
   │     │  │
   │     │  ├─ Go(5, 0, 0)  ← 4초: 안 움직임 (drop[4]=2이므로 자두 못 받음, +0)
   │     │  │  └─ ...
   │     │  │
   │     │  └─ Go(5, 1, -1) ← remainMove < 0 → return -1e9 (불가능)
   │     │
   │     └─ Go(4, 1, -1) ← remainMove < 0 → return -1e9 (불가능)
   │
   └─ Go(2, 0, 0)  ← 1초: 1번 나무로 이동 (drop[1]=1이므로 자두 받음, +1) ⭐
      │
      └─ Go(3, 0, 0)  ← 2초: 안 움직임 (drop[2]=1이므로 자두 받음, +1) ⭐
         └─ ... (이동 불가능, 계속 1번 나무에 있음)
            └─ 결과: 1 + 1 + 1 + 0 + 0 + 1 + 1 = 5
```

**🔍 최적 경로 분석**:
```
초  0  1  2  3  4  5  6  (curTime)
나무 2  1  1  2  2  1  1  (drop[i])
위치 1→ 1  1  2→ 2  2→ 2  (curTree: 0=1번, 1=2번)
획득 X  O  O  O  O  X  X  = 4개

하지만 더 나은 경로:
위치 2→ 1→ 1  2→ 2  1→ 1  (이동: 0초, 1초, 3초 총 3번 - 불가능!)

최적 경로 (이동 2번):
위치 2→ 1  1  1  1  1  1
획득 O  O  O  X  X  O  O  = 5개

또는:
위치 1  1  1  2→ 2  2→ 2
획득 X  O  O  O  O  X  X  = 4개

최적해: 6개 (문제에서 출력)
```

**💡 메모이제이션의 효과**:
```
Go(2, 0, 1)이 여러 경로에서 호출될 수 있음:
  - Go(1, 0, 2) → Go(2, 0, 1) (안 움직임 + 이동)
  - Go(1, 1, 1) → Go(2, 0, 1) (이동)

→ 첫 번째 계산 후 dp[2][0][1]에 저장
→ 두 번째 호출 시 즉시 반환 (중복 계산 방지!)
```

### 3️⃣ 3차원 DP 배열

```cpp
int dp[1004][2][34];
// [현재 시간][현재 나무 위치(0 or 1)][남은 이동 횟수]
```

**✅ 핵심**:
- 시간: 0 ~ n (최대 1,000)
- 나무: 0 (1번 나무), 1 (2번 나무)
- 남은 이동: 0 ~ m (최대 30)
- -1로 초기화하여 "아직 계산 안 됨" 표시

### 4️⃣ 메모이제이션 (중복 계산 방지)

```cpp
int &ret = dp[curTime][curTree][remainMove];
if(ret != -1) return ret;  // ⭐ 이미 계산된 값이 있으면 즉시 반환
```

**✅ 핵심**:
- `int &ret`: 참조를 사용하여 dp 배열 값을 직접 수정
- 이미 계산된 상태는 다시 계산하지 않음
- 시간복잡도를 지수 시간에서 다항 시간으로 감소

### 5️⃣ 토글 연산자 (XOR)로 간결한 코드

```cpp
// curTree^1 : XOR 연산으로 0↔1 토글
// 0 ^ 1 = 1
// 1 ^ 1 = 0

return ret = max(
    Go(curTime + 1, curTree  , remainMove    ),     // 안 움직임
    Go(curTime + 1, curTree^1, remainMove - 1)      // 다른 나무로 이동 (토글!)
) + (curTree == drop[curTime] - 1);
```

**✅ 핵심**:
- `curTree^1`을 사용하면 if-else 없이 다른 나무 번호를 계산 가능
- 코드가 간결해지고 가독성이 향상됨
- 나무가 0, 1로 인덱싱되므로 XOR 연산이 자연스럽게 적용됨

**🔍 토글 연산자를 사용하지 않는다면?**
```cpp
// ❌ 토글 연산자 미사용 시
int otherTree;
if(curTree == 1)
    otherTree = 2;
else
    otherTree = 1;

return ret = max(
    Go(curTime + 1, curTree   , remainMove    ),
    Go(curTime + 1, otherTree , remainMove - 1)
) + (curTree == drop[curTime]);
```

**비교**:
- 토글 연산자 사용: 1줄로 간결하게 표현 (`curTree^1`)
- 토글 연산자 미사용: if-else 4줄 + 변수 선언 필요
- **코드 간결성과 가독성에서 큰 차이!**

### 6️⃣ 종료 조건

```cpp
// 남은 이동 횟수가 음수면 불가능
if(remainMove < 0) return -1e9;  // max 연산에서 선택되지 않도록

// 모든 시간이 지나면 0 반환
if(curTime == n) return 0;
```

**✅ 핵심**:
- 이동 횟수를 초과하면 매우 작은 값 반환 (불가능한 경로)
- 시간이 끝나면 더 이상 자두를 받을 수 없으므로 0 반환
- 이 문제는 "m번 이하" 이동이므로 정확히 m번 사용할 필요 없음

### 7️⃣ 자두 획득 조건

```cpp
+ (curTree == drop[curTime] - 1)
```

**✅ 핵심**:
- `drop[curTime]`: 현재 시간에 자두가 떨어지는 나무 (1 또는 2)
- `drop[curTime] - 1`: 0 또는 1로 변환 (curTree와 비교 가능)
- 현재 나무 위치와 자두가 떨어지는 나무가 같으면 +1

### 8️⃣ 시작 조건 (2가지 경우)

```cpp
// 자두는 처음에 1번 나무(0) 아래에 있음
cout << max(
    Go(0, 0, m),      // 1번 나무에 그대로 있기 (이동 0번)
    Go(0, 1, m - 1)   // 2번 나무로 이동하기 (이동 1번)
);
```

**✅ 핵심**:
- 자두는 처음에 1번 나무(인덱스 0) 아래에 위치
- 경우 1: 그대로 있기 → 이동 0번
- 경우 2: 시작하자마자 2번 나무로 이동 → 이동 1번 소모
- 두 경우 중 최댓값 선택

## ⏱️ 시간복잡도

**O(T × 2 × W)**

여기서:
- T = 시간 (최대 1,000)
- 2 = 나무 개수 (1번, 2번)
- W = 최대 이동 횟수 (최대 30)

**계산**:
```
전체 상태 개수 = 1,000 × 2 × 30 = 60,000
각 상태당 연산 = O(1) (메모이제이션으로 1번만 계산)
총 시간복잡도 = O(60,000) ≈ O(T × W)
```

**실제 실행 시간**: 0~4ms (매우 빠름) ✅

---

## 💾 공간복잡도

**O(T × 2 × W)**

- `dp[1004][2][34]`: 약 68KB
- `drop[1004]`: 약 4KB
- 재귀 스택: O(T) = 최대 1,000 깊이

**총 메모리**: 약 72KB (매우 효율적) ✅

## 🚨 주의사항

1. **DP 배열 초기화**: `-1`로 초기화하여 "계산 안 됨" 표시
2. **이동 횟수 체크**: `remainMove < 0`이면 불가능한 경로
3. **인덱스 변환**: `drop[i]`는 1 또는 2, `curTree`는 0 또는 1
4. **시작 조건**: 자두는 1번 나무(0)에서 시작
5. **이하 조건**: m번 "이하" 이동 가능 (정확히 m번 아님)
6. **토글 연산자**: `curTree^1`로 간결하게 다른 나무 표현 가능
