## 🔗 문제 링크

[백준 4781번 - 사탕 가게](https://www.acmicpc.net/problem/4781)

**난이도**: Gold 4

## 🤔 접근법

(바텀 업 DP 응용 문제인데, 형변환과 부동소수점을 알아야 풀 수 있다.)

상근이가 가진 돈으로 구매할 수 있는 사탕의 **최대 칼로리**를 구하는 문제이다.

각 사탕은 **무한히 구매 가능**하며 (같은 사탕을 여러 개 살 수 있음), 돈의 범위 내에서 칼로리 합을 최대화해야 한다.

이 문제는 **Unbounded Knapsack (무한 배낭)** 문제이다.

특이한 점은 **가격이 float 타입**으로 주어진다는 것!

**핵심은 부동소수점을 정수로 변환하여 DP를 수행하는 것!**

---

## 💡 핵심 아이디어

### 🔑 Unbounded Knapsack + 부동소수점 처리

**문제 조건**:
- 사탕 종류: n개 (1 ≤ n ≤ 5,000)
- 가진 돈: m원 (0.01 ≤ m ≤ 100.00, 소수점 둘째자리)
- 각 사탕: 칼로리 c (정수), 가격 p (소수점 둘째자리)
- 각 사탕은 **무한히 구매 가능**

**알고리즘 흐름**:
```
1. float 가격을 int로 변환 (× 100 + 0.5 반올림)
   예: 8.00 → 800
   예: 7.50 → 750

2. DP 배열 정의:
   dp[i] = i센트로 살 수 있는 최대 칼로리

3. 점화식 (Unbounded Knapsack):
   dp[j] = max(dp[j], dp[j - intTempM] + tempK)

   - j: 현재 금액 (센트 단위)
   - intTempM: 현재 사탕 가격 (센트 단위)
   - tempK: 현재 사탕 칼로리

4. 결과:
   dp[intTotalM] = 가진 돈으로 살 수 있는 최대 칼로리
```

**시간 복잡도**: O(n × m × 100)
- n = 사탕 종류 (최대 5,000)
- m = 가진 돈 (최대 100원)
- 100 = 100을 곱한 변환
- 전체: 5,000 × 10,000 = 50,000,000 (약 5천만 번 연산, 충분히 통과)

**공간 복잡도**: O(m × 100)
- dp 배열: O(10,001) = 약 40KB

## 🔑 주요 구현 포인트

### 1️⃣ ⚠️ 부동소수점 → 정수 변환 (매우 중요!)

**문제 상황**:
```cpp
float totalMoney = 8.00;
int intTotalM = (int)(totalMoney * 100);  // ❌ 위험!
```

**왜 위험한가?**
```
컴퓨터는 소수를 정확히 저장할 수 없음!

8.00 * 100 = 800.0  (이론상)
           = 799.9999... 또는 800.0000001  (실제)

int 캐스팅:
  (int)799.9999... = 799  ❌ 틀림! (800이어야 함)
  (int)800.0000001 = 800  ✅ 맞음
```

**부동소수점 오차 예시**:
```cpp
// 예시 1: 안전한 경우
float x = 8.00;
x * 100;  // 800.00000000... (오차 거의 없음)

// 예시 2: 위험한 경우
float x = 7.99;
x * 100;  // 798.99999999... (오차 발생!)
         // (int) → 798 (❌ 799여야 함!)
```

<br>

**✅ 해결 방법: + 0.5 반올림**

```cpp
int intTotalM = (int)(totalMoney * 100 + 0.5);  // ✅ 안전!
```

**반올림 원리**:
```
원래 값     + 0.5        int 캐스팅    결과
799.999  →  800.499  →   800         ✅ 정답
800.001  →  800.501  →   800         ✅ 정답
799.500  →  800.000  →   800         ✅ 정답
```

**핵심**:
- 부동소수점 오차는 보통 ±0.001 이하
- `+ 0.5`를 더하면 오차 범위 내에서 올바른 정수로 반올림됨
- `+ 0.1`이나 `+ 0.9`도 작동하지만, **0.5가 표준 반올림 방식**

<br>

### 2️⃣ 왜 0.5를 더할까?

**다른 값도 되는 이유**:
```cpp
// 부동소수점 오차가 ±0.001 수준이라면:
int a = (int)(totalMoney * 100 + 0.1);  // ✅ 대부분 정답
int b = (int)(totalMoney * 100 + 0.5);  // ✅ 항상 정답
int c = (int)(totalMoney * 100 + 0.9);  // ✅ 대부분 정답
```

**0.5를 쓰는 이유**:
```
1. 수학적 표준: 0.5가 올림/버림의 경계
2. 안전 마진: 0.1보다 더 큰 여유
3. 직관성: "중간값 더하기"로 이해하기 쉬움
```

**극단적 케이스 (매우 드물지만)**:
```cpp
799.91 + 0.1 = 800.01 → 800  ✅ (아슬아슬!)
799.91 + 0.5 = 800.41 → 800  ✅ (안전!)
```

<br>

### 3️⃣ Unbounded Knapsack DP

```cpp
// DP(바텁업 + 메모이제이션)
for (int i = 0; i < candies; ++i)
{
    int   tempK;  // 사탕의 칼로리
    float tempM;  // 사탕의 가격

    cin >> tempK >> tempM;  // 칼로리, 가격 순서

    // float tempM을 int로 변환해서 사용(반올림 처리로 부동소수점 오차 방지)
    int intTempM = (int)(tempM * 100 + 0.5);

    // intTempM 부터 intTotalM 까지 DP 갱신
    for (int j = intTempM; j <= intTotalM; ++j)
    {
        // 현재 값 = 현재 값 vs 점프해온 이전 자리 값(현재 - 가격) + 현재 사탕 칼로리
        dp[j] = max(dp[j], dp[j - intTempM] + tempK);
    }
}
```

**✅ 핵심**:
- **j는 intTempM부터 시작**: `j - intTempM`이 음수가 되지 않도록
- **dp[j] 갱신**: 현재 값 vs 점프해온 이전 자리 값 `dp[j - intTempM]` + 현재 사탕 칼로리
- **무한 배낭**: 같은 사탕을 여러 번 선택 가능

<br>

### 4️⃣ 입력 순서 주의

```cpp
cin >> calorie >> price;  // ✅ 칼로리, 가격 순서
```

**문제 지문**:
```
각 사탕의 칼로리 c와 가격 p가 주어진다.
예: 700 7.00 → 칼로리 700, 가격 7.00
```

<br>

### 5️⃣ while 문으로 여러 테스트 케이스 처리

```cpp
while (true)
{
    cin >> candies >> totalMoney;

    if (candies == 0)  // 종료 조건
        break;

    memset(dp, 0, sizeof(dp));  // ⚠️ 매번 초기화 필수!

    // DP 수행...
}
```

**✅ 핵심**:
- 입력의 마지막 줄: `0 0.00` (종료)
- **매 테스트 케이스마다 dp 배열 초기화** 필수!

## 📊 예제 상세 시뮬레이션

**입력**:
```
2 8.00
700 7.00
199 2.00
3 8.00
700 7.00
299 3.00
499 5.00
0 0.00
```

<br>

### 🎯 테스트 케이스 1

**초기 설정**:
```
candies = 2, totalMoney = 8.00 → intTotalM = 800
dp[0~800] = 0
```

**사탕 1번 (칼로리 700, 가격 7.00 → intTempM = 700)**:
```
j = 700: dp[700] = max(0, dp[0] + 700) = 700
j = 701: dp[701] = max(0, dp[1] + 700) = 700
...
j = 800: dp[800] = max(0, dp[100] + 700) = 700
```

**사탕 2번 (칼로리 199, 가격 2.00 → intTempM = 200)**:
```
j = 200: dp[200] = max(0, dp[0] + 199) = 199
j = 400: dp[400] = max(0, dp[200] + 199) = 398
j = 600: dp[600] = max(0, dp[400] + 199) = 597
j = 700: dp[700] = max(700, dp[500] + 199) = max(700, 597) = 700
j = 800: dp[800] = max(700, dp[600] + 199) = max(700, 796) = 796 ✅
```

**결과**: `796` (예: 사탕 2번 4개 = 199×4 = 796칼로리)

<br>

### 🎯 테스트 케이스 2

**초기 설정**:
```
candies = 3, totalMoney = 8.00 → intTotalM = 800센트
dp[0~800] = 0
```

**사탕 1번 (칼로리 700, 가격 700센트)**:
```
dp[700] = 700
dp[800] = 700
```

**사탕 2번 (칼로리 299, 가격 300센트)**:
```
dp[300] = 299
dp[600] = 598
dp[800] = max(700, dp[500] + 299) = 700 (dp[500]=0이므로)
```

**사탕 3번 (칼로리 499, 가격 500센트)**:
```
dp[500] = 499
dp[700] = max(700, dp[200] + 499) = 700
dp[800] = max(700, dp[300] + 499) = max(700, 798) = 798 ✅
```

**결과**: `798` (예: 사탕 2번 1개 + 사탕 3번 1개 = 299 + 499 = 798칼로리)

**O(n × m × 100)**

여기서:
- n = 사탕 종류 (최대 5,000)
- m = 가진 돈 (최대 100.00원 → 10,000센트)
- 각 사탕마다 최대 10,000번 DP 갱신

**계산**:
```
최악의 경우: 5,000 × 10,000 = 50,000,000 (약 5천만 번 연산)

```

## 🎯 핵심 요약

1. **알고리즘**: Unbounded Knapsack (무한 배낭) DP
2. **부동소수점 처리**: `(int)(value * 100 + 0.5)` 반올림 필수
3. **DP 정의**: `dp[i]` = i센트로 살 수 있는 최대 칼로리
4. **점화식**: `dp[j] = max(dp[j], dp[j - price] + calorie)`
5. **시작 위치**: `j = price` (음수 인덱스 방지)
6. **매 케이스 초기화**: `memset(dp, 0, sizeof(dp))`
