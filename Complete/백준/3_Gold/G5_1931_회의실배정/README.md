## 🤔 접근법

한 개의 회의실을 사용하고자 하는 N개의 회의가 있을 때, **겹치지 않게 최대한 많은 회의를 배정**하는 문제이다.

이는 전형적인 **그리디 알고리즘** 문제로, **끝나는 시간이 빠른 회의부터 선택**하는 것이 최적해를 보장한다.

핵심은 **회의를 끝나는 시간 기준으로 정렬**한 후, **이전 회의가 끝난 시간 이후에 시작하는 회의만 선택**하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 그리디 알고리즘 (Greedy) + 정렬 (Sorting)

**핵심 아이디어**:
```
1. 회의를 끝나는 시간 기준으로 정렬 (끝나는 시간이 같으면 시작 시간 순)
2. 가장 빨리 끝나는 회의부터 선택
3. 다음 회의의 시작 시간이 현재 회의의 끝나는 시간보다 크거나 같으면 선택
4. 선택한 회의의 개수 카운트
5. 최댓값 출력
```

**시간 복잡도**: O(N log N)
- N = 회의의 수 (최대 100,000)
- 정렬: O(N log N)
- 선택 과정: O(N)
- 전체: O(N log N) + O(N) = O(N log N)

**공간 복잡도**: O(N)
- vector<pair<int, int>> v: O(N)

## 🔑 핵심 포인트

### 1️⃣ 왜 끝나는 시간 기준으로 정렬하는가?

**그리디 알고리즘의 핵심**: **가장 빨리 끝나는 회의를 선택하면, 나머지 시간에 더 많은 회의를 배정할 수 있다!**

**반례 검증**:

<table>
<tr>
<td width="50%">

**❌ 시작 시간 기준 정렬**

```
회의: [(1,10), (2,3), (3,4)]
정렬: [(1,10), (2,3), (3,4)]

선택: (1,10)
→ (2,3), (3,4) 모두 선택 불가
→ 총 1개
```

</td>
<td width="50%">

**✅ 끝나는 시간 기준 정렬**

```
회의: [(1,10), (2,3), (3,4)]
정렬: [(2,3), (3,4), (1,10)]

선택: (2,3) → (3,4) → (1,10) 불가
→ 총 2개 (최적해!)
```

</td>
</tr>
</table>

**결론**: 끝나는 시간이 빠를수록 다음 회의를 선택할 기회가 많아진다!

---

### 2️⃣ (끝나는 시간, 시작 시간) 순서로 저장하는 이유

```cpp
v.emplace_back(to, from);  // (끝나는 시간, 시작 시간) 순서로 저장
```

**✅ 장점**:
- `sort(v.begin(), v.end())`는 **pair의 first (끝나는 시간) 기준으로 자동 정렬**
- ※ first가 같으면 **second (시작 시간) 기준으로 자동 정렬**
- ※ 추가 비교 함수 작성 불필요!

**⚠️ 주의**:
- 입력은 `(시작 시간, 끝나는 시간)` 순서
- 저장은 `(끝나는 시간, 시작 시간)` 순서
- 이렇게 하면 sort가 자동으로 끝나는 시간 기준 정렬

---

### 3️⃣ 선택 조건

```cpp
if(v[i].second < to) continue;  // 시작 시간 < 끝나는 시간 → 선택 불가
```

**✅ 핵심**:
- `v[i].second`: 다음 회의의 **시작 시간**
- `to`: 현재 선택한 회의의 **끝나는 시간**
- 조건: **다음 회의의 시작 시간 >= 현재 회의의 끝나는 시간**
- 같은 시간에 끝나고 시작할 수 있음 (문제 조건)

---

### 4️⃣ 첫 회의는 무조건 선택

```cpp
int ret = 1;  // 첫 회의는 무조건 선택

to   = v[0].first;   // 첫 회의의 끝나는 시간
from = v[0].second;  // 첫 회의의 시작 시간
```

**✅ 핵심**:
- 끝나는 시간 기준으로 정렬했으므로, **가장 빨리 끝나는 회의가 v[0]**
- 첫 회의는 항상 선택 가능하므로 ret = 1로 초기화
- 두 번째 회의부터 선택 여부 판단

## 💾 공간복잡도

**O(N)**
- `vector<pair<int, int>> v`: 회의 정보 저장 (N개)
- 추가 배열이나 재귀 스택 없음
