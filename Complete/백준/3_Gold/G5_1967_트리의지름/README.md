## 🤔 접근법

트리에서 **가장 먼 두 노드 사이의 거리** = 트리의 지름을 구하는 문제이다.

단순하게 생각하면 모든 노드에서 DFS를 돌려 O(n²)으로 구할 수 있지만,
사실 **DFS를 딱 2번만** 수행하는 O(n) 알고리즘이 존재한다.

※ 핵심은 **"임의의 노드에서 가장 먼 노드는 반드시 지름의 한 끝점이다"** 라는 성질!

(이걸 몰라서, 각 노드마다 모든 노드마다 찾기를 진행함.)

---

## 💡 정답 풀이 방법

**알고리즘**: DFS × 2회 (트리 지름 알고리즘)

**핵심 아이디어**:
```
1. 임의의 노드(1번)에서 DFS → 가장 먼 노드 A를 찾는다
2. A에서 DFS → 가장 먼 노드 B까지의 거리 = 트리의 지름
```

**시간 복잡도**: O(N)
- N = 노드 개수 (최대 10,000)
- DFS 2회: 각 O(N) → 전체 O(N)

**공간 복잡도**: O(N)
- graph 인접리스트: O(N)
- DFS 재귀 스택: O(N) (트리 높이)

## 🔑 핵심 포인트

### 1️⃣ 왜 DFS를 2번만 해도 되는가?

**🎯 핵심 정리**: 트리에서 임의의 노드 S에서 가장 먼 노드 A는 **반드시 지름의 한쪽 끝점**이다.

**직관적 설명**:

지름의 양 끝점을 `u`, `v`라 하고, 임의의 시작점을 `S`라 하자.

```
경우 1: S가 지름 경로 위에 있을 때
   u ─────── S ─────── v
   S에서 가장 먼 노드는 u 또는 v (지름 끝점)  ✅

경우 2: S가 지름 경로 밖에 있을 때
   S
   │
   x ─── u ─────────── v  (지름 경로)
   S에서 가장 먼 노드는 u 또는 v 중 하나  ✅
   (만약 다른 노드 w가 더 멀다면, w-v 또는 u-w가 u-v보다 길어야 하는데
    이는 u-v가 지름이라는 전제에 모순!)
```

따라서:
- 1번에서 DFS → A (지름 끝점 1개 확보)
- A에서 DFS → B (나머지 끝점 확보 + 거리 = 지름)

### 2️⃣ 입력이 부모→자식 방향이지만 양방향으로 저장

```cpp
// 입력은 부모→자식 방향이지만, 지름 탐색은 양방향 필요
graph[a].emplace_back(w, b);
graph[b].emplace_back(w, a); // 양방향 간선
```

**✅ 핵심**: 지름은 트리의 어느 방향으로도 탐색 가능해야 하므로 양방향 저장

### 3️⃣ par(부모) 매개변수로 역방향 방지

```cpp
void DFS(int cur, int par, int dist)
{
    for (pair<int, int> edge : graph[cur])
    {
        int next = edge.second;
        if (next != par) // 부모 방향으로 역행 방지
            DFS(next, cur, dist + w);
    }
}
```

**✅ 핵심**:
- 트리는 사이클이 없지만, 양방향 간선이므로 부모 방향으로 되돌아가는 것을 막아야 함
- visited 배열 없이 par만으로 충분 (트리 구조 덕분에)

### 4️⃣ maxDist 초기화 후 DFS 2회 실행

```cpp
// 1번 노드에서 가장 먼 노드 A 탐색
maxDist = 0;
DFS(1, 0, 0);

// A에서 가장 먼 노드까지의 거리 = 트리의 지름
maxDist = 0;
DFS(farNode, 0, 0);
```

**✅ 핵심**: 2번째 DFS 전에 `maxDist = 0` 으로 반드시 초기화

## 📊 예제 실행 흐름

**입력**:
```
12
1 2 3 / 1 3 2 / 2 4 5 / 3 5 11 / 3 6 9
4 7 1 / 4 8 7 / 5 9 15 / 5 10 4 / 6 11 6 / 6 12 10
```

**트리 구조**:
```
              1
           3/   \2
           2     3
          5|    11\ \9
           4     5   6
         1/ \7  15/\4 6/\10
         7   8  9 10 11 12
```

**1번 DFS - 각 노드까지의 거리**:
```
1→2  = 3        1→3  = 2
1→4  = 8        1→5  = 13
1→6  = 11       1→7  = 9
1→8  = 15       1→9  = 28  ← 최대! A = 9
1→10 = 17       1→11 = 17
1→12 = 21
```

**2번 DFS (A=9에서) - 각 노드까지의 거리**:
```
9→5  = 15       9→3  = 26
9→1  = 28       9→2  = 31
9→6  = 35       9→4  = 36
9→10 = 19       9→7  = 37
9→11 = 41       9→8  = 43
9→12 = 45  ← 최대! 트리의 지름 = 45
```

**출력**: `45`

## ⏱️ 시간복잡도

**O(N)**
- N = 노드 수 (최대 10,000)
- DFS 2회, 각 O(N) → 전체 O(N)
- 브루트포스 O(N²) = 1억 대비 압도적으로 빠름

---

## 💾 공간복잡도

**O(N)**
- `graph[10001]`: 양방향 인접리스트 (최대 간선 2×9,999)
- DFS 재귀 스택: 트리 높이 (최악 O(N), 일직선 트리)

## 🚨 주의사항

1. **양방향 간선 필수**: 입력이 부모→자식 방향이더라도 반드시 양방향 저장
2. **maxDist 재초기화**: 2번째 DFS 전에 `maxDist = 0` 초기화 필수
3. **par=0 시작**: 루트(1번)는 부모가 없으므로 `DFS(1, 0, 0)` (노드 번호 1~n이므로 0은 안전)
4. **visited 불필요**: 트리 구조 + par 체크만으로 충분
