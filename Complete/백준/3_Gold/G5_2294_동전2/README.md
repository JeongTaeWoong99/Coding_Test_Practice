## 🔗 문제 링크

[백준 2294번 - 동전 2](https://www.acmicpc.net/problem/2294)

**난이도**: Gold 5

---

## 🤔 접근법

n가지 종류의 동전을 사용하여 k원을 만들 때, 필요한 최소 동전 개수를 구하는 문제이다.

각 동전은 무한히 사용할 수 있으며, 불가능한 경우 -1을 출력한다.

핵심은 **동적 계획법(DP)을 사용하여 각 금액까지의 최소 동전 개수를 저장**하는 것!

이 문제는 **Bottom-up(반복문 + 메모이제이션)** 방식으로 풀 수 있다.

※ 바텀업 방식이 시간과 메모리 측면에서 더 효율적이다. (탑다운 대비 2~3배 빠름)

---

## 💡 정답 풀이 방법

**알고리즘**: 동적 계획법 (DP) - 바텀업 (Bottom-up)

**핵심 아이디어**:
```
1. dp[i] = i원을 만드는 최소 동전 개수

2. 초기화:
   - dp[0] = 0 (0원을 만드는데 필요한 동전 개수는 0개)
   - 나머지는 모두 INF (불가능한 경우)

3. 동전 입력받으면서 DP 갱신:
   - 각 동전 val에 대해
   - val원부터 k원까지 순회하며
   - dp[money] = min(dp[money], dp[money - val] + 1)

4. 결과:
   - dp[k] == INF이면 -1 출력 (불가능)
   - 아니면 dp[k] 출력 (최소 동전 개수)
```

**시간 복잡도**: O(n × k)
- n = 동전 종류 개수 (최대 100)
- k = 목표 금액 (최대 10,000)
- 각 동전마다 k번 순회
- 전체: 100 × 10,000 = 1,000,000 (약 100만 번 연산)

**공간 복잡도**: O(k)
- dp 배열: O(k) = 10,004

### 1️⃣ DP 배열 갱신 과정 (예시: 동전 [1, 5, 12], k = 15)

**초기화**:
```
dp[0] = 0
dp[1] ~ dp[15] = INF (987654321)

즉: dp = [0, INF, INF, INF, INF, INF, INF, INF, INF, INF, INF, INF, INF, INF, INF, INF]
```

### 바텀업 vs 탑다운 비교

| 항목 | Bottom-up (이 코드) | Top-down (재귀) |
|-----|-------------------|----------------|
| **구현 방식** | 반복문 | 재귀 + 메모이제이션 |
| **시작점** | 0원 → k원 | k원 → 0원 |
| **함수 오버헤드** | 없음 ✅ | 재귀 호출 오버헤드 |
| **캐시 효율** | 높음 (순차 접근) | 낮음 (랜덤 접근) |
| **스택 오버플로우** | 없음 ✅ | 가능성 있음 |
| **메모리** | 적음 ✅ | 많음 (재귀 스택) |
| **속도** | 빠름 ✅ (2~3배) | 느림 |
| **직관성** | 구현 직관적 | 문제 사고방식에 가까움 |

**✅ 결론: 이 문제는 Bottom-up 방식이 압도적으로 유리!**

**이유**:
1. **모든 상태 필요**: 0원부터 k원까지 대부분의 dp 값 사용
2. **순차적 계산**: 작은 금액부터 큰 금액으로 자연스럽게 진행
3. **가지치기 불필요**: 모든 금액이 의미있음
4. **함수 호출 없음**: 반복문만 사용하여 오버헤드 제로
5. **캐시 효율**: 메모리 순차 접근으로 CPU 캐시 hit율 높음

### ★ 동전을 val원부터 시작하는 이유

```cpp
for (int money = val; money <= k; money++)
```

**왜 0부터가 아니라 val부터?**
```
val = 5일 때:

money = 0: dp[0] = min(0, dp[-5] + 1) ❌ 음수 인덱스 (불가능)
money = 1: dp[1] = min(1, dp[-4] + 1) ❌ 음수 인덱스 (불가능)
money = 2: dp[2] = min(2, dp[-3] + 1) ❌ 음수 인덱스 (불가능)
money = 3: dp[3] = min(3, dp[-2] + 1) ❌ 음수 인덱스 (불가능)
money = 4: dp[4] = min(4, dp[-1] + 1) ❌ 음수 인덱스 (불가능)
money = 5: dp[5] = min(5, dp[0] + 1) ✅ 가능 (dp[0] = 0)
```

**✅ 핵심**:
- val원 미만은 해당 동전으로 만들 수 없음
- `dp[money - val]`이 유효하려면 `money >= val`이어야 함
- 불필요한 연산 방지

- 매우 빠른 알고리즘

## 💾 공간복잡도

**O(k)**
- `dp[10004]`: 각 금액별 최소 동전 개수 저장
- 동전 저장 불필요 (입력받으면서 바로 DP 갱신)
- 추가 공간 복잡도 없음

## 🚨 주의사항

1. **INF 초기화**: dp 배열을 INF로 초기화하여 불가능한 경우 구분
2. **dp[0] = 0**: 0원을 만드는데 필요한 동전 개수는 0개
3. **배열 크기**: k 최대 10,000이므로 10,004 이상 확보 (안전 마진)
4. **음수 인덱스 방지**: money는 val부터 시작
5. **INF 비교**: dp[k] == INF이면 불가능 (-1 출력)
6. **중복 동전 허용**: 같은 동전이 여러 번 주어져도 결과는 동일 (최솟값 유지)
7. **동전 가치 범위**: 최대 100,000이지만 k보다 큰 동전은 사용 불가 (입력받으면서 자동 처리)
8. **바텀업 우선**: 이 문제는 탑다운보다 바텀업이 2~3배 빠름
