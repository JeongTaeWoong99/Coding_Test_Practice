## 🔗 문제 링크

[백준 5557번 - 1학년](https://www.acmicpc.net/problem/5557)



**난이도**: Gold 5

---

## 🤔 접근법

n개의 숫자가 주어지고, 첫 번째 숫자부터 마지막 직전 숫자까지 +/-를 넣어서 마지막 숫자와 같아지는 경우의 수를 구하는 문제이다.

단, 1학년 수준의 덧셈/뺄셈이므로 **중간 계산값이 항상 0~20 범위** 안에 있어야 한다.

핵심은 **`dp[idx][sum]` = idx번째 인덱스에서 현재 합이 sum일 때의 경우의 수**로 정의하고, 탑다운 메모이제이션으로 해결하는 것!

---

## 💡 정답 풀이 방법

**알고리즘** : 동적 프로그래밍 (Top-Down DP + 메모이제이션)

**핵심 아이디어** :
```
1. 시작 : DP(0, arr[0])으로 첫 번째 숫자를 초기 합으로 시작
2. 각 단계에서 두 가지 선택 :
   - 다음 숫자를 더하는 경우 : DP(idx+1, sum + arr[idx+1])
   - 다음 숫자를 빼는 경우  : DP(idx+1, sum - arr[idx+1])
3. 가지치기 : 합이 0~20 범위를 벗어나면 즉시 0 반환
4. 종료 조건 : 마지막 연산자 위치(idx == n-2)에 도달했을 때
               sum == arr[n-1]이면 1, 아니면 0 반환
5. 메모이제이션 : dp[idx][sum]에 결과 캐싱
```

**시간 복잡도** : O(n × 21)
- idx : 최대 n개 (≤ 100)
- sum : 0~20 범위 (21가지)

**공간 복잡도** : O(n × 21)
- dp[104][21] 배열

## 🔄 탑다운 vs 바텀업 비교

| | 탑다운 (현재 코드) | 바텀업 |
|---|---|---|
| **방향** | DP(0, arr[0]) → 재귀 호출 | dp\[0\]\[arr\[0\]\] 초기화 → 반복문 |
| **계산 범위** | 도달 가능한 상태만 계산 | 전체 n × 21 셀 순서대로 계산 |
| **희소 상태** | ✅ 자연스럽게 스킵 | ❌ 0인 셀도 모두 순회 |
| **초기값 처리** | 재귀 종료 조건으로 처리 | 초기 행(dp[0][arr[0]] = ?)을 별도 설정 |

**탑다운이 더 자연스러운 이유 :**

이 문제의 상태 공간은 **희소(sparse)** 하다.

시작점은 `(idx=0, sum=arr[0])` 단 하나이고, 각 단계에서 ±arr[idx+1]씩만 변화한다.
따라서 n × 21 = 100 × 21 = 2,100개의 셀 중 실제로 도달 가능한 셀은 극히 일부다.

```
idx=0 : sum=arr[0]만 존재           → 1가지
idx=1 : +arr[1] 또는 -arr[1]        → 최대 2가지
idx=2 : 각 합에서 또 +/- arr[2]     → 최대 4가지
...
idx=k : 최대 2^k가지 (단, 0~20 범위로 포화) → 최대 21가지
```

탑다운은 이 경로를 자연스럽게 따라가므로 불필요한 계산이 없다.
바텀업은 도달 불가능한 셀도 모두 순회하므로 코드가 복잡해질 수 있다.

> 단, 이 문제는 n × 21 = 2,100으로 충분히 작아서 바텀업도 성능 차이는 없다.
> 탑다운의 장점은 **코드 구조가 문제의 흐름과 일치해서 직관적**이라는 점에 있다.

## 🔑 핵심 포인트

### 1️⃣ DP 테이블 정의

```cpp
ll dp[104][21]; // dp[idx][sum] = idx번째에서 합이 sum인 경우의 수
                // 경우의 수가 매우 커질 수 있으므로 ll 사용
```

**✅ 핵심** :
- idx 범위 : 0 ~ n-2 (연산자를 넣는 위치)
- sum 범위 : 0 ~ 20 (1학년 계산 범위)
- 값 : 해당 상태를 만족하는 경우의 수

### 2️⃣ 범위 가지치기

```cpp
if (sum < 0 || sum > 20)
{
    return 0;
}
```

**✅ 핵심** :
- 중간 계산값이 0~20을 벗어나면 유효하지 않은 경우
- 즉시 0 반환으로 불필요한 재귀 차단

### 3️⃣ 종료 조건 (Base Case)

```cpp
if (idx == n - 2)
{
    if (sum == arr[n - 1])
    {
        return 1;
    }

    return 0;
}
```

**✅ 핵심** :
- `idx == n-2` : 마지막 연산자 위치 (n-2번째와 n-1번째 숫자 사이)
- 이 시점의 sum이 마지막 숫자(arr[n-1])와 같으면 유효한 수식

### 4️⃣ 타입 주의

```cpp
typedef long long ll; // 결과가 '2^63 - 1' 까지 나올 수 있으므로 ll 사용

int    n;            // n    : 숫자 개수 (최대 100, int 충분)
int    arr[104];     // arr  : 입력 배열 (값 범위 0~20, int 충분)
ll     dp[104][21];  // dp   : 경우의 수 (값이 매우 커지므로 ll)
```

**⚠️ 주의** :
- `arr` 값은 0~20으로 `int`로 충분
- 경우의 수(dp)는 매우 커질 수 있으므로 반드시 `ll`
- `arr`를 `ll`로 선언하면 함수 파라미터 `int sum`에 전달 시 narrowing conversion 에러 발생

## 📊 DP 테이블 예시 (arr = [2, 2, 2, 2], n = 4)

```
목표 : 2 ± 2 ± 2 = 2

DP 호출 트리 :
DP(0, 2)
├─ [+2] → DP(1, 4)
│   ├─ [+2] → DP(2, 6) : 6 ≠ 2 → 0    dp[2][6] = 0
│   └─ [-2] → DP(2, 2) : 2 == 2 → 1   dp[2][2] = 1
│   → dp[1][4] = 1
│
└─ [-2] → DP(1, 0)
    ├─ [+2] → DP(2, 2) : 이미 계산됨 → 1  ⚡ 메모이제이션 적중!
    └─ [-2] → sum=-2, 범위 초과 → 0
    → dp[1][0] = 1

dp[0][2] = 1 + 1 = 2
```

| idx | sum=0 | sum=2 | sum=4 | sum=6 |
|-----|-------|-------|-------|-------|
| 0   |   -   | **2** |   -   |   -   |
| 1   | **1** |   -   | **1** |   -   |
| 2   |   -   | **1** |   -   |   0   |

**유효한 수식 :**
```
2 + 2 - 2 = 2  ✅
2 - 2 + 2 = 2  ✅
2 + 2 + 2 = 6  ❌
2 - 2 - 2 = -2 ❌ (음수 → 범위 초과)
```

## ⏱️ 시간복잡도

**O(n × 21)**
- n : 숫자 개수 (최대 100)
- 합 범위 : 0~20 (21가지)
- 각 상태는 최대 1번만 계산 (메모이제이션)

---

## 💾 공간복잡도

**O(n × 21)**
- `dp[104][21]` : DP 테이블
- `arr[104]` : 입력 배열

---

## 🚨 주의사항

1. **타입 선택** : `arr`와 `n`은 `int`로 충분하나 `dp`는 반드시 `ll`
2. **narrowing conversion** : `arr`를 `ll`로 선언하면 `int sum` 파라미터 전달 시 컴파일 경고/에러
3. **경우의 수가 0인 상태도 캐싱됨** : `if(ret) return ret;` 조건은 dp값이 0인 경우를 재계산할 수 있음
   - 이 문제에서는 0인 상태를 재방문해도 결과에 영향 없음 (0을 더하므로)
   - 단, 정확한 메모이제이션이 필요하면 `-1`로 초기화하고 `if(ret != -1)` 체크
4. **마지막 숫자는 연산에 포함 안 됨** : arr[n-1]은 목표값이므로 +/-에 사용하지 않음
