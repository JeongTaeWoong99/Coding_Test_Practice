## 🔗 문제 링크
[백준 14003번 - 가장 긴 증가하는 부분 수열 5](https://www.acmicpc.net/problem/14003)

---

## 🤔 접근법

가장 긴 증가하는 부분 수열(LIS)을 찾고, 그 수열까지 출력해야 하는 문제.

N이 최대 1,000,000이므로 O(N²) DP는 시간 초과.

**이분 탐색을 활용한 O(N log N) 알고리즘**이 필요.

핵심은 **LIS 길이를 구하면서 동시에 역추적 정보를 저장**하는 것!

---

## 💡 정답 풀이 방법

**알고리즘**: 이분 탐색(Binary Search) + 역추적(Backtracking)

**핵심 아이디어**:
```
1. lis 배열: 길이가 i인 증가 수열의 마지막 값 중 최솟값 저장
2. lower_bound: 현재 숫자가 들어갈 위치를 이분 탐색으로 찾기
3. ans 배열: 각 숫자의 {LIS에서의 위치, 실제 값} 저장
4. 역추적: 뒤에서부터 len-1, len-2, ... 순서로 수열 복원
```

**시간 복잡도**: O(N log N)
- 각 숫자마다 lower_bound 수행 (log N)
- N개의 숫자 처리: N × log N

**공간 복잡도**: O(N)
- lis[1000004], ans[1000004] 배열

## 🔑 주요 구현 포인트

### 1️⃣ lis 배열이란? (LIS = Longest Increasing Subsequence)

```cpp
int lis[1000004];  // LIS를 저장하는 배열
```

**lis는 "리스트(List)"가 아니라 "LIS(Longest Increasing Subsequence)"의 약자!**

**LIS 배열의 의미:**
- `lis[i]` = 길이가 `i+1`인 증가 수열의 마지막 값 중 **최솟값**
- 이 배열은 항상 오름차순으로 유지됨

**예시:**
```
입력: 10 20 10 30 20 50

lis[0] = 10  → 길이 1인 증가 수열의 마지막 최솟값
lis[1] = 20  → 길이 2인 증가 수열의 마지막 최솟값
lis[2] = 30  → 길이 3인 증가 수열의 마지막 최솟값
lis[3] = 50  → 길이 4인 증가 수열의 마지막 최솟값
```

**왜 최솟값을 저장하는가?**
- 작은 값을 저장해야 나중에 더 큰 값이 올 때 수열을 확장하기 유리
- 예: `lis[1] = 20`보다 `lis[1] = 10`이 더 좋음 (30이 와도 확장 가능)

### 2️⃣ INF로 초기화하는 이유

```cpp
const int INF = 1e9 + 4;     // 무한대 값(10억 + 4)
fill_n(lis, 1000004, INF);   // LIS 배열 초기화
```

**왜 INF = 10억 + 4인가?**

**문제 조건:**
- 입력 범위: -1,000,000,000 ≤ Ai ≤ 1,000,000,000 (즉, -10억 ~ 10억)

**INF를 사용하는 이유:**
1. **입력 범위를 벗어난 값**으로 초기화해야 함
2. **lower_bound가 올바르게 동작**하려면 "빈 자리"를 표시할 값이 필요
3. 10억보다 큰 값(10억 + 4)을 사용하면 어떤 입력도 INF보다 작음

**예시:**
```
입력: -999999999, 1000000000

INF = 1e9 + 4 = 1,000,000,004

lis 배열 초기값:
lis[0] = 1000000004
lis[1] = 1000000004
lis[2] = 1000000004
...

첫 번째 숫자(-999999999) 처리:
lower_bound(lis, lis+0, -999999999)
→ lis[0]을 가리킴 (INF > -999999999 이므로)
→ lis[0] = -999999999 갱신 ✅

두 번째 숫자(1000000000) 처리:
lower_bound(lis, lis+1, 1000000000)
→ lis[1]을 가리킴 (INF > 1000000000 이므로)
→ lis[1] = 1000000000 갱신 ✅
```

**만약 INF = 0으로 초기화하면?**
```
lis[0] = 0, lis[1] = 0, ...

첫 번째 숫자(-999999999) 처리:
lower_bound(lis, lis+0, -999999999)
→ lis[0]을 가리킴 (0 > -999999999)
→ lis[0] = -999999999 ✅

두 번째 숫자(1000000000) 처리:
lower_bound(lis, lis+1, 1000000000)
→ lis[1]을 가리켜야 하는데...
→ 0 < 1000000000이므로 잘못된 위치를 가리킴 ❌
```

**결론:**
- **INF는 입력 가능한 모든 값보다 큰 값**이어야 함
- 10억 + 4는 입력 범위(10억)를 초과하므로 안전
- 이렇게 해야 lower_bound가 "빈 자리"를 올바르게 찾음

### 3️⃣ lower_bound로 위치 찾기

```cpp
// lower_bound로 num이 들어갈 "인덱스" 찾기
int pos = lower_bound(lis, lis + len, num) - lis;
```

**lower_bound의 역할:**
- `num` 이상인 첫 번째 원소의 위치를 찾음
- lis 배열은 항상 오름차순이므로 이분 탐색으로 O(log N)
- ★☆ 포인터를 반환하므로 `- lis`를 하여 인덱스로 변환(주소 - 주소 = 인덱스값)

**예시:**
```
lis = [10, 20, 30, INF, INF, ...]
len = 3

num = 25:
  lower_bound(lis, lis+3, 25) → lis[1]의 주소 (20 < 25 ≤ 30)
  pos = lis[1]의 주소 - lis = 1

num = 40:
  lower_bound(lis, lis+3, 40) → lis[3]의 주소 (30 < 40 ≤ INF)
  pos = lis[3]의 주소 - lis = 3 → 새로운 위치!
```

---

#### ⚠️ 자주 헷갈리는 포인트 (중요!)

**❓ Q1: lower_bound는 O(N²) 아닌가요?**

**A:** 아닙니다! lower_bound는 **이분 탐색(Binary Search)**을 사용합니다.

```
🔸 선형 탐색 (Linear Search): 앞에서부터 하나씩 비교 → O(N)
🔸 이분 탐색 (Binary Search): 절반씩 나눠서 비교 → O(log N)
```

**시간 복잡도 비교:**

| 탐색 방법 | 1번째 입력 | 2번째 입력 | N번째 입력 | **총 시간** |
|---------|----------|----------|----------|-----------|
| **선형 탐색** | O(1) | O(2) | O(N) | **O(N²)** ❌ |
| **이분 탐색** | O(log 1) | O(log 2) | O(log N) | **O(N log N)** ✅ |

**이분 탐색 동작 예시:**
```
lis = [10, 20, 30, 50, INF, ...]
len = 4
num = 35를 찾는다면?

선형 탐색이라면 (앞에서부터):
  10 < 35? → 다음
  20 < 35? → 다음
  30 < 35? → 다음
  50 ≥ 35! → 찾음! (4번 비교)

이분 탐색 (lower_bound의 실제 동작):
  Step 1: 중간(인덱스 2) 확인 → lis[2]=30 < 35
          오른쪽 절반만 탐색
  Step 2: 중간(인덱스 3) 확인 → lis[3]=50 ≥ 35
          찾음! (2번 비교만!)
```

**결론:**
- ✅ lis 배열이 **오름차순 정렬**되어 있기 때문에 이분 탐색 가능
- ✅ N=1,000,000일 때: 1조 번 → 2천만 번으로 감소!

---

**❓ Q2: `lowerPos - lis`는 왜 하는 건가요?**

**A:** **포인터를 인덱스로 변환**하기 위해서입니다!

**핵심: 포인터의 차이 = 배열의 인덱스**

```cpp
int lis[1000004];

lis      → 배열의 시작 주소 (0번째 원소의 주소)
lis + 1  → 배열의 1번째 원소 주소
lis + 2  → 배열의 2번째 원소 주소
...
```

**구체적 예시:**
```cpp
lis = [10, 20, 30, 50, INF, ...]

// 메모리 주소 (가상):
주소:     1000  1004  1008  1012  1016  ...
값:       10    20    30    50    INF   ...
인덱스:   0     1     2     3     4     ...

lis의 주소 = 1000

num = 35를 찾는다면:
  lowerPos = lower_bound(lis, lis + 4, 35)
           = 1012 (lis[3]의 주소, 값은 50)

  pos = lowerPos - lis
      = 1012 - 1000
      = 12 바이트 차이
      = 12 ÷ 4바이트(int 크기) = 3 (인덱스)

  따라서 pos = 3 ✅
```

**왜 이렇게 하나요?**
```
🔸 lowerPos: 주소 (포인터)
🔸 우리가 필요한 것: 인덱스 (숫자)
✅ 포인터 빼기를 하면 자동으로 인덱스를 계산해줍니다!
```

---

**❓ Q3: `*lowerPos = num`은 무슨 역할인가요?**

**A:** lowerPos가 **가리키는 주소의 값을 num으로 변경**합니다.

```cpp
*lowerPos = num;  // 역참조 연산자 *
```

**구체적 예시:**
```cpp
lis = [10, 20, 30, INF, INF, ...]
num = 25를 처리한다면:

1. lower_bound(lis, lis + 3, 25)
   → lis[2]를 가리킴 (30 ≥ 25이므로)

2. lowerPos = lis + 2의 주소

3. *lowerPos = num
   → lis[2] = 25로 변경!

결과:
  lis = [10, 20, 25, INF, INF, ...]
```

**왜 이렇게 하나요?**
- "길이가 i인 증가 수열의 마지막 값 중 **최솟값**을 저장"
- 더 작은 값을 저장해야 나중에 더 큰 값이 올 때 수열 확장에 유리
- 예: `lis[2] = 30`보다 `lis[2] = 25`가 더 좋음

---

#### 💡 현재 코드의 장점

이 문제에서 사용한 코드 스타일:

```cpp
// lower_bound로 num이 들어갈 "인덱스" 찾기
int pos = lower_bound(lis, lis + len, num) - lis;

// 새로운 값이면 길이 증가
if(lis[pos] == INF) len++;

// LIS 배열 갱신
lis[pos] = num;
```

**이 방식의 장점:**
- ✅ 한 줄로 인덱스를 바로 구함 (간결)
- ✅ `lis[pos]`로 배열 인덱스 방식 사용 (직관적)
- ✅ 포인터 역참조(`*`) 없이 깔끔하게 작성
- ✅ 디버깅할 때 pos 값 확인 가능

**참고: 포인터 방식과의 비교**

포인터를 직접 사용하는 방식도 가능합니다:
```cpp
auto lowerPos = lower_bound(lis, lis + len, num);
int pos = lowerPos - lis;

if(*lowerPos == INF) len++;  // 포인터 역참조
*lowerPos = num;             // 포인터 역참조
```

하지만 배열 인덱스 방식(`lis[pos]`)이 더 직관적이고 읽기 쉽습니다!

### 4️⃣ 역추적을 위한 정보 저장

```cpp
pair<int, int> ans[1000004];  // {LIS에서의 위치, 실제 값}

ans[i].first  = pos;      // LIS에서의 위치
ans[i].second = num;      // 실제 값
```

**왜 역추적 정보를 저장하는가?**
- lis 배열은 **길이만** 알려줌 (실제 수열은 알 수 없음)
- 각 숫자가 **LIS의 몇 번째 위치**에 속하는지 저장
- 나중에 뒤에서부터 위치를 역순으로 찾아가며 수열 복원

**예시:**
```
입력: 10 20 10 30 20 50

ans[0] = {0, 10}  → 인덱스 0에서 입력받은 10은 LIS 위치 0     -> 역출럭
ans[1] = {1, 20}  → 인덱스 1에서 입력받은 20은 LIS 위치 1     -> 역출력
ans[2] = {0, 10}  → 인덱스 2에서 입력받은 10은 LIS 위치 0     -> 1를 찾고 있기 때문에, 0 PASS
ans[3] = {2, 30}  → 인덱스 3에서 입력받은 30은 LIS 위치 2     -> 역출력
ans[4] = {1, 20}  → 인덱스 4에서 입력받은 20은 LIS 위치 1     -> 2를 찾고 있기 때문에, 1 PASS
ans[5] = {3, 50}  → 인덱스 5에서 입력받은 50은 LIS 위치 3     -> 역출력

※ LIS 위치값 때문에, 역추적 수열 복원으로 출력할 때, 순서대로 꼬이지 않고 출력할 수 있음!
```

### 5️⃣ 역추적으로 수열 복원

```cpp
// 뒤에서부터 len-1, len-2, ..., 0 순서로 찾기
for(int i = n - 1; i >= 0; i--)
{
    if(ans[i].first == len - 1)
    {
        stk.push(ans[i].second);
        len--;
    }
}
```

**역추적 로직:**
1. 뒤에서부터 탐색 (`i = n-1` → `0`)
2. `ans[i].first == len-1`인 숫자를 찾음.
3. 찾으면 스택에 저장하고 `len--` (다음은 `len-2` 찾기)
4. 스택에서 꺼내면 오름차순 수열 완성

---

### 🔍 왜 뒤에서부터 찾아야 하는가? (중요!)

#### 💡 핵심 원리

**LIS는 "뒤에서부터 확정"되는 구조입니다!**

```
같은 LIS 위치(pos)에 여러 후보가 있을 수 있음!
→ ans[i].first가 같은 값이 여러 개 존재
→ 어떤 것을 선택하느냐에 따라 올바른 LIS가 될 수도, 아닐 수도 있음!
```

#### ❌ 반례: 앞에서부터 찾으면 실패하는 경우

**예제 입력:**
```
7
1 5 2 3 4 6 7
```

**처리 과정:**
```
i=0: num=1 → pos=0, lis=[1, INF, ...]      → ans[0]={0, 1}
i=1: num=5 → pos=1, lis=[1, 5, ...]        → ans[1]={1, 5}
i=2: num=2 → pos=1, lis=[1, 2, ...]        → ans[2]={1, 2} ⚠️ (5를 2로 교체!)
i=3: num=3 → pos=2, lis=[1, 2, 3, ...]     → ans[3]={2, 3}
i=4: num=4 → pos=3, lis=[1, 2, 3, 4, ...]  → ans[4]={3, 4}
i=5: num=6 → pos=4, lis=[1, 2, 3, 4, 6]    → ans[5]={4, 6}
i=6: num=7 → pos=5, lis=[1, 2, 3, 4, 6, 7] → ans[6]={5, 7}
```

**ans 배열 상태:**
```
인덱스  ans[i].first  ans[i].second  설명
  0         0             1          → LIS[0] 확정
  1         1             5          → LIS[1] 후보 (1) ⚠️ 잘못된 경로!
  2         1             2          → LIS[1] 후보 (2) ✅ 올바른 경로!
  3         2             3          → LIS[2] 확정
  4         3             4          → LIS[3] 확정
  5         4             6          → LIS[4] 확정
  6         5             7          → LIS[5] 확정
```

**앞에서부터 찾으면?** (❌ 틀린 방법)
```cpp
for(int i = 0; i < n; i++)  // ❌ 앞에서부터!
{
    if(ans[i].first == len - 1)
    {
        stk.push(ans[i].second);
        len--;
    }
}
```

**실행 결과:**
```
len=6일 때: ans[6]={5, 7} 선택 → stk=[7]
len=5일 때: ans[5]={4, 6} 선택 → stk=[7, 6]
len=4일 때: ans[4]={3, 4} 선택 → stk=[7, 6, 4]
len=3일 때: ans[3]={2, 3} 선택 → stk=[7, 6, 4, 3]
len=2일 때: ans[1]={1, 5} 선택 → stk=[7, 6, 4, 3, 5] ❌ 5 선택!
len=1일 때: ans[0]={0, 1} 선택 → stk=[7, 6, 4, 3, 5, 1]

출력: 1 5 3 4 6 7
확인: 1 < 5? ✅
      5 < 3? ❌❌❌ 증가 수열이 아님!
```

**뒤에서부터 찾으면?** (✅ 올바른 방법)
```cpp
for(int i = n - 1; i >= 0; i--)  // ✅ 뒤에서부터!
{
    if(ans[i].first == len - 1)
    {
        stk.push(ans[i].second);
        len--;
    }
}
```

**실행 결과:**
```
i=6: ans[6]={5, 7} → 5==5 → stk=[7], len=5
i=5: ans[5]={4, 6} → 4==4 → stk=[7, 6], len=4
i=4: ans[4]={3, 4} → 3==3 → stk=[7, 6, 4], len=3
i=3: ans[3]={2, 3} → 2==2 → stk=[7, 6, 4, 3], len=2
i=2: ans[2]={1, 2} → 1==1 → stk=[7, 6, 4, 3, 2], len=1 ✅ 2 선택!
i=1: ans[1]={1, 5} → 1!=0 → PASS (이미 len=1 처리됨)
i=0: ans[0]={0, 1} → 0==0 → stk=[7, 6, 4, 3, 2, 1], len=0

출력: 1 2 3 4 6 7 ✅✅✅ 정답!
```

#### 🧠 왜 뒤에서부터 찾아야 하는가?

**1. LIS는 뒤에서부터 확정되는 구조**
```
[1, 5, 2, 3, 4, 6, 7]
     ↑  ↑
  잘못   올바름

역추적 순서:
7의 이전 값은? → 6 (확정!)
6의 이전 값은? → 4 (확정!)
4의 이전 값은? → 3 (확정!)
3의 이전 값은? → 2 (확정!) ⚠️ 5가 아님!
2의 이전 값은? → 1 (확정!)

→ 뒤에서부터 거슬러 올라가야 "연결 관계"가 명확함!
```

**2. 앞에서부터 찾으면 "오래된" 후보 선택**
```
ans[1] = {1, 5}  ← 나중에 교체되어 버려진 값
ans[2] = {1, 2}  ← 실제 LIS를 구성하는 값

앞에서부터 찾으면: ans[1]의 5를 먼저 만남 → 잘못된 선택!
뒤에서부터 찾으면: ans[2]의 2를 먼저 만남 → 올바른 선택!
```

**3. 입력 순서상 뒤쪽이 최신 값**
```
LIS 배열은 계속 갱신됨 (같은 위치에 더 작은 값으로 교체)
→ 나중에 입력된 값이 "최종 선택된 값"
→ 뒤에서부터 찾아야 최신 값을 찾을 수 있음
```

#### 📚 스택을 사용하는 이유

```cpp
// 역순으로 찾아서 정순으로 출력
for(int i = n - 1; i >= 0; i--)  // 뒤 → 앞
{
    stk.push(ans[i].second);      // 스택에 넣기
}

while(!stk.empty())
{
    cout << stk.top() << " ";     // 스택에서 꺼내기 (역순 → 정순)
    stk.pop();
}
```

**동작 원리:**
```
역추적 순서: 7 → 6 → 4 → 3 → 2 → 1 (뒤에서 앞으로)
스택 LIFO:  [7] → [7,6] → ... → [7,6,4,3,2,1]
스택 pop:   1 ← 2 ← 3 ← 4 ← 6 ← 7 (자동으로 정순!)
출력:       1 2 3 4 6 7 ✅
```

**핵심:**
- **LIFO (Last In First Out)** 구조
- 마지막에 넣은 것이 먼저 나옴
- 뒤에서 앞으로 찾아서 → 스택에 넣고 → 꺼내면 자동 정렬!

```
LIS 길이 출력: 4

  ans[5] = {3, 50}
  ans[5].first == 3 ✅ → 스택에 50 추가
  len-- → len = 3
  stk = [50]

  ans[4] = {1, 20}

  ans[3] = {2, 30}

  stk = [50, 30]

  ans[2] = {0, 10}
```

## 🚨 주의사항

1. **INF 값 설정**: 입력 범위를 벗어난 값으로 초기화 (10억 + 4)
2. **역추적 방향**: 반드시 뒤에서부터 앞으로 탐색
3. **스택 사용**: 역순으로 찾은 수열을 오름차순으로 출력하기 위해 스택 활용
4. **범위 설정**: N ≤ 1,000,000이므로 배열 크기 충분히 확보
5. **INF가 아닐 때**: 기존 값 교체 (len 증가 없음)

## 💡 핵심 요약

**이 문제의 핵심은 3가지:**

1️⃣ **lis 배열의 의미**: "길이가 i인 증가 수열의 마지막 최솟값" 저장

2️⃣ **INF 초기화**: 입력 범위(-10억~10억)를 벗어난 값으로 초기화해야 lower_bound가 올바르게 동작

3️⃣ **역추적**: ans 배열에 {위치, 값}을 저장하고, 뒤에서부터 len-1 → 0 순서로 복원

**O(N log N) 이분 탐색 + 역추적으로 효율적인 LIS 구현!**
