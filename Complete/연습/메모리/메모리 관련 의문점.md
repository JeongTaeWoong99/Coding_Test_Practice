# 💾 메모리 관련 의문점 정리

**📅 작성일**: 2026-01-04

**📌 주제**: 지역 변수 vs 전역 변수 메모리 사용량 차이

---

## 🤔 의문점

코드에서 지역 변수와 전역 변수의 메모리 사용량이 동일하게 측정되는 이유는?

```cpp
// 함수 안에서 선언 (지역 변수)
for (int i = 0; i < n; i++)
{
    int   tempK;  // 4바이트
    float tempM;  // 4바이트
}

// 전역 변수로 선언
int   tempK;  // 4바이트
float tempM;  // 4바이트
```

**백준 제출 시**: 둘 다 2060KB로 동일하게 측정됨!

---

## 💡 결론

### 🔸 3가지 이유로 메모리 사용량이 동일함

1. **스택은 미리 할당됨** (매번 할당 아님!)
2. **변수 크기가 너무 작음** (8바이트 vs 2060KB)
3. **백준은 최대 메모리 측정** (작은 차이 무시됨)

---

## 📚 상세 설명

### 1️⃣ C++ 프로그램의 메모리 구조

```
┌─────────────────────┐ 높은 주소
│   Stack (스택)       │ ← 지역 변수, 함수 호출
├─────────────────────┤
│   Heap (힙)          │ ← new, malloc (동적 할당)
├─────────────────────┤
│   Data (데이터)      │ ← 전역 변수, static
├─────────────────────┤
│   Code (코드)        │ ← 실행 코드
└─────────────────────┘ 낮은 주소
```

<br>

### 2️⃣ 지역 변수 vs 전역 변수

| 구분 | 저장 위치 | 할당 시점 | 해제 시점 |
|------|----------|----------|----------|
| **전역 변수** | Data 영역 | 프로그램 시작 | 프로그램 종료 |
| **지역 변수** | Stack 영역 | 함수 진입 | 함수 종료 |

<br>

### 3️⃣ 왜 메모리 사용량이 똑같을까?

#### 🔸 이유 1: 스택은 미리 할당됨

```
프로그램 시작 시 (싱글 스레드 기준):
  - 메인 스레드 스택 크기: 약 8MB 미리 할당 (OS 설정에 따라 다름)
  - 각 스레드마다 독립적인 스택 존재
  - 한 스레드 내의 모든 함수가 해당 스레드의 스택을 공유

for문 안에서:
  for (int i = 0; i < n; i++)
  {
      int   tempK;  // 4바이트
      float tempM;  // 4바이트

      // 실제로는 "할당"이 아니라 "스택 포인터만 이동"!
  }
```

**⚠️ 중요 - 스레드와 스택:**
- **싱글 스레드 (백준 기준)**: 메인 스레드 1개 → 스택 1개
- **멀티 스레드**: 스레드마다 독립적인 스택 존재
  - CPU 코어 4개 → 스레드 4개 → 스택 4개
  - 각 스레드는 자신만의 스택에서 함수 호출 관리

**핵심**: 매번 새로 할당하는 게 아니라, **이미 있는 스택에서 자리만 잡음!**

<br>

#### 🔸 이유 2: 변수 크기가 너무 작음

```
전체 메모리: 2060KB
tempK + tempM: 8바이트 = 0.008KB

비율: 0.008 / 2060 = 0.0004% ← 측정 불가능!
```

**비유**:
```
바다(2060KB)에 물 한 방울(8바이트)을 떨어뜨림
→ 바다 크기 변화 없음!
```

<br>

#### 🔸 이유 3: 백준은 최대 메모리 측정

```
백준 메모리 측정 방식:
프로그램 실행 중 사용한 "최대 메모리"

예시:
┌─────────────────────────────────┐
│ 시간 0ms:  2060KB (프로그램 시작) │
│ 시간 1ms:  2060KB (dp 배열 사용)  │
│ 시간 2ms:  2060KB (for문 실행)    │
└─────────────────────────────────┘
최대 메모리: 2060KB ← 이 값을 출력!
```

**핵심**: `int` 2개(8바이트) 차이는 **측정 단위보다 작아서 보이지 않음!**

## 🔍 스택 포인터 동작 원리

### 📌 스택 포인터만 이동 (실제 할당 아님!)

```cpp
for (int i = 0; i < 1000; i++)
{
    int   tempK;  // 스택 포인터 -4 이동
    float tempM;  // 스택 포인터 -4 이동

    // 사용...

}  // 블록 종료: 스택 포인터 원위치!
```

**시각화**:
```
반복 1:
┌──────────┐
│ tempM    │ ← SP (스택 포인터)
│ tempK    │
└──────────┘

블록 종료:
┌──────────┐
│          │
│          │
└──────────┘ ← SP (원위치)

반복 2:
┌──────────┐
│ tempM    │ ← SP (같은 위치 재사용!)
│ tempK    │
└──────────┘

블록 종료:
┌──────────┐
│          │
│          │
└──────────┘ ← SP (원위치)
```

**핵심**:
- ✅ **같은 메모리 공간을 재사용!**
- ✅ **할당/해제 아님, 포인터만 이동!**
- ✅ **엄청 빠름! (1 CPU 사이클)**

---


### ✅ 올바른 이해

```
1. OS는 가상 메모리 공간 제공 (32bit : 4GB, 64bit : 수백 TB)
   실제 물리 메모리는 필요할 때만 할당

2. 스레드마다 독립적인 스택 존재 (각 약 8MB)
   - 싱글 스레드: 메인 스레드 1개 → 스택 1개
   - 멀티 스레드: 스레드 N개 → 스택 N개
   - 한 스레드 내의 모든 함수가 해당 스레드의 스택을 공유

3. for문 안에서는 스택 포인터만 이동 (할당 아님!)
   같은 공간 재사용
```

## 🧪 실험: 큰 배열로 테스트

```cpp
// Case 1: 전역 변수
int bigArray[100000];  // 400KB

int main()
{
    // ...
}
```

```cpp
// Case 2: 지역 변수
int main()
{
    int bigArray[100000];  // 400KB (스택에 할당)
    // ...
}
```

**결과**:
- Case 1 (전역): 약 2400KB
- Case 2 (지역): 약 2400KB (똑같음!)

**이유**: 스택도 미리 할당되어 있어서!

<br>

⚠️ **주의: 스택 오버플로우**

```cpp
int main()
{
    int bigArray[10000000];  // 40MB - 너무 큼!
    // Stack Overflow 발생 가능! (스택 크기 보통 8MB)
}
```

**해결**:
- ✅ **전역 변수 사용** (Data 영역, 크기 제한 거의 없음)
- ✅ **동적 할당** (`new`, `malloc` - Heap 영역)

---

## 💡 코딩 테스트 팁

| 상황 | 권장 방법 |
|------|----------|
| 작은 변수 (int, float) | 전역/지역 상관없음 |
| 큰 배열 (>1MB) | **전역 변수 권장** (스택 오버플로우 방지) |
| 재귀 함수 | **전역 변수 권장** (스택 깊이 제한) |

**예시 (올바른 사용)**:
```cpp
int dp[10004];  // 40KB ← 전역 변수 ✅ 올바른 선택!

for (int i = 0; i < n; i++)
{
    int tempK;   // 4바이트 ← 지역 변수 ✅ OK!
    float tempM; // 4바이트 ← 지역 변수 ✅ OK!
}
```

---

## 🎯 핵심 요약

1. **OS 메모리 할당**:
   - ✅ 가상 메모리 공간 제공, 필요할 때만 물리 메모리 할당 (O)

2. **스택 크기**:
   - ✅ 스레드마다 8MB 스택 1개, 한 스레드 내 모든 함수가 공유 (O)
   - ✅ 싱글 스레드 (백준): 메인 스레드 1개 → 스택 1개
   - ✅ 멀티 스레드: 스레드 N개 → 스택 N개

3. **지역 변수**:
   - ✅ 스택 포인터만 이동! (완벽한 이해!)
   - ✅ 같은 공간 재사용! (완벽한 이해!)
   - ✅ 크기 작아서 측정 안 됨! (완벽한 이해!)

## 📖 참고 자료

### 스택 크기 확인 방법

**Windows (PowerShell)**:
```bash
dumpbin /headers Test.exe | findstr stack
```

**일반적인 결과**:
```
   1000000 size of stack reserve   (16MB 예약)
    100000 size of stack commit    (1MB 커밋)
```

<br>

**Linux/Mac**:
```bash
ulimit -s        # 스택 크기 확인 (KB 단위)
ulimit -s 16384  # 16MB로 설정
```
