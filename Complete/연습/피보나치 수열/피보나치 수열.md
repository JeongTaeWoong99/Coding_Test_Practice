# 피보나치 수열

## DP

**DP (Dynamic Programming, 동적 계획법)**

한 번 계산한 결과를 **메모리에 저장**하여 중복 계산을 방지하는 알고리즘 기법.

### 핵심 개념

- **메모이제이션 (Memoization)** : 계산 결과를 배열에 저장
- **중복 제거** : 같은 값을 여러 번 계산하지 않음
- **최적 부분 구조** : 큰 문제를 작은 문제로 나눠서 해결

### DP의 두 가지 접근법

| 구분 | 탑다운 (Top-down)      | 바텀업 (Bottom-up) |
|-----|---------------------|-------------------|
| **구현** | 재귀 함수               | 반복문 (for) |
| **방향** | 큰 문제 → 작은 문제        | 작은 문제 → 큰 문제 |
| **오버헤드** | ⚠️ 함수 호출 있음         | ✅ 함수 호출 없음 |
| **속도** | 빠름                  | **더 빠름** (오버헤드 없음) |
| **메모리** | 스택 + dp 배열          | dp 배열만 |
| **장점** | 재귀로 직관적, 일부만 계산 가능＊ | 가장 빠름, 스택 안전 |
| **단점** | 함수 호출 느림, 스택 위험     | 모든 값 계산 |

**일부만 계산 가능** : 2차원 DP, 희소 행렬 등 **특수한 경우에만** 해당. 

피보나치처럼 순차적인 경우는 둘 다 모든 값 계산.

## 피보나치 수열 비교

### 1️⃣ 순수 재귀 (재귀만, DP 없음)

```cpp
int Fibo(int n)
{
    if (n <= 1) return n;
    return Fibo(n - 1) + Fibo(n - 2);  // 중복 계산 발생!
}
```

| 항목 | 설명                                   |
|-----|--------------------------------------|
| **메모이제이션** | ❌ 없음                                 |
| **중복 계산** | ❌ 엄청나게 많음 (같은 값 여러 번)                |
| **함수 호출** | ⚠️ 지수적(= 기하급수적)으로 증가 (Fibo(5) = 15번) |
| **시간 복잡도** | O(2^n) - 지수적 증가                      |
| **장점** | 수학적 정의와 동일, 매우 직관적                   |
| **단점** | 중복 계산 + 함수 호출로 극도로 느림                |
| **사용 여부** | ❌ **절대 사용 금지** (학습용만)                |

**호출 트리 예시 (Fibo(5)):**
```
                Fibo(5)
               /       \
          Fibo(4)      Fibo(3) ← 중복!
          /    \        /    \
     Fibo(3) Fibo(2) Fibo(2) Fibo(1)
     /   \
 Fibo(2) Fibo(1)

총 15번 호출! (Fibo(3)이 2번, Fibo(2)가 3번 중복)
```

---

### 2️⃣ 탑다운 (Top-down) - 재귀 + DP

```cpp
int dp[1004];  // -1로 초기화

int Fibo(int n)
{
    if(n <= 1) return n;

    int &ret = dp[n];
    
    if (ret != -1) return ret;  // 이미 계산했으면 바로 리턴

    return ret = Fibo(n - 1) + Fibo(n - 2);  // 계산 & 저장
}
```

| 항목 | 설명 |
|-----|------|
| **메모이제이션** | ✅ 있음 (dp 배열) |
| **구현 방식** | 재귀 함수 사용 |
| **계산 방향** | 큰 값 → 작은 값 (재귀 호출) |
| **계산 범위** | Fibo(n) 구하려면 0~n 모두 계산 |
| **중복 계산** | ✅ 없음 (각 값당 1번만) |
| **함수 호출** | ⚠️ 각 값당 1번 (총 n+1번) |
| **시간 복잡도** | O(n) |
| **장점** | 재귀로 직관적, 메모이제이션으로 빠름 |
| **단점** | 함수 호출 오버헤드 (~5배 느림) |

**실행 과정 (Fibo(5)):**
```
Fibo(5) → Fibo(4) → Fibo(3) → Fibo(2) → Fibo(1) → Fibo(0)
                                      ↑ 이후는 저장된 값 사용

계산 순서: Fibo(0), Fibo(1), Fibo(2), Fibo(3), Fibo(4), Fibo(5)
총 11번 호출 (각 값당 1번 + 중간 조회)
```

### 3️⃣ 바텀업 (Bottom-up) - 반복문 + DP

```cpp
int dp[1004];

int main()
{
    dp[0] = 0;
    dp[1] = 1;

    for (int i = 2; i <= n; i++)  // 반복문 사용!
        dp[i] = dp[i - 1] + dp[i - 2];

    cout << dp[n];
}
```

| 항목 | 설명 |
|-----|------|
| **메모이제이션** | ✅ 있음 (dp 배열) |
| **구현 방식** | 반복문 (for) 사용 |
| **계산 방향** | 작은 값 → 큰 값 (0부터 n까지) |
| **계산 범위** | Fibo(n) 구하려면 0~n 모두 계산 |
| **중복 계산** | ✅ 없음 |
| **함수 호출** | ✅ 없음 (for문만) |
| **시간 복잡도** | O(n) |
| **장점** | **가장 빠름** (오버헤드 없음), 스택 안전 |
| **단점** | 재귀보다 덜 직관적일 수 있음 |

**실행 과정 (Fibo(5)):**
```
dp[0] = 0          ← 초기값
dp[1] = 1          ← 초기값
dp[2] = 0 + 1 = 1  ← for문 1회
dp[3] = 1 + 1 = 2  ← for문 2회
dp[4] = 1 + 2 = 3  ← for문 3회
dp[5] = 2 + 3 = 5  ← for문 4회

총 4번 반복 (함수 호출 0번!)
```

## 📊 성능 비교

### ⏱️ 실행 시간 비교 (Fibo(40) 기준)

| 방식 | 실행 시간 | 함수 호출 | 계산량 | 추천도 |
|-----|----------|----------|--------|--------|
| **순수 재귀** | ~1초 | 약 2억 번 | O(2^40) | ❌ 사용 금지 |
| **탑다운** | ~0.001초 | 81번 | O(41) | ⚠️ 상황에 따라 |
| **바텀업** | ~0.0005초 | 0번 | O(41) | 🚀 **추천!** |

**🎯 핵심:**
- 순수 재귀 : 중복 계산 + 함수 호출 = 최악
- 탑다운 : 메모이제이션으로 빠름 but 함수 호출 오버헤드
- 바텀업 : 메모이제이션 + 오버헤드 없음 = **최고**

---

### 🔍 피보나치에서 계산량 비교

```
Fibo(10)을 구할 때:

탑다운: Fibo(0), Fibo(1), ..., Fibo(10) → 11개 계산
바텀업: dp[0], dp[1], ..., dp[10]       → 11개 계산

→ 계산량 동일! (0~10 모두 필요)
```

**⚠️ 중요 : 피보나치는 순차적이라 탑다운/바텀업 계산량 동일**

그런데 왜 바텀업이 더 빠를까?

---

### ⚡ 함수 호출 오버헤드의 영향

**함수 호출 1번의 비용:**
```
- 스택 프레임 생성(함수 스택) : ~10 CPU 사이클
- 파라미터 전달 : ~5 사이클
- 반환값 처리 : ~5 사이클
총 : ~20 사이클
```

**단순 연산 1번의 비용:**
```
dp[i] = dp[i-1] + dp[i-2]:
- 메모리 읽기 2번 : ~2 사이클
- 덧셈 : ~1 사이클
- 메모리 쓰기 : ~1 사이클
총: ~4 사이클
```

**⚡ 결과: 함수 호출은 단순 연산보다 약 5배 느림!**

```
탑다운 (n=100만):
- 계산량: 100만
- 함수 호출: 100만 번
- 실제 비용: 100만 × (4 + 20) = 2,400만 사이클

바텀업 (n=100만):
- 계산량: 100만
- 함수 호출: 0번
- 실제 비용: 100만 × 4 = 400만 사이클

→ 바텀업이 6배 빠름!
```

## 🎯 언제 무엇을 사용할까?

### ✅ 바텀업 추천 (90% 이상의 경우)

**사용 상황:**
- 일반적인 DP 문제 (피보나치, LIS, 배낭, 타일링 등)
- 코딩 테스트 (대부분의 경우)
- 속도가 중요한 경우
- n이 매우 큰 경우 (스택 오버플로우 방지)

**이유:**
- 함수 호출 오버헤드 없음 (5~10배 빠름)
- 스택 오버플로우 위험 없음
- 캐시 친화적 (순차 메모리 접근)

---

### ⚠️ 탑다운 고려 (10% 미만의 경우)

**사용 상황:**
- 재귀로 표현이 훨씬 자연스러운 경우
- **계산량 차이가 10배 이상 나는 경우**

**예시: 계산량이 극단적으로 다를 때**

```cpp
// 1000×1000 배열에서 (999, 999) 경로 탐색
// 단, 장애물이 매우 많아서 실제 경로는 거의 없음

탑다운 : 실제 경로만 탐색 (~2,000개 칸) => 재귀를 통한 '가지치기'
바텀업 : 모든 칸 순회 (1,000,000개 칸) => 전부 확인

→ 계산량 500배 차이! 탑다운 압승!

★ 희소 행렬과 같이, 가지치기를 해야하는 문제는 탑다운!
★ 함수 오버헤드 보다, 계산량 오버헤드가 더 클 때, 탑다운!
```

**⚠️ 주의 : 피보나치는 해당 안 됨** (모든 값이 순차적으로 필요)

**📁 실제 예시 코드 :** `피보나치 수열 탑다운 문제.txt` 참고

### 🔍 왜 바텀업으로는 안 되는가?

시각화:
바텀업 (모든 칸 확인):

┌─┬─┬─┬─┬─┬─┬─┬─┬─┬─┐

│✓│✓│✓│✓│✓│✓│✓│✓│✓│✓│ ← 모든 칸 확인!

├─┼─┼─┼─┼─┼─┼─┼─┼─┼─┤

│✓│X│✓│X│✓│X│✓│X│✓│✓│ ← X(장애물)도 체크함

├─┼─┼─┼─┼─┼─┼─┼─┼─┼─┤

│✓│✓│✓│✓│✓│✓│✓│✓│✓│✓│

└─┴─┴─┴─┴─┴─┴─┴─┴─┴─┘
방문: 100% (1,000,000칸)

탑다운 (필요한 경로만):

┌─┬─┬─┬─┬─┬─┬─┬─┬─┬─┐

│✓│✓│  │ │ │ │ │ │ │ │ ← 실제 경로만!

├─┼─┼─┼─┼─┼─┼─┼─┼─┼─┤

│✓│X│ │ │ │ │ │ │ │ │ ← X 만나면 중단!

├─┼─┼─┼─┼─┼─┼─┼─┼─┼─┤

│✓│✓│✓│ │ │ │ │ │ │ │

└─┴─┴─┴─┴─┴─┴─┴─┴─┴─┘

방문: 0.2% (~2,000칸)


**핵심 차이: 탐색 방식**

```
탑다운 (재귀) :
- 목표 지점에서 시작해서 역추적
- 갈 수 없는 경로는 즉시 백트래킹 (return 0)
- 실제로 도달 가능한 칸만 방문!

바텀업 (for문):
- 시작점부터 모든 칸을 순차 순회
- 장애물도 일일이 체크해야 함
- 도달 불가능한 칸도 모두 확인!
```

**실행 과정 비교 (10×10 희소 행렬)**

```
탑다운:
TopDown(9,9) → TopDown(8,9) → TopDown(7,9) → ...
              → TopDown(9,8) → (장애물!) return 0 ← 즉시 중단!

방문한 칸: ~20개 (실제 경로만)

바텀업:
for(y = 0; y < 10; y++)      ← 모든 행
  for(x = 0; x < 10; x++)    ← 모든 열
    if(장애물) continue       ← 모두 체크

방문한 칸 : 100개 (전체 칸)
```

**⚡ 성능 차이:**
- 탑다운 : 20개 칸 방문 + 함수 호출 20번 = ~500 연산
- 바텀업 : 100개 칸 방문 = ~500 연산

→ **이 경우 비슷!** (10×10은 작아서 차이 미미)

**📈 크기가 커지면? (1000×1000)**
- 탑다운 : ~2,000개 칸 + 함수 호출 2,000번 = ~50,000 연산
- 바텀업 : 1,000,000개 칸 = ~5,000,000 연산

→ **100배 차이! 탑다운 압승!**

**🎯 핵심: for문은 조건부 스킵이 불가능!**

```cpp
// 바텀업: 모든 칸을 확인해야 함
for(int y = 0; y < N; y++)       // 모든 y
{
    for(int x = 0; x < M; x++)   // 모든 x
    {
        if(arr[y][x] == 1) continue;  // 장애물 체크 (필수)
        // 계산...
    }
}
// → 도달 불가능한 칸도 모두 순회함!

// 탑다운 : 필요한 경로만 탐색
int TopDown(int y, int x)
{
    if(y >= N || x >= M || arr[y][x] == 1)
        return 0;  // ← 즉시 중단! 더 이상 탐색 안 함!

    // 재귀로 필요한 칸만 방문
    return TopDown(y + 1, x) + TopDown(y, x + 1);
}
```

**💡 결론:**

| 상황 | 탑다운 | 바텀업 |
|-----|-------|-------|
| **일반적인 경우** | 모든 칸 방문 + 오버헤드 | 모든 칸 방문 → **바텀업 승** |
| **희소 행렬** | 일부만 방문 + 오버헤드 | 모든 칸 방문 → **탑다운 승** |

**희소 행렬 :** 실제 계산이 필요한 칸이 전체의 1% 미만

## 📚 핵심 요약

### 세 가지 방식 비교

| 구분 | 방식 | 중복 계산 | 함수 호출 | 속도 |
|-----|------|----------|----------|------|
| **순수 재귀** | 재귀만 | ❌ 지수적 | ❌ 지수적 | 🐢 O(2^n) |
| **탑다운** | 재귀 + DP | ✅ 없음 | ⚠️ n번 | 🐇 O(n) |
| **바텀업** | for + DP | ✅ 없음 | ✅ 없음 | 🚀 O(n) |

### 최종 결론

**🚀 일반적인 경우: 바텀업 사용!**

**이유:**
1. 함수 호출 오버헤드 없음 (5~10배 빠름)
2. 스택 오버플로우 위험 없음
3. 코드가 간결하고 효율적

**⚠️ 예외: 계산량 차이가 10배 이상 나는 특수한 경우만 탑다운 고려**

**❌ 순수 재귀: 절대 사용 금지 (학습용만)**
