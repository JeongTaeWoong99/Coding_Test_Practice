## 🤔 접근법

`number` 배열에서 **서로 다른 세 수를 뽑아 그 합이 0이 되는 조합의 개수**를 구하는 문제.

서로 다른 3개를 뽑는 것은 순서가 의미 없는 **조합(nC3)** 이다.
배열의 길이가 최대 13으로 매우 작으므로(13C3 = 286), 모든 3개 조합을 직접 만들어 합을 확인하는 **완전 탐색(브루트포스)** 으로 충분하다.

핵심은 같은 조합을 중복해서 세지 않는 것이다.
**인덱스를 항상 `i < j < k`가 되도록** 잡으면 `(0,1,2)`와 `(2,1,0)` 같은 순서만 다른 중복이 자연스럽게 제거된다.

---

## 💡 정답 풀이 방법

**알고리즘**: 조합 완전 탐색 (3중 반복문)

```
1. answer = 0
2. i = 0 ~ n-3        (첫 번째 수)
   j = i+1 ~ n-2      (두 번째 수, i 다음부터)
   k = j+1 ~ n-1      (세 번째 수, j 다음부터)
   → number[i] + number[j] + number[k] == 0 이면 answer++
3. answer 반환
```

```cpp
for (int i = 0; i < n - 2; i++)
{
    for (int j = i + 1; j < n - 1; j++)
    {
        for (int k = j + 1; k < n; k++)
        {
            if (number[i] + number[j] + number[k] == 0)
            {
                answer++;
            }
        }
    }
}
```

## 🔑 핵심 개념

### 1️⃣ 조합 공식 — `i < j < k` 인덱스 규칙

서로 다른 3개를 뽑는 조합은 **각 반복의 시작점을 이전 인덱스 다음으로** 잡는 것이 핵심이다.

```cpp
for (i = 0    ; ...)      // 첫 번째
  for (j = i + 1; ...)    // i 다음부터 → 항상 i < j
    for (k = j + 1; ...)  // j 다음부터 → 항상 j < k
```

- `j`를 `i+1`부터 → 이미 고른 `i`를 다시 뽑지 않음
- `k`를 `j+1`부터 → `(1,2,3)`과 `(3,2,1)` 같은 순서만 다른 중복 방지

덕분에 각 조합이 **정확히 한 번씩만** 검사된다.

### 2️⃣ 루프 경계 — `n - 2`, `n - 1`

뒤에 뽑아야 할 자리를 남겨두기 위한 경계다.
`i`는 뒤에 `j`, `k` 두 자리가 필요하므로 `n - 2`까지, `j`는 뒤에 `k` 한 자리가 필요하므로 `n - 1`까지 돈다.

### 3️⃣ 제약이 작으면 브루트포스가 정답

`number` 길이가 최대 13이라 전체 조합 수가 최대 286개뿐이다.
이렇게 입력 크기가 작을 때는 복잡한 최적화 없이 가장 단순하고 명확한 완전 탐색이 최선이다.

## ⏱️ 시간복잡도

**O(n³)**
- 3중 반복문으로 모든 3개 조합(nC3)을 탐색
- n이 최대 13으로 작아 충분히 빠르다
