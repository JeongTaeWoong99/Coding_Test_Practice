## 🤔 접근법

빈 병 `a`개를 마트에 가져가면 콜라 `b`개로 바꿔주고, 처음에 `n`병을 가지고 있을 때 받을 수 있는 콜라의 총 개수를 구하는 시뮬레이션 문제.

교환할 때마다 병 수가 줄어들지만, 받은 콜라를 다 마시면 다시 빈 병이 되어 또 교환할 수 있다.
**현재 병 수가 필요 병 수(`a`) 이상인 동안** 계속 교환을 반복하면 된다.

한 번 교환할 때:
- 교환 가능 횟수 = `n / a` (몫)
- 새로 받는 병 = `(n / a) * b`
- 교환 후 남는 병 = `n % a` (나머지)

---

## 💡 정답 풀이 방법

**알고리즘**: 시뮬레이션 (수학적 반복)

```
1. answer = 0
2. n >= a 인 동안 반복:
   a. received = (n / a) * b   (이번에 새로 받는 병 수)
   b. rested   = n % a          (교환하고 남은 병 수)
   c. answer += received        (받은 콜라 누적)
   d. n = received + rested     (다음 라운드의 보유 병 수)
3. answer 반환
```

```cpp
while (n >= a)
{
    int received = n / a * b; // 몫(n/a)에 b를 곱해 새로 받는 병 수 계산
    int rested   = n % a;     // 교환 후 남은 병

    answer += received;
    n       = received + rested;
}
```

---

## 🔑 핵심 개념

### 1️⃣ 반복 조건 — `n >= a`

교환은 "보유 병 수가 필요 병 수 이상"일 때만 가능하다. 따라서 루프 조건은 반드시 `n >= a`여야 한다.
`n < a`로 잘못 쓰면 교환 가능한 상황에서 멈추고, 교환 불가능한 상황에서 돌아가 정반대로 동작한다.

### 2️⃣ 한 병씩 빼지 않고 몫·나머지로 한 번에 처리

`n`이 매우 클 수 있으므로 병을 하나씩 교환하면 비효율적이다.
`n / a`(교환 횟수)와 `n % a`(남는 병)를 이용하면 한 라운드를 **O(1)** 로 처리할 수 있어,
보유 병 수가 매 반복마다 빠르게 줄어든다.

### 3️⃣ 다음 라운드 보유 병 = 받은 병 + 남은 병

```cpp
n = received + rested;
```

교환으로 새로 받은 병(`received`)과 이번에 못 바꾼 나머지 병(`rested`)을 합한 것이
다음 라운드에 다시 교환할 수 있는 전체 병 수가 된다.

---

## ⏱️ 시간복잡도

**O(log n)**
- 매 반복마다 보유 병 수가 약 `b/a` 비율로 줄어들어(보통 `b < a`), 반복 횟수가 로그 규모로 감소한다.
