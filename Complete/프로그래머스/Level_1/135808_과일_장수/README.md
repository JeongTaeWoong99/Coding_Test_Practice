## 🤔 접근법

사과 한 박스에 m개씩 담아 팔되, 박스 가격은 **그 박스에 담긴 사과 중 최저 점수 × m**으로 정해지는 그리디 문제.
m개를 채우지 못하는 나머지 사과는 판매할 수 없으므로 버려진다.

**핵심**: 어차피 버려야 할 나머지(m개 미만)라면, 가장 낮은 점수의 사과들을 버리는 것이 이득이다.
점수를 **내림차순 정렬**하면 앞에서부터 m개씩 그룹을 지을 때 그룹의 마지막 원소가 곧 최솟값이 되고,
끝까지 m개를 채우지 못하는 나머지(=가장 낮은 점수들)는 자연스럽게 제외된다.

---

## 💡 정답 풀이 방법

**알고리즘**: 그리디 + 정렬

```
1. score를 내림차순 정렬
2. i = 0부터 m씩 증가하며 (i + m <= n) 인 동안:
   a. boxMin = score[i + m - 1] (내림차순이므로 그룹의 마지막 원소 = 최솟값)
   b. answer += boxMin * m
3. m개를 채우지 못하는 나머지는 자동으로 버려짐 (루프 조건에서 제외)
4. answer 반환
```

## 🔑 핵심 개념

### 1️⃣ 왜 가장 낮은 점수를 버려야 하는가

박스 가격은 `최솟값 × m`으로 정해지므로, 낮은 점수의 사과를 박스에 끼워 넣으면
그 박스 전체의 가격이 낮아져 손해다. 예를 들어 `score=[1,10,10,10], m=3`이면

```
[10,10,10] 박스 + 1 버림 → 30
[1,10,10] 박스 + 10 버림 → 3   (훨씬 손해)
```

따라서 어차피 m개를 못 채워 버려야 할 나머지라면, 가장 낮은 점수들을 버리는 것이 항상 최선이다.

### 2️⃣ 내림차순 정렬 + 마지막 원소 = 최솟값

```cpp
sort(score.begin(), score.end(), greater<int>());

for (int i = 0; i + m <= n; i += m)
{
    int boxMin = score[i + m - 1];   // 내림차순이므로 그룹의 마지막 원소가 최솟값
    answer += boxMin * m;
}
```

내림차순으로 정렬했기 때문에 `[i, i+m)` 구간에서 가장 작은 값은 항상 `score[i + m - 1]`이다.
별도의 min 변수를 추적할 필요 없이 인덱스만으로 바로 구할 수 있다.

### 3️⃣ 루프 조건 `i + m <= n` — 나머지 자동 처리

```cpp
for (int i = 0; i + m <= n; i += m)
```

`i + m`이 `n`을 넘어서면 루프가 종료되므로, m개를 채우지 못하는 마지막 나머지(정렬 후 맨 뒤 = 가장 낮은 점수들)는
별도의 분기 없이 자연스럽게 버려진다.

## ⏱️ 시간복잡도

**O(n log n)**
- n: score 길이
- 정렬에 O(n log n), 이후 그룹화는 O(n)
