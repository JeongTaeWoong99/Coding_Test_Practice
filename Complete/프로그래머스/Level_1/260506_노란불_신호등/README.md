## 🤔 접근법

n개의 신호등이 각자의 주기(초록→노란→빨간)로 반복될 때, 모든 신호등이 **동시에 노란불**이 되는 가장 빠른 시각을 찾는 문제.

**핵심**: 신호등들의 전체 패턴은 **모든 주기의 LCM(최소공배수)** 마다 반복된다.  
→ LCM 안에 정답이 없으면 영원히 없다 → `-1` 반환.

---

## 💡 정답 풀이 방법

**알고리즘**: 브루트포스 + LCM 탐색 상한

```
1. 각 신호등의 한 주기 길이 T = G + Y + R 계산
2. 모든 T의 LCM 계산 → 탐색 범위 확정
3. t=1부터 LCM까지 순회하며 모든 신호등이 노란불인 시각 탐색
```

## 🔑 핵심 개념

### 1️⃣ LCM (Least Common Multiple = 최소공배수)

LCM은 여러 수들을 모두 나누어 떨어지게 하는 **가장 작은 공통 배수**다.

```
LCM(5, 7) = 35    ← 5의 배수이면서 동시에 7의 배수인 수 중 가장 작은 것
LCM(4, 6) = 12    ← 4의 배수이면서 동시에 6의 배수인 수 중 가장 작은 것
LCM(6, 6) =  6    ← 같은 수끼리의 LCM = 자기 자신
```

이 문제에서 LCM이 필요한 이유:
- 신호1의 주기가 5, 신호2의 주기가 7이면
- 두 신호등이 같은 상태가 될 가능성이 있는 **공통 주기** = LCM(5, 7) = 35
- 35초 이후에는 t=1 ~ 35와 완전히 같은 패턴이 반복된다
- → **35초 안에 정답이 없으면 영원히 없다**

---

### 2️⃣ LCM 공식

```cpp
periodLCM = periodLCM / gcd(periodLCM, totalTime) * totalTime;
```

기본 공식: **LCM(a, b) = a × b / gcd(a, b)**

나눗셈을 먼저 쓰는 이유 → 정수 오버플로우 방지  
(`a * b`를 먼저 계산하면 값이 커질 수 있으므로, 먼저 나누어서 크기를 줄임)

```
LCM(a, b) = a * b / gcd(a, b)
          = a / gcd(a, b) * b    ← a/gcd(a,b)는 항상 나누어 떨어짐 (수학적 보장)
```

---

### ⚠️ "periodLCM이 작은 값으로 덮어씌워지지 않나?" 오해 해소

```cpp
for (auto& s : signals)
{
    int totalTime = ...;
    periodLCM = periodLCM / gcd(periodLCM, totalTime) * totalTime;
}
```

**LCM의 핵심 성질: LCM(a, b) ≥ a 항상 성립**  
→ periodLCM은 루프를 돌수록 **절대 작아지지 않는다**. 항상 같거나 커진다.

**직관적 증명:**
```
LCM(35, 5) = ?
  gcd(35, 5) = 5
  LCM = 35 / 5 * 5 = 35   ← 35 그대로! (5가 35의 약수이므로)

LCM(35, 7) = ?
  gcd(35, 7) = 7
  LCM = 35 / 7 * 7 = 35   ← 마찬가지로 35 그대로!

LCM(35, 6) = ?
  gcd(35, 6) = 1
  LCM = 35 / 1 * 6 = 210  ← 더 커짐!
```

즉, 새로운 수가 기존 periodLCM의 약수라면 → **LCM은 변하지 않음**  
새로운 수가 기존 periodLCM과 공약수가 없으면 → **LCM은 더 커짐**  
→ **절대로 작아지지 않는다.**

### 3️⃣ pos로 신호 색상 판별하는 이유

시각 t에서 신호등이 몇 번째 주기의 몇 번째 상태인지 계산:

```cpp
int pos = (t - 1) % totalTime;
```

**(t-1)을 쓰는 이유**: 시간은 1초부터 시작하지만, 배열 인덱스는 0부터 시작.
t=1을 pos=0(초록 시작)으로 맞추기 위해 -1을 함.

**신호 [G=2, Y=1, R=2] (T=5) 예시:**
```
t=1 → pos=(1-1)%5=0 → 초록  ┐
t=2 → pos=(2-1)%5=1 → 초록  ┘ (0 ~ G-1 = 0~1 : 초록)

t=3 → pos=(3-1)%5=2 → 노란  (G=2 : 노란 시작)

t=4 → pos=(4-1)%5=3 → 빨간  ┐
t=5 → pos=(5-1)%5=4 → 빨간  ┘ (G+Y=3 이상 : 빨간)

t=6 → pos=(6-1)%5=0 → 초록  ← 새 주기 시작!
t=7 → pos=(7-1)%5=1 → 초록
t=8 → pos=(8-1)%5=2 → 노란  ✅
```

**노란불 조건:**
```
pos가 [G, G+Y-1] 범위에 있으면 노란불

반대로, 이 조건에서 벗어나면 노란불 아님:
  pos < G        → 아직 초록 (G=2면 pos가 0이나 1)
  pos >= G + Y   → 이미 빨간 (G+Y=3이면 pos가 3이나 4)
```

코드에서:
```cpp
if (pos < green || pos >= green + yellow)
{
    allYellow = false;   // 이 신호등은 노란불 아님
    break;               // 더 볼 필요 없이 이 t는 탈락
}
```

## 📊 테스트케이스 추적

### 🟡 케이스 1 — `[[2,1,2], [5,1,1]]` → 13

**LCM 계산 과정:**
```
periodLCM = 1

신호1: totalTime = 2+1+2 = 5
  gcd(1, 5) = 1
  periodLCM = 1 / 1 * 5 = 5

신호2: totalTime = 5+1+1 = 7
  gcd(5, 7) = 1
  periodLCM = 5 / 1 * 7 = 35     ← LCM(5,7)=35, 더 커짐!

탐색 범위: t = 1 ~ 35
```

**노란불 시각 목록:**
```
신호1 [G=2, Y=1, T=5] — 노란불 조건: pos == 2  (2 이상, 3 미만)
  t= 3 → pos = (3-1) % 5 = 2  ✅
  t= 8 → pos = (8-1) % 5 = 2  ✅
  t=13 → pos = (13-1) % 5 = 2 ✅

신호2 [G=5, Y=1, T=7] — 노란불 조건: pos == 5  (5 이상, 6 미만)
  t= 6 → pos = (6-1)  % 7 = 5 ✅
  t=13 → pos = (13-1) % 7 = 5 ✅
```

**탐색 결과:** t=13에서 두 신호등 모두 노란불 → **return 13** ✅

### 🟡 케이스 2 — `[[2,3,2], [3,1,3], [2,1,1]]` → 11

**LCM 계산 과정:**
```
periodLCM = 1

신호1: totalTime = 2+3+2 = 7
  gcd(1, 7) = 1
  periodLCM = 1 / 1 * 7 = 7

신호2: totalTime = 3+1+3 = 7
  gcd(7, 7) = 7
  periodLCM = 7 / 7 * 7 = 7    ← 주기가 같으면 LCM 그대로!

신호3: totalTime = 2+1+1 = 4
  gcd(7, 4) = 1
  periodLCM = 7 / 1 * 4 = 28   ← LCM(7,4)=28, 더 커짐!

탐색 범위: t = 1 ~ 28
```

**t=4 체크 (후보):**
```
신호1 [G=2, Y=3, T=7]: pos=(4-1)%7=3  → [2,4] 범위  ✅
신호2 [G=3, Y=1, T=7]: pos=(4-1)%7=3  → [3,3] 범위  ✅
신호3 [G=2, Y=1, T=4]: pos=(4-1)%4=3  → [2,2] 범위  ❌ 빨간불!
```

**t=11 체크:**
```
신호1 [G=2, Y=3, T=7]: pos=(11-1)%7=10%7=3  → [2,4]  ✅
신호2 [G=3, Y=1, T=7]: pos=(11-1)%7=10%7=3  → [3,3]  ✅
신호3 [G=2, Y=1, T=4]: pos=(11-1)%4=10%4=2  → [2,2]  ✅

→ 전부 노란불!  return 11  ✅
```

## ⏱️ 시간복잡도

**O(LCM × n)**
- LCM: 주기가 최대 20, 신호등이 최대 5개 → LCM 최대 약 232,560
- n: 신호등 수 (최대 5)
- 전체: 약 1,160,000 연산 (충분히 통과)
