## 🤔 접근법

수포자 3명이 각자 **정해진 패턴대로 찍을 때**, 가장 많이 맞힌 사람을 구하는 문제.

```
1번 : 1, 2, 3, 4, 5                    → 5개 주기
2번 : 2, 1, 2, 3, 2, 4, 2, 5           → 8개 주기
3번 : 3, 3, 1, 1, 2, 2, 4, 4, 5, 5     → 10개 주기
```

**완전 탐색**으로 분류되어 있지만, 순열·조합을 만들어보는 탐색이 아니다.
패턴이 이미 고정되어 있으므로 **정답 배열과 순서대로 하나씩 비교**하면 끝난다.

관건은 두 가지다.

1. **문제 수가 패턴 길이를 넘어가는 경우** → 패턴은 처음으로 되돌아가 반복된다
2. **최고 점수가 여러 명인 경우** → 번호 오름차순으로 전부 반환해야 한다

> ⚠️ 비교 횟수는 항상 **`answers`의 크기**만큼이다.
> 예를 들어 `answers = [1, 2]` 면 문제가 2개뿐이므로 비교도 2번만 일어나고,
> 3~5번째 자리는 "틀린 것"이 아니라 **애초에 존재하지 않는다**. (1번 수포자 2점)

## 💡 정답 풀이 방법

**알고리즘**: 패턴 매핑 테이블 + 나머지 연산 순환

```
1. 수포자 3명의 찍기 패턴을 배열로 미리 만들어 둔다
2. i = 0 ~ answers.size()-1 순회
   각 수포자 p 에 대해:
   → answers[i] == patterns[p][i % patterns[p].size()] 이면 score[p]++
3. 세 점수 중 최댓값 maxScore 를 구한다
4. score[p] == maxScore 인 수포자 번호(p + 1)를 오름차순으로 담아 반환
```

```cpp
for (int i = 0; i < (int)answers.size(); i++)
{
    for (int p = 0; p < 3; p++)
    {
        if (answers[i] == patterns[p][i % patterns[p].size()])
        {
            score[p]++;
        }
    }
}
```

## 🔑 핵심 개념

### 1️⃣ 패턴은 매핑 테이블로

2번(짝수 자리마다 2), 3번(같은 수를 두 번씩)은 규칙이 있어 공식으로도 만들 수 있지만,
**패턴 길이가 5·8·10으로 짧고 완전히 고정**되어 있으므로 그냥 적어두는 편이 낫다.

```cpp
vector<int> patterns[3] =
{
    { 1, 2, 3, 4, 5 },                 // 1번 수포자 : 5개 주기
    { 2, 1, 2, 3, 2, 4, 2, 5 },        // 2번 수포자 : 8개 주기
    { 3, 3, 1, 1, 2, 2, 4, 4, 5, 5 }   // 3번 수포자 : 10개 주기
};
```

| 구분 | 공식 계산 | 매핑 테이블 |
|------|----------|-----------|
| 정확성 | 규칙이 맞는지 머리로 검산해야 함 | 문제에 적힌 패턴이 코드에 그대로 보임 |
| 분기 | 수포자마다 다른 규칙 → 함수 3개 | 배열 하나로 통일 |

> 💡 값의 개수가 적고 고정되어 있으면, **계산보다 표가 낫다.**

### 2️⃣ 주기 반복은 `% 길이`

문제 수는 최대 10,000개인데 패턴은 길어야 10개다.
인덱스를 패턴 길이로 나눈 나머지로 접근하면 자동으로 처음부터 다시 돌아간다.

```cpp
patterns[p][i % patterns[p].size()]
```

- 1번 수포자, `i = 7` → `7 % 5 = 2` → `patterns[0][2] = 3`
- 3번 수포자, `i = 12` → `12 % 10 = 2` → `patterns[2][2] = 1`

패턴을 문제 수만큼 미리 늘려 만들 필요가 전혀 없다.

### 3️⃣ 동점자 전원 반환

문제에서 "**가장 높은 점수를 받은 사람이 여럿이면 오름차순 정렬**"을 요구한다.
`p = 0, 1, 2` 순서로 순회하며 담으면 정렬은 자연스럽게 해결된다.

```cpp
for (int p = 0; p < 3; p++)
{
    if (score[p] == maxScore)
    {
        answer.emplace_back(p + 1); // 인덱스 → 수포자 번호
    }
}
```

> ⚠️ 최댓값 하나만 찾아 `return { maxIdx + 1 }` 로 끝내면 동점 케이스에서 틀린다.
> 실제로 예제 2번(`[1,3,2,4,2]`)이 `1, 2, 3` 전원 동점이다.

## 📊 테스트 케이스

| answers | 점수 (1번/2번/3번) | 출력 | 포인트 |
|---------|------------------|------|--------|
| `[1,2,3,4,5]` | 5 / 0 / 0 | `[1]` | 단독 1위 |
| `[1,3,2,4,2]` | 2 / 2 / 2 | `[1,2,3]` | 동점자 전원 반환 |
| `[1,2]` | 2 / 0 / 0 | `[1]` | 정답 개수만큼만 비교 |

## ⏱️ 시간복잡도

**O(n)** — n: answers 크기 (최대 10,000)

문제 하나당 수포자 3명을 확인하므로 `3n` 이지만 상수는 무시되어 선형이다.
