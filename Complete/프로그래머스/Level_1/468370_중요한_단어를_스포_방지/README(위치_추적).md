## 🤔 접근법

메시지에서 스포일러 구간이 주어질 때, 스포일러 단어 중 **처음 공개되는 고유한 단어**를 세는 문제.

**핵심**: 단어를 파싱할 때 **문자 위치(시작/끝 인덱스)** 를 함께 저장하고, 스포일러 구간과 직접 비교한다.

---

## 💡 정답 풀이 방법

**알고리즘**: 단어 파싱 + 구간 겹침 판별 + unordered_set 중복 체크

```
1. 메시지를 파싱하여 {단어, {시작 인덱스, 끝 인덱스}} 쌍으로 저장
2. 스포일러 구간 밖의 단어들을 seenWords에 추가
3. 스포일러 구간을 왼쪽부터 순서대로 처리
   - 구간과 겹치는 단어 중 seenWords에 없으면 → 중요한 단어 (count++)
   - 해당 단어를 seenWords에 등록 (이후 중복 방지)
```

---

## 🔑 핵심 개념

### 1️⃣ 단어-구간 겹침 조건

단어 범위 [ws, we]와 구간 [s, e]가 겹치는 조건:

```
ws <= e  AND  we >= s
```

단어 끝이 구간 시작보다 앞에 있으면(we < s) 겹치지 않고,  
단어 시작이 구간 끝보다 뒤에 있으면(ws > e) 겹치지 않는다.  
→ 이 두 경우의 부정 = 겹침 조건

---

### 2️⃣ 왜 비스포일러 단어를 먼저 전부 수집해야 하나

스포일러 구간 뒤에 등장하는 비스포일러 단어도 "이미 알려진 단어"로 처리해야 한다.

예시: 스포일러 구간 이후에 "phone"이 비스포일러로 다시 등장하면, 앞의 스포일러 "phone"은 중요한 단어가 아님.

→ **비스포일러 단어를 먼저 전부 수집** 후 스포일러 처리 — 2-pass 구조

---

## 📊 예시 추적 (예시 2)

```
message = "my phone number is 01012345678 and may i have your phone number"
spoiler = [[5,5], [25,28], [34,40], [53,59]]
```

비스포일러 수집: `seenWords = { "my", "number", "is", "and", "have", "your" }`

```
구간 [5,5]   → "phone"        → 없음 → ✅ count=1
구간 [25,28] → "01012345678"  → 없음 → ✅ count=2
구간 [34,40] → "may"          → 없음 → ✅ count=3
              → "i"           → 없음 → ✅ count=4
구간 [53,59] → "phone"        → 있음 → ❌
              → "number"      → 있음 → ❌
→ answer = 4 ✅
```

---

## ⏱️ 시간복잡도

**O(W × S)**
- W: 단어 수 (최대 ~10,000)
- S: 스포일러 구간 수 (최대 1,000)
- seenWords 조회: O(1) average (unordered_set)
