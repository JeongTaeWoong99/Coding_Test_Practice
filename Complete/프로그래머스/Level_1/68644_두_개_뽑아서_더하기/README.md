## 🤔 접근법

배열에서 **서로 다른 두 인덱스**를 골라 더했을 때 만들 수 있는 모든 값을,
**중복 없이 오름차순**으로 반환하는 문제.

핵심 요구사항은 세 가지다.

1. 모든 두 개 조합의 합 구하기
2. 중복 제거
3. 오름차순 정렬

값의 범위가 `0 ≤ numbers[i] ≤ 100`으로 매우 작다는 점에 주목하면,
두 수의 합은 **0 ~ 200** 사이로 고정된다. 즉 나올 수 있는 결과가 201가지뿐이다.

그러면 **합을 인덱스로 쓰는 카운팅 배열**을 두고 등장 여부만 체크하면,
중복 제거와 정렬을 별도 자료구조 없이 한 번에 해결할 수 있다.

- **방식 1** : `set<int>`에 모든 합을 넣고 그대로 vector로 옮기기 (set이 중복 제거 + 정렬 담당)
- **방식 2** : 크기 201짜리 카운팅 배열에 체크 후, 0번 인덱스부터 순회하며 담기

## 💡 정답 풀이 방법

**알고리즘**: 완전 탐색 + 카운팅 배열 (값의 범위가 작을 때)

```
1. numArr[201]을 0으로 초기화
2. i < j 인 모든 쌍을 순회하며 numArr[numbers[i] + numbers[j]]++ 
3. sum = 0 ~ 200 순회하며 numArr[sum] != 0 인 sum만 answer에 담기
4. answer 반환 (이미 오름차순)
```

```cpp
int numArr[201] = {};

for (int i = 0; i < numbers.size(); ++i)
{
    for (int j = i + 1; j < numbers.size(); ++j)
    {
        numArr[numbers[i] + numbers[j]]++;
    }
}

for (int sum = 0; sum <= 200; ++sum)
{
    if (numArr[sum] != 0)
    {
        answer.emplace_back(sum);
    }
}
```

## 🔑 핵심 개념

### 1️⃣ 값의 범위가 작으면 "값 = 인덱스"로 쓴다

`numbers[i]`가 최대 100이므로 두 수의 합은 최대 200.
따라서 크기 **201**짜리 배열(인덱스 0~200)이면 모든 경우를 담을 수 있다.

> ⚠️ 배열 크기를 200으로 잡으면 합이 정확히 200일 때 인덱스 200에 접근해 **범위 밖 접근**이 된다.
> 0부터 시작하는 인덱스이므로 크기는 항상 `최댓값 + 1`.

### 2️⃣ 중복 제거와 정렬이 공짜로 해결된다

- **중복 제거** : 같은 합이 여러 번 나와도 `numArr[sum]` 값만 늘어날 뿐, 담을 땐 한 번만 담긴다
- **정렬** : `sum`을 0부터 증가시키며 순회하므로, 담기는 순서가 곧 오름차순

즉 `set`도 `sort`도 필요 없다.

### 3️⃣ `j = i + 1` 로 조합 중복 방지

"서로 다른 인덱스 두 개"이므로 `(i, j)`와 `(j, i)`는 같은 쌍이다.
안쪽 반복문을 `i + 1`부터 시작하면 각 쌍을 정확히 한 번씩만 계산한다.
(자기 자신끼리 더하는 `i == j` 경우도 자동으로 배제된다)

```
numbers = [2, 1, 3, 4, 1]
(2,1)=3 (2,3)=5 (2,4)=6 (2,1)=3
(1,3)=4 (1,4)=5 (1,1)=2
(3,4)=7 (3,1)=4
(4,1)=5
→ 담기는 값 : 2, 3, 4, 5, 6, 7
```

## ⚖️ 두 방식 비교

| 구분 | 방식 1 (set) | 방식 2 (카운팅 배열) |
|------|------------|------------------|
| 중복 제거 | set이 자동 처리 | 등장 여부 체크로 처리 |
| 정렬 | set이 자동 정렬 | 인덱스 순회로 자동 정렬 |
| 시간복잡도 | O(N² log N) | O(N² + 200) |
| 장점 | 값 범위를 몰라도 항상 동작 | 더 빠름, 삽입마다 로그 비용 없음 |
| 단점 | 삽입마다 O(log N) | 값의 최댓값을 알아야 배열 크기를 정할 수 있음 |

`numbers` 길이가 최대 100이라 조합은 많아야 `100 × 99 / 2 = 4,950`개.
두 방식 모두 충분히 빠르지만, **값 범위가 명시된 문제**라 카운팅 배열이 더 깔끔하다.

## ⏱️ 시간복잡도

**O(N²)** — N: numbers 크기 (최대 100). 모든 두 개 조합을 순회.
결과 수집은 값 범위가 고정(201)이라 상수 시간.
