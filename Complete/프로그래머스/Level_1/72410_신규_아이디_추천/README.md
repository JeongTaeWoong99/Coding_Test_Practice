## 🤔 접근법

문제에서 **1~7단계 처리 순서를 그대로 제시**해주는 단순 치환/구현 문제.

정규식이나 단일 순회로 압축하려 하면 오히려 실수가 늘어난다. **문제가 시킨 순서를 그대로 코드로 옮기는 것**이 가장 안전하고 읽기 좋다.

**핵심 규칙**:
- 길이는 3자 이상 15자 이하
- 소문자, 숫자, `-`, `_`, `.` 만 허용
- 마침표(`.`)는 처음/끝에 올 수 없고, 연속 사용도 불가

---

## 💡 정답 풀이 방법

**알고리즘**: 문자열 구현 (단계별 치환)

```
1단계: 모든 대문자 → 소문자 (tolower)
2단계: 허용 문자(소문자, 숫자, -, _, .) 외 전부 제거
3단계: 연속된 마침표(..) → 하나(.)로 축약
4단계: 처음과 끝의 마침표 제거
5단계: 빈 문자열이면 "a" 대입
6단계: 16자 이상이면 15자로 자른 뒤, 끝의 마침표 제거
7단계: 2자 이하이면 마지막 문자를 3자가 될 때까지 반복
```

---

## 🔑 핵심 개념

### 1️⃣ 4단계와 6단계가 같은 작업 → 함수로 분리

끝 마침표 제거가 **두 번** 필요하다. 4단계에서 한 번, 6단계에서 15자로 자른 뒤 또 한 번.

15자로 잘랐을 때 `"abcdefghijklmn."` 처럼 마침표로 끝날 수 있기 때문이다. 그래서 별도 함수로 빼서 재사용한다.

```cpp
// 문자열 양쪽 끝의 마침표(.) 제거
string RemoveEdgeDot(string s)
{
    while (!s.empty() && s.front() == '.') // 앞쪽
    {
        s.erase(s.begin());
    }

    while (!s.empty() && s.back() == '.')  // 뒤쪽
    {
        s.pop_back();
    }

    return s;
}
```

> ⚠️ **주의**: `s.empty()` 체크를 앞에 두지 않으면 `"..."` 같은 입력에서 빈 문자열에 `front()`/`back()`을 호출해 **미정의 동작**이 발생한다.

### 2️⃣ 3단계 — 새 문자열에 옮겨 담으며 축약

제자리에서 지우는 대신, **직전에 담은 문자**와 비교하며 새 문자열을 만든다. 인덱스 꼬임 없이 O(N).

```cpp
for (char c : answer)
{
    if (c == '.' && !temp.empty() && temp.back() == '.') // 직전 문자도 '.' 이면 스킵
    {
        continue;
    }

    temp += c;
}
```

### 3️⃣ 7단계는 `if`가 아니라 `while`

`"a"` 한 글자면 `"aa"` → `"aaa"` 로 **두 번** 늘려야 한다. `if`로 한 번만 처리하면 2자에서 멈춘다.

```cpp
while (answer.size() <= 2)
{
    answer += answer.back(); // 매번 갱신된 마지막 문자를 붙임
}
```

> 5단계에서 빈 문자열을 `"a"`로 채웠기 때문에, 여기서 `answer.back()` 호출은 항상 안전하다.

### 4️⃣ 단계 순서를 바꾸면 틀린다

- 2단계(문자 제거)를 3단계(마침표 축약)보다 **먼저** 해야 한다. `"a!!b"` 에서 `!`를 지워야 비로소 마침표가 붙는 케이스가 생기듯, 제거 후에야 연속 마침표가 드러난다.
- 6단계(자르기) 후 **반드시** 끝 마침표를 다시 제거해야 한다.

## 📊 테스트 케이스

| 입력 | 출력 | 포인트 |
|------|------|--------|
| `...!@BaT#*..y.abcdefghijklm` | `bat.y.abcdefghi` | 전 단계 종합 |
| `z-` | `z--` | 7단계 (2자 → 3자) |
| `=.=` | `aaa` | 5단계(빈 문자열) → 7단계 2회 반복 |
| `123_.def` | `123_.def` | 변경 없음 |
| `abcdefghijklmn.p` | `abcdefghijklmn` | 6단계 자른 뒤 끝 마침표 제거 |

## ⏱️ 시간복잡도

**O(N)** — N: new_id 길이 (최대 1,000)

각 단계가 문자열을 한 번씩만 순회하므로 상수 배의 선형 시간.
