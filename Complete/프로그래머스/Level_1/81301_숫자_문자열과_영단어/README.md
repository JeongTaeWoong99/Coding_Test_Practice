## 🤔 접근법

숫자와 영단어(`zero`~`nine`)가 섞인 문자열을, 영단어를 해당 숫자로 **치환**한 뒤 통째로 정수 변환하는 문제.

첫 글자로 단어를 판별해 인덱스를 점프하는 방식도 가능하지만, 9개 단어를 일일이 분기해야 해서 버그가 나기 쉽다.
대신 `string::find` + `string::replace`로 **"단어를 찾아 숫자로 바꾸기"** 를 9번(0~9) 반복하면, 위치 계산을 STL이 대신 처리해 로직이 단순해진다.

---

## 💡 정답 풀이 방법

**알고리즘**: 문자열 치환(구현)

```
1. words[10] = { "zero", ..., "nine" }  (인덱스 = 숫자)
2. num = 0 ~ 9 반복:
   a. s.find(words[num])로 단어 위치 pos 탐색
   b. 찾으면(npos 아니면) s.replace(pos, 길이, to_string(num))
   c. 같은 단어가 또 있을 수 있으니 while로 전부 치환
3. 치환 끝나면 s는 숫자 문자만 남음 → stoi(s)
```

## 🔑 핵심 개념

### 1️⃣ `size_t` — 크기·인덱스를 담는 부호 없는 정수 타입

`size_t`는 **부호 없는(unsigned) 정수** 타입으로, 배열/문자열의 크기나 인덱스처럼 **음수가 될 수 없는 값**을 담기 위해 존재한다. (`sizeof` 연산자의 반환 타입이기도 함)

- 플랫폼에 따라 폭이 다름 → 64bit 환경에서 8바이트, 32bit에서 4바이트
- `s.find(...)`의 반환 타입이 `size_t`이므로, 그 결과를 받는 변수도 `size_t`로 맞추는 것이 안전하다
- "못 찾음"을 뜻하는 `string::npos`는 사실 `size_t`가 표현 가능한 **최댓값**(`-1`을 unsigned로 해석한 값)이다

### 2️⃣ `find` — 부분 문자열의 "시작 위치"를 반환

```cpp
size_t pos = s.find(words[num]);
```

`find`는 `words[num]`이 `s` 안에서 **처음 등장하는 위치(인덱스)** 를 돌려준다. 못 찾으면 `string::npos`.
즉 `pos`에 담기는 건 "값"이 아니라 **"자리(인덱스)"** 다.

```cpp
while ((pos = s.find(words[num])) != string::npos) { ... }
// npos가 아니면 = 아직 찾을 단어가 남아있다
```

### 3️⃣ `replace` 후에는 매번 처음부터 다시 탐색

```cpp
s.replace(pos, words[num].size(), to_string(num));
```

`replace`는 `pos`부터 `words[num].size()`개의 문자를 지우고 그 자리에 숫자 한 글자를 끼워 넣는다.
→ 치환할 때마다 `s`의 **내용과 길이가 바뀌므로**, 다음 `while` 반복의 `s.find`는 **바뀐 s의 맨 앞(0번)부터** 다시 검색한다.

> 매번 앞에서부터 재탐색하는 건 살짝 비효율적이지만, 이 문제의 입력 크기에서는 전혀 문제되지 않는다.

## ⏱️ 시간복잡도

문자열 길이를 N이라 하면:

- 바깥 for : 숫자 0~9 → **10번 (상수)**
- 안쪽 while : 한 단어가 최대 N/3번 등장 (단어 길이 ≥ 3) → 치환 횟수 **O(N)**
- 매 반복의 `find` + `replace` : 각각 문자열을 훑음 → **O(N)**

→ 대략 **O(10 × N × N) = O(N²)** (최악).
다만 상수 10이 붙고 N도 매우 작아(정수 범위상 s 길이는 최대 약 50자) 실질적으로 즉시 끝난다.

> 💡 질문했던 "S × 10 × N" 감각은 정확하다. 10(숫자 종류) × 치환 반복 × 재탐색 스캔이라, 재탐색 때문에 N이 한 번 더 곱해져 O(N²)에 가깝다.
> 한 번의 스캔으로 끝내려면 인덱스를 이어받으며(`find`의 시작 위치 인자 활용) 치환하거나, 앞에서부터 파싱하는 방식으로 **O(N)** 까지 줄일 수 있다.
