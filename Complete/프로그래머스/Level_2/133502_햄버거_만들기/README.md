## 🤔 접근법

재료가 아래에서부터 순서대로 쌓일 때, **빵-야채-고기-빵(`1-2-3-1`)** 이 연속으로 4개 쌓이면 햄버거 1개가 완성되어 빠져나간다. 빠져나간 자리는 메워지므로, 그 위·아래 재료가 새로 맞붙어 또 다른 햄버거가 완성될 수도 있다.

```
[2, 1, 1, 2, 3, 1, 2, 3, 1]
        └ 1,2,3,1 ┘ 완성! → 제거하면 남은 [2,1]과 뒤쪽이 붙어
[2, 1,            2, 3, 1]
    └  1,2,3,1  ┘ 또 완성!  → 총 2개
```

이렇게 "맨 위 일부를 보고 조건이 맞으면 빼낸다"는 동작은 **스택**으로 정확히 표현된다. 재료를 하나씩 쌓고, 쌓을 때마다 스택 맨 위 4개가 `1-2-3-1`인지 검사해 맞으면 4개를 제거하고 카운트한다.

> **⚠️ 흔한 오답**: `count`를 1→2→3→4로 순차 증가시키며 세는 방식은 제거 후 재료가 다시 맞붙는 경우를 놓친다. 위 예제에서 정답은 2지만 이 방식은 1을 반환한다. 반드시 스택(또는 제자리 스택)으로 풀어야 한다.

## 💡 풀이 방법 1 — 스택 (가장 직관적)

**알고리즘**: 스택

별도의 `stk` 벡터에 재료를 쌓고, 맨 위 4개가 `1-2-3-1`이면 `resize`로 4개를 잘라낸다.

```
1. 재료 cur를 stk에 push
2. top = stk 크기
3. top >= 4 이고 stk 맨 위 4개가 1-2-3-1이면
   - stk를 top-4 크기로 줄이기 (4개 제거)
   - answer++
```

```cpp
stk.emplace_back(cur);

int top = stk.size();

if (top >= 4 && stk[top - 4] == 1 && stk[top - 3] == 2 && stk[top - 2] == 3 && stk[top - 1] == 1)
{
    stk.resize(top - 4); // 사용한 재료 4개 제거

    answer++;
}
```

## 💡 풀이 방법 2 — 제자리(in-place) 스택

**알고리즘**: 스택 (입력 배열 재사용)

별도 스택을 만들지 않고 **입력 배열 `ingredient` 자체를 스택으로 덮어쓴다**. `top` 인덱스가 "현재 스택 높이"를 가리키며, push는 `ingredient[top++] = cur`, pop 4개는 `top -= 4` 한 줄로 끝난다. 추가 메모리를 전혀 쓰지 않는 점이 강점이다.

```
1. ingredient[top++] = cur   (현재 위치에 재료 쓰기)
2. top >= 4 이고 맨 위 4개가 1-2-3-1이면
   - top -= 4   (포인터만 되돌리면 곧 덮어써짐)
   - answer++
```

```cpp
ingredient[top++] = cur; // 스택 맨 위에 쌓기

if (top >= 4 && ingredient[top - 4] == 1 && ingredient[top - 3] == 2 && ingredient[top - 2] == 3 && ingredient[top - 1] == 1)
{
    top -= 4; // 사용한 4개만큼 포인터 되돌리기

    answer++;
}
```

> **📝 핵심**: `top`을 되돌려두면 다음 재료가 그 자리를 자연스럽게 덮어쓰므로 따로 지울 필요가 없다.

## 🔄 두 풀이 비교

| 항목 | 풀이 1 (별도 스택) | 풀이 2 (제자리 스택) |
|------|------------------|--------------------|
| 추가 메모리 | O(N) (`stk` 벡터) | O(1) (인덱스 하나) |
| push | `stk.emplace_back(cur)` | `ingredient[top++] = cur` |
| pop 4개 | `stk.resize(top - 4)` | `top -= 4` |
| 입력 보존 | 보존됨 | 덮어써짐(파괴적) |
| 가독성 | 매우 직관적 | 약간의 트릭 필요 |

> 동작 원리는 완전히 같다. 풀이 2는 "입력 배열을 그대로 스택으로 본다"는 발상으로 메모리를 절약한 최적화 버전이다.

## 🔑 핵심 개념

### 1️⃣ 맨 위 4개만 검사 — 스택의 부분 패턴 매칭

햄버거 완성 조건은 항상 **스택 맨 위 연속 4개**로만 결정된다. 따라서 매번 전체를 훑지 않고 `top-4 ~ top-1` 네 칸만 확인하면 된다.

```cpp
stk[top - 4] == 1 && stk[top - 3] == 2 && stk[top - 2] == 3 && stk[top - 1] == 1
```

### 2️⃣ 제거 후 재결합 — 스택이어야 하는 이유

`1-2-3-1`을 빼내면 그 아래 재료와 위 재료가 새로 인접한다. 스택은 pop 즉시 새 맨 위가 드러나므로, 다음 push에서 곧바로 재결합된 패턴을 검사할 수 있다. 단순 카운트 방식이 틀리는 핵심 지점이 바로 이 "재결합"이다.

### 3️⃣ 배열을 스택으로 재사용 (풀이 2)

스택은 결국 "맨 위 인덱스 하나 + 연속 메모리"면 충분하다. 입력 배열이 이미 연속 메모리이므로, `top` 인덱스만 따로 두면 별도 컨테이너 없이 스택을 구현할 수 있다. 빼낸 자리는 어차피 다음 push가 덮어쓰므로 명시적 삭제도 불필요하다.

## ⏱️ 시간복잡도

**O(N)** — N은 `ingredient`의 길이.

- 각 재료는 정확히 한 번 push되고, 햄버거로 완성될 때 한 번 pop된다 → 총 연산은 N에 비례.
- 두 풀이 모두 동일하게 O(N)이며, 차이는 공간복잡도(풀이 1 = O(N), 풀이 2 = O(1))에 있다.
