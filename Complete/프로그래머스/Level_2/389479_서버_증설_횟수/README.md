## 🤔 접근법

24시간 동안 시간대별 이용자 수가 주어질 때, 최소 증설 횟수를 구하는 시뮬레이션 문제.

기본 서버 1대가 이미 운영 중이며, 증설 서버 1대당 m명을 추가 수용한다.

이용자가 n×m명 이상 (n+1)×m명 미만이면 n대를 증설 → `neededCnt = players[i] / m`.
증설된 서버는 k시간 후 반납되므로, **현재 운영 중인 서버 수**를 추적하면서 부족한 만큼만 추가 증설한다.

---

## 💡 정답 풀이 방법

**알고리즘**: 시뮬레이션

```
매 시간 i:
  1. 만료된 서버 반납
  2. neededCnt = players[i] / m
  3. runningCnt < neededCnt 이면 (neededCnt - runningCnt)대 증설
  4. increaseCnt += 증설 수
```

---

## 🔑 핵심 개념

### 1️⃣ 기본 서버 + 증설 서버

기본 서버 1대가 항상 동작 중 → 이용자가 m명 미만이면 증설 불필요.

```
n×m ≤ users < (n+1)×m  →  n대 증설 필요
총 수용 인원 = (기본 1대 + 증설 n대) × m = (n+1) × m ≥ users
→  neededCnt = users / m  (정수 나눗셈)
```

```
users=4, m=3  →  neededCnt = 4/3 = 1  →  1대만 증설
총 수용 = (1+1) × 3 = 6 ≥ 4  ✅
```

### 2️⃣ 부족분만 증설

이미 운영 중인 서버를 재활용하고 부족한 차이만 추가한다.

```cpp
int addCnt = neededCnt - runningCnt;
```

### 3️⃣ 만료 시간 관리

서버를 i시에 증설하면 k시간 후인 i+k시에 반납.  
이 만료 정보를 **Queue** 또는 **배열**로 관리하는 두 가지 방법이 있다.

---

## 🔄 두 풀이 비교

| 항목 | Queue 풀이 | 배열 풀이 |
|------|-----------|---------|
| 만료 등록 | `expireQ.emplace(i+k, addCnt)` | `expire[i+k] += addCnt` |
| 만료 처리 | `while (front().first <= i)` 반복 체크 | `runningCnt -= expire[i]` 한 줄 |
| 가독성 | 보통 | 직관적 |
| 범용성 | 시간 범위 제한 없이 동작 | 24시간 고정에 특화 |
| 적합한 상황 | 시간 범위가 가변적인 문제 | 이 문제처럼 시간이 고정된 경우 |

> **📝 핵심**: 배열 풀이가 가능한 이유는 `players.size() == 24` 고정이기 때문.  
> 시간 범위가 가변적이었다면 Queue 풀이가 정석.

---

## 📌 언제 어느 풀이를 써야 하는가?

**Queue를 써야 하는 경우:**
- 입력 크기가 가변적이거나 매우 큰 경우
- 배열 크기를 정적으로 잡기 어려운 경우
- 만료 조건이 단순 시간이 아닌 복잡한 조건인 경우

**배열을 써야 하는 경우:**
- 시간 범위가 고정되어 있는 경우 (이 문제: 항상 24시간)
- 간결한 코드가 필요한 경우
- 인덱스로 만료 시점에 직접 접근 가능한 경우

## ⏱️ 시간복잡도

**O(n)** — n = players.size() = 24 (고정)

- Queue 풀이: 각 서버 묶음이 enqueue / dequeue 각 1회 → O(n)
- 배열 풀이: 단순 배열 인덱스 접근 → O(n)
