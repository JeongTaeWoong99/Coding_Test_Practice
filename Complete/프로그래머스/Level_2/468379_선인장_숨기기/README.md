## 🤔 접근법

m×n 격자에 h×w 크기의 선인장 구역을 배치할 때, **비를 가장 늦게 맞는 위치**를 찾는 문제.  

선인장 구역의 첫 피해 시점 = 구역 내 셀의 **최솟값(min)**.  
이 최솟값이 **최대(max)** 인 위치를 찾으면 된다 → **max of min** 문제.

INF(비가 오지 않는 셀)가 포함된 윈도우는 영원히 안 맞으므로 최적의 자리.

---

## ❌ 왜 나이브 방식이 안 되는가

처음 생각할 수 있는 방법: **모든 (m-h+1)×(n-w+1) 위치마다 h×w 범위를 직접 순회**하여 min 확인.

```
모든 위치 수 : (m - h + 1) × (n - w + 1)
각 위치마다 min : h × w 번 비교

→ 총 시간복잡도 : O((m-h+1)(n-w+1) × h × w)
```

**최악의 경우 예시** (m=n=707, h=w=353):

```
위치 수 ≈ 355 × 355 ≈ 126,025
윈도우 크기 ≈ 353 × 353 ≈ 124,609

총 연산 ≈ 126,025 × 124,609 ≈ 15,700,000,000 (약 157억)
```

제약 조건 m×n ≤ 500,000이므로 **TLE 확실**.

## ✅ 왜 슬라이딩 윈도우를 써야 하는가

2D 직사각형 범위의 min은 **1D 슬라이딩 윈도우 min을 두 번** 적용하면 O(m×n)에 구할 수 있다.

```
min(직사각형 [i..i+h-1][j..j+w-1])
  = min( min(행 i의 열 j~j+w-1),
         min(행 i+1의 열 j~j+w-1),
         ...
         min(행 i+h-1의 열 j~j+w-1) )
  = 열 방향 min( 행 방향 min )
```

**Step 1**: 각 행에 너비 w의 1D 슬라이딩 윈도우 min → rowMin[i][j]  
**Step 2**: rowMin의 각 열에 높이 h의 1D 슬라이딩 윈도우 min → result[i][j]

```
예시 (m=4, n=5, h=2, w=2):

원본 grid:          Step 1 (행 방향):     Step 2 (열 방향):
1  ∞  ∞  ∞  8       1  ∞  ∞  8            1  ∞  ∞  8
∞  5  ∞  3  ∞   →   5  5  3  3     →      5  5  3  3
∞  ∞  6  7  4       ∞  6  6  4            ∞  6  3  3
∞  2  ∞  ∞  ∞       2  2  ∞  ∞            2  2  6  4

result[2][2] = 6 = 최댓값 → 정답 [2, 2]
```

## ✅ 왜 데크(deque)를 써야 하는가

1D 슬라이딩 윈도우 min을 O(n)에 구하기 위해 **단조 덱(Monotonic Deque)**을 사용한다.

**나이브 방식의 문제:**
```
배열 [3, 1, 4, 1, 5], 윈도우 크기 k=3

j=2: min(3, 1, 4) → 3번 비교
j=3: min(1, 4, 1) → 3번 비교
j=4: min(4, 1, 5) → 3번 비교

→ O(n × k) — 윈도우 이동마다 k번 다시 비교
```

**단조 덱의 핵심 아이디어:**

> 덱은 **항상 앞→뒤 방향으로 값이 증가(단조 증가)**하도록 유지한다.  
> 따라서 **덱의 맨 앞(front) = 현재 윈도우의 최솟값** 이 항상 성립한다.

**덱 유지 규칙 (새 원소 j를 추가할 때):**

```
① while (덱 앞 인덱스가 윈도우 밖) → pop_front()
   이유: 윈도우가 오른쪽으로 이동하면서 왼쪽 원소가 범위를 벗어남

② while (덱 뒤 원소의 값 >= 새 원소의 값) → pop_back()
   이유: 새 원소가 더 작거나 같으므로, 뒤쪽의 큰 원소는
         앞으로 절대 최솟값이 될 수 없음 → 버려도 됨

③ push_back(j)  →  새 원소를 덱 뒤에 추가
```

**추적 예시** (배열 [3, 1, 4, 1, 5], k=3):

```
j=0: ①없음 ②없음 ③push(0) → dq=[0(값3)]
j=1: ①없음 ②3≥1이므로 pop(0) ③push(1) → dq=[1(값1)]
j=2: ①없음 ②1≥4? No ③push(2) → dq=[1(값1),2(값4)]
     → 윈도우[0~2] front=1, min=1 ✅
j=3: ①1≤3-3=0? No ②4≥1이므로 pop(2), 1≥1이므로 pop(1) ③push(3) → dq=[3(값1)]
     → 윈도우[1~3] front=3, min=1 ✅
j=4: ①3≤4-3=1? No ②1≥5? No ③push(4) → dq=[3(값1),4(값5)]
     → 윈도우[2~4] front=3, min=1 ✅
```

각 원소가 덱에 한 번 들어가고 한 번 나오므로 **전체 O(n)**.  
1D를 두 번 적용하면 → 최종 **O(m×n)**.

## 💡 정답 풀이 방법

**알고리즘**: 2D 슬라이딩 윈도우 Min (단조 덱)

```
1. m×n 격자 생성, 모든 셀을 INF로 초기화
2. drops[i] = [r, c] → grid[r][c] = i+1 (비가 오는 순서 기록)
3. Step 1: 각 행에 너비 w의 슬라이딩 윈도우 min → rowMin[m][nc]
4. Step 2: rowMin의 각 열에 높이 h의 슬라이딩 윈도우 min → result[mr][nc]
5. result에서 최댓값(가장 늦게 비 맞는 위치) 탐색 → 정답 [r, c]
```

---

## 🔑 핵심 개념

### 1️⃣ INF 처리

비가 오지 않는 셀(drops에 없는 위치) → `INT_MAX`로 초기화.  
슬라이딩 윈도우 min 계산 시 INF는 "무한대"처럼 작동.  
result에서 INF가 나오면 → 그 윈도우는 영원히 비를 맞지 않음 → 가장 좋은 자리.

```cpp
const int INF = INT_MAX;
vector<int> gridRow(n, INF);
vector<vector<int>> grid(m, gridRow);
```

### 2️⃣ 단조 덱의 ≥ 조건

뒤 제거 조건 `grid[i][dq.back()] >= grid[i][j]`에서 `>=`을 쓰는 이유:  
- 같은 값이 있을 때 오래된 인덱스를 버리고 최신 인덱스 유지
- 윈도우가 이동해도 항상 유효한 최솟값 인덱스를 유지

### 3️⃣ max of min 탐색 시 동점 처리

같은 최댓값이 여러 위치에 있을 때 → `>` (strict) 조건으로 **먼저 발견된 위치** 유지.  
행 우선(row-major) 순회 → 가장 위쪽, 가장 왼쪽 위치 반환.

```
drops → grid:
```

## ⏱️ 시간복잡도

**O(m × n)**
- Step 1: 행 m개 × 각 행 O(n) = O(m×n)
- Step 2: 열 nc개 × 각 열 O(m) = O(m×n)
- Step 3: result 순회 O(mr×nc) ≤ O(m×n)

---

## 💾 공간복잡도

**O(m × n)**  
- grid, rowMin, result 각각 최대 m×n 크기 (m×n ≤ 500,000)
