## 🤔 접근법

m×n 격자에 h×w 크기의 선인장 구역을 배치할 때, **비를 가장 늦게 맞는 위치**를 찾는 문제.

선인장 구역의 첫 피해 시점 = 구역 내 셀의 **최솟값(min)**.  
이 최솟값이 **최대(max)** 인 위치 → **max of min** 문제.

INF(비가 오지 않는 셀)가 포함된 윈도우 = 영원히 안 맞음 = 최적.

---

## ❌ 왜 나이브 방식이 안 되는가

처음 생각: **모든 가능한 위치마다 h×w 범위를 직접 순회**하여 min 확인.

```
총 복잡도 : O((m-h+1) × (n-w+1) × h × w)

최악 예시 (m=n=707, h=w=353):
  위치 수 ≈ 355 × 355 ≈ 126,025
  윈도우  ≈ 353 × 353 ≈ 124,609
  총 연산 ≈ 15,700,000,000 (약 157억) → TLE
```

---

## ✅ 왜 슬라이딩 윈도우를 써야 하는가

2D 직사각형 범위 min은 **1D 슬라이딩 윈도우 min을 두 번** 적용하면 O(m×n)에 구할 수 있다.

```
min(직사각형) = 열 방향 min( 행 방향 min )

Step 1: 각 행에 너비 w의 1D 슬라이딩 윈도우 min → rowMin
Step 2: rowMin의 각 열에 높이 h의 1D 슬라이딩 윈도우 min → result
```

---

## 💡 단조 덱 완전 이해

> 1D 슬라이딩 윈도우 min을 **O(n)** 에 구하는 핵심 자료구조.

---

### 📌 Step 0 — "단조 덱"이란?

**Deque(덱)** = 앞·뒤 양쪽에서 삽입/삭제 가능한 자료구조.

**단조 덱(Monotonic Deque)** = 덱에 있는 원소들의 값이 **항상 한 방향으로만 증가**하도록 유지한 덱.

- 최솟값을 구할 때: 앞→뒤로 **증가 (작은 것이 앞에)**
- 덱의 맨 앞(front) = 덱에서 가장 작은 값

```
예) 단조 증가 덱 상태:
  [idx=3(값=1)] → [idx=5(값=3)] → [idx=7(값=4)]
   ↑ front(최솟값=1)                     back ↑
```

---

### 📌 Step 1 — "front = 최솟값"이 항상 성립하는 이유

#### 핵심 불변 조건 유지 방법

새 원소 `j`를 추가할 때 두 가지 규칙을 따른다:

**규칙 ①: 뒤 제거 (단조성 유지)**
```
while (덱 뒤 원소의 값 >= 새 원소의 값)
    pop_back()
```

이 규칙 때문에, 삽입 후에는 반드시:  
`덱 뒤 원소 값 < 새 원소 값` → 앞→뒤로 값이 증가  
→ **front = 가장 작은 값** 이 항상 성립

**규칙 ②: 앞 제거 (윈도우 만료)**
```
while (덱 front 인덱스 <= j - k)
    pop_front()
```

이 규칙 때문에, front는 **항상 현재 윈도우 범위 안**에 있다.

**따라서:**
- front = 덱에서 가장 작은 값 (규칙 ①)
- front = 현재 윈도우 안에 있는 원소 (규칙 ②)
- 결론: **front = 현재 윈도우의 최솟값** ✅

---

### 📌 Step 2 — 뒤 제거의 핵심 통찰

```
왜 arr[back] >= arr[j]인 경우 back을 버려도 되는가?
```

> **"back은 j와 같은 윈도우에 있는 동안 절대로 최솟값이 될 수 없다."**

증명:
- `j`는 `back`보다 나중에 들어왔다 (더 오른쪽 인덱스, `j > back`)
- `arr[j] <= arr[back]` (값이 더 작거나 같다)
- `j`는 `back`보다 나중에 윈도우를 떠난다 (더 최근 원소이므로)

→ back과 j가 같은 윈도우에 있는 모든 순간에, j가 더 작거나 같으므로  
   back은 그 윈도우의 최솟값이 될 수 없다.  
→ back이 혼자 남는 순간(j가 윈도우를 벗어난 시점)에는, back도 이미 윈도우를 벗어난다  
   (back이 j보다 먼저 만료되기 때문)  
→ **결론: back은 어떤 미래 윈도우에서도 최솟값이 될 수 없다 → 버려도 된다!**

### 📌 Step 3 — 완전 추적 예시

배열: `[3, 1, 4, 2, 5]`, 윈도우 크기 k=3

```
j=0 (값=3):
  ① 앞 제거: 덱 비어있음 → 스킵
  ② 뒤 제거: 덱 비어있음 → 스킵
  ③ 삽입:   dq = [0(3)]
  ④ 기록:   j=0 < k-1=2, 아직 윈도우 미완성

j=1 (값=1):
  ① 앞 제거: front=0, 0 ≤ 1-3=-2? NO → 스킵
  ② 뒤 제거: back=0(값=3), 3 ≥ 1? YES → pop
     ▶ 이유: idx=1(값=1)이 idx=0(값=3)보다 작고 더 오래 남음
             idx=0은 절대 최솟값 불가 → 버림
     덱 비어있음, while 종료
  ③ 삽입:   dq = [1(1)]
  ④ 기록:   j=1 < 2, 아직 미완성

j=2 (값=4):
  ① 앞 제거: front=1, 1 ≤ 2-3=-1? NO → 스킵
  ② 뒤 제거: back=1(값=1), 1 ≥ 4? NO → 스킵
     ▶ 이유: 1 < 4이므로 idx=1(값=1)은 아직 최솟값 후보, 유지
  ③ 삽입:   dq = [1(1), 2(4)]
  ④ 기록:   j=2 = k-1 ✅
     front = idx=1, arr[1]=1 → result[0]=1
     윈도우 [0~2] = {3,1,4}, 실제 min=1 ✅

j=3 (값=2):
  ① 앞 제거: front=1, 1 ≤ 3-3=0? NO → 스킵
             (idx=1은 아직 윈도우[1~3] 안)
  ② 뒤 제거: back=2(값=4), 4 ≥ 2? YES → pop
     ▶ 이유: idx=3(값=2)이 idx=2(값=4)보다 작고 더 오래 남음
             idx=2는 절대 최솟값 불가 → 버림
     back=1(값=1), 1 ≥ 2? NO → 스킵 (1 < 2, 유효한 후보)
  ③ 삽입:   dq = [1(1), 3(2)]
  ④ 기록:   j=3 ✅
     front = idx=1, arr[1]=1 → result[1]=1
     윈도우 [1~3] = {1,4,2}, 실제 min=1 ✅

j=4 (값=5):
  ① 앞 제거: front=1, 1 ≤ 4-3=1? YES → pop
     ▶ 이유: 현재 윈도우는 [4-3+1,4] = [2,4]
             idx=1은 범위 밖(인덱스 1 < 2) → 만료, 버림
     front=3, 3 ≤ 1? NO → 스킵
  ② 뒤 제거: back=3(값=2), 2 ≥ 5? NO → 스킵
  ③ 삽입:   dq = [3(2), 4(5)]
  ④ 기록:   j=4 ✅
     front = idx=3, arr[3]=2 → result[2]=2
     윈도우 [2~4] = {4,2,5}, 실제 min=2 ✅

최종 결과: [1, 1, 2] ✅
```

### 📌 Step 4 — 코드와의 1:1 대응

```cpp
for (int j = 0; j < n; j++)
{
    // ① 앞 제거: dq.front()의 인덱스가 윈도우 [j-w+1, j] 밖이면 제거
    //   dq.front() <= j - w  ←→  인덱스 < 윈도우 시작점(j-w+1)
    while (!dq.empty() && dq.front() <= j - w)
    {
        dq.pop_front();
    }

    // ② 뒤 제거: 뒤쪽 값이 현재값보다 크거나 같으면 제거 (단조성 유지)
    //   grid[i][dq.back()] >= grid[i][j]  ←→  뒤쪽 값이 새 값보다 크거나 같음
    while (!dq.empty() && grid[i][dq.back()] >= grid[i][j])
    {
        dq.pop_back();
    }

    // ③ 삽입: 인덱스(j)를 덱 뒤에 추가 (값이 아닌 인덱스를 저장하는 이유:
    //    나중에 앞 제거 조건 체크와 arr[dq.front()] 값 조회에 모두 활용)
    dq.emplace_back(j);

    // ④ 기록: 윈도우가 꽉 찼을 때 (j >= w-1)
    //    dq.front() = 현재 윈도우의 최솟값 인덱스
    //    grid[i][dq.front()] = 그 최솟값
    if (j >= w - 1)
    {
        rowMin[i][j - w + 1] = grid[i][dq.front()];
    }
}
```

**왜 값이 아닌 인덱스를 덱에 저장하는가?**
- 값을 저장하면 "앞 제거" 조건(`인덱스 만료`)을 체크할 수 없다.
- 인덱스를 저장하면 `dq.front()`로 만료 여부 확인 + `arr[dq.front()]`로 최솟값 조회 모두 가능.

---

### 📌 Step 5 — Phase 2 (열 방향)도 동일한 원리

Phase 2에서는 행 방향 대신 **열 방향**으로 같은 논리를 적용한다.

```
Phase 1: 각 행 i마다, j=0~n-1 순회, 너비 w의 윈도우 min → rowMin[i][j]
Phase 2: 각 열 j마다, i=0~m-1 순회, 높이 h의 윈도우 min → result[i][j]
```

Phase 2의 코드에서 달라지는 것:
- `grid[i][dq.back()]` → `rowMin[dq.back()][j]` (행 대신 열 기준)
- `dq.front() <= j - w` → `dq.front() <= i - h` (열 윈도우 대신 행 윈도우)
- `rowMin[i][j - w + 1]` → `result[i - h + 1][j]` (기록 위치)

두 for 루프의 구조는 완전히 동일하다.

## 💡 정답 풀이 방법

**알고리즘**: 2D 슬라이딩 윈도우 Min (단조 덱)

```
1. m×n 격자 생성, 모든 셀 INF로 초기화
2. drops[i]=[r,c] → grid[r][c] = i+1 (비가 오는 순서 기록)
3. Step 1: 각 행에 너비 w 슬라이딩 윈도우 min → rowMin[m][nc]
4. Step 2: rowMin의 각 열에 높이 h 슬라이딩 윈도우 min → result[mr][nc]
5. result에서 최댓값 위치 탐색 → 정답 [r, c]
```

---

## 🔑 핵심 개념

### 1️⃣ INF 처리

비가 오지 않는 셀 = `INT_MAX`로 초기화.  
슬라이딩 윈도우에서 INF는 "무한대"처럼 작동 → min 연산에서 유한값에 밀림.  
result에 INF가 나오면 그 윈도우는 영원히 비를 맞지 않음 = 최적.

### 2️⃣ 덱에 값이 아닌 인덱스를 저장

인덱스를 저장해야:
- 앞 제거 조건(`dq.front() <= j - w`) 체크 가능
- 최솟값은 `arr[dq.front()]`로 조회

### 3️⃣ ≥ 조건 (같은 값도 제거)

`arr[dq.back()] >= arr[j]`에서 `>=` (equal 포함):  
같은 값이 있으면 오래된 것을 버리고 최신 인덱스 유지 → 앞 제거 조건에서 더 오래 유효.

## ⏱️ 시간복잡도

**O(m × n)**
- 각 원소가 덱에 한 번 들어가고 한 번 나옴 → 각 행/열 O(n) 또는 O(m)
- Step 1: m개 행 × O(n) = O(m×n)
- Step 2: nc개 열 × O(m) = O(m×n)

---

## 💾 공간복잡도

**O(m × n)** — grid, rowMin, result 각각 최대 m×n (m×n ≤ 500,000)
