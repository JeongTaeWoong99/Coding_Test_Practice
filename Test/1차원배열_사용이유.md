# 🎯 백준 17143 낚시왕 - 1차원 배열 사용 이유

<br>

## 📊 질문 2: 왜 `a[max_n*max_n]` 1차원 배열로 선언했나?

### 🤔 의문의 코드

```cpp
struct Shark
{
    int yPos, xPos;
    int speed;
    int dir;
    int siz;
    int death;
}
a[max_n*max_n];  // max_n = 100, max_n*max_n = 10,000
```

**질문:**
- 왜 `a[10000]` 1차원 배열?
- `a[100][100]` 2차원 배열이 아닌 이유?

<br>

---

## 🎯 핵심: 상어는 "객체"이고, 위치는 "속성"이다

### 📋 데이터 구조 설계 철학

이 문제에서 관리해야 할 것은 **2가지**입니다:

1. **각 상어의 정보** (속력, 방향, 크기 등) → `Shark 구조체 배열`
2. **격자판의 상태** (각 칸에 어떤 상어가 있는지) → `shark[y][x]` 2차원 배열

<br>

---

## 🔍 1차원 배열로 선언한 이유

### ✅ 이유 1: 상어는 독립적인 개체

**상어의 특징:**
- 각 상어는 고유한 ID(인덱스)를 가짐
- 상어는 이동하면서 위치가 바뀜
- 하지만 속력, 크기, 방향 등의 **정체성**은 유지됨

**예시:**
```cpp
// 1번 상어의 정보
a[1].yPos = 3;   // 현재 y 위치 (변함)
a[1].xPos = 2;   // 현재 x 위치 (변함)
a[1].speed = 5;  // 속력 (고정)
a[1].dir = 0;    // 방향 (변할 수 있음)
a[1].siz = 8;    // 크기 (고정)
a[1].death = 0;  // 죽음 여부 (변할 수 있음)

// 2번 상어의 정보
a[2].yPos = 1;
a[2].xPos = 4;
a[2].speed = 3;
// ...
```

**핵심:**
- `a[1]` = "1번 상어"라는 객체
- `a[2]` = "2번 상어"라는 객체
- 인덱스 = 상어의 고유 ID

<br>

### ✅ 이유 2: 위치와 객체를 분리

**2차원 배열 `shark[y][x]`는 따로 관리:**

```cpp
int shark[100][100];  // 격자판: 각 칸에 있는 상어의 ID 저장
```

**데이터 구조:**
```
a[1] = {yPos: 3, xPos: 2, speed: 5, ...}  → 1번 상어 정보
a[2] = {yPos: 1, xPos: 4, speed: 3, ...}  → 2번 상어 정보

shark[3][2] = 1  → (3, 2) 위치에 1번 상어가 있음
shark[1][4] = 2  → (1, 4) 위치에 2번 상어가 있음
shark[0][0] = 0  → (0, 0) 위치는 빈 칸
```

**장점:**
- 상어가 이동해도 `a[i]`의 인덱스는 변하지 않음
- 상어 정보에 빠르게 접근 가능 (O(1))
- 격자판에서 상어를 쉽게 추가/삭제 가능

<br>

## 🆚 만약 2차원 배열로 했다면?

### ❌ 잘못된 설계 예시

```cpp
Shark a[100][100];  // 격자판 모양으로 상어 정보 저장?
```

**문제점:**

**1️⃣ 상어 이동 시 복잡함**
```cpp
// 상어가 (3, 2)에서 (5, 7)로 이동하면?
a[5][7] = a[3][2];  // 복사
a[3][2] = {0, 0, 0, 0, 0, 0};  // 초기화 필요

// 만약 상어가 10칸 이동하면 10번 복사해야 함!
```

**2️⃣ 상어 추적 불가능**
```cpp
// "1번 상어"가 어디 있는지 찾으려면?
for(int y = 0; y < R; y++)
{
    for(int x = 0; x < C; x++)
    {
        if(a[y][x]의 ID가 1이면) 찾았다!
    }
}
// O(R × C) 시간 소요! 비효율적
```

**3️⃣ 메모리 낭비**
```cpp
// 격자판 10,000칸 모두에 Shark 구조체 할당
// 하지만 실제 상어는 최대 M마리 (문제에서 M ≤ 10,000)
// 빈 칸에도 구조체를 할당하면 메모리 낭비
```

<br>

---

## ✅ 현재 설계의 장점

### 🎯 효율적인 분리 설계

```cpp
// 1. 상어 정보 배열 (1차원)
Shark a[10000];  // 상어 ID → 상어 정보 매핑

// 2. 격자판 (2차원)
int shark[100][100];  // (y, x) → 상어 ID 매핑
```

**연결 구조:**
```
격자판 shark[3][2] = 1
           ↓
        (인덱스 1로 접근)
           ↓
상어 정보 a[1] = {yPos: 3, xPos: 2, speed: 5, ...}
```

**장점 정리:**

| 작업 | 시간 복잡도 | 방법 |
|-----|-----------|------|
| 상어 정보 조회 | O(1) | `a[i]` |
| 특정 위치의 상어 찾기 | O(1) | `shark[y][x]` |
| 상어 이동 | O(1) | `a[i].yPos = ny; a[i].xPos = nx;` |
| 격자판 업데이트 | O(1) | `shark[ny][nx] = i;` |

<br>

## 📊 메모리 사용량 비교

### 현재 설계 (1차원 배열)

```cpp
Shark a[10000];        // 10,000 × sizeof(Shark) = 10,000 × 24 = 240KB
int shark[100][100];   // 100 × 100 × 4 = 40KB
                       // 총: 약 280KB
```

### 만약 2차원 배열로 설계했다면

```cpp
Shark a[100][100];     // 10,000 × sizeof(Shark) = 240KB
// 하지만 빈 칸도 Shark 구조체를 할당해야 함
// 메모리는 비슷하지만 로직이 복잡해짐
```

## 🎯 왜 max_n*max_n = 10,000인가?

### 문제 조건 확인

```
2 ≤ R, C ≤ 100
0 ≤ M ≤ R×C
```

**의미:**
- 격자판 최대 크기: 100 × 100 = 10,000칸
- 상어 최대 개수: M ≤ R×C ≤ 10,000마리
- 각 칸에 최대 1마리만 있을 수 있으므로, 상어는 최대 10,000마리

**따라서:**
```cpp
a[max_n * max_n]  // a[10000]
// → 상어를 인덱스 1부터 M(≤10,000)까지 저장
```

**인덱스 사용 방식:**
```cpp
for (int i = 1; i <= M; i++)  // 1번부터 M번까지 상어
{
    a[i].yPos = ...;
    a[i].xPos = ...;
    // ...
}
```

## 💡 정리

### 핵심 개념

**1차원 배열 `a[10000]`:**
- **목적:** 각 상어의 정보 저장 (객체 배열)
- **인덱스:** 상어의 고유 ID (1 ~ M)
- **내용:** 위치, 속력, 방향, 크기, 죽음 여부

**2차원 배열 `shark[100][100]`:**
- **목적:** 격자판 상태 저장 (위치 맵)
- **인덱스:** (y, x) 좌표
- **내용:** 해당 칸에 있는 상어의 ID (0이면 빈 칸)

**설계 철학:**
```
객체(상어) ≠ 위치(격자판)
→ 분리해서 관리하는 것이 효율적!
```

**비유:**
- `a[]` = 학생 명부 (학생 ID → 학생 정보)
- `shark[][]` = 교실 좌석표 (좌석 위치 → 앉아있는 학생 ID)
- 학생이 자리를 옮겨도 학생 정보는 그대로, 좌석표만 업데이트!

## 🎯 결론

| 질문 | 답변 |
|-----|------|
| **왜 1차원 배열?** | 상어는 독립적인 객체, 인덱스 = 상어 ID |
| **왜 2차원 아님?** | 위치는 별도로 `shark[y][x]`로 관리 |
| **왜 10000?** | 상어 최대 개수 = R×C ≤ 10,000 |
| **장점?** | 빠른 조회(O(1)), 쉬운 이동, 명확한 구조 |
